C# Server Plugins#

Besides Lua scripts, the World server loads plugins: .NET assemblies built against Axiom.Plugins.Api. Use a plugin when you want compiled C#, NuGet packages, typed events and hooks that can change or stop what the game is about to do (XP, damage, items, shop prices, quests, chat). Use Lua for quick content scripting.

Piece File Job
Axiom.Plugins.Api src/Shared/Axiom.Plugins.Api The contract: IAxiomPlugin, IPluginContext, events, hooks, IPlayer, commands, messages. Version PluginApi.Version (1.0).
PluginCatalog Core/Plugins/PluginCatalog.cs Finds Plugins/*/plugin.json, checks ids, API version and dependencies, orders them, loads each into its own AssemblyLoadContext. Once per process.
PluginHost Core/Plugins/PluginHost.cs One per zone host: makes this host's copy of every plugin, raises events, runs hooks, routes .commands and plugin messages, .plugins.
PluginPlayer Core/Plugins/PluginPlayer.cs IPlayer over a PlayerSession.
PluginsConfig Utils/Config/PluginsConfig.cs World:Plugins in appsettings.
Sample src/Plugins/Axiom.SamplePlugin Every feature in one file: events, hooks, commands, config, shared state, timers, messages.

A plugin's folder#

The server looks in World:Plugins:Directory (default Plugins, next to the server executable), one folder per plugin:

Plugins/sample/
├── plugin.json              the manifest
├── config.json              optional settings (comments and trailing commas allowed)
├── Axiom.SamplePlugin.dll   the entry assembly (+ its own dependencies)
└── data/                    IPluginContext.DataDirectory: files the plugin may write

{
  "id": "sample",                       // a-z 0-9 _ -, 2-48 characters
  "name": "Sample Plugin",
  "version": "1.0.0",
  "apiVersion": "1.0",                  // loads when the major matches and the minor isn't newer than the server's
  "assembly": "Axiom.SamplePlugin.dll",
  "entry": "",                          // optional: the IAxiomPlugin class (default: the first public one)
  "dependsOn": [],                      // must load first; this plugin is skipped if one is missing
  "loadAfter": []                       // load first if present
}

World:Plugins: Enabled (true), Directory, Disabled (ids not to load, and whatever depends on them), AllowReload (false). See the Configuration reference.

Writing one#

// MyPlugin.cs - a class library, net10.0, <EnableDynamicLoading>true</EnableDynamicLoading>,
// referencing Axiom.Plugins.Api with Private=false and ExcludeAssets=runtime (the server supplies it).
using Axiom.Plugins;

public sealed class DoubleXpWeekend : IAxiomPlugin
{
    public void Load(IPluginContext ctx)
    {
        double mult = ctx.Config.Get("multiplier", 2.0);

        ctx.Hooks.Register<ExperienceHook>(h =>
        {
            if (DateTime.Now.DayOfWeek is DayOfWeek.Saturday or DayOfWeek.Sunday)
                h.Amount = (int)Math.Min(int.MaxValue, h.Amount * mult);
        });

        ctx.Events.On<PlayerEnteredWorld>(e => e.Player.SendMessage($"Weekend XP is x{mult}."));
        ctx.Commands.Register("xp", "Show the XP multiplier.", 1, (player, args) => $"XP x{mult} on weekends.");
    }
}

Build, copy the DLL with plugin.json (and config.json) into Plugins/<id>/, restart the World server. The log says [Plugins] … for every plugin loaded or skipped, and why.

What a plugin gets#

IPluginContext
Events.On<T> things that happened: PlayerEnteredWorld, PlayerLeftWorld, PlayerLevelledUp, PlayerDied, PlayerChatted, NpcKilled, PlayerKilled, Interacted, ItemUsed, ItemObtained, Harvested, Crafted, SkillUsed, ZoneEntered, DoodadUsed, Traded, TradePackSold, AchievementEarned, and AnyPlayerEvent (any Lua event by name, e.g. OnTheft).
Hooks.Register<T> change or stop things before they happen: ChatHook (edit the message), ExperienceHook (Amount), DamageHook (Amount; players or NPC template ids), ItemGainHook (Quantity), ShopPurchaseHook (UnitPrice), QuestAcceptHook. h.Deny("reason") cancels and tells the player. Hooks run in load order; each sees what the previous one changed.
Commands.Register .name args in any chat channel, with a minimum access level (1 everyone, 3+ staff). Checked before Lua's commands.
Players this zone thread's players (TryGet, TryFind, All), CountEverywhere, IsOnlineAnywhere, BroadcastMessage, Announce.
IPlayer ids, name, level, class, position, zone, instance, health, gold; SendMessage, SendAnnouncement, GiveGold/TakeGold, GiveItem/TakeItem/CountItem (all or nothing), Teleport, Kick, SendPluginMessage.
Scheduler After(ms), Every(ms), NowMs - on this copy's thread.
Config Get<T>("rewards:gold", fallback), Bind<T>("section") over config.json.
Shared one thread-safe store for every copy of the plugin (AddOrUpdate is atomic).
Host Index, Name, IsHome, ZoneThreads, HostCount; Broadcast / OnBroadcast to the copies on the other zone threads.
Messages.On data from a client mod on a named channel (C2WPluginMessage 183); reply with IPlayer.SendPluginMessage (W2CPluginMessage 182). Max 16 KiB, channel names up to 64 characters. The stock client ignores them.
Log, Info, DataDirectory logging into the server log, the manifest, a writable folder.

Threading#

The server runs one copy of your plugin per zone thread (one copy without zone threads). Load, events, hooks, commands, messages and timers of a copy all run on that copy's thread, one at a time, so a plugin never needs a lock for its own fields. What every copy must agree on goes in ctx.Shared; work for the others goes through ctx.Host.Broadcast. Jobs that must happen once per server go behind if (ctx.Host.IsHome). A player object is only valid on the thread that gave it to you: keep the NetworkId or name, not the object.

An exception in a plugin is caught and logged ([Plugins] <id> threw in <what> on <host>) and never reaches the game; the first 20, then every 1000th, are logged.

Loading, reloading, .plugins#

Each plugin gets its own AssemblyLoadContext: its dependencies are its own (two plugins may ship different versions of a library), but Axiom.Plugins.Api always comes from the server. Assemblies are loaded from memory, so a rebuilt DLL can be copied over a running server.

.plugins in chat lists the plugins and the commands you may use (staff also see skipped plugins and why). With World:Plugins:AllowReload true, staff can .plugins reload <id>: every zone host drops its copy, the code is loaded again and new copies start. It's for development: the shared store starts empty.

Notes#

  • IPluginContext.Config's comment mentions overriding a plugin's settings from appsettings (Plugins:Config:<id>); the current server only reads config.json.
  • The sample's .csproj writes its build straight to a fixed OutputPath (F:\Development\…\plugins_bin\sample_plugin). Change it to your server's Plugins/sample folder.
