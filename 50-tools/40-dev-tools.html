Tools

Dev Tools#

Tools ▸ Axiom ▸ Dev Tools (Shift+Alt+D). A sidebar of tabs grouped by category, a status bar of service pills (World DB ● Auth ● Persistence ● World ● Data, click for details), and a shared log at the bottom (filter by level/source, Copy, Clear). Ctrl+F searches tabs, Ctrl+PageUp/PageDown switches. A tab with unsaved work gets a dot, and closing the window warns.

All tabs read their paths from one place, the Settings tab (ProjectSettings/AxiomDevTools.asset), so two tabs can never point at different copies of the database. Each tab's ? button opens its guide. The full generated list of tabs is in the Editor menu reference.

Project#

Overview#

The first screen: is the stack healthy?

  • Servers: Auth, Persistence, World, Auction, MySQL up or down.
  • World DB: which file, locked by a running server or not, patches it hasn't applied.
  • Game data: gamedata.bin in StreamingAssets vs what Auth serves vs what Play Mode last downloaded, with a rebuild button.
  • Protocol: Axiom.Network.dll in Assets/AxiomMMOKit/Plugins vs the source it was built from.
  • Content: how much is in the database, what's missing art. Shortcuts to common tools.

Everything red has a sentence saying what to do.

Settings#

Every path the tools use, on one page (Dev Tools 3.1). Set the server repository once (or Auto-detect: it looks next to the Unity project, up to four folders up and two down) and the rest is worked out from the server's own layout (src/Servers/…; older src/Axiom.Server.World layouts are found too):

Path Default
World database the newest worldserver.db of Axiom.Server.World (a bin/**/Data/ copy is what a running server uses). Use this one pins a copy
SQL patches src/Servers/Axiom.Server.World/SQL/patches
Server Data folder src/Servers/Axiom.Server.World/Data (movement collision, navmesh, zone map, NPC collision follow it)
NavBake tool src/Tools/Axiom.Tools.NavBake
Auth game data every built Axiom.Server.Auth under bin/
Tile scenes Assets/AxiomMMOKit/Axiom.Client/World/Tiles

Change… overrides one row, Use default goes back. Green is ready, yellow is needed by one feature only, red is required: a red row puts a banner on every tab and a number on the Settings tab. Exports into the server's Data folder are also written to each built copy under bin/, so a restart picks them up. It replaces the path pickers that used to be spread over the Hub and the Game Data, SQL Patches, World Map, NavMesh, Zones and World Tiles tabs; old per-tool preferences are brought over once. Details: Editor settings.

Content & Data#

Tab
Content Studio entry point to the Content Studio window.
Game Data the client content pipeline: read items and gear visuals from the active world DB → pack (AGDB) → AES-256 encrypt → write gamedata.bin to StreamingAssets and the output folder. One green button (SyncAndExport, also used by the Hub and the Item wizard). Copying to the Auth server stays a deliberate manual step (or let the World server's OutputPaths write it) so a tool never overwrites a deployed build. "Decrypt → Inspect" writes a readable copy outside StreamingAssets.
SQL Patches browse the server's SQL/patches (applied or not), open a patch, write a new one from the SQL box (unsaved SQL marks the tab). Patch rules: worldserver.db.

Characters & Gear#

Tab
Characters & Races races (ids, names, faction), bodies: a drop slot for every key CharacterBodyKeys looks for (Character_{Race}_{Gender} …) and what each falls back to; Wardrobe: every gear visual against every body, which prefab variant each body will actually wear, warnings where skinned armour would land on the wrong rig.
Gear Workshop pick an item and a body, drop the gear prefab, adjust slot, sockets, hidden body parts and offsets live in the Scene, then Save for everyone (the item's GearVisuals row, DB + patch) or Save as variant (IronPlate_Female prefab beside the base, no DB change). Outfits: import a modular outfit pack (one HDRP material per outfit, one prefab per part).

See Characters, gear & animation and Asset & character pipeline.

World Building#

Tab
World Map the world at a glance (tiles, zones, spawners, markers), and NPC spawners with two-way sync: Load, DB → Scene (a NpcSpawnerMarker per NpcSpawners row), move/edit markers, Scene → DB (new, moved, edited, deleted rows in one transaction) or Export Patch. + Add at Camera. Every marker carries its DbId, so the tab computes a real diff.
Doodads world objects (DoodadSpawns): Load (all or near the Scene view) with a model preview per marker; Place: pick an object and click the ground (Shift keeps rotation); move/rotate/scale; Save writes one numbered patch (and the DB unless locked). Only loaded rows can be deleted by removing markers, so an empty scene can never wipe the table.
Spawn Points player spawn/respawn points (SpawnPointTables) as PlayerSpawnPointMarkers: Load, DB → Scene, Scene → DB, + Add at Camera; exactly one default.
World Tiles the tile grid: create aligned 512 m terrain tiles, Preview split / Split active scene into tile scenes, Add all tile scenes to Build Settings, Export All Terrain (heightmaps for the server), Validate world partition (oversized terrains, objects outside their tile...).
HLOD Proxies bake each tile's far proxy (TileProxyBaker), only what changed; preview in the Scene view.
Zones define zones (key, names, levels, PvP mode, colour), paint them on 32 m cells with a brush on a top-down map or on the terrain, Open zone (every tile it touches), Organize tile scenes into zone folders, Save to StreamingAssets and the server.
NavMesh bake the server navmesh from the exported movement collision (only changed pages), overlay walkable areas and blocking edges.

Workflows: World tools.

Diagnostics#

Validate runs the checks that are invisible in a table view and only show at runtime as "why isn't this NPC spawning":

  • spawners referencing a TemplateId with no NpcTemplates row (the server skips them);
  • Count ≤ 0 or negative Radius;
  • spawners with no collider beneath them (needs markers loaded with World Map ▸ DB → Scene) - NPCs would fall;
  • stacked duplicates at the same rounded coordinates (an accidental double export doubles the NPCs);
  • no default spawn point (players can't enter the world) or more than one.

Broader checks: Validation.

Writing a tab#

Implement IDevToolsTab (Title, Order, OnEnable/OnDisable/OnGUI, optional OnSceneGUI, HasUnsavedChanges, Category (a DevToolsCategories group), Icon, Description, HelpDoc (a Markdown file name in docs/)); no registration needed. Read paths from AxiomProjectPaths / AxiomEditor, never a path field of your own. Example in The editor suite.
