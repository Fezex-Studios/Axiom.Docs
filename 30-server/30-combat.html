Server Systems

Combat, Effects & Statuses#

Combat in Axiom is data-driven and unified: a sword swing, a fireball, a health potion, a poison tick and an NPC's ability all become lists of effects carried out by one EffectApplier, rolled with one set of formulas from one table of numbers.

Piece File Job
CombatManager Core/Combat/CombatManager.cs The cast pipeline, NPC swings, hits, death, respawn.
Effect, EffectCatalog Core/Effects Effects loaded from the Effects table, per owner.
EffectApplier Core/Effects/EffectApplier.cs Check then Apply a list of effects. The only place health goes down or up.
StatusManager, StatusHost Core/Statuses Buffs, debuffs, DoTs/HoTs, crowd control, stacking, dispels.
StatsService, StatSheet Core/Stats Every stat, recalculated when level, gear or statuses change; regen.
GameRules Core/Rules/GameRules.cs Every formula number, from CombatRules.
CombatMath Core/Combat/CombatMath.cs Miss, glance, crit, armor, resistance, power scaling.
ThreatService Core/Threat NPC aggro (NPCs).
AreaTargeting, LineOfSight Core/Combat Who an area hit catches; terrain line of sight.
AbilityManager, AbilityCatalog Core/Abilities Classes, learned skills and ranks, passives, hotbar (Progression).
InteractionSkillService Core/Interaction Skills used on world objects (gathering, furniture).

The cast pipeline#

The client sends C2WAttack { SkillId, TargetNetworkId, Yaw } (opcode 52; C2WAttackHandler). CombatManager.TryUseAbility checks, refusing before anything is spent:

  1. Caster in the world and alive.
  2. The ability exists and they know it (AbilityManager).
  3. Not stunned; not silenced (for spells).
  4. Not already casting.
  5. Off cooldown and off the global cooldown (silently dropped otherwise).
  6. Standing still, if the cast needs it (CastWhileMoving = 0).
  7. A valid target for its TargetRule (0 Enemy, 1 Self, 2 Friendly, 3 Area enemies, 4 Area allies, 5 Doodad): attackable, in range (+ RangeTolerance, + slack for a moving target), in line of sight, in the facing cone if RequiresFacing, PvP allowed for players.
  8. Enough mana.
  9. EffectApplier.Check says every effect can land.
  10. Start the global cooldown.

Then:

  • Instant (CastTimeMs = 0): goes off now.
  • Cast time (shortened by Haste): W2CCastStart to everyone who can see the caster; the Scheduler completes it later unless moving, a stun, a silence, an Interrupt effect, death or C2WCancelCast ends it (W2CCastEnd). At completion the target is checked again (dead, out of range, behind a hill?).
  • Going off: spend mana, start the skill's cooldown (hasted), run its effects on each target (scaled by rank: RankBonusPct per rank), deliver each hit.

DeliverHit is the single "a hit happened" path for abilities, NPC swings and DoT ticks: W2CCombatEvent to everyone who can see the target, the victim's health update, death handling.

Effects#

Every row of Effects is one thing that happens. Columns:

Column Meaning
OwnerType, OwnerId whose effect: 1 Item, 2 Skill, 3 Status (a tick), 4 legacy doodad func, 5 Doodad function template, 6 Skill step
Sort order within the owner's list
Kind the verb (below)
Target 0 self, 1 the target
Min, Max amount range (damage, heal), or stacks/count depending on kind
RefId what the kind refers to (status, skill, item, doodad template, mount...)
DurationMs for statuses, taunts, mounts
School 0 Physical, 1 Fire, 2 Frost, 3 Nature, 4 Arcane, 5 Holy, 6 Shadow
Coefficient power scaling: amount += coefficient × AttackPower (physical) or SpellPower (magic) / HealingPower (heals)
RequiresStatus, BonusStatus + BonusPct, ConsumesStatus combos: only if the target has a status; bigger if it does; remove it afterwards
Script Lua hook name for Kind = 0

Effect kinds#

# Kind Does
0 Script nothing itself; the caller fires a Lua hook (OnItemUse...)
1 Heal roll heal (crit, HealingPower, HealingDonePct), heal threat
2 Apply Status StatusManager.Apply(RefId); Min = stacks, DurationMs overrides
3 Cast Skill run another skill's effects (sub-skills)
4 Mount mount RefId
5 Summon Pet pet template RefId
6 Damage roll damage: miss/glance/crit, armor or resistance, DamageDone/Taken, threat
7 Dispel remove statuses of dispel type RefId (Min 0 debuffs / 1 buffs, Max count)
8 Taunt NPC fixates on the caster for DurationMs
9 Interrupt stop the target's cast
10 Summon NPC Min..Max adds of template RefId (NPC abilities)
11 Give Item TryAddItem(RefId, Min..Max) (harvests, chests)
12 Place Doodad place doodad template RefId (seeds, kits)
13–41 world verbs open crafting, enter/leave dungeon, take gold, house access, open storage, start fishing, pick up/sell pack, trade quote, drive vehicle, siege actions, climb, dig treasure, change faction, world interaction, house traversal, furniture use, doodad use, open siege window, claim lodestone, grant Patron

Because doodad actions and item uses are effects too, "plant a seed", "open a chest", "drink a potion" and "cast fireball" all go through the same checks and the same applier.

EffectApplier has two steps:

if (!_effects.Check(effects, context, out string reason))   // can every effect land? changes nothing
{
    if (reason != null) W2CInteractDeniedPacketSender.Send(peer, reason);
    return;
}
var result = _effects.Apply(effects, context);              // do them in order, sum what happened

EffectContext carries the source (EffectActor: player or NPC), the target, the origin (for logs), rank scaling and world-interaction details.

Statuses#

StatusTemplates + StatusModifiers + Effects (OwnerType 3):

Column Meaning
Name, Description, IconName, IsDebuff display
DurationMs, TickIntervalMs lifetime; 0 tick = no ticks
StackRule, MaxStacks 0 Refresh (one copy, reset duration), 1 Stack (add a stack), 2 Per caster (one per caster), 3 Ignore (keep the old one)
DispelType 0 none, 1 magic, 2 poison, 3 disease, 4 curse, 5 physical
Crowd flags: 1 Stun, 2 Root, 4 Silence, 8 Break on damage
StatusModifiers rows Stat, Flat, Percent: change the stat sheet while active
Effects rows with OwnerType = 3 run every tick, once per stack, through the same applier (so a bleed uses the same armor/crit maths as a sword)

The Scheduler runs each status's ticks and expiry; there's no per-tick sweep over all entities. Crowd control has diminishing returns for players (CrowdDiminishWindowMs: half, quarter, then immune) and bosses are immune if BossCrowdControlImmune = 1. Statuses end on logout (not saved). Clients get the definitions in W2CStatusCatalog and changes in W2CStatusUpdate.

Stats and formulas#

StatId (shared enum): Strength, Agility, Vitality, Intelligence, Spirit, MaxHealth, MaxMana, AttackPower, SpellPower, Armor, CritChance, Haste, HealthRegen, ManaRegen, six resistances, DamageDonePct, DamageTakenPct, HealingDonePct, ThreatPct, MoveSpeedPct, HealingPower.

StatsService.Recalculate builds each player's StatSheet from: class base and per-level values (Classes), level × StatPerLevel, gear (ItemStats, scaled by grade), passives (AbilityPassiveModifiers) and active statuses (StatusModifiers). When max health changes, current health keeps its percentage, so swapping gear can't refill you.

Every number is a row of CombatRules (key, value, description). A few:

Key Default Meaning
HealthBase, HealthPerVitality 60, 4 max health
AttackPowerPerStrength, SpellPowerPerIntelligence 2, 2 power
CritBase, CritPerAgility, CritMultiplier 5, 0.05, 1.5 crits
MissBase, MissPerLevel, GlancePerLevel, GlanceMultiplier 5, 1, 4, 0.7 level difference
ArmorConstant, ArmorPerAttackerLevel, ArmorCap 200, 50, 75 armor reduction = armor / (armor + 200 + 50 × attacker level), max 75 %
GlobalCooldownMs, GlobalCooldownMinMs 1000, 750 GCD
AreaMaxTargets 8 area cap (nearest first; falloff per extra target)
ThreatPerDamage, ThreatPerHeal, ThreatSwitchPct 1, 0.5, 110 threat
OutOfCombatMs, RegenIntervalMs 6000, 2000 regen

The full list (149 keys) is in the worldserver.db reference. Tune by changing a row and restarting the World server; a key the table doesn't have uses the default in GameRules.cs. A misspelled key is logged and ignored.

Skill steps (combos, cones, channels, chains, projectiles)#

A skill with SkillSteps rows runs them in StepNo order instead of its own effects. Each step has a TargetMode (target, self, area at target, area at caster, cone, chain, line), geometry (Radius, ConeDegrees, ChainRange, ChainJumps, MaxTargets, ProjectileSpeed), timing (DelayMs, Repeat, RepeatIntervalMs, Channeled), a condition (ConditionKind: target/caster has status, health below %, distance, is player, chance; ElseStepNo), and presentation (AnimationParameter, VfxKey). Each step's effects are Effects rows with OwnerType = 6. See SKILL_PLOTS (note).

Death and respawn#

At zero health a player dies: stays where they fell, can't act, loses every status and their cast, comes off every threat table, and sees the death screen (W2CDeathHandlers on the client). C2WRespawn brings them back at the nearest respawn point (SpawnPointTables with IsRespawnPoint, matching faction) at full health and mana. NPC death: see NPCs.

PvP#

Player targets are only valid when World:AllowPlayerVersusPlayer is on and the zone's PvP mode, factions, flags and duel state allow it (PvpService). See PvP & sieges.

Recipes#

A new skill (data only)#

A Mage "Ignite": 1.5 s cast, fire damage plus a burning DoT.

-- 1. The burning status: 4 ticks of fire damage over 8 s, magic-dispellable
INSERT OR REPLACE INTO StatusTemplates (Id, Name, Description, IconName, IsDebuff, DispelType, StackRule, MaxStacks, DurationMs, TickIntervalMs, Crowd)
VALUES (4100, 'Burning', 'Taking fire damage every 2 seconds.', 'Status/burning', 1, 1, 0, 1, 8000, 2000, 0);
INSERT OR REPLACE INTO Effects (Id, OwnerType, OwnerId, Sort, Kind, Target, Min, Max, RefId, DurationMs, School, Coefficient)
VALUES (9100, 3, 4100, 0, 6, 1, 4, 6, 0, 0, 1, 0.08);           -- OwnerType 3 = status tick: Damage, Fire

-- 2. The skill
INSERT OR REPLACE INTO Skills (Id, Name, Description, IconName, ClassId, TargetRule, Range, CastTimeMs, CooldownMs, ManaCost,
                               OnGlobalCooldown, IsSpell, RequiresFacing, RequiredLevel, MaxRank, RankLevelStep, RankBonusPct, PointCost,
                               AnimationParameter, MinDamage, MaxDamage, HotbarSlot)
VALUES (4120, 'Ignite', 'Sets the target ablaze.', 'Skills/Axiom/Mage/ignite', 3, 0, 25, 1500, 8000, 18,
        1, 1, 1, 6, 3, 5, 10, 1, 'Cast', 0, 0, 0);

-- 3. What it does: hit, then apply Burning
INSERT OR REPLACE INTO Effects (Id, OwnerType, OwnerId, Sort, Kind, Target, Min, Max, RefId, DurationMs, School, Coefficient)
VALUES (9101, 2, 4120, 0, 6, 1, 18, 26, 0,    0, 1, 0.7),        -- Damage, Fire, 0.7 x spell power
       (9102, 2, 4120, 1, 2, 1, 1,  1,  4100, 0, 0, 0);          -- Apply Status 4100, 1 stack

Restart the World server. The skill reaches clients in the skill catalogue; the icon must exist under Resources/Icons/Skills/... and AnimationParameter must be a trigger in the character Animator (Characters). Content Studio shows skills' effects as sentences ("Deal 18–26 Fire damage + 0.7× power") so you can check your work.

A new effect kind (code)#

Example: Lifesteal (heal the caster for a percentage of damage dealt by the previous row).

  1. Enum: add Lifesteal = 42 to EffectKind in GameData/Effects/EffectRow.cs and to Assets/AxiomMMOKit/Editor/ContentStudio/Schema/ContentEnums.cs (so Content Studio offers it).
  2. Check (EffectApplier.CheckOne): case EffectKind.Lifesteal: return context.Source.IsValid && !context.Source.IsDead;
  3. Apply (EffectApplier.ApplyKind):

csharp case EffectKind.Lifesteal: { // result.Damage = damage the earlier Damage rows of this list dealt to the target if (!source.IsValid || source.IsDead || result.Damage <= 0) return true; int amount = (int)MathF.Round(result.Damage * effect.Min / 100f); int before = source.Health; int after = Math.Min(source.MaxHealth, before + amount); source.SetHealth(after); result.Healed += after - before; if (source.IsPlayer && source.Peer != null) W2CHealthUpdatePacketSender.Send(source.Peer, source.Player); // same as the Heal case return true; }

  1. Data: an Effects row after the damage row: Kind 42, Target 0, Min 25 = heal for 25 % of the damage.
  2. No protocol change: the client sees the heal through the normal combat event and health update.

Read EffectApplier before you write the case: reuse its helpers (damage, heal, status) rather than changing health directly, so threat, crits, death and combat events stay consistent.

A new stat#

Add the value at the end of StatId (before Count) in Axiom.Network/Shared/Combat/CombatTypes.cs, derive or apply it in StatsService/CombatMath, add any formula numbers to GameRules (with defaults) and CombatRules, show it in the client's character window, then rebuild the DLL, bump the protocol version and copy it to the client.
