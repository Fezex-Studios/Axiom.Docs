World Streaming, Floating Origin & Zones#

Code: Assets/AxiomMMOKit/Axiom.Client/Scripts/World/Streaming and Scripts/World/Zones.

Class Job
WorldStreamer Loads and unloads tile_X_Z scenes around the local player. The ground gate (IsAreaReady).
TileProxyStreamer + TileProxyManifest HLOD: a cheap baked proxy for every tile out to farRadius.
FloatingOrigin Moves the whole world back towards (0,0,0) when the player gets far from it.
WorldOrigin The one conversion between world space (network) and local space (Unity transforms).
WorldSettings The shard's layout sent by the server in W2CEnterWorld (tick rate, interest radii, tile size, zone map hash).
ZoneTracker + ZoneBannerUI Which zone the player is in (from the local zones.aczmap) and the banner.
WorldObjectPrefabRegistry Maps a model key (Character_Human_Male, Orc_Grunt, Tree_Oak...) to a prefab, from Resources/World/WorldObjectPrefabs.

The scenes#

main_world                persistent: camera, lights, sky, registries, UI, every object spawned from packets
tile_-1_1  (axiom_wilds)  additive, one per 512 m tile, authored at real world coordinates
tile_-2_1  (zone_test1)
tile_32_32 (the_warrens)  dungeons live in a far-away block of tiles (32 × 512 = 16 384 m)
tile_33_32 (the_sunken_crypt)

Tile scenes live in Assets/AxiomMMOKit/Axiom.Client/World/Tiles/<area>/tile_X_Z.unity and must be in Build Settings (the streamer asks Application.CanStreamedLevelBeLoaded). A tile without a scene is simply empty - open sea or unbuilt land - and nothing waits for it. They are created by Dev Tools ▸ World Tiles (World tools).

Objects spawned from packets (players, NPCs, doodads, corpses) go into main_world, never into a tile, so they survive the tile under them unloading.

WorldStreamer#

Setting Default
loadRadius 1 tiles around the player's tile to keep loaded (1 = the 3×3)
unloadRadius 2 unload only beyond this (hysteresis, so walking along a border doesn't thrash)
maxConcurrentOperations 2 loads/unloads in flight, issued nearest first
refreshInterval 0.2 s
prefetchDistance 192 m near an edge, also load the 3×3 of the tile you're heading into (≈10 s of lead on a horse)
smoothStreamingWhilePlaying on backgroundLoadingPriority Low (2 ms/frame) while playing, High (50 ms) behind a loading screen

What it follows: the local player once spawned; with no connection it follows the main camera, so you can fly around a world scene in the editor without a server.

The ground gate. IsAreaReady(worldPos) is true when every existing tile in the 3×3 around a point is loaded. LocalCharacterMotor won't simulate until it is, so a player spawning or being teleported onto an unloaded tile doesn't fall through terrain that isn't there yet. With no tile scenes anywhere (a legacy single-scene world), it's always true.

Events: TileLoaded(coord, scene), TileUnloaded(coord). A tile that finishes loading after the origin has shifted has its roots moved into local space in sceneLoaded, before any Start runs.

If the server says its tiles are a different size than this build's WorldGrid.TileSize, WorldSettings.TileSizeMatches is false and streaming is disabled with a loud error: rebuild Axiom.Movement.dll into the client.

HLOD proxies (the horizon)#

Beyond the loaded 3×3, TileProxyStreamer shows each tile's proxy: a low-poly terrain with a baked top-down texture plus the big static props merged into one mesh (about two draw calls, no shadows). The proxy is hidden the moment the real tile has loaded and shown again only once it has finished unloading, so there's never a hole.

  • farRadius 5 tiles (≈2.5 km), loadsPerRefresh 4, raiseCameraFarClip on.
  • Proxies load from Resources/World/Proxies/tile_X_Z_proxy listed in Resources/World/TileProxies.asset (TileProxyManifest: X, Z, Prefab, MinY/MaxY, Triangles, SourceHash, BakedAt).
  • None show inside a dungeon (InstanceState.InDungeon). No manifest = it does nothing.
  • Baked with Dev Tools ▸ HLOD Proxies; SourceHash lets it re-bake only changed tiles. See HLOD (note).

Floating origin#

A float has 24 bits of mantissa: at 8 km from the origin the smallest step is ~1 mm, at 32 km ~4 mm, and skinned meshes, shadows and the camera visibly jitter. So the client moves the world instead of the player.

Two spaces:

  • World space: what the server, the database, every packet and heightmap use.
  • Local space: what Unity transforms hold = world − WorldOrigin.Offset (only X and Z; Y never shifts).

The rule: every position arriving from the network goes through WorldOrigin.ToLocal before touching a transform; every position leaving for the network comes from WorldOrigin.ToWorld. Distances, raycasts, the camera and UI projection work in local space unchanged.

// in a handler - convert INSIDE the queued lambda, not when the packet arrives:
WorldLoader.RunWhenReady(() =>
{
    var pos = WorldOrigin.ToLocal(packet.X, packet.Y, packet.Z);
    marker.transform.position = pos;
});

// leaving for the server - the GM panel's "My Position" + teleport (Staff/GmPanelWindow.cs):
var w = WorldOrigin.ToWorld(me.transform.position);
GmPanelState.Send(GmCommand.GotoPosition, p => { p.X = w.x; p.Y = w.y; p.Z = w.z; });

A shift (FloatingOrigin, threshold 6144 m = 12 tiles by default), in one frame between Updates:

  1. new origin = the player's position snapped to a tile boundary (whole tiles, so shifts are exact in float);
  2. every root object in every loaded scene (and DontDestroyOnLoad) moves by the delta;
  3. world-space particles and trails are shifted;
  4. Physics.SyncTransforms;
  5. WorldOrigin.Shifted(delta) is raised: anything caching a local position outside a transform (interpolation buffers, the motor's state, the camera's last target, damage numbers) adds the delta.

If you write a component that stores a Vector3 position in a field, subscribe:

void OnEnable()  => WorldOrigin.Shifted += OnShift;
void OnDisable() => WorldOrigin.Shifted -= OnShift;
void OnShift(Vector3 delta) { _cachedTarget += delta; }

Known limits: static batching (turn it off), baked light probes/APV don't move. Use the Shift Origin To Player Now context menu or lower the threshold to test. WorldOrigin.Reset() runs on connect and disconnect.

WorldSettings#

Sent by the server in W2CEnterWorld.World, with defaults for older servers:

Field Default Used by
TickRate 20 RemotePlaybackClock (interpolation)
ShardName "" UI, logs
InterestSpawnRadius / DespawnRadius 75 / 85 gizmos, UI
TileSize 512 TileSizeMatches check
ZoneMapHash "" ZoneTracker stale-map check

(NetworkCells is an editor gizmo that draws the two interest circles; its "keep in sync" constants predate WorldSettings.)

Zones on the client#

ZoneTracker loads StreamingAssets/World/zones.aczmap - the same file the server uses, written by Dev Tools ▸ Zones - and checks the player's zone every 0.25 s locally (crossing a border costs no traffic). It raises ZoneChanged(previous, current); ZoneBannerUI shows the name and subtitle. If its hash differs from WorldSettings.ServerZoneMapHash it logs an error (the client build shipped a stale map). The server tracks zones independently for anything with rules (PvP, quests): see Zones & terrain.

Editor markers in the world scenes#

NpcSpawnerMarker, DoodadSpawnMarker and PlayerSpawnPointMarker are editor-time stand-ins for rows in NpcSpawners, DoodadSpawns and SpawnPointTables. Each carries the row's DbId and the last synced values so the World Map / Dev Tools windows can show what changed and write it to worldserver.db. They are never sent to players. See World tools.
