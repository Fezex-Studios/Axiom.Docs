Unity Client

User Interface#

All new UI is UI Toolkit, built in C# (no UXML), styled by USS. The older uGUI screens were migrated; UiBootstrap disables any legacy uGUI controller still sitting in a scene. Design notes: UI (note).

Code: Assets/AxiomMMOKit/Axiom.Client/Scripts/UI/Toolkit (framework, windows, maps, shops, Lua) and the rest of Scripts/UI (HUD pieces, chat, inventory, character select...).

The building blocks#

Type Role
UiRoot The one UI Toolkit panel (UIDocument), created on first use, DontDestroyOnLoad. Layers bottom→top: Screens (login, character select), Nameplates, Hud, Windows, Modal, Tooltip, Drag. UI scale is Axiom.UI.Scale in PlayerPrefs; the root gets axiom-compact (< 1200 px wide), axiom-hud-narrow (< 760) and axiom-hud-short (< 600 tall) classes for responsive USS. Empty space ignores the mouse so clicks reach the world. Runs per-frame tickers; IsTypingInField.
ToolkitWindow Base class for a window: a plain C# singleton, no GameObject or prefab. Build once, OnOpened, OnClosed, Tick while open.
UiHudComponent Base MonoBehaviour for always-on HUD pieces (health bar, cast bar, target frame, chat, quest tracker, party/raid frames, zone banner...). Build() into Root on the Hud layer.
WorldUIManager Window stack: Escape closes the topmost, CloseAll on death/logout, hotkeys, "is any blocking window open".
UiGameMenu The bottom menu bar and UiGameMenu.Dispatch("bag" / "quests" / "map" / ...).
UiBootstrap On server_select / main_world load: shuts down the previous session's UI, disables legacy uGUI, ensures an EventSystem with the Input System module, and creates the screen's UI (login screens, or the full HUD).
UiSession UiSession.Get<T>(): one controller MonoBehaviour per session on a shared object, disposed on scene change.
UiTooltip, UiDialog.Confirm Tooltips and confirm dialogs (modal layer).
RichText.Safe(text) Escapes < so player-typed text can't inject rich-text tags. Use it for every name, chat line or description you display.

Theme#

UiRoot loads Resources/UI/AxiomPanelSettings if present (scaling), else fixed pixels × the player's UI scale preference, and the theme Resources/UI/AxiomTheme.tss = Unity's default runtime theme + AxiomBase.uss (layout primitives, ac-* classes) + AxiomSkin.uss (the look). Feature sheets (UI/Chat/ChatPolish.uss, UI/Selection/SelectionScreens.uss...) are added per window. Art: Resources/UI/Art, UI/Classic (9-slice frames, bars, coins, buttons). Common classes: ac-row, ac-column, ac-grow, ac-muted, ac-gold, ac-bad, ac-section-title, ac-text-wrap, ac-divider.

A complete window#

An "Inspect" window that shows another player's name, level and gear. The packets (C2WInspectRequestPacket → W2CInspectResultPacket) are built in Add a packet; this is the UI half.

// Scripts/UI/Toolkit/Windows/InspectWindow.cs
using Axiom.Client.Axiom.Client.Networking;
using Axiom.Network.Shared.Packets.W2C;
using UnityEngine.UIElements;

namespace Axiom.Client.Axiom.Client.Scripts.UI.Toolkit.Windows
{
    public sealed class InspectWindow : ToolkitWindow
    {
        public static readonly InspectWindow Instance = new InspectWindow();
        private Label _name, _level;
        private VisualElement _gear;

        private InspectWindow() : base("inspect", "Inspect", 340, 0) { }   // id (position saved per id), title, width, height (0 = fit)

        protected override void Build(VisualElement content)
        {
            _name  = Ui.Label(content, "", "ac-section-title");
            _level = Ui.Label(content, "", "ac-muted");
            Ui.Divider(content);
            _gear  = Ui.Row(content, "ac-wrap");
        }

        /// Called by W2CInspectResultHandler (main thread).
        public void Present(W2CInspectResultPacket result)
        {
            Ensure();                                         // build if never opened
            _name.text  = RichText.Safe(result.Name);         // player text: always escape
            _level.text = "Level " + result.Level;
            _gear.Clear();
            foreach (int itemId in result.Gear)               // item ids by EquipSlot, 0 = nothing
            {
                if (itemId == 0) continue;
                var slot = new UiItemSlot();
                slot.Set(itemId, 1);                          // icon + tooltip from gamedata.bin
                _gear.Add(slot);
            }
            Open();                                           // through WorldUIManager: Escape closes it
        }
    }
}

Opening it from somewhere else: InspectWindow.Instance.Toggle(). To add it to the game menu, add a case "inspect": to UiGameMenu.Dispatch (and a button/key if wanted).

Rules that keep windows well-behaved:

  • Subscribe in OnOpened, unsubscribe in OnClosed (see QuestLogWindow: QuestState.Changed += Render). A closed window should cost nothing.
  • Read current values from the state class when opening; don't rely on having received the last event.
  • Never change authoritative state locally - send the request and redraw when the server's packet updates the state.
  • Tick() runs every frame while open; throttle (QuestLogWindow redraws timers once a second).
  • Dangerous actions go through UiDialog.Confirm(title, message, onConfirm).

HUD components#

public sealed class PingDisplay : UiHudComponent
{
    private Label _label;
    protected override string ClassName => "axiom-ping";
    protected override void Build() { _label = Ui.Label(Root, "", "ac-muted"); }
    private void Update()
    {
        var peer = ClientNetwork.Instance?.ServerPeer;
        _label.text = peer == null ? "" : peer.Ping + " ms";
    }
}

Create it with the rest of the HUD in UiBootstrap.Loaded (UiSession.Get<PingDisplay>();). Position it in USS on .axiom-ping (absolute position on the Hud layer).

Lua UI addons#

Designers can write UI in Lua without a C# build:

  • Source: Assets/AxiomMMOKit/Axiom.Client/Lua/DesignerScripts/UI/*.lua (000_axiom_sdk.lua first, then yours in name order).
  • Tools ▸ Axiom ▸ UI ▸ Lua ▸ Pack Scripts packs them into Resources/UI/LuaUiScripts - players only run the packed library. The editor reads the folder directly.
  • MoonSharp sandbox with budgets: 5 000 000 instructions to load, 200 000 per call (a runaway function is dropped).
  • /lua reload in chat reloads; UI.Command("name", fn) adds a chat command.
  • Annotations for VS Code (LuaLS): Lua/LuaSDK/Client/library/axiom_ui.lua, with examples (gold_tracker, low_health_warning, target_frame, notes) and TEMPLATE.lua.
-- /gold: gold earned this session
local session = 0
local w = UI.Window("goldtracker", "Gold Tracker", 260, 0)
local row = w:Row(); row:Label("This session", "ac-muted"):Grow(1)
local value = row:Label("", "ac-gold")

SDK.On("GoldChanged", function(gold, previous)
  if gold > previous then session = session + (gold - previous) end
  value:SetText(SDK.FormatGold(session))
end)
UI.Command("gold", function() w:Toggle() end)
API
UI Window(id,title,w,h), Open/Close/Toggle(id), Command(name,fn), Every(s,fn), After(s,fn), Print(text), SaveVar(key,v), LoadVar(key), SetScale(s)
Element Label, Button, Input, Row, Column, Box, Scroll, Divider, Bar, Slot, SetText, SetValue, SetItem, SetColor, AddClass, Show/Hide, Clear, Enabled, Width/Height/Grow, OnClick, Tooltip
Game (read-only) Name, Level, Gold, Health/MaxHealth, Mana/MaxMana, Labor/LaborMax, Count(itemId), ItemName(id), TargetId/HasTarget/TargetName/TargetHealth/TargetMaxHealth
SDK On/Off(event, fn) for HealthChanged, ManaChanged, LaborChanged, GoldChanged, LevelChanged, TargetChanged; FormatGold, Ratio, Clamp, Load(key, default)

Lua UI can read game state and show things. It cannot send packets - anything that changes the game goes through C# and the server. Full reference: Client Lua SDK.
