Guild & Family Progression: Missions, Levels, Buffs#

Guilds and families have a level, XP and (guilds only) Prestige. Members earn them by completing missions. Each level unlocks perks (mission slots, Change Mission attempts, the guild member cap) and better buffs for every member. Prestige is the guild's shared money: see Guild Shop & Prestige.

Piece File Job
MissionCatalog Core/Social/Missions/MissionCatalog.cs Reads and validates Missions, OrganizationLevels, OrganizationBuffs (and the shop tables) at start.
MissionRegistry Core/Social/Missions/MissionRegistry.cs The state of the whole shard, one object shared by every zone host (ShardShared): drawing, counting, levels, change attempts, donations, buffs, saving.
MissionService Core/Social/Missions/MissionService.cs Per zone host: game events → progress, rewards, commands, sending state; the home host saves. Hands each system its buff percent.
C2WMissionCommandHandler Core/Packets/C2WHandlers/C2WMissionHandlers.cs C2WMissionCommand (184).
Packets and enums Shared/Axiom.Network/Shared/Packets/MissionPackets.cs MissionKind, OrganizationBuffKind, MissionAction, W2CMissionState (185).
Client Scripts/Gameplay/Social/MissionState.cs, OrganizationAuras.cs, UiCommunityView.cs Community ▸ Guild/Family ▸ Mission, the Guild Buffs card on Manage, the Guild/Family Blessing auras.

Missions#

Individual missions Group missions
Who each member has their own shared by the whole guild or family
Drawn every day (daily reset) every week (weekly reset)
Counts what that member does what every member does, on any zone host
Change Mission the member, using a daily attempt the leader: a guild pays Prestige (MissionGroupChangePrestige), a family uses a daily attempt
Personal reward into the bag (mailed when it's full) mailed to every member who contributed

Missions arrive sealed; opening one (MissionAction.Open / OpenAll) starts it counting. Leaving a guild or family clears your individual missions for it. Drawing is weighted (Weight) from the rows whose MinLevel the organisation has reached.

MissionService listens to LuaEngine.EventFired, the same game events quests, achievements and Lua scripts use, and maps them to a MissionKind:

Kind Event Counts
1 KillNpc OnKill an NPC you attacked dies (TargetId = template, 0 any)
2 CompleteQuest OnQuestComplete a quest turned in
3 EarnXp OnXpGained XP points actually awarded
4 Harvest OnHarvest items gathered (per item)
5 Craft OnCraft items crafted (per item)
6 SpendLabor OnLaborSpent labor points spent
7 UseItem OnItemUse an item used
8 DonateItem (MissionAction.Donate) items handed in with the card's Donate button
9 TradePackSold OnTradePackSold a trade pack delivered

Completing a mission gives the organisation RewardOrgXp (and RewardPrestige for guilds) and the member(s) RewardGold and RewardItemId × RewardItemCount. Reward mail carries an idempotency key, so a retry never pays twice.

Levels and buffs#

OrganizationLevels has one row per owner (0 guild, 1 family) and level: XpToNext, MaxMembers (guilds; 0 = the GuildMaxMembers rule), IndividualSlots, GroupSlots, ChangeAttempts, Perks (the text members see). Levels run 1, 2, 3… with no gaps. The seed gives guilds 10 levels (100 → 150 members) and families 5.

OrganizationBuffs rows are Owner, MinLevel, Kind, Value (%). For each kind, the row with the highest MinLevel the level reaches applies, so "+5% XP at level 1, +10% at level 2" is two rows, and a new kind joins the list with a row at the level it starts. Guild and family buffs add up, and the guild's temporary buffs add on top.

MissionService.Initialize hands each system a callback that returns a member's percent:

Kind Applied in
1 Experience ProgressionService.OrganizationXpBonusPct (kills and quests)
2 GoldLoot LootManager.GoldLootBonusPct (each sharer's own buff on their share)
3 LaborRegen ProfessionService.LaborRegenBonusPct
4 Proficiency ProfessionService.ProficiencyBonusPct
5 Honor PvpService.HonorBonusPct
6 TradePackGold TradePackService.TradePackGoldBonusPct (paid on top, untaxed)

OrganizationBuffs replaces the older OrganizationLevels.XpBonusPct, which is ignored once the table exists.

State and saving#

The registry lives in memory for the whole shard. The home host saves what changed every ~10 s (and at shutdown) to Persistence's shard_state table, so Persistence needed no new table:

  • kind mission_org, key g:<guildId> / f:<familyId>: level, XP, Prestige, this week's group missions with each member's contribution, change attempts, shop sales, timed buffs and the guild log;
  • kind mission_char, key <characterId>: that character's daily missions, change attempts and weekly shop purchases.

Until the saved state is read at start nothing counts and the pages say "loading", so a slow Persistence server can't wipe progress.

Rule Default
MissionsEnabled 1 0 turns missions off
MissionResetHourUtc 0 daily reset hour (UTC)
MissionWeeklyResetDay 0 weekly reset day (0 Sunday … 6 Saturday)
MissionGroupChangePrestige 50 Prestige a guild leader pays to change a group mission

Recipes#

Content: a new mission#

Content Studio ▸ Quests & Progression ▸ Guild & Family Missions ▸ add a row (or INSERT INTO Missions), then restart the World server. Bad rows are skipped with a [Missions] Mission N … skipped: … warning, never a crash. A DonateItem mission needs TargetId to be a real item.

Code: a new mission kind ("Win Arena Match")#

  1. Add WinArena = 10 to MissionKind (shared; rebuild the DLL).
  2. Fire an event when it happens (or reuse one): add OnArenaWin to PlayerEvent and fire it through the Lua engine where the match ends, so Lua can listen too. Add the event to LuaSDK/Server/library/axiom_server.lua.
  3. In MissionService.OnGameEvent, map it: case PlayerEvent.OnArenaWin: kind = MissionKind.WinArena; target = 0; amount = 1; break;.
  4. Client: a label in UiCommunityView (the MissionKind switch), and the name in Content Studio's ContentEnums (Add("MissionKind", …)).

Code: a new buff kind ("Gathering Speed")#

  1. Add the kind to OrganizationBuffKind (shared) and to ContentEnums (OrganizationBuffKind).
  2. Give the system that should use it a Func<PlayerSession, int> property, and set it in MissionService.Initialize with Buff(s, OrganizationBuffKind.GatherSpeed).
  3. Client: the text in UiCommunityView's buff-kind switch, so the Guild Buffs card and the auras' tooltips describe it.
  4. Add rows to OrganizationBuffs (and GuildBuffOffers if it can be bought as a timed buff).
