Getting Started

Axiom Setup#

Tools ▸ Axiom ▸ Setup takes a new project from an import to playing on your own servers. When the import finishes it pops up by itself, as a floating window centred on the editor with a welcome line. It waits until Unity has stopped compiling and importing, so it appears after the import's last reload, not in the middle of it. Each step shows one of three marks, says why in one sentence, and offers a button that fixes it:

  • ✔ done;
  • ● needs you;
  • ○ waiting for an earlier step.

Nothing changes until you press a button.

It pops up again: - at each editor start (once per session) until every step is done; - when a step that used to pass starts failing, for example the render pipeline was unassigned or a package removed; - after a kit update is imported over the project.

Untick Show at start-up until setup is done, and when something breaks at the bottom to stop that. You can always open it from the menu or from the Setup button in Dev Tools ▸ Settings.

The steps#

# Step Checks The button
1 Render pipeline HDRP is installed and assigned in Graphics Settings Use assigns one already in the project; Open the HDRP Wizard (press Fix All there) creates and configures everything. Then the starter house materials are converted to HDRP/Lit.
2 Packages HDRP, Input System, Cinemachine, uGUI/TextMeshPro and Newtonsoft are in Packages/manifest.json, and no second Newtonsoft.Json.dll sits in Assets/ Install … adds what's missing (Unity picks versions that match the editor); Remove the bundled Newtonsoft.Json copy deletes a duplicate DLL folder, after asking.
3 Server files the server repository (AxiomCore) is found Unzip next to my project unpacks AxiomCore_Server_Source.zip beside the Unity project (never over an existing folder); Choose the folder… opens Settings.
4 .NET 10 SDK and MySQL dotnet --list-sdks lists 10.x; something answers on the MySQL host and port links to the downloads; Check again. Restart Unity after installing the SDK so it sees dotnet.
5 Server settings every server has a 32+ character secret, they all share it, the three with databases have a real MySQL password, and the World server's game-data settings (ClientContent key and outputs) are right Write the settings for all servers writes appsettings.Local.json in each server folder: it reuses a secret the servers already share (else makes a new one), sets the MySQL host, port, user and password you typed, and keeps every other setting and the database names. An existing file is copied to .bak first. Set up the game data settings is Project Health's fix.
6 Databases Persistence and Auth answer on their ports Start Persistence and Auth builds them if needed and starts them through Server Control. On first start each creates its MySQL database and tables (Persistence AutoMigrate, Auth migrations). If one stops, the step shows the error line.
7 Which world database the tools edit Settings' World database is the copy the World server runs (the built one under bin/Debug) Build the World server when there's no built copy yet; Use the World server's copy switches Settings. Editing another copy means the running server never sees your changes.
8 First run the World server is running and Editor Login has an account Start the World server; Create the account and use it registers a test account on your Auth server and fills in Editor Login; Open server_select and press Play.

Notes#

  • Its own assembly. Setup lives in its own assembly (Editor/Setup, Axiom.Setup.Editor) with no package dependencies, so steps 1 and 2 work even when the rest of the editor suite can't compile yet, for example while HDRP is missing. Steps 3–8 use the suite (paths, Server Control, Project Health) through AxiomSetupBridge and say "waits for the Axiom editor tools to compile" until it loads.
  • Where things are saved.
  • Settings files: appsettings.Local.json, which git ignores, so your MySQL password stays out of the repository.
  • Editor Login: EditorPrefs on this machine.
  • The automatic opening: EditorPrefs, per project.
  • If the kit doesn't compile. The pop-up comes from Setup's own assembly, but Unity doesn't load any new scripts while the project has compile errors. If a package install fails during the import, fix the red errors in the Console (usually by installing the missing package from Package Manager) and the pop-up appears.
  • Making yourself staff. Setup doesn't change an account's access level. Run UPDATE axiom_auth.accounts SET access_level = 5 WHERE username = '…'; for the GM panel.
  • Code.
  • Editor/Setup/SetupLogic.cs: the rules, in plain C# and tested outside Unity.
  • SetupJson.cs: a small JSON reader and writer that keeps comments out and key order in.
  • AxiomSetupWindow.cs: the window and the automatic opening.
  • AxiomSetupServices.cs: what it needs from the suite.
