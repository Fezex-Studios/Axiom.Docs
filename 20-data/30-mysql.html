Data & Databases

MySQL Databases#

Three services each own one MySQL database. Nothing else connects to it: the World server reaches player data only through the Persistence service's HTTP API.

Database Owner Connection string Schema created by
axiom_auth Auth server ConnectionStrings:Auth EF migrations, applied automatically at Auth start (MigrateAsync)
axiom_persistence Persistence server ConnectionStrings:Persistence EF migrations, applied by you (dotnet ef database update); Persistence refuses to start if required ones are missing
axiom_auction Auction server ConnectionStrings:AuctionDb EnsureCreated + CREATE TABLE IF NOT EXISTS at Auction start

All three use Pomelo's EF Core MySQL provider (MySQL 8 recommended). Every table column is listed in the generated MySQL reference.

Older installs used archecore_auth, archecore_persistence and archecore_auction. scripts/MySQL/migrate_databases_to_axiom.sql moves every table to the new names with RENAME TABLE (instant, keeps everything). Stop all servers and back up first.

First-time setup#

-- as root in MySQL Workbench or the mysql shell
CREATE DATABASE axiom_auth        CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE axiom_persistence CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE axiom_auction     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- recommended: a dedicated user instead of root
CREATE USER 'axiom'@'localhost' IDENTIFIED BY 'a-long-random-password';
GRANT ALL PRIVILEGES ON axiom_auth.*        TO 'axiom'@'localhost';
GRANT ALL PRIVILEGES ON axiom_persistence.* TO 'axiom'@'localhost';
GRANT ALL PRIVILEGES ON axiom_auction.*     TO 'axiom'@'localhost';

Put the connection strings in each server's appsettings.Local.json (git-ignored; copy appsettings.Local.example.json):

{ "ConnectionStrings": { "Persistence": "Server=127.0.0.1;Port=3306;Database=axiom_persistence;User=axiom;Password=…;" } }

Then create the Persistence schema once (and after every update that adds migrations):

cd src/Servers/Axiom.Server.Persistence
dotnet tool install --global dotnet-ef        # once per machine
dotnet ef database update

If you can't run dotnet ef, Axiom.Server.Persistence/SQL/*.sql has a hand-runnable script for each feature migration (world_outbox.sql, account_patron.sql, item_uids.sql...).

On start, Persistence lists pending migrations: it refuses to start without the class-based characters, warehouse and world outbox migrations, warns about the rest, and switches Patron off if account_patron is missing.

scripts/MySQLServer is a small Windows helper (built as Start.DatabaseServer.exe) to start/stop a MySQL service named LocalMySQLServer and open a shell.

axiom_auth#

Owned by Axiom.Server.Auth (Data/AuthDbContext.cs, Migrations/).

Table Rows mean Key columns
accounts one login account_id, username (unique), password_hash (BCrypt, work factor 12), access_level 1–5, banned_until, ban_reason, banned_by, created_at
sessions one live launch token token (PK), account_id (unique: one per account), expires_at. Deleted when the World server redeems it.
refresh_tokens a remembered launcher login token_hash (only the hash is stored), account_id, expires_at. Replaced on every use.
failed_logins account-wide failure counter username, attempts, locked_until

SessionPurgeService deletes expired sessions and refresh tokens periodically.

Access levels#

Level Name Can
1 Player play
2 Ingame Helper helper tools
3 Community Manager staff panel (AccountAccessRules.CanUseStaffPanel = 3–5)
4 Game Master GM commands
5 Developer everything, sees IP addresses in the panel

An account with a level outside 1–5 can't log in. Staff can't act on staff at or above their own level. Debug mutations (grant items, level up) additionally need World:AllowDebugCommands = true. See Staff & GM tools.

-- make yourself a developer (log in again afterwards)
UPDATE axiom_auth.accounts SET access_level = 5 WHERE username = 'aidan';

-- lift a ban
UPDATE axiom_auth.accounts SET banned_until = NULL, ban_reason = NULL WHERE username = 'someone';

-- unlock after too many failed passwords
DELETE FROM axiom_auth.failed_logins WHERE username = 'aidan';

axiom_persistence#

Owned by Axiom.Server.Persistence (Api/Data/PersistenceDbContext.cs, Api/Models/, Migrations/, plus a few raw-SQL tables). Every write comes from a World server request (Persistence flow).

Characters#

Table Rows mean Notes
characters one character character_id, account_id, name (unique), class_id, race_id, gender_id, appearance (JSON), level, experience, pos_x/y/z, gold (copper), inventory_capacity, warehouse_gold, warehouse_capacity, save_seq (the last applied save number)
character_inventory one occupied bag slot PK (character_id, slot). No row = empty slot. item_template_id, quantity, bound, item instance columns
character_equipment one worn item slot = EquipSlot number
character_warehouse_items one warehouse slot
character_quests one quest the character has touched status, progress = comma-separated counts per objective ("3,1")
character_abilities, character_skillsets, character_hotbar learned ranks, skill sets, hotbar (kind 1 ability / 2 item, ref_id)
character_proficiency points per profession
character_pvp faction, honor, crime points, infamy, jail until
character_achievements, character_profile achievement progress; worn title
character_dungeon_entries runs used per dungeon per period

Item instance columns appear on every table that holds an item (inventory, equipment, warehouse, coffers, mail, auction): grade, wear (durability used), gem1..3, and item_uid (a unique id per copy of a piece of gear; ItemUidAudit records any uid found in two places in item_uid_conflicts). All zero = a plain item.

Account-wide#

Table
account_labor the labor pool shared by all characters on an account (points, accrued_at_unix_ms for offline regen)
account_patron Patron subscription expiry and Loyalty Tokens (raw SQL table)
account_credits cash shop credits (bought with real money; never gold)

World and social#

Table
doodads player-placed persistent doodads: crops, crates, houses, furniture, placed packs. phase_id, phase_ends_at_unix_ms, owner, access, version (out-of-order safe), storage_seq. World-spawned doodads from DoodadSpawns are never stored.
doodad_storage coffer contents (written only inside a character save)
guilds, guild_members, guild_ranks guilds; rank 0 = leader, 1–4 with permission flags
community_contacts, community_families, community_family_members friends/blocks/mutes, families (raw SQL)
shard_state key/value JSON per shard and kind: territories, sieges, world event schedules, zone conflict stages
trade_demand current demand % per outlet and pack, per shard
world_outbox obligations the World server still owes (outbox)

Mail and cash shop#

Table
mail one delivery waiting for a character: sender, subject, gold, one item stack, mailbox (general or marketplace). Everything that gives a player something offline goes here: auction proceeds, purchases, cash shop, refunds, GM gifts.
mail_receipts delivery keys already posted, so a retried delivery isn't posted twice
cash_shop_items, cash_shop_mail the cash shop catalogue (seed: SQL/cash_shop_seed.sql) 
-- give an account 1000 cash shop credits
INSERT INTO axiom_persistence.account_credits (account_id, balance, updated_at_ticks)
VALUES (1, 1000, 0) ON DUPLICATE KEY UPDATE balance = balance + 1000;

-- mail a character 20 Iron Ore (item 2001 in this example) from "Game Master".
-- Works online or offline: they find it next time they open a mailbox.
SET @now_ticks = CAST(UNIX_TIMESTAMP() AS UNSIGNED) * 10000000 + 621355968000000000;  -- .NET ticks for "now"
INSERT INTO axiom_persistence.mail (character_id, sender, subject, gold, item_template_id, item_quantity, created_at_ticks)
SELECT character_id, 'Game Master', 'A gift from the team', 0, 2001, 20, @now_ticks
  FROM axiom_persistence.characters WHERE name = 'Aidan';

gold is in copper in the mail table too. Axiom.Server.Persistence/SQL/admin_mail_examples.sql has more examples (everyone on an account, everyone above a level).

Don't edit a character's rows while they're online. The World server holds the live state and its next save replaces the inventory wholesale. Use GM commands for online players; edit SQL only for offline characters.

axiom_auction#

Owned by Axiom.Server.Auction (Data/, Models/). Tables are created at start-up.

Table
auction_listings one thing for sale. The item is in nobody's inventory: it left the seller's bag in the same save that created the listing's outbox entry. price (buyout), start_bid, current_bid, bidder, bid_count, expires_at_ticks, instance columns.
auction_bids one bid, keyed by the World server's bid_key (a retried bid is recognised)
auction_purchases one completed buyout, keyed by purchase_key
auction_create_receipts listing creations already done, by key
mail_outbox mail the auction house owes (proceeds, won items, expired listings), delivered to Persistence /mail/send by a background worker every MailDispatchSeconds

Settings: Auction:ListingHours (24), FeePercent (5), MaxResults (100). See Auction server.

Backups#

Back up axiom_persistence (player data) and axiom_auth (accounts) regularly:

mysqldump -u root -p --single-transaction --routines axiom_auth axiom_persistence axiom_auction > axiom_$(date +%F).sql

--single-transaction gives a consistent snapshot without locking the live servers. worldserver.db doesn't need this: it's rebuilt from git (migrations + patches).
