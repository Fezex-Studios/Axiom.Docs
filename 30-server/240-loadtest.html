Server Systems

Load Testing#

src/Tools/Axiom.LoadTest runs headless bots speaking the real protocol. They log in (through Auth or a bypass), select or create characters, run the shared CharacterMotor against the same exported collision as the server, walk to homes spread over the zones, jump, visit NPCs and reconnect. It measures what players would feel (entry time, RTT, movement gaps, corrections) and, by following the World server's log, what the server spent on each tick.

Bots walk, jump, talk, reconnect and can fight or form parties. They don't craft, trade or render. A pass is evidence about that workload on that machine, not a capacity certificate.

Starting it#

Run Start_Axiom_LoadTest.cmd (it builds, runs the self-tests and opens the console), or:

cd src/Tools/Axiom.LoadTest
dotnet run -c Release            # the console

The console#

Screen What you do there
Run a test Pick a preset, see it at a glance (target, players or ladder, fidelity, timing and total duration, whether the World server log is found, the pass limits), run it. The plan is shown first; fleets run a preflight check before starting.
Presets & settings Every setting in groups (Fleet, Server, Bots, Scenario, Timing, World, Launch behaviour, Gameplay, Pass / fail, Settle), each with its value, a • when it differs from the default, what it means and what is allowed. / searches all settings; you can list only changed ones or show advanced ones. Input is checked as you type and the whole preset is re-validated after each change (fleets with the same checks a run makes). Save, save as a copy, delete.
New preset (guided) Capacity ladder, fleet at one size or single generator, then sizes, fidelity, bypass or login, host, hold time and the World server log (found automatically from the repo layout).
Results & reports Every past run with its steps (1k✔ 2k✔ 4k✖). Open or build its HTML report, rebuild it with a World server log, diagnose, show the text report, compare two runs step by step, delete.
Tools Self-tests, network self-test, build a report or diagnose any folder, zones preview, forget the session password.
Options Automatic report, open it after runs, confirm before running, live dashboard, colours, results folder, World log and its time zone for old reports. Saved per PC in loadtest.preferences.json (git-ignored).

Keys: ↑↓ move, Enter choose, Esc back, a letter or number jumps to an item, / filters long lists, Ctrl+C stops a run cleanly (reports are still written). With piped input the menus fall back to typing the key.

Commands (scripts and CI)#

dotnet run -c Release -- fleet presets/20-ladder-1k-2k-4k-5k-mixed.json    # preflight, then the ladder; HTML report at the end
dotnet run -c Release -- run presets/08-launch-day-500.json               # one generator
dotnet run -c Release -- report results/ladder-20261101-054924 --open     # (re)build the HTML report
dotnet run -c Release -- report <folder> --server-log <log file or logs folder> --log-tz America/New_York
dotnet run -c Release -- preflight presets/20-ladder-1k-2k-4k-5k-mixed.json
dotnet run -c Release -- plan | fleet-plan | zones <preset>                # what would happen, no connections
dotnet run -c Release -- validate | register | settle | fleet-settle <preset>
dotnet run -c Release -- diagnose <results folder>
dotnet run -c Release -- compare a/summary.json b/summary.json
dotnet run -c Release -- aggregate m1/summary.json m2/summary.json
dotnet run -c Release -- selftest            # offline checks
dotnet run -c Release -- selftest-network    # loopback UDP test

Exit codes: 0 pass, 1 fail or review, 2 review required (single run), 130 cancelled.

One-time server setup#

  1. Merge Servers/Axiom.Server.World/appsettings.Local.loadtest.example.json into your appsettings.Local.json (don't replace it; it holds your secrets). It raises World:MaxPlayers 500 → 12000 and Performance:MaximumConnections 2048 → 12000, turns on AllowLoadTestBypass (remove it afterwards) and raises the login queue limits. Without it a 1,000-bot run stops at about 500: the server answers "The world is full".
  2. Run the servers as Release. A Debug World server is 2–4x slower on the tick.
  3. Point ServerLogPath in your presets at the World server's bin/Release/net10.0/logs folder.

After changing terrain, re-export the heightmap and Movement Collision, rebake the navmesh and restart the World server; bots read the server's own Data/world_collision. Preflight says which of collision, navmesh and zones.aczmap is stale.

Authentication#

AuthMode How bots get a token
login real /login against AuthUrl with accounts AccountPrefix + index, password from the AXIOM_LOADTEST_PASSWORD environment variable (8+ characters). register creates them first.
bypass token loadtest:{n}, accepted only when the World server has World:AllowLoadTestBypass = true (never in production). No Auth or MySQL accounts needed.

Bot fidelity#

Fidelity What a bot does
full Everything a client does: local prediction, replay after corrections. Correction is measured. About 4x the CPU. At most 512 per generator.
lite The same inputs at the same rate, dead-reckoned, no physics or replay.
mixed FullFidelityFraction (10%) full "probe" bots, the rest lite. One PC can drive thousands.

SkipSnapshotDecode with BlindFraction lets lite bots count snapshot bytes without decoding them (the server still sends them). Lite bots skip client work only; at 1k a full-fidelity run once showed a higher server tick than mixed, so compare both when it matters.

Fleets and ladders#

One generator process runs up to 512 full or 1024 lite bots. A fleet preset ({ "Settings": {...}, "TotalBots": … }) starts many generators, gives each a slice of accounts, starts them together and combines their results. A ladder ("Ladder": [1000, 2000, 4000]) runs several sizes one after another with a cooldown, so you see where the server stops keeping up.

BotsPerGenerator: 0 sizes generators from this PC's cores minus ReservedCores (5) and the fidelity, and re-sizes after each ladder step from the CPU it measured. On several machines, run the same fleet with different OnlyGenerators and the same StartAtUtc, then aggregate. Only generator 0 follows the server log.

Preset For
23-smoke-500-full First run after any change.
20-ladder-1k-2k-4k-5k-mixed The main test.
21-ladder-1k-2k-4k-5k-full Same ladder, every bot runs client physics.
24-ladder-500-to-10k-mixed Finer steps up to 10,000.
22-stress-10000-mixed One 10k run (needs a second PC for the generators).
01–10 Single-generator checks: real login, wander, crowd, route, reconnect, launch-day 10/100/500, login surge, hotspot. EDIT-… presets need coordinates.

Live dashboard#

While a fleet step runs the console shows one frame redrawn every second: phase and hold countdown, players ready against the total, failures, tick p99 per zone host with a sparkline, players per zone, GC pause, the PC's CPU split between servers, bots and database, free RAM, network, each generator's state and recent events. Turn it off in Options for the old one-line status every 5 s.

The HTML report#

Every ladder, fleet and run folder gets load-test-report.html when it finishes (it opens by itself). It is one self-contained file that works offline, with dark and light themes and Print / PDF.

Section What it shows
Summary Verdict, highest passing CCU, worst and typical server tick, ready share, RTT, movement gap, failures, PC CPU, traffic
Capacity (ladders) Tick time vs players against the 40 ms limit and 50 ms budget, player experience vs players, where the busiest zone's tick goes per step, PC CPU, the step table
Server performance Tick p99 and p50 per zone host over time, start gap, players per zone host (the server's count), host table with the busiest stage
Tick stages Stacked average ms per stage (= the average tick) or the slowest tick per stage; hold averages with KiB/tick
Runtime, GC & replication GC pause, collections, heap, AoI work and known links, snapshot entities, bytes and candidates, queued actions
Population, Player experience, Latency Bots by state and zone, login pipeline; RTT, movement gap, correction and crowding over time with phase bands; a p50/p95/p99/max table (worst generator)
Test PC, Network, Events CPU by owner, free RAM, generator loop and cores, throughput, bot events and failures by cause
World map Heat map of bot positions during the hold, final positions by zone
Generators, Zones, Configuration Per-generator limits, per-zone numbers, every setting that ran, the machine

Server telemetry#

Generator 0 follows the World server's log and keeps only the numbers from its diagnostic lines, in server-stages.csv: [TickHealth] (tick p50/p99/max, start gap, GC, gcPause, heap), [TickStages], [TickAlloc], [AoI], [CrowdWork] and [ZoneThreads] (see what the health report means). No log text reaches a report.

For older runs, or runs without ServerLogPath, the report imports the same lines from a log afterwards (--server-log). The log is stamped in the server PC's local time; the importer handles the hour that repeats when clocks go back, and --log-tz (or Options) sets the zone when the report is built on another PC.

Reading results#

Status Meaning
PASS Every configured check passed.
SERVER AT LIMIT Tick work p99 or start gap p99 over the limit (MaxServerWorkP99Ms 40, MaxServerStartGapP99Ms 75, of a 50 ms tick). The number you came for.
GENERATOR LIMITED A test process fell behind (late loop, pegged core). Its latencies describe the test PC. Use lite or mixed, more generators or another PC.
SERVER REFUSED BOTS World full, connection limit or login busy. Raise the limit; says nothing about capacity. The ladder stops.
ENDED EARLY AbortFailureFraction of the bots failed.
CANCELLED Stopped by hand; partial numbers.
REVIEW A configured check failed; the Diagnosis says which.

Every step ends with a Diagnosis naming what limited it. In the report, the stage that grows with player count is what to optimise; compare two ladder steps, then tune the matching World:Performance budgets (Interest & replication, which also lists the capacity measured so far). Percentiles are never averaged across generators or windows; the worst is shown.

Program.SupportedProtocol is the protocol the bots were last checked against; bump it (after checking the bot adapters in Bot.cs) when you change packets they use. The tool's own src/Tools/Axiom.LoadTest/LOADTEST.md has the full file list of a results folder; Fleet (archive) and Validation (archive) are older notes.
