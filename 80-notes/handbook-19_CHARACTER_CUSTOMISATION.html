19. Character Customisation#

Players choose skin colour, hair style, hair colour, eye colour, a face and height, plus any sliders you define, on the creation screen. The look is saved with the character and everyone sees it.

It works the classic MMO way: the choices are rows in the world database, each optionally limited to one race and/or body type, and a character saves only which rows it picked.

The choices: Content Studio > Appearance Options#

Column Meaning
Kind 1 skin colour · 2 hair style · 3 hair colour · 4 eye colour · 5 face preset · 6 morph slider
Name shown on the creation screen (tooltip for colour swatches)
RaceId / BodyTypeId 0 = everyone; otherwise only that race / body type
Value depends on Kind (below)
SortOrder order on the screen, lowest first
IsPlayable 0 hides it from the creation screen

Axiom starts you with 6 skin tones (one, Moonlit, fairies only), 5 hair colours and 4 eye colours. Hair styles, faces and sliders need art first.

After any change: restart the World server. Clients get the new list at their next login.

Skin, hair and eye colours (Kinds 1, 3, 4)#

Value: #RRGGBB. It's a tint over the texture: #FFFFFF shows the texture as painted, darker values darken it. So paint your skin texture light, and let the tints make it fair, tanned or deep.

  • Skin tints the body's skin pieces (everything listed in Character Sockets except Hair and Underwear; on an unsplit body, its biggest mesh).
  • Eyes tint meshes whose name contains eye (not eyebrow).
  • Hair colour tints the chosen hair style (Kind 2).

Which material property is tinted: Dev Tools > Characters & Races > Pipeline > Appearance (_BaseColor for HDRP and URP Lit, _Color for Standard).

Hair styles (Kind 2)#

Value: a prefab path in a Resources folder, e.g. Hair/Long01 for Assets/AxiomMMOKit/Axiom.Client/Resources/Hair/Long01.prefab.

  • Skinned hair (bound to the body's skeleton, like armour) binds to the body automatically. Best for long hair that moves with the head and neck.
  • Rigid hair (a plain mesh) goes on the body's Head socket. Make its prefab like a hat: empty root at the top of the head, mesh as a child.
  • While a style is worn, the body's own Hair part is hidden. A helmet that hides Hair hides the style too.
  • Make styles per body if needed: Hair/Long01_Male with BodyTypeId 1, Hair/Long01_Female with BodyTypeId 2.

Face presets (Kind 5)#

Value: blend shapes on the body and their weights (0-100): BrowHeavy=60;JawWide=30;NoseSmall=20. The body model needs those blend shapes (shape keys in Blender); names must match exactly.

Sliders (Kind 6)#

Value: one blend shape name, e.g. NoseLength. Each row becomes a slider (0-100) on the creation screen. Up to 32.

Height#

A slider from 90 % to 110 % for everyone, scaling the whole body. Equipment and sockets scale with it.

How it fits together#

Piece Where
The options world database AppearanceOptions; the World server loads them on start and sends them with the character list
A character's look MySQL characters.appearance (JSON); old characters have none and use the defaults
Checking the World server keeps only options that exist and fit the race / body type, and clamps height and sliders. A bad id becomes the default; it never refuses
Drawing the client (CharacterLook) in the world, on character select and on the creation preview

Adding a hair style, start to finish#

  1. Model the hair on your body (skinned, on the same skeleton), or as a rigid mesh.
  2. Prefab in Assets/AxiomMMOKit/Axiom.Client/Resources/Hair/, e.g. Ponytail.prefab.
  3. Content Studio > Appearance Options > New: Kind 2, Name Ponytail, Value Hair/Ponytail, SortOrder 10. Ctrl+S.
  4. Restart the World server, log in, Create character: it's under Hair style. Pick a Hair colour to tint it.

Troubleshooting#

Problem Fix
No Appearance section on the creation screen no options yet, or the World server wasn't restarted after the migration
Skin colour does nothing the material doesn't use _BaseColor: set the right property on the Pipeline page
A face preset does nothing the body has no blend shapes with those exact names
"Missing hair prefab at Resources/…" the Value path doesn't match a prefab in a Resources folder
"Hair style … doesn't fit this body" skinned hair made for another skeleton: test it on Pipeline > Test binding
