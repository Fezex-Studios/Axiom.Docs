Unity Client

Client Data & State#

The client has five sources of data. Picking the right one is most of the work when adding a feature.

Source What's in it When it updates Example
gamedata.bin Items and gear visuals from worldserver.db, encrypted when the World server re-exports and the client downloads it at the server-select screen item names, descriptions, icons, GearVisuals
Catalogue packets Definitions the server sends after entering the world every login, always in sync with the server skills, statuses, quests, recipes, trade routes, factions, achievements
State packets → state classes Your character and the world around you continuously gold, bag, health, quest progress, guild
Resources / StreamingAssets Art, prefabs, UI, collision, zone map with a client build icons, models, stylesheets, zones.aczmap
PlayerPrefs Per-machine options when the player changes them keybinds, camera, movement scheme, UI scale

gamedata.bin#

Format, encryption, life cycle and troubleshooting: gamedata.bin. On the client:

ItemRecord item = ItemRepository.GetById(itemId);   // null if unknown (also GetByName, Search, GetByCategory, GetAll)
string name     = ItemNames.Get(itemId);            // "#90123" if unknown
Sprite icon     = ItemIcons.Get(itemId);            // null if no icon - show a text fallback
GameDataDatabase.Changed += Rebuild;                // raised after (re)loading

Catalogues (sent on entering the world)#

Packet Client cache Holds
W2CItemGearCatalog (85) GearCatalog.Set(items, grades, repairGoldPerPoint) gear stats, item grades, repair cost
W2CStatusCatalog (87) StatusState.SetCatalog buffs/debuffs: names, icons, stacking
W2CSkillCatalog (89) SkillBook.SetCatalog skills, ranks, steps, animation parameters
W2CQuestCatalog (62) QuestState.SetCatalog quests and objectives
W2CCraftingCatalog (116) CraftingCatalog.Apply professions, recipes, materials
W2CTradeCatalog (125) TradeState.ApplyCatalog trade packs, outlets, routes
W2CFactionCatalog (132) FactionState.ApplyCatalog factions and relations
W2CExplorationCatalog (142) ExplorationState.ApplyCatalog exploration points, treasure maps
W2CAchievementCatalog (145) AchievementState.ApplyCatalog achievements, collections, titles
W2CMovementConfig (169) MovementPredictionClient motor profile, collision revision

They travel on the ordered channel before W2CWorldEntryReady, so the world entry gate guarantees they're present when the player can act. A catalogue is the right choice for definitions only needed in the world: no file format, no distribution step, never out of date.

State classes#

Handlers write, the UI reads: a static state class caches the latest truth and raises C# events. Static because the data arrives during the server_select → main_world load, before any HUD object exists, and a window opened ten minutes later must still read the current value.

Class Covers
LocalCharacterState character data, race/gender, level, XP, health, mana, stats, gold, bag, equipment, item cooldowns, HasEnteredWorld
QuestState, CraftingState, StatusState, CastState, DeathState quests, crafting, buffs, casting, death
SocialState, CommunityState friends/party/raid, guild/family
TradeState, WarehouseState, StorageState trade packs, warehouse, house storage
FactionState, SiegeState PvP and sieges
ExplorationState, AchievementState exploration, achievements
InstanceState, PatronState, MailNoticeState dungeons, patron, mail notices
AccountAccessState, GmPanelState staff access, GM panel

Events live next to them (Scripts/UI/Events: PlayerStatEvents.OnGoldChanged/OnHealthChanged/OnLevelChanged/OnStatsChanged/OnEquipmentChanged/OnExperienceChanged, PlayerInventoryEvents, ConnectionEvents, AdminEvents) or on the state class itself.

// LocalCharacterState.ApplyGold - the whole pattern in five lines
public static void ApplyGold(int gold)
{
    Gold = gold;                               // cache (read by panels that open later)
    PlayerStatEvents.RaiseGoldChanged(gold);   // notify panels already open
}

// a UI component
void OnEnable()  { PlayerStatEvents.OnGoldChanged += Show; Show(LocalCharacterState.Gold); }
void OnDisable() { PlayerStatEvents.OnGoldChanged -= Show; }

ClientNetwork resets the per-world state on connect, on disconnect and on returning to character select (LocalCharacterState, CommunityState, ExplorationState, AchievementState, MailNoticeState, AccountAccessState, snapshots, spawn queue, prediction, WorldOrigin, WorldSettings); the other classes are overwritten by their catalogue or W2CEnterWorld. When you add a state class that must not survive a character switch, add its Reset() next to those calls (they appear in three places in ClientNetwork.cs - search for MailNoticeState.Reset).

Icons#

Items use Items.icon_name, skills and statuses IconName. ItemIcons.GetByName(name) loads Resources/Icons/<name> (after IconAliasLibrary mapping), as a Sprite or by wrapping a plain Texture2D, and caches hits and misses. So Skills.IconName = "Skills/Axiom/Warrior/strike" → Resources/Icons/Skills/Axiom/Warrior/strike.png. Adding an icon = dropping a PNG with the right name into Resources/Icons.

UI/IconAliases.json maps existing icon names to imported artwork ({"entries":[{"iconName":"ore_iron","resourceName":"Imported/ore_iron_01"}]}) without touching the database. Tools ▸ Axiom ▸ UI ▸ Imported DDS Icons browses imported icons.

Path Written by Read by

Where should new data live?#

  1. Needed before entering the world (character creation, server select) or must be browsable offline → gamedata.bin (bump the format version).
  2. Definitions only used in the world → a catalogue packet.
  3. Per-character changing values → a state packet + a state class.
  4. Art, prefabs, layouts → Resources / an asset; reference it from the database by a string key, never by GUID.
  5. Personal preferences → PlayerPrefs with an Axiom. key prefix.

The server stays the authority for everything gameplay-relevant; the client never trusts its own copy for a decision.
