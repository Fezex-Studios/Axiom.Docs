Axiom Editor Tools Reference#

The complete reference for every tool in the Axiom menu in Unity: what it does, how to use it, what it reads and writes, and what to do when it fails.

This guide goes deeper than Handbook/02_TOOLS_REFERENCE.md (a one-line-per-tool menu map) and complements EDITOR_SUITE.md (how to get started) and CONTENT_STUDIO.md (the full Content Studio guide). Start there if you are new. Come here when you need to know exactly what a tool touches.

Updated 25 Oct 2026 for the reorganized Editor folder (one folder per menu area, AxiomMenu and AxiomAssetPaths as the single source of menu paths and asset locations, tooltips on every control, the Maintenance menu removed). 116 C# files, Unity 6.3 (6000.3).

Every tool also explains itself in the editor: hover any button or field for a tooltip, and Tools > Axiom > Home > Tools lists every tool with a description and a search box.

1. How the whole system fits together#

Axiom has three kinds of data, and each tool works on exactly one of them.

Kind Where it lives Who owns it Tools that edit it
Game content: items, NPCs, skills, loot, quests, shops, doodads, spawns worldserver.db (SQLite) on the World server The server Content Studio, Create wizards, Dev Tools (spawners, doodads, zones, spawn points)
Client assets: models, prefabs, materials, icons, scenes Assets/ in Unity The client Art & Assets tools, Gear Workshop, World Tiles, Maps, HLOD
Packed client data: item names, icons, gear looks gamedata.bin (encrypted) Built from the database Game Data tab, Item wizard

Player accounts, characters, and the auction house live in MySQL on the servers. The editor never edits those. It only checks that MySQL is reachable.

The golden rule: content flows through patches#

Every tool that changes game content does the same thing:

you edit  -->  Create / Commit / Save
                 |
                 +--> worldserver.db            (written in one transaction, backed up first)
                 +--> SQL/patches/NNN_title.sql (the same change as a numbered patch)

restart the World server  -->  it loads the new content
  • The database write makes the change appear on your machine.
  • The patch file makes it appear everywhere else. Commit it to git. When any server starts, it applies every patch its database has not had (tracked in the schema_versions table).
  • Never hand-edit worldserver.db with an outside tool while the server is running. Use Content Studio.

How the server and client agree#

The editor also produces files the server and client must hold identical copies of. A mismatch is a login or gameplay failure, so the tools check for it:

File Produced by Why both sides must match
Axiom.Network.dll / Axiom.Movement.dll in Assets/AxiomMMOKit/Plugins built from src/Axiom.Network Same packet protocol
Movement collision files (StreamingAssets/World/MovementCollision) Server Exports > Movement Collision > Export Same walkable ground: "collision data mismatch" at login if they differ
NPC collision (npc_collision.json) Server Exports > NPC Collision > Export Server NPC bodies match client models
Zone map (zones.aczmap) Zones tab Server sends its hash on entering the world; the client logs an error if it differs
Movement collision (Data/world_collision) World Tiles tab > Server collision, Server Exports > Movement Collision The server's ground and walls match the scenes you built
gamedata.bin Game Data tab The client shows the right item names and icons

3. The four workspaces#

3.1 Home (the Hub)#

Tools > Axiom > Home (Ctrl+Alt+H). The front door. Open it first each session.

Status page. One line per thing that can be wrong, each with a button that fixes it:

Line Meaning Fix button
World database / Patches folder Paths are set and the files exist Find paths automatically
Database lock Something holds a write lock on worldserver.db (usually the running World server) Stop the server or wait
Patches not applied .sql files in the patches folder this database has not had Restart the server, or point Settings at the database the server actually runs
Content Studio Unsaved edits waiting Open Content Studio
Client item catalog gamedata.bin is older than the database Update now
Model keys NPCs, doodads, mounts whose model key has no prefab in the catalog (they show as placeholders or are invisible) Open Asset Audit
Tile scenes World tile scenes missing from Build Settings (they will not stream in) Add them
Unfinished wizards A Create wizard you started and did not finish Continue

Create page. Large buttons for each Create wizard. Tools page. Every Axiom tool and every Dev Tools tab, generated automatically: each [MenuItem] under Tools/Axiom/ with its [AxiomTool] description, plus each Dev Tools tab with its own description. Grouped like the menu. A search box matches names, descriptions and keywords (try collision, prefab, patch). ☆ stars a tool into Favourites; Recent lists the last 15 you opened from here. Hover a tool for its menu path. This replaced the old Tool Browser window. Settings page. The shared paths, plus a list of every worldserver.db found, newest first, with a Use button. There are two copies on purpose: Data/worldserver.db is the source copied into bin/ on build, and the server runs on the bin/ copy. Point Settings at the bin/ one. Guides page. The handbook and reference guides as tiles, then every Markdown document in the project with a filter box.

3.2 Content Studio#

Tools > Axiom > Content Studio (Ctrl+Alt+E). Every content table in worldserver.db as records instead of SQL. It is the tool for editing what already exists and for any table no wizard covers (quests, skills, recipes, factions, zones' data, achievements, world events, vehicles, territories...).

The complete guide is ContentStudio/CONTENT_STUDIO.md. The essentials:

Workflow.

edit --> pending changes --> validate --> commit
         (undo/redo, kept     (live        |-- worldserver.db (one transaction, backed up first)
          across restarts)     problems)   +-- SQL/patches/0NN_content_<title>.sql
Action Shortcut
Commit Ctrl+S
Undo / Redo Ctrl+Z / Ctrl+Y
Go to any record Ctrl+K
Validate everything F5

Layout. Tables (left) | records (middle) | inspector (right) | dock with Problems / Changes / Activity.

Search syntax in the records list.

Query Matches
iron sword every word appears somewhere in the row
rarity:epic that column contains the text (reference and enum names count)
Kind=11 that column equals exactly
#new #modified #deleted #changed pending edits
#error #warning #issues validation results

How the data layer is built (useful when something looks wrong):

Layer Role
ContentDatabase, SqlBackend, TableSchema Reads the live database. The database decides which tables and columns exist.
ContentSchema + ContentSchema.Definitions.cs Annotates what columns mean: that Items.rarity_id points at ItemRarities, that Effects.RefId points at a skill, item or status depending on Kind, that UseTimeMs is milliseconds. A table or column with no annotation still appears and is editable, described by naming conventions (...ItemId is an item, Is... is a checkbox, ...Ms is milliseconds).
WorkingSet + Changeset The disk state plus pending edits. A change is stored as state (before and after for each touched row), so setting a field back to its original value removes the change and the patch is the smallest possible.
ContentValidator Two layers: generic (references, required references, enums, ranges, icons, model keys) and domain (the rules the server's catalogs enforce at load time: exploration, trade, doodads, quest chains that loop). Errors block a commit unless you explicitly commit anyway.
CommitService Backup, then in one transaction run the patch and record it in schema_versions, then move the patch file into SQL/patches. If any step fails, nothing changes.
RecordOps New, deep-duplicate, delete-with-children, CSV round trips. Duplicate re-points references between copied rows at the copies, so a duplicated doodad starts in its own first phase.

Generated SQL. INSERT OR REPLACE for new rows, UPDATE ... SET of only the changed columns for edits (so two designers editing different fields of the same item never overwrite each other), DELETE for removed rows. Tables are written in name order and foreign keys are checked when the patch commits, so a child row can come before its parent.

Write patch only. For when the World server is running and holds the database. The patch is written and the database is left alone. The server applies it on its next start.

3.3 Dev Tools#

Tools > Axiom > Dev Tools (Shift+Alt+D). The day-to-day workbench. Tabs on the left, a status bar with live pills (World DB, Auth, Persistence, World, Data) on top, and a shared log on the bottom. A dot after a tab name means unsaved work in that tab. Hover a tab for its description; every button and field in every tab has a tooltip. The buttons under the tab list open Home, the handbook, Server Control and Settings.

Keyboard: Ctrl+F searches tabs, Ctrl+PageUp / Ctrl+PageDown move between tabs.

Tabs are discovered by reflection (see section 18), so this list is whatever is in DevTools/Tabs:

Tab What it is for Reads Writes

World Map NPC spawners as scene markers with two-way sync to the database. Every marker carries its database id, so the tab can tell "row 42, moved 3 units" from "new spawner" and compute a real diff NpcSpawners, NpcTemplates Numbered patch (and the database unless locked)

Doodads tab, step by step#

  1. Open the tile scene you are working on.
  2. Load into scene. Puts a marker (with a model preview) at every saved doodad. Tick Only near the Scene view to load just the area around where you are looking.
  3. Place. Click an object in the list, press Place in the Scene view, then click the ground. Each click places one. Random rotation varies the facing; hold Shift to keep the last facing. Esc stops.
  4. Move, rotate, scale with the normal Unity tools. Only Y rotation and a uniform scale are saved; scale 1 means "normal size".
  5. Delete a marker to remove that spawn.
  6. Save to database. Shows counts (+new, ~moved, -removed) and writes one patch.

Marker colours: grey = new, orange = moved or edited, blue = matches the database.

Safety: a missing marker only deletes a spawn if that spawn was loaded into a scene that is still open. Opening the tab in an empty scene can never wipe the table. Clear markers removes markers without touching the database.

World Tiles tab, the model#

main_world   persistent scene: camera, lighting, sky, registries, UI, spawn/NPC markers. Never streamed.
tile_{x}_{z} one scene per 512 m tile: terrain and static scenery at real world coordinates.
             Streamed as a 3x3 block around the player.

Workflow: create terrain tiles (aligned 512 m terrains that auto-connect) or split an existing scene; edit tiles by opening several additively; add them to Build Settings; Export the server collision (Server collision section) for the server after every sculpting pass; validate before committing.

A stale heightmap export is a bug, not a formality: it reintroduces the "server thinks you are underground" problem the whole system exists to remove.

Tile scenes can sit in zone subfolders (Tiles/sunreach/tile_-1_-2.unity). The streamer loads tiles by name, so folder placement is purely for people. TileSceneIndex finds them at any depth.

Zones tab#

Zones are not tiles. Tiles are 512 m streaming squares. Zones are design regions of any shape, painted onto 32 m cells. A zone spans many tiles, and a border tile can hold parts of two zones. Each zone has a key, display name, subtitle, level range, PvP mode, and editor colour. The tab has a top-down map with a round brush (paint, erase, pick), pan and zoom, and an optional background image of your world map art. Open zone opens every tile the zone touches next to main_world. Organize moves tile scenes into folders named after the zone covering most of each.

NavMesh tab#

NPCs are moved by the world server, which has no Unity, so it uses its own navmesh baked by Axiom.Tools.NavBake (Recast/Detour through DotRecast) from the movement collision export: the exact triangles that already constrain players. An NPC therefore can never walk where a player cannot.

  1. Export Movement Collision after editing scenes.
  2. Bake (only pages whose collision changed are rebaked).
  3. Look at the overlay: walkable areas in a tint, edges where NPCs stop as lines. Holes where you expected floor are almost always a collider missing from the export.
  4. Copy Data/navmesh with the server build.

Tools > Axiom > World > Navigation > Show NavMesh Overlay toggles the same overlay.

HLOD Proxies tab#

Bakes one far-distance proxy prefab per tile that TileProxyStreamer shows beyond the streamed 3x3 block: - Terrain: coarse grid (8 m quads at the default 64 cells), skirts down the edges so neighbours never crack, and a baked top-down albedo with tree canopies painted on. - Props: every big static mesh (buildings, cliffs, bridges), lowest LOD, merged into one mesh with a tiny colour-palette texture, up to a triangle budget. - Two draw calls per tile, shadows off.

Only tiles whose scene or dependencies changed since the last bake are rebuilt. Output goes to Resources/World/Proxies/ plus the manifest Resources/World/TileProxies.asset. The output folder must be inside a Resources folder.

Game Data tab#

world DB (items + gear visuals) --> AGDB v3 pack --> AES-256 encrypt --> StreamingAssets/GameData/gamedata.bin + output folder

Getting gamedata.bin onto the Auth server stays a manual copy. That is deliberate: a tool that reaches into a server folder automatically will eventually overwrite a deployed build at the worst moment. The key must match GameDataCrypto.cs on the client.

3.4 Server Control#

Tools > Axiom > Server Control. Build, start, stop and restart the servers from Unity, one log tab each.

Control Effect
Start All Starts in dependency order: Persistence, Auth, World (then Auction if its toggle is on)
Stop All Stops every server process
Restart World The one you use after content changes
Build All dotnet build for the active servers
Auction toggle Include the optional auction service
Stop when Unity quits On by default
Per server: Start, Stop, Restart, Build, Open folder
Log: Follow, Copy, Clear, filter Last 5,000 lines kept per server

Servers run from their built .dll, one process each, so Stop really stops them. Start builds first when there is no build yet. If Unity reloads scripts while a server is running, the process is re-attached by PID but its new output is not captured until you restart it.

4. Create wizards#

Tools > Axiom > Create > ... or Home > Create. One window, a wizard per kind of content. Use a wizard for anything new; use Content Studio to change what exists.

How every wizard works#

  1. Start. Copy an existing one (strongly recommended: you get something that already works) or start blank. Not offered blank for world objects.
  2. Details. The important fields first, with Content Studio's own editors (reference pickers, enums, icons, model keys). Everything else is under More fields.
  3. Extras. What the content needs to be usable: gear looks, loot, shops, spawns.
  4. Finish. - Check validates just your new rows. - Create checks again, then writes one numbered patch named after what you made (for example 061_content_new_npc_frost_wolf.sql) and into the database. - Discard throws it away. Nothing was written.

Your work is kept across window closes and Unity restarts. All reads and writes go through ContentSession, which uses Content Studio's own data layer, so a wizard cannot make a row Content Studio would reject. It is schema-tolerant: a missing table or column is skipped, not an exception.

Id clashes. If Content Studio has unsaved new rows that would take the same ids, Create stops and tells you. Commit or discard them in Content Studio first.

If the database is locked, wizards refuse and write nothing. A patch-only write would leave the database behind, so the next tool asking for "the next free id" would hand out the same id twice.

The wizards#

Wizard Makes Notable sections
Item Weapons, armour, potions, materials Gear stats, on-use effect, dropped by, sold by, how it looks, and Update gamedata.bin after Create (on by default)
NPC Monsters, guards, vendors, quest givers Model (drag an FBX in: it becomes a world prefab), abilities, own loot table, vendor shop, spawners placed where the Scene view is looking
World Object Ore, herbs, trees, chests, stations, doors (doodads) Phases, actions per phase, what each action gives, timers between phases, placement. Always starts from a copy and gives the copy its own actions
Loot Table A gold range and drops Chance per kill (0.25 = one kill in four), give it to an NPC, see who uses it
Dungeon An instanced dungeon end to end Run rules, region and entry and exit points, mobs and boss, entrance and exit portals. A copy moves to the next free region automatically

Menu: Tools > Axiom > Create > Item... / NPC... / World Object (gatherable, chest, station)... / Loot Table... / Dungeon...

5. Project tools#

5.1 Project Setup and Health#

Tools > Axiom > Project Setup and Health. Checks everything a development machine needs for client and servers to work together. Nothing is changed until you press a Fix button. Every JSON file it edits gets a .bak first and only the keys it manages are touched.

Check What it verifies
Server repository Where the server source is (pick the folder if it cannot be found)
World server settings ClientContent in appsettings.json: where gamedata.bin is written and the encryption key
Auth server Serves gamedata.bin (/gamedata/version)
Client game data gamedata.bin bundled in StreamingAssets and the working copy
Shared network DLL Axiom.Network.dll protocol vs the source ProtocolVersion.cs, and says which numbers differ
MessagePack Client version is 3.1.12, same as the servers, so packets serialize identically

5.2 Build and Release#

Tools > Axiom > Build and Release. Produces a release into Builds/<version>/. Steps run in order and a failure stops the rest.

  1. Set the Version (PlayerSettings.bundleVersion). Bump patch increments the last number.
  2. Run all checks (calls Tools > Axiom > Validation > Run All Checks). Note: it only reports; failures appear in the Console and do not stop the build, so read them before shipping.
  3. Build the client for the active build target using the enabled scenes in Build Settings. Output: Builds/<version>/Client/.
  4. Publish servers with dotnet publish -c Release. Pick World, Auth, Persistence (on by default) and Auction (off by default). Output: Builds/<version>/Server/<Name>/.
  5. Release notes: RELEASE_NOTES.md from the last 40 git commits of the client and server repositories.

LuaUiScriptPacker and NetcodeBuildValidator run automatically as pre-build steps (section 8 and 9).

5.3 Find a Tool#

Tools > Axiom > Help > Find a Tool… opens Home > Tools with the search box focused (see 3.1). It replaced the separate Tool Browser window: same search, favourites and recent list, now with a description for every tool and every Dev Tools tab. Your old favourites are kept by key; tools whose menu path changed need starring again.

5.4 Settings#

Tools > Axiom > Settings... opens Dev Tools > Settings: every path the suite uses on one page. You set the server repository once (or let Auto-detect find it); the world database, SQL patches, the server's Data folder, the navmesh, zone map and NPC collision files, the NavBake tool and the Auth server's game data copy are all worked out from it. Any of them can be overridden and put back. Saved in ProjectSettings/AxiomDevTools.asset, with paths near the project stored relative so the file can be committed. See EDITOR_SETTINGS.md.

5.5 Help menu#

Tools > Axiom > Help opens guides from the server repository's docs/ folder: on the offline documentation website (<server>/Axiom-Docs) when it's built, otherwise in your system's default Markdown app. The top of the menu is Documentation Website, Rebuild Documentation (runs scripts/docs/build_docs.py) and Open Docs Folder, then the Handbook (Start Here, Getting Started, Tools Reference, Content Pipeline), then How To ▸ (adding items, weapons, armour, animations, characters, NPCs, the ranger-gear walkthrough, customisation), Troubleshooting, and Reference ▸ with the deep guides (this Editor Tools Reference, Editor Suite, Content Studio, Asset Pipeline, Character Animation, Client Characters, Items and Grades, World Building, HLOD Tile Proxies, Movement and Camera, Dungeons, Quests, Loot, Mounts and Pets, UI). Find a Tool… is at the bottom.

Make World Prefab From Selected Model#

Select one or more imported models (FBX or OBJ) in the Project window. For each it builds a prefab and registers it in WorldObjectPrefabs under a key (the model's file name unless that key is taken). The key must equal the database's ModelType exactly (case-sensitive) or the client shows a placeholder cube.

The prefab root is named for the key and sits at the model's base centre (feet, wheels, foundation), which is the convention everything in Axiom places by. The model is a child. Then, by the model's folder:

Folder Result
Characters/ Animator kept, CharacterSockets added
Creatures/ (and Creatures/Humanoid/) Animator kept, root motion off, a capsule trigger on the layer the interaction raycast uses (the NPC_ORC layer) so it can be targeted
Mounts/ A RiderSeat child at the top of the bounds (move it to the saddle)
Vehicles/ Seat1..Seat2 children and a BoxCollider
Housing/, Dungeons/ Mesh colliders from import are kept
anything else One BoxCollider round the bounds: what the interact ray hits

Models with children named *_LOD0, *_LOD1... get a LODGroup. Output goes to Axiom.Client/Art/Objects/<folder>/.

Art import rules (automatic)#

AxiomArtImporter sets model import settings by folder, on first import only (a hand-tuned setting is never overwritten). It applies to models under Assets/AxiomMMOKit/Axiom.Client/Art/:

Folder Import
Characters/ Humanoid, avatar from the model, no animation clips, blend shapes on
Animations/ Humanoid, clips only, loops detected by name (Idle, Walk, Run, Swim, Loop, Cycle)
Gear/Skinned/ Generic rig kept (bones re-pointed by name at runtime)
Gear/ Static, no rig
Mounts/, Creatures/ Generic rig, clips allowed (Humanoid if the folder is .../Humanoid/)
Housing/, Dungeons/ Static, lightmap UVs, mesh colliders
Vehicles/ Static, no colliders

Everything: scale factor 1, file scale on, cameras and lights off, Read/Write off, mesh compression off. UiArtImporter imports Resources/UI/Art with no mipmaps, no compression, clamped, bilinear, so 9-sliced frames stay crisp at any UI scale.

Known gap: the rules above are tied to a path prefix. Models under Entities/ (for example Entities/Mounts) do not match any rule and import with defaults.

Body parts and sockets#

  • Body part splitter cuts a body that is one skinned mesh into Head, Torso, Arms, Hands, Legs, Feet by bone weights (each triangle goes to the part of the bone that moves it most; bones are classified through the Humanoid Avatar). This is what lets gear hide the skin it covers. Output: Entities/Characters/BodyParts/.
  • Body sockets are child transforms named Socket_<Name> under the right bone, so any weapon fits any body with its offsets at zero. Which sockets exist, the bone each hangs from, and how each starts (in hand, back diagonal, back flat, left or right hip, on top) are defined in the Character Pipeline asset (Resources/Characters/CharacterPipeline.asset), edited in Dev Tools > Characters > Pipeline. Without that asset the code falls back to built-in defaults.

Navigation#

Show NavMesh Overlay draws the server navmesh (walkable polygons tinted, edges where the mesh ends drawn as lines). Only pages near the Scene camera are drawn, and each is meshed once and cached until the file changes, so leaving it on while you build costs almost nothing.

Marker inspectors#

Selecting a spawner or doodad marker in the Scene shows custom inspectors that resolve its id against the real database (so "7" shows as "Orc Grunt"), show whether it is saved, and say what the next save will do. Template lists are cached and refreshed at most every 30 seconds so the inspector never hits SQLite on every repaint.

8. Server Exports#

Menu: Tools > Axiom > Server Exports (was Networking). Data the servers need from Unity; these keep client and server in agreement.

Tool What it does
Movement Collision > Export Bakes colliders from every world scene and catalog prefab into StreamingAssets/World/MovementCollision and copies them to the server. Incremental: each scene's and prefab's result is cached in Library/AxiomCollisionCache, keyed by a hash of the asset and everything it depends on (prefabs, meshes, terrain data, scripts, the exporter, the movement DLL). Only changed scenes are opened
Movement Collision > Export (Full Rebuild) Ignores the cache
Movement Collision > Verify Incremental Export Builds incrementally and fully into two temporary folders and compares every byte. The incremental output must be byte-identical, because the collision hash clients are checked against depends on it
NPC Collision > Export Writes npc_collision.json (version 3, shapes only). One body per ModelType, in this order: a collider named Body (capsule or box), else an upright CapsuleCollider, else (creatures only) a box collider, else (creatures only) a capsule measured from the mesh. Behaviour flags are authored in worldserver.db, not here
NPC Collision > Select Profiles Asset Selects the optional per-template shape overrides asset (Axiom.Client/Content/NpcCollisionProfiles.asset)
NPC Collision > Show NPC Bodies In Scene A toggle menu item. See below
Validate Netcode Build Checks the DLL and MessagePack versions. Also runs automatically before every client build

Tools > Axiom > Server Exports > NPC Collision > Show NPC Bodies In Scene (a checked menu item) draws the body the server will use for a selected NPC: green = from a collider on the prefab, orange = measured from the mesh. If an orange body looks wrong, add an upright CapsuleCollider or a BoxCollider named Body and export again.

Mismatch symptom: "collision data mismatch" at login means the server and client hold different collision files. Re-export (the exporter deploys to the server) and restart the World server.

After installing the reorganized Editor folder, export movement collision once. The export stamp includes the exporter's own script, which moved to Editor/ServerExports/; until you re-export, Validate Netcode Build reports the export as stale. The exporter now finds its own script by name, so later folder moves won't do this again.

Batch mode (build machine):

Unity -batchmode -projectPath <project> -executeMethod Axiom.Client.Axiom.Client.Editor.Netcode.MovementCollisionExporter.ExportFromCommandLine

Optional: -axiomFullRebuild (ignore the cache), -axiomNoDeploy (do not copy to the server). Exit code 0 means success.

10. Content tools#

Currency Shops (Tools > Axiom > Content > Currency Shops)#

Edits the layout of honor, vocation and other currency shops. It edits server offers and synchronizes only the currency display records to the client. The honor currency has id -1, matching the server's ShopManager.HonorCurrencyId. A catalog holds three lists: currencies (item id, name, icon, description, create-item, bind on pickup, no trade), shops (shop id, NPC template, name, allow remote, include gold shop, offers), and vendors. Writes Resources/UI/Shops/CurrencyItems.json.

11. Validation (the checks)#

Tools > Axiom > Validation > Run All Checks runs every check and shows a report: PASS, FAIL with the reason, or SKIP (needs Play Mode, or must not run in it). Checks are found by reflection. Run them before committing UI, housing or networking work, and before every release.

The individual checks are grouped in submenus:

Submenu Checks
UI ▸ Auction View, Chat, Coin Amounts, Crafting Scope, HUD Navigation, Resize and Community, Window Geometry, Toolkit Audit (open scenes)
Housing ▸ Geometry and Packets, Housing Menu, Placard Actions, Starter Prefabs
Furniture ▸ Setup
Maps ▸ Atlas and Coordinates
Shops ▸ Open Shop Layout (Play Mode, with a shop open)
Gameplay ▸ Interaction Skill Packets (the shared DLL and the real packet contract), NPC Quest and Vendor Priority

NPC Quest and Vendor Priority used to require exactly protocol 31 and so failed on every newer DLL; it now accepts 31 or newer.

A check is a static method that throws on failure. A check that cannot run in the current mode throws a message containing "Play Mode" and is reported as SKIP.

13. Python tooling#

Python scripts live outside Assets/ in <project>/Tools/Python/ so Unity never imports them.

Setup: install Python 3 with Add to PATH, then pip install pillow numpy.

PythonRunner (in Assets/AxiomMMOKit/Editor/AssetPipeline) runs a script on a background thread (the editor never freezes), tries python, py, python3 in turn, captures output to the Console tagged [Python] (errors in red), and applies a timeout (default 300 s).

Menu What it does
Tools > Axiom > Art & Assets > Python > Pack Terrain Mask Maps Runs pack_mask_maps.py over AxiomAssetPaths.TerrainLayers (Assets/AxiomMMOKit/Axiom.Client/Art/Terrain/Layers) and refreshes assets
Tools > Axiom > Art & Assets > Python > Open Scripts Folder Reveals Tools/Python

pack_mask_maps.py packs an HDRP Mask Map into <FolderName>_mask.png for every texture folder with an AO and a height map: R metallic (default 0), G ambient occlusion, B height, A smoothness (from a smoothness map, else 1 - roughness, else a constant, default 0.15). It skips existing files unless --force. After packing, set each _mask.png to sRGB off and assign it as the Terrain Layer's Mask Map.

To add a script: drop a .py in Tools/Python/ and call PythonRunner.RunAsync("name.py", "args") from any menu item.

15. Common workflows#

Add a new monster with its own drops#

  1. Home > Create > NPC. Copy Orc (or anything close).
  2. Set name, level, health, damage. Drag its FBX onto Model.
  3. Loot: make a loot table for this NPC and add drops.
  4. Move the Scene view to where it lives; Add a spawner where the Scene view is looking.
  5. Check, Create. Restart the World server.

Add a new ore vein that gives a new material#

  1. Create > Item: "Mithril Ore", category material, no gear stats. Create.
  2. Create > World Object: copy Iron, rename, drag in the model.
  3. On the Full phase's action, under Gives, change the item to Mithril Ore. Adjust the respawn timer on Depleted. Create.
  4. Dev Tools > Doodads: pick it, place it around the mountain, Save to database. Restart the server.

Add a weapon sold by a vendor#

  1. Create > Item: gear stats, rarity, level. Sold by: the vendor's shop and price. How it looks: the prefab, attach to main hand.
  2. Create (leave Update gamedata.bin ticked). Restart the server.

Turn an FBX into an interactive doodad#

  1. Select the FBX. Make World Prefab From Selected Model. Note the key it registered.
  2. Create > World Object. Set the Model to that key.
  3. Add phases, actions and timers. Create. Place it in the world with the Doodads tab.
  4. For a gate or wall that blocks movement, set the template's block box and tick Blocks on the standing phase. The prefab's own colliders are only for clicking; the client builds a separate Blocker from the server's data.

Paint terrain#

See WORLD_BUILDING_GUIDE.md. Short version: create a Terrain Layer per texture set, pack the HDRP Mask Map with Pack Terrain Mask Maps, then Paint Texture. Use the same layer set on every tile so tiles blend without seams. Re-export heightmaps after sculpting.

Change something that already exists#

Content Studio > Ctrl+K > type its name > edit > Ctrl+S. Restart the server.

After pulling from git#

Restart the World server (it applies new patches). If items were added: Dev Tools > Game Data, or Home > Tools > Update Game Data.

Reorganize assets without breaking tools#

  1. Move assets only in the Unity Project window (so .meta files and GUIDs move with them).
  2. If you moved a folder a tool writes to or reads from, change its one line in Editor/Core/AxiomAssetPaths.cs. No other editor file hard-codes an Assets/... location.
  3. Runtime Resources.Load("...") keys are relative to the Resources folder, so moving a whole Resources folder doesn't change them; moving files between Resources folders does.
  4. Run Asset Audit and Run All Checks.

Make a release#

Tools > Axiom > Build and Release: bump version, run checks, build client, publish servers, write notes. Read the Console for check failures before shipping.

16. Troubleshooting#

Symptom Cause and fix
"The world database isn't open" Home > Settings: set the world database to the bin/ copy the server runs
Create or a tab says the database is locked The server is writing. Wait, or stop the server, and retry. Nothing was written. Content Studio offers Write patch only instead
My change is not in game Restart the World server. Make sure Settings points at the bin/ database. For items, rebuild gamedata.bin
Home: "patches not applied" The database you are pointed at is behind. Restart the server, or pick the right database in Settings
NPC or object is invisible or a cube Its model key has no prefab, or the key does not match ModelType exactly (case-sensitive). Run Asset Audit, then Make World Prefab
New item has no name or icon Rebuild gamedata.bin and check the client item database path in Settings
"Id clash with Content Studio" Content Studio has unsaved new rows with the same ids. Commit or discard them there
Doodads tab says spawns will be removed that you did not delete Markers for those spawns are missing from an open scene. Press Load into scene or Clear markers
A wizard field is missing That column does not exist in your database yet. Restart the server once to apply patches, then reopen
"collision data mismatch" at login Client and server collision differ. Export Movement Collision, restart World
Zone hash error in the client log The client and server zones.aczmap differ. Save in the Zones tab (writes both)
NPCs walk through walls or stop in open ground Collider missing from the collision export. Re-export, rebake the navmesh, check the overlay
Server cannot find collision or heightmap files after reorganizing Update the folder in Editor/Core/AxiomAssetPaths.cs (section 15, Reorganize assets), then export again
Validate Netcode Build says the movement collision export is stale right after installing the new Editor folder Expected once: Server Exports > Movement Collision > Export, then restart the World server

Python menu does nothing Python not on PATH, or Pillow and NumPy not installed. The Console says which

A Dev Tools tab shows an error box Press Copy full exception. Other tabs keep working

17. Safety nets#

Protection Details
Automatic backup Before every commit that touches the database: Library/Axiom/WorldDbBackups/, newest 15 kept
One transaction The patch and its schema_versions row commit together. The patch file moves into SQL/patches only after that succeeded
Lock check Wizards and the Doodads tab refuse to write to a locked database rather than diverge from it
Delete guard Doodads, spawners and zones only delete rows that were loaded into a scene that is still open
.bak files Project Health backs up every JSON file before editing
Build gates Lua packing fails the build on any script error or loose .lua; Netcode validation runs before builds

What cannot be undone: a committed patch that has already been applied by a server (restore a backup and delete the patch), and overwritten heightmap or collision exports (re-export from the scene). Content Studio's Ctrl+Z only covers uncommitted edits.

18. Extending the suite#

Programmers only. The structural recommendations are in EDITOR_ARCHITECTURE_PLAN.md.

  • Menus. Add a path constant to Core/AxiomMenu.cs in the right section and use it with a priority from AxiomMenu.Order: csharp [MenuItem(AxiomMenu.World + "My Tool…", false, AxiomMenu.Order.World + 10)] [AxiomTool("One or two sentences: what it does and when to use it.", Keywords = "extra search words")] static void Open() { ... } [AxiomTool] is what Home > Tools shows and searches. To open another tool, call EditorApplication.ExecuteMenuItem(AxiomMenu.SomeTool), never a string literal. Files outside namespace Axiom.EditorTools reach these through using AxiomMenu = global::Axiom.EditorTools.AxiomMenu; and using AxiomToolAttribute = global::Axiom.EditorTools.AxiomToolAttribute;.
  • Asset locations. Never write "Assets/..." in a tool. Use (or add) a constant in Core/AxiomAssetPaths.cs.
  • Tooltips. Every button, toggle and field gets one. IMGUI: GUILayout.Button(new GUIContent("Label", "What it does.")); for a control drawn without a label, call DevToolsContext.Tip("…") right after it. UI Toolkit: set tooltip = "…". DevToolsContext.PathField(..., tooltip: "…") and DevToolsContext.ActionButton(label, tooltip, colour) take one too.
  • Paths and status. AxiomEditor.WorldDbPath, PatchDir, FindDoc, OpenDoc. WorldDbStatus.Get() (cached) and WorldDbStatus.IsLocked(path). AxiomPaths.ProjectRoot, AxiomPaths.ServerRoot, AxiomPaths.Project("Axiom.Server.World") for server projects.
  • A new Dev Tools tab. Implement IDevToolsTab with a parameterless constructor. It is found by reflection: no list to update. Set Title, Order (gaps of 10 so you can insert), and a category. The shell passes you a DevToolsContext with the shared settings, the shared log, and shared widgets (path field, status line). DevToolsWindow.OpenTab("name") opens it from anywhere.
  • A new Create wizard. Subclass CreateWizard. Set Id, Title, Blurb, RootTable, DetailColumns. Override BuildExtras for sections, OnStarted to fix up a copy, AfterCommit for follow-ups. Found automatically. All reads and writes go through ContentSession.
  • A new check. A static, parameterless method with [MenuItem(AxiomMenu.CheckUI + "Name", false, AxiomMenu.Order.ValidationChecks)] (or CheckHousing, CheckMaps, CheckGameplay...) that throws on failure. Anything under AxiomMenu.Validation is picked up by Run All Checks. Throw a message containing "Play Mode" to be reported as SKIP.
  • Writing content from code. Never write SQL by hand. Build a Changeset through a WorkingSet (RecordOps.NewRow, Insert, SetRow, Delete) and call CommitService.Commit, which writes the transaction, the numbered patch and the backup together.
  • Running a script. PythonRunner.RunAsync("script.py", "args", timeoutSeconds, onDone).
  • Naming. New code should use namespace Axiom.EditorTools.<Area>. Never use a namespace segment named Editor on its own; it collides with UnityEditor.Editor. Some older tools still use Axiom.Client.Editor.*, and code inside those (or inside the client's Axiom.Client.Axiom.Client.*) must write global::Axiom.… to reach other Axiom namespaces.
  • Assembly. There are still no editor assembly definitions, so all of Assets/AxiomMMOKit/Editor compiles together into Assembly-CSharp-Editor. Editor-only code must live in Editor/, or be wrapped in #if UNITY_EDITOR if it sits inside Axiom.Client/.
