Characters, Gear & Animation#

Code: Assets/AxiomMMOKit/Axiom.Client/Scripts/Gameplay (PlayerRegistry, NpcRegistry, RemoteEntityInterpolator, Player/PlayerController) and Scripts/Gameplay/Characters.

The pieces on one character#

Player (prefab, pivot at the FEET)                   ← PlayerRegistry.Spawn(W2CSpawnPlayer)
├── PlayerController       local/remote split; nameplate name, health; reports state from the simulation
├── LocalCharacterMotor    LOCAL player only: input → shared CharacterMotor → transform
├── RemoteEntityInterpolator  everyone else: snapshot buffer → transform
├── CharacterModel         picks and swaps the visible body; swim lift; rider seat
├── CharacterAppearance    dresses the body from gear item ids (GearVisualLibrary)
├── CharacterLook          skin/hair/eye colour, hair style, face preset, morphs, height
├── CharacterAnimator      drives the Animator from movement + combat events
└── Model (child)          capsule placeholder, replaced by the body prefab

One writer per transform: PlayerController enables exactly one of motor/interpolator. Two systems writing transform.position is what once put remote players under the terrain.

NPCs are the same idea with NpcIdentity + NpcRegistry (models from WorldObjectPrefabs by the template's ModelType). A killed NPC's model lingers DeathLingerSeconds (2.5 s) for its Die animation after the server despawns it.

Remote entities: interpolation#

RemoteEntityInterpolator keeps a snapshot buffer keyed by server tick (not arrival time) and renders at newest tick − delay (about 200 ms), interpolating between two real samples. Nothing is predicted, so nothing snaps back. The delay must exceed the gap between updates; the tick rate comes from WorldSettings.TickRate. Jumps of remote players are simulated locally from W2CJumpEvent (PlayerRegistry.BeginJump, falling back to NpcRegistry), so arcs look smooth.

Positions arrive in world space and are converted with WorldOrigin.ToLocal (floating origin); facing on the wire is radians, the registries take degrees.

Choosing a body#

CharacterBodyKeys.Resolve(race, gender, faction) tries WorldObjectPrefabs keys, most specific first, and the first key with a prefab wins:

Key Example Gear variants it asks for
Character_{Race}_{Gender} Character_Elf_Female Elf_Female, Female
Character_{Race} Character_Elf Elf
Character_Default_{Gender} Character_Default_Female Female
Character_Faction{N} Character_Faction2 –
Character_Default –

Race and gender names come from worldserver.db (Races: Human, Elf, Fairy; BodyTypes: Male, Female). The shipped WorldObjectPrefabs has Character_Default, Character_Human_Male and Character_Human_Female, so an elf currently falls back to Character_Default. You can add art a little at a time.

Body prefab rules: rigged, with an Animator; pivot at the feet; facing +Z (a root rotation is kept as a visual correction); its colliders are switched off (the player root's is the gameplay one). Optional CharacterSockets (explicit sockets and which renderers are which body part) and SwimBodyOffset (how it sits in water). Mounted: if the mount model has a child RiderSeat, the body sits there.

Gear visuals#

What a character wears comes from the server as item ids per equip slot (W2CSpawnPlayer.Gear, W2CPlayerAppearance). CharacterAppearance.Apply(int[] gear) looks each one up in GearVisualLibrary - definitions from the GearVisuals table in worldserver.db, shipped inside gamedata.bin - and loads the prefab from Resources.

GearVisuals column Meaning
Id row id
ItemId the item (0 = the default look for any item in EquipSlot without its own row)
EquipSlot 1 Head, 2 Chest, 3 Legs, 4 Hands, 5 Feet, 6 MainHand, 7 OffHand, 8 Neck, 9 Ring, 10 Trinket, 11 Backpack
PrefabKey Resources path without extension (Gear/Chest/IronPlate)
AttachType 0 Socket (rigid, parented to a socket: weapons, shields, most helmets) · 1 Skinned (same skeleton as the body, bones re-pointed by name: chest, legs, gloves, boots)
DrawnSocket, SheathSocket e.g. MainHand in combat, Back / HipLeft when sheathed
HideBodyParts flags of base-body parts hidden while worn: Head 1, Hair 2, Torso 4, Arms 8, Hands 16, Legs 32, Feet 64, Hips 128, Shoulders 256, Neck 512, Ears 1024, Beard 2048, Wings 4096, Tail 8192, Underwear 16384, Custom1-8 = bits 16-23
Position*, Rotation*, Scale, SheathScale placement offsets for socket gear

Variants: for each piece, Resources/{PrefabKey}_{variant} is tried before the plain key, using the variants of the body that was actually picked. Gear/Chest/IronPlate on an elf woman tries IronPlate_Elf_Female, IronPlate_Female, then IronPlate. Variants share the row's offsets and flags; adjust inside the variant prefab.

Weapons move between hand and sheath via CharacterAppearance.SetWeaponsDrawn (called by the animator when combat starts/ends). Gear without a database definition simply isn't drawn. GearSkinning validates every bone binding before changing renderers.

The legacy GearVisuals.asset ScriptableObject in Art/Resources/World is an import source only: runtime definitions come from the database via gamedata.bin. Edit gear looks in Content Studio ▸ Items ▸ Gear Visuals, Tools ▸ Axiom ▸ Characters & Gear ▸ Gear Visuals (Database) or the Gear Workshop (fit live on any race/gender), then export game data.

Sockets and the Character Pipeline#

CharacterPipeline (Art/Resources/Characters/CharacterPipeline.asset, edited in Dev Tools ▸ Characters & Races ▸ Pipeline) is one place for the rules every character tool and the runtime share:

  • Sockets: MainHand (RightHand), OffHand (LeftHand), Back (UpperChest, diagonal), BackOffHand (flat), HipLeft, HipRight (Hips), Head. A socket is found via CharacterSockets, else a child named Socket_<Name>, else the humanoid bone.
  • Part rules / name rules: which body part each bone's skin or a mesh named Body_Torso, *_Legs, *hair* belongs to (for "Split body into parts").
  • Bone aliases: pelvis = Hips = mixamorig:Hips, so gear authored on one naming binds to another (Unity/Mixamo, Unreal, Blender Rigify, 3ds Max Biped built in).
  • Appearance colour properties (_BaseColor by default) for skin, hair, eyes.

Without the asset the built-in defaults apply.

Customisation (CharacterLook)#

AppearanceData (protocol 43) is saved with the character: SkinColor, HairStyle, HairColor, EyeColor, FacePreset (option ids, 0 = body default), HeightPercent (90-110), MorphIds + MorphValues (0-100).

The options are rows of AppearanceOptions in worldserver.db (Kind: 1 skin colour #RRGGBB, 2 hair style = a Resources prefab key, 3 hair colour, 4 eye colour, 5 face preset "Smile=40;JawWide=20", 6 morph slider = a blend shape name; RaceId/BodyTypeId 0 = any). The server validates choices; the client applies them: tints on the colour property, hair prefabs bound like armour (skinned) or placed on Head, blend shapes, uniform scale. A helmet hiding Hair hides the hair style too.

Animation#

CharacterAnimator drives your Animator controller. Every parameter is optional - a controller with only Speed works.

Type Parameters
float Speed, MoveX, MoveZ, VerticalSpeed, LocomotionDirection
bool Grounded, Swimming, Mounted, Flying, Seated, Dead, InCombat, Casting, HasStrafeClips (marker)
int SkillId
trigger Jump, Land, Attack, CastRelease, CastInterrupted, Hit, Crit, Miss, Die, Revive
per ability any trigger/bool named in Skills.AnimationParameter; skill-plot steps use the step's own trigger if present

Inputs: the local motor's MoveState or a remote's interpolated velocity and MovementState bits; W2CCastStart/W2CCastEnd; W2CCombatEvent (hits, crits, misses, kills). Root motion is always off - the server owns positions.

No strafe clips? The body turns toward the direction of travel (up to 90°) and backpedalling plays the run cycle in reverse (LocomotionDirection = -1). Add a bool HasStrafeClips to the controller when you have a real 2D blend tree.

Full guides: Character animation (note), Animation series (archive), Bring your own characters.

Crowds#

With hundreds of players in view, bodies are the expensive part. CrowdPresentationManager caps how many remote bodies are fully presented; actors beyond the cap keep their network state, targeting, collision and interpolation but show a cheap representation. Settings in Art/Resources/Settings/CrowdSettings.json:

{ "detailedRemotePlayers": 150, "nameplates": 300, "healthBars": 75, "markerDistance": 85,
  "selectionSeconds": 0.15, "retentionSeconds": 1.5, "retentionDistance": 12,
  "promotionsPerFrame": 3, "pooledBodies": 32, "cosmeticProjectiles": 96, "reservedProjectiles": 24 }

Values are clamped to safe ranges; a broken file falls back to the defaults. CharacterBodyPool reuses bare bodies (gear detached first).

Recipes#

A body for a new race#

  1. Add the race in Content Studio ▸ Items ▸ Races (or Dev Tools ▸ Characters & Races) (Races row: name, description, playable, sort). Restart the World server so creation accepts it; re-export game data.
  2. Import the rig (Humanoid), make a prefab with pivot at the feet, an Animator with your controller, run Add missing sockets / Split body into parts in Dev Tools ▸ Characters & Races.
  3. Add WorldObjectPrefabs entries Character_Elf_Male / Character_Elf_Female (Tools ▸ Axiom ▸ Art & Assets ▸ Select World Prefab Catalog and add a row, or Make World Prefab From Selected Model).
  4. Optional gear variants: IronPlate_Elf_Female next to IronPlate.
  5. Run Tools ▸ Axiom ▸ Art & Assets ▸ Asset Audit - it lists every body key a race/gender could ask for.

A new chest piece#

  1. Model it skinned to the same skeleton (bone names may differ if aliases cover them).
  2. Put the prefab under Resources/Gear/Chest/ (e.g. Resources/Gear/Chest/LeatherVest).
  3. Create the item (Tools ▸ Axiom ▸ Create ▸ Item… or Content Studio ▸ Items; Gear Stats EquipSlot Chest), then add a Gear Visuals row: PrefabKey = Gear/Chest/LeatherVest, Attach = Skinned, Hide = Torso | Arms.
  4. Export game data (gamedata.bin) and restart the World server so new clients get it.

A sword#

Socket attach, DrawnSocket = MainHand, SheathSocket = HipLeft; tune Position/Rotation in the Gear Workshop with a preview body. Build the mesh grip-at-origin, blade +Y, edge +Z and the default socket poses fit without offsets.
