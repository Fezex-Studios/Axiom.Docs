Add a Server System#

We'll build playtime rewards: every 30 minutes a player is online, they get an item. Nothing new on the wire, no new table - this page is about the shape of a World server system. Add a packet with Add a packet, saved per-character state with Add a persisted field, new content tables with Add a worldserver.db table.

Before you start, read The World server: start-up order, two-phase initialisation, the tick, the threading rule, the Scheduler.

1. Tuning numbers: CombatRules#

Numbers designers will want to change go in GameRules.Defaults (Core/Rules/GameRules.cs) and can be overridden by a CombatRules row (Key, Value) in worldserver.db - "change a row, restart", never a rebuild.

            // ── Playtime rewards ──
            ["PlaytimeRewardMinutes"]     = 30,     // minutes online per reward (0 = off)
            ["PlaytimeRewardItemId"]      = 0,      // the item given (0 = off)
            ["PlaytimeRewardCount"]       = 1,

A CombatRules row with an unknown key is ignored with a warning, so typos show up in the log.

2. The service#

src/Servers/Axiom.Server.World/Core/Playtime/PlaytimeRewardService.cs:

using System.Collections.Generic;
using Axiom.Network.Shared;
using Axiom.Server.World.Core.Lua;
using Axiom.Server.World.Core.Managers;
using Axiom.Server.World.Core.Packets.W2CSenders;
using Axiom.Server.World.Core.Rules;
using Axiom.Server.World.Core.Services;
using NLog;

namespace Axiom.Server.World.Core.Playtime;

/// <summary>
/// Every PlaytimeRewardMinutes a character is online, give PlaytimeRewardItemId.
/// Online time is counted in memory per character and resets on logout
/// (persist it with a component if it should carry over). Tick thread only.
/// </summary>
public sealed class PlaytimeRewardService : IInitializable
{
    private static readonly Logger Logger = LogManager.GetCurrentClassLogger();

    private readonly GameRules _rules;
    private PlayerManager _players;
    private ItemManager _items;
    private Scheduler _scheduler;

    private readonly Dictionary<long, int> _minutes = new();     // characterId -> minutes online this login
    private readonly HashSet<long> _seen = new();

    // Phase 1: only what the service needs to EXIST.
    public PlaytimeRewardService(GameRules rules) => _rules = rules;

    // Phase 2: find the managers it talks to. No loading, no network here.
    public void Initialize(ServiceContainer services)
    {
        _players   = services.Get<PlayerManager>();
        _items     = services.Get<ItemManager>();
        _scheduler = services.Get<Scheduler>();
    }

    /// Called once after game data has loaded (step 3b/8 of start-up).
    public void Start()
    {
        int every = (int)_rules["PlaytimeRewardMinutes"];
        int itemId = (int)_rules["PlaytimeRewardItemId"];
        if (every <= 0 || itemId <= 0) { Logger.Info("[Playtime] Off (PlaytimeRewardMinutes / PlaytimeRewardItemId)."); return; }
        if (!_items.Exists(itemId)) { Logger.Warn("[Playtime] Item {Id} doesn't exist - rewards off.", itemId); return; }

        _scheduler.Every(60_000, Sweep, "playtime rewards");     // runs on the tick thread
        Logger.Info("[Playtime] Item {Id} every {Minutes} min online.", itemId, every);
    }

    private void Sweep()
    {
        int every  = (int)_rules["PlaytimeRewardMinutes"];
        int itemId = (int)_rules["PlaytimeRewardItemId"];
        int count  = (int)_rules["PlaytimeRewardCount"];
        _seen.Clear();

        foreach (var peer in _players.GetAllConnectedPeers())
        {
            if (!_players.TryGetSession(peer, out var session) || session.NetworkId == null) continue;   // not in the world yet
            long id = session.CharacterId;
            _seen.Add(id);

            int minutes = _minutes.TryGetValue(id, out var m) ? m + 1 : 1;
            _minutes[id] = minutes;
            if (minutes % every != 0) continue;

            if (_players.TryAddItem(peer, itemId, count))
            {
                Tell(peer, $"Thanks for playing! {minutes} minutes online - you received a reward.");
                _players.FireGameEvent(peer, PlayerEvent.OnPlaytimeReward, itemId, minutes);   // Lua, quests, achievements hear it
            }
            else
            {
                _minutes[id] = minutes - 1;          // try again next minute
                Tell(peer, "Your bag is full - make room to receive your playtime reward.");
            }
        }

        // Forget characters that logged out (their count starts again next login).
        var gone = new List<long>();
        foreach (var id in _minutes.Keys) if (!_seen.Contains(id)) gone.Add(id);
        foreach (var id in gone) _minutes.Remove(id);
    }

    private void Tell(LiteNetLib.NetPeer peer, string text) =>
        W2CChatMessagePacketSender.Send(_players.Replication, new[] { peer }, 0, "System", text, ChatChannel.System);
}

Why it looks like this:

  • IInitializable - constructors take only what the object needs to exist; managers find each other in Initialize after everything is registered, so construction order doesn't matter.
  • Scheduler, not Task.Delay/Timer - Every callbacks run on the tick thread, so they can touch sessions, inventories and the interest grid. A .NET timer would run on a thread-pool thread and corrupt state.
  • Look up, don't keep - the sweep re-resolves sessions every time; never keep NetPeer or PlayerSession references across ticks in a long-lived collection (keep ids).
  • Give items through PlayerManager.TryAddItem - it stacks, sends the bag update, fires OnItemObtained and marks the inventory dirty for saving. For gold use TryAddGold. For anything valuable, consider an immediate save (_players.SaveInBackground(session)).

3. Wire it into start-up (Core/WorldServer.cs)#

    private Axiom.Server.World.Core.Playtime.PlaytimeRewardService _playtime;   // with the other fields

    // step 2, "construct every manager" (after _rules exists):
    _playtime = new Axiom.Server.World.Core.Playtime.PlaytimeRewardService(_rules);

    // BuildServiceContainer / RegisterServices:
    services.Register(_playtime);

    // after game data is loaded (step 3b), e.g. next to the other Scheduler.Every calls:
    _playtime.Start();

Register makes it available to packet handlers' constructors and other managers' Initialize. A handler that asks for an unregistered type fails at boot with a clear message.

4. A Lua event#

Add to Core/Lua/PlayerEvent.cs (append; ids are stable for Lua - never reuse one):

        OnPlaytimeReward = 28, // (player, itemTemplateId, minutesOnline) - a playtime reward was given (PlaytimeRewardService)

The Events table and Server:On("OnPlaytimeReward", fn) pick it up automatically (they're built from the enum). Also add it to the editor annotations in LuaSDK/Server/library/axiom_server.lua (the AxiomEvent alias, an ---@overload line, the Events table) so scripts get autocompletion. Then in a script:

Server:On("OnPlaytimeReward", function(player, itemId, minutes)
    if minutes >= 120 then
        player:SendMessage("Two hours! Take a break and stretch.")
    end
end)

5. Content#

Add a CombatRules row in Content Studio ▸ Combat ▸ Combat Rules: PlaytimeRewardItemId = 90301 (any real item), commit, restart the World server. The log shows [Playtime] Item 90301 every 30 min online.

6. Test it quickly#

Set PlaytimeRewardMinutes = 1 in your local database, log in, wait a minute. For automated tests, the service has no dependency on networking beyond PlayerManager; put the counting logic in a pure function if you want to unit test it.
