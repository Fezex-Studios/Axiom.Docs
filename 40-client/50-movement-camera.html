Unity Client

Input, Local Movement & Camera#

The architecture of server-authoritative movement (inputs, simulation, acknowledgements, reconciliation, collision hashes) is in Movement & netcode. This page covers the client classes around it.

Code: Assets/AxiomMMOKit/Axiom.Client/Movement, Scripts/Gameplay/MMOCamera.cs, Scripts/Gameplay/CameraSettings.cs.

The input pipeline#

PlayerInputActions + GameHotkeys     rebindable InputActions (new Input System, defined in code)
          │
MMOCamera (Update, order -200)       mouse look → camera yaw, steering/free-look flags
          │
LocalPlayerInput.Gather (fixed step) → InputSnapshot
          │   IMovementScheme (Modern | Classic)
          ▼
      MovementIntent  → Resolve (turn, face, move in basis, slow a backpedal)
          ▼
      MoveInput  → LocalCharacterMotor (shared CharacterMotor, 60 Hz)  → C2WMovementInputs

Gather() runs inside the motor's fixed step loop, which may run 0, 1 or several times per frame, so it reads input state and the fixed dt; true edges (jump, autorun) are latched in Update and consumed there.

Keybinds#

Everything is defined in code (no .inputactions asset), with two binding slots per action like classic MMOs' options screen. Overrides are saved in PlayerPrefs (StartRebind, SaveOverrides, ResetToDefaults); the options window lists PlayerInputActions.All and GameHotkeys.All together and reports conflicts.

Action Default Action Default
Move Forward / Back W / S (↑ / ↓) Interact / second F / G
Move Left / Right (strafe) Q / E Skill 1–10 (hotbar, 1 = Attack) 1 … 0
Turn Left / Right A / D (← / →) Character / Inventory C / I
Jump · Swim Up Space Spellbook · Guild K · U
Swim Down X Professions · Achievements O · Y
Walk (toggle) Left Ctrl Quest tracker L
Autorun Num Lock / Mouse back Target next enemy · self Tab · F1

Hardcoded (not yet rebindable) in WorldUIManager: M map, P farms, Shift+B market & mail, F12 GM panel, Esc closes the topmost window / cancels a cast / opens the pause menu.

There is no sprint, by design: you walk or run; mounts and buffs go faster.

PressedThisFrame is valid only in per-frame code, never inside the fixed loop.

Add a hotkey (making the map key rebindable)#

// Movement/GameHotkeys.cs - next to the others in Ensure():
_map = Add("World Map", "<Keyboard>/m", null);
// a property, and add _map to All so the options screen lists it:
public static InputAction ToggleMap { get { Ensure(); return _map; } }

// Scripts/UI/World/WorldUIManager.cs - replace the hardcoded keyboard.mKey line:
if (GameHotkeys.Pressed(GameHotkeys.ToggleMap)) UiGameMenu.Dispatch("map");

WorldUIManager already skips hotkeys while a text field has focus (UiRoot.IsTypingInField), while a blocking window is open, or before the player has entered the world. If you read a hotkey anywhere else, check WorldUIManager.IsTypingInField first.

Control schemes#

MovementSettings (PlayerPrefs, Options ▸ Controls):

Setting
Scheme Classic (character-relative; the code default) or Modern (camera-relative)
ModernFacing Modern: face the camera (WASD strafes, S backpedals) or turn to face where you run
ClassicAdStrafe Classic: A/D strafe instead of turn
FaceTargetInCombat standing in combat, turn to your target (within 40 m)
KeyboardTurnSpeed degrees/s (Classic)
BackpedalSpeed fraction of run speed backwards

Writes save immediately and raise MovementSettings.Changed.

A scheme is one class:

public interface IMovementScheme
{
    MovementIntent Build(in InputSnapshot input);   // Forward, Strafe, Turn, Steering, FreeLook, CameraYaw, CharacterYaw, Dt...
    void Reset();                                    // death, teleport, menu opened
}

MovementIntent = Move (x right, y forward), BasisIsFacing or BasisYaw, TurnDelta, FaceYaw + FaceRate, CarryCamera. To add a scheme: a class in Movement/Schemes, a value in MovementScheme, a case in LocalPlayerInput.SchemeFor. Nothing in the motor changes, and the server never knows - it only sees MoveInput.

LocalCharacterMotor#

The Unity adapter around the shared Axiom.Movement.CharacterMotor:

  • Fixed timestep (simulationRate 60, at most maxStepsPerFrame 5): frame time accumulates, the simulation steps whole times, the render pose is interpolated between the last two states. Same inputs → same result on client and server.
  • Online: ConfigureOnline(W2CMovementConfig, WorldCollisionSet) replaces the inspector values with the server's motor profile, state, physics step, collision layer and epoch. It then sends C2WMovementReady { Epoch, CollisionHash } once the collision revision, the collision area and the streamed tiles are ready. The inspector values (walk 2.5, run 5, jump 0.8 m, gravity -30, slope 50°, step 0.4 m...) only matter offline.
  • Inputs go out in batches (about every 50 ms) with redundancy; a jump is sent at once.
  • Server corrections are replayed from the input history; small visual errors are smoothed with a decaying offset.
  • Collision files are prefetched 192 m ahead so the gate (8 m around the feet) never stops you at a file boundary.
  • Never touches CharacterController: one writer per transform.

UnityCollisionWorld is the ICollisionWorld over PhysX for offline/editor play, and filters out colliders parented under the character itself (a child collider used to make characters "hang" after one jump). IMovingPlatform lets carts and lifts be stood on. Online, the motor collides with the exported collision set (StreamingAssets/World/MovementCollision), identical to the server's.

MMOCamera#

A third-person orbit camera for both schemes.

Mouse Does
Left drag free look: camera orbits, character doesn't turn; cursor hidden while dragging
Right drag steering: camera and character turn together; A/D strafe
Both buttons run forward
Wheel zoom (each context remembers its own zoom); fully in = first person

Execution order matters: mouse look in Update at -200, before LocalPlayerInput (-100); placement in LateUpdate after the motor wrote the render pose.

Context profiles (CameraContext): Explore, Combat (closer, optional over-the-shoulder), Mounted (higher pivot, further, wider FOV at speed), Vehicle, Swimming (lower pivot). Pivot, shoulder and FOV ease between contexts. The camera never dips under the terrain.

CameraSettings (PlayerPrefs): FollowStyle (Smart / Always / Never auto-align), ScreenShake (off by default), SpeedFov, TargetAssist, CombatShoulder, Sensitivity, VerticalScale, InvertY.

Debugging#

  • Character hangs in the air after a jump: a collider under the player prefab not filtered - check what the ground probe hits.
  • Stuck at a loading screen after a teleport: C2WMovementReady not sent - collision not loaded for that area, or WorldStreamer.IsAreaReady false (tile scene missing from Build Settings).
  • Constant rubber-banding: client and server collision differ (collision hash mismatch in the log) - re-export Movement Collision and copy to both. See Movement debugging.
