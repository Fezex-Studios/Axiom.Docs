Client & Editor Notes
Feature note, kept next to the code it describes. Source: docs/notes/client/ASSET_PIPELINE.md

Asset pipeline#

How art gets from a DCC tool into the game. Built 10 Oct 2026, before housing and dungeon art multiplies. The rule underneath it all: the world database names a model key (ModelType); the WorldObjectPrefabs catalog maps that key to a prefab. Data and art meet only there.

Folder layout#

Source art goes under Assets/AxiomMMOKit/Axiom.Client/Art/. The folder decides how it imports (AxiomArtImporter). The rules apply on first import only, so a setting you change by hand is never overwritten.

Folder What Import
Art/Characters/ Player bodies Humanoid, avatar from the model, blendshapes, no clips
Art/Animations/ Clips (Mixamo etc.) Humanoid, clips only, in place (root locked); Idle/Walk/Run/Swim/Sail/Ride/Loop/Cycle loop
Art/Animations/Controllers/ Animator controllers Made by Create Character Animator Controller
Art/Creatures/ NPC models Generic rig with clips (.../Humanoid/ subfolder: Humanoid)
Art/Mounts/ Horses, donkeys Generic rig with clips
Art/Gear/ Weapons, shields, helms Static, no rig
Art/Gear/Skinned/ Armour on the character rig Generic rig kept (bones re-pointed by name at runtime)
Art/Housing/ Houses, furniture, house parts Static, mesh colliders, lightmap UVs
Art/Dungeons/ Dungeon kit pieces Static, mesh colliders, lightmap UVs
Art/Vehicles/ Carts Static, no colliders (the prefab's root collider is the body)
Art/Props/, Art/Doodads/, Art/Nature/ Nodes, crates, trees, stations Static, no colliders
Art/FX/ Effect meshes Static

Textures anywhere under Art/:

  • _N, _Normal or _Nrm become normal maps.
  • _M, _Mask, _ORM, _Rough, _AO or _Metal are linear (not sRGB).
  • Everything is capped at 2048, except characters and housing.

Conventions every model follows#

  • Scale: 1 unit = 1 metre. A character is about 1.8 m.
  • Pivot at the base centre: feet, keel, foundation. The server places things by their base. Make World Prefab moves the model so the root sits there anyway, and the audit warns when a prefab's base is off by more than 25 cm.
  • Forward is +Z: the front of a cart, a character's face, a door's outside.
  • No root motion: the server owns position.
  • LODs: name children *_LOD0, *_LOD1... and the prefab maker adds a LODGroup.

Making a world prefab#

  1. Drop the model in the right Art folder.
  2. Select it, then Tools > Axiom > Art & Assets > Make World Prefab From Selected Model. This writes Assets/AxiomMMOKit/Axiom.Client/Prefabs/World/<Folder>/<Name>.prefab and registers it under the key <Name>. What it adds depends on the folder:
Folder Added
Characters CharacterSockets
Creatures A click capsule on the same layer as NPC_ORC (so it can be clicked and Tab-targeted), root motion off
Mounts A RiderSeat child (move it to the saddle)
Vehicles Seat1-Seat2 children (move them onto the bench) and a box collider
Housing, Dungeons Nothing; they keep their mesh colliders
Everything else A box collider for the interact ray
  1. In Content Studio, set the row's ModelType to that key. Rows are DoodadTemplates, NpcTemplates, Mounts, Vehicles, TradePacks.

The audit#

Tools > Axiom > Art & Assets > Asset Audit reads every ModelType in worldserver.db, plus the keys the client asks for by name, and checks each against the catalog. Each key gets one status:

Status Meaning
Missing Data uses it but nothing is assigned. It's drawn as a placeholder or not at all.
Warning Assigned but suspect. Examples: a vehicle without Seat children, a character without a Humanoid Animator and controller, an NPC or mount with no Animator, a house without HouseRoot, a pivot that's off.
Optional Nice to have, such as per-faction bodies
Unused In the catalog, but no data uses it

What you can do from the window:

  • Assign prefabs in place: drag one onto a row.
  • Add missing keys: one click adds every Missing key as an empty entry.
  • Copy report: the whole list as text.
  • Gear tab: every wearable item (ItemStats in a visible slot) and whether GearVisuals.asset gives it its own look, a slot default, or nothing. Drag a prefab onto a row to give that item its own look.

Run it after every content commit. A new doodad with a new ModelType shows as Missing until its prefab exists.

Keys the client asks for by name#

Key What
Character_Default, Character_Faction{N} Player bodies (CLIENT_CHARACTERS.md)
Corpse Default corpse

Housing#

A house is a doodad (DoodadTemplates with LandRadius > 0) whose ModelType prefab carries HouseRoot. Doors, windows, ladders and the placard are bound parts:

  • Doors and windows: HouseDoor / HouseWindow
  • Climb parts: HouseClimbable
  • Placard: HousePlacard

Furniture surfaces are FurniturePlacementSurface. The setup menu under Tools > Axiom > World > Housing builds the starter cottage and scarecrow; Validate starter prefabs checks them. For a new house:

  1. Model it in Art/Housing/, with mesh colliders on (automatic). The floor must be walkable. Keep wall thickness at 0.2 m or more, so the capsule can't tunnel.
  2. Make the prefab, add HouseRoot, and place the part components on the door, window and placard children.
  3. Add the server's attachment layout and floor surface for it (HouseAttachmentLayout, FurnitureRules). The server validates furniture and traversal against those numbers, not against your colliders.
  4. Create the DoodadTemplate and phases (construction stages, standing, taxes due) in Content Studio, with ModelType = your key. Stage visuals are children listed in a DoodadVisuals component on the prefab, keyed by each phase's Visual key.
  5. Run the audit: the house should be OK.

Dungeons#

A dungeon is a tile scene at a far coordinate: The Warrens at tile 32,32 and the Sunken Crypt at 33,32. Players enter by an instance layer, so it never loads for the open world.

  1. Build it from Art/Dungeons/ kit pieces (modular: 4 m grid, pivots on grid corners, mesh colliders automatic). Mark the static pieces Static so lightmaps bake.
  2. Make a tile scene with Dev Tools > World Tiles at the dungeon's tile, and export the server collision (Dev Tools > World Tiles > Server collision).
  3. Add the Dungeons row, NPC spawners with DungeonId, the portal doodads (ModelType DungeonPortal) and the boss's loot in Content Studio.
  4. Bake the map page (Tools > Axiom > World > Maps) so the minimap works inside.

Budgets (starting points)#

Asset Triangles (LOD0) Textures
Player body 25-40k 2 x 2048
Gear piece 2-8k 1024
NPC 10-25k (bosses 60k) 2048
Doodad / prop 0.5-5k 512-1024, shared atlases preferred
House 20-40k plus parts 2048 trim sheets
Cart 5-15k 1024-2048
Dungeon kit piece 0.5-4k Shared trim sheets

These keep a 50-player siege with houses in view inside a frame budget. Measure in Play Mode, and adjust from what the profiler shows.
