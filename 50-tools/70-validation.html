Validation & Checks#

Problems found in the editor are cheap; problems found in a server log at boot are less cheap; problems found by players are expensive. The project has checks at each layer.

Run All Checks#

Tools ▸ Axiom ▸ Validation ▸ Run All Checks runs every check under the Validation menu and shows a pass / fail / skip report. Run it before committing and before every release (Build and Release has a Run all checks button; wait for the report before pressing Build release, because a build started while the checks run makes them report false failures). Checks that only make sense in or out of Play Mode report skipped.

Check Verifies
UI ▸ Auction View the auction window lists, sorts and pages sample listings
UI ▸ Chat channels, tabs, links and message limits
UI ▸ Resize and Community windows resize at six screen sizes; the community window lays out its pages
UI ▸ Crafting Scope recipes appear at the right stations and proficiency ranks
UI ▸ Coin Amounts gold/silver/copper formatting and conversion
UI ▸ HUD Navigation menu buttons in order, open the right windows, have art
UI ▸ Window Geometry every window fits at twelve resolutions, normal and compact
UI ▸ Toolkit Audit (open scenes) leftover uGUI canvases and legacy controllers
Gameplay ▸ Interaction Skill Packets the shared DLL's protocol and the interaction/skill packet contracts are current
Gameplay ▸ NPC Quest and Vendor Priority quest markers and the NPC right-click order (quest vs shop) update as quests are taken and handed in
Housing ▸ Geometry and Packets plot geometry rules; housing packets round-trip
Housing ▸ Housing Menu / Placard Actions / Starter Prefabs the right actions for owners, visitors and empty plots; the placard prefab
Furniture ▸ Setup placement rules (cottage floor edges) and the DLL version
Maps ▸ Atlas and Coordinates atlas pages exist, sane bounds, world → pixel conversion
Shops ▸ Open Shop Layout (Play Mode, shop open) the shop window hierarchy and stray scrollbars

Writing a check#

A check is any static, parameterless method with a MenuItem under Tools/Axiom/Validation/…; the runner finds it by reflection. Throw to fail; return to pass; put "Play Mode" in the message to be reported as skipped.

using System;
using Axiom.EditorTools;
using UnityEditor;

public static class MyItemChecks
{
    [MenuItem(AxiomMenu.Validation + "Content/Shop Rows The Server Would Skip")]
    [AxiomTool("Fails if a ShopItems row is neither bought nor sold (ShopManager skips those at boot).")]
    public static void ShopRows()
    {
        using var conn = new SQLite.SQLiteConnection(AxiomEditor.WorldDbPath, SQLite.SQLiteOpenFlags.ReadOnly);
        int bad = conn.ExecuteScalar<int>("SELECT COUNT(*) FROM ShopItems WHERE BuyPrice = 0 AND SellPrice = 0");
        if (bad > 0) throw new Exception($"{bad} shop rows have BuyPrice 0 and SellPrice 0.");
    }
}

The best checks mirror a rule the server enforces at load (here ShopManager: BuyPrice 0 = not for sale, both 0 = skipped), so the mistake shows up in the editor instead of the server log. Column names: worldserver.db reference.

Netcode and exports#

Tools ▸ Axiom ▸ Server Exports ▸ Validate Netcode Build checks that the shared Axiom.Network.dll / Axiom.Movement.dll in Assets/AxiomMMOKit/Plugins match the server source, the MessagePack version, the NPC collision export and that the movement collision export is current. Verify Incremental Export proves the incremental movement collision export is byte-identical to a full rebuild. Run both before shipping a client.

On the server#

  • At start-up every catalogue (items, skills, effects, doodads, quests, loot, trade, dungeons...) validates its rows and logs [Catalog]-style warnings for rows it skips; schema and patch problems stop the boot (World server). Read the first screen of the World log after every content change.
  • Persistence refuses to start if its database migrations aren't applied.
  • Load tests: Axiom.LoadTest selftest, selftest-network, and scenario runs (Load testing).

A pre-release routine#

  1. Content Studio: F5, zero errors.
  2. Dev Tools ▸ Validate ▸ Run Checks; Asset Audit.
  3. Server Exports: Movement Collision export, NPC Collision export, Validate Netcode Build.
  4. Run All Checks.
  5. Start all servers from scratch on a copy of production data; read the logs.
  6. A load test preset at the expected player count.
  7. Build and Release.
