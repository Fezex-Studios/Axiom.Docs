UI overhaul: UI Toolkit, the classic MMO-style theme, and Lua UI#

The game's windows are moving from hand-positioned uGUI to UI Toolkit. They stay built at runtime by code, with no scenes, prefabs or Inspector wiring, but they're styled with USS, Unity's CSS: flexbox layout, one theme file, hover states, and live reload while you play in the editor. Lua scripts can build windows too.

Step What Status
1 Foundation: theme, components, window base class, tooltip, dialog, Lua UI, and the shop window as the pilot this patch
2 Core windows: inventory (with drag and drop), character, professions, coffer, loot, mail, auction next
3 HUD: hotbar, unit/target/party frames, cast bars, chat, XP and labor bars, plus the nameplate layer (screen-space, so no world-space uGUI)
4 Login, character select and create; then delete the old uGUI windows

Until each piece is ported, the old uGUI windows keep working next to the new ones.

1. How it fits together#

UiRoot (created on first use, DontDestroyOnLoad)
  UIDocument + PanelSettings (1920x1080 reference, scale with screen)
  Theme: Resources/UI/AxiomTheme.tss
         = Unity's default runtime theme + Resources/UI/AxiomBase.uss
  Layers: Windows  <  Modal (dialogs)  <  Tooltip

ToolkitWindow (C# base class, implements IUIPanel)
  -> UiWindow (framed, draggable, remembers its position, close button)
       -> Content: your layout, made with Ui.Row / Ui.Label / Ui.Button / UiItemSlot ...

WorldUIManager opens and closes them: Escape closes the topmost, and
CloseAll closes them on death or logout.
File What
Resources/UI/AxiomBase.uss The theme (classic MMO-style parchment). Every colour, font, frame and spacing.
Resources/UI/AxiomTheme.tss Unity's default runtime theme + AxiomBase.uss.
Resources/UI/Art/*.png Parchment panels, cards, tabs, buttons, slots, fields, the dark tooltip, coin, arrows and icons: original art in a classic MMO style. They're 9-sliced by the USS, so each can be any size.
Resources/UI/Fonts/ Alegreya (serif, used throughout) and Alegreya Sans (spare). Both are SIL Open Font License; the licence files are next to them.
Scripts/UI/Toolkit/UiRoot.cs The panel, the layers, per-frame ticks, UI scale, "is a text field focused".
Scripts/UI/Toolkit/Ui.cs Builders: Ui.Row, Column, Box, Label, Button, Image, Scroll, Divider, SetShown.
Scripts/UI/Toolkit/UiWindow.cs The window element.
Scripts/UI/Toolkit/ToolkitWindow.cs Base class for a game window.
Scripts/UI/Toolkit/UiWidgets.cs UiItemSlot, UiBar, UiDialog (confirm).
Scripts/UI/Toolkit/UiControls.cs UiTabs, UiPager (first/prev/1-of-N/next/last), UiSearchField (with placeholder), UiPrice (amount + coin).
Scripts/UI/Toolkit/UiTooltip.cs The tooltip, for items or plain text.
Scripts/UI/Toolkit/Windows/ShopWindow.cs The pilot window.
Scripts/UI/Toolkit/Lua/ Lua UI (section 5).
Editor/UiArtImporter.cs Import settings for the UI art: no mipmaps, no compression, clamped.

2. Styling (USS)#

Open Resources/UI/AxiomBase.uss and edit it while the game is running in the editor. Unity re-imports it and the open windows restyle immediately, with no recompile and no restart.

It's CSS with a few differences:

:root { --ac-gold: #8A5A12; }                  /* variables */

.ac-window {                                   /* a class */
    position: absolute;
    background-image: url("Art/window.png");   /* the parchment frame */
    -unity-slice-left: 16;                     /* 9-slice: the corners don't stretch */
    -unity-slice-right: 16;
    -unity-slice-top: 16;
    -unity-slice-bottom: 16;
    padding: 8px 16px 14px 16px;
}

.shop__name  { flex-grow: 1; margin-left: 10px; }  /* flexbox */
.ac-row:hover { background-image: url("Art/row_hover.png"); }
Button.ac-button:active { scale: 0.97 0.97; }

Differences from web CSS to keep in mind:

  • Layout is flexbox only, and the default direction is column. Use flex-direction: row (or the ac-rowlayout class) for rows.
  • Sizes are px or %.
  • Fonts: set -unity-font: url(...) together with -unity-font-definition: initial;, as the theme does.
  • Text colours inside a label can use rich text: <color=#E8C06A>gold</color>, <b>, <size=80%>.
  • :hover, :active, :disabled and :focus work. Transitions work (transition-property, transition-duration).

The theme's classes#

Class For
ac-window, __titlebar, __title, __close, __content windows
ac-button, ac-icon-button + ac-icon ac-icon-refresh/-trash buttons (normal, hover, pressed, disabled)
ac-field, ac-field__placeholder text inputs
ac-check checkboxes (Toggle)
ac-tabs, ac-tab, ac-tab--active tab strips
ac-grid, ac-card, ac-card__body, __name, __price two-column card grids (the shop)
ac-inset, ac-band a recessed panel; a darker band (totals)
ac-row a list row (highlights on hover)
ac-divider a grooved rule
ac-pager, __arrow, __label page arrows
ac-coin the gold coin after a price
ac-slot, __icon, __count item slots
ac-bar, __fill, __label progress bars (the fill is tinted per bar)
ac-scroll a scrolling list with the themed scrollbar
ac-tooltip the tooltip
ac-dialog, ac-modal-shade confirm dialogs
ac-h1, ac-h2, ac-text, ac-muted, ac-gold, ac-good, ac-bad, ac-small, ac-price text (dark ink on parchment)
ac-rowlayout, ac-col, ac-grow, ac-center layout
shop__* the shop window's own classes

Naming: shared pieces are ac-thing; a window's own pieces are window__part (shop__price). Put a window's own rules in a section at the end of the file.

Seeing it visually: UI Builder#

Window > UI Toolkit > UI Builder edits USS visually:

  1. Open AxiomBase.uss in its StyleSheets panel.
  2. Add a test UXML with elements carrying the classes (ac-window, ac-button...).
  3. Tweak the rules in the Inspector and watch the result.

The game's windows are still built by code. They just use the same classes, so what you style in the Builder is what the game shows.

3. Making a window (C#)#

using Axiom.Client.UI.Toolkit;
using UnityEngine.UIElements;

public sealed class MailWindow : ToolkitWindow
{
    public static readonly MailWindow Instance = new MailWindow();
    private MailWindow() : base("mail", "Mailbox", 520, 460) { }   // id (position memory), title, width, height (0 = fit content)

    private ScrollView _list;

    protected override void Build(VisualElement content)          // once, on first open
    {
        Ui.Label(content, "Your mail", "ac-h2");
        _list = Ui.Scroll(Ui.Column(content, "ac-inset", "ac-grow"));
        Ui.Button(content, "Take all", TakeAll);
    }

    protected override void OnOpened() { /* subscribe to state events, refresh */ }
    protected override void OnClosed() { /* unsubscribe */ }
    protected override void Tick()     { /* every frame while open (optional) */ }
}

MailWindow.Instance.Open();     // or Toggle(); Escape closes it
  • Rows: var row = Ui.Row(_list, "ac-row");, then add a new UiItemSlot().Set(itemId, count), labels and buttons to it.
  • Item tooltips come for free on a UiItemSlot. Set slot.TooltipExtra for a gold line, like a price.
  • Confirm: UiDialog.Confirm("Sell item?", "Sell 5x Ore for 20g?", onConfirm, "Sell");
  • Hotkeys: a ToolkitWindow is an IUIPanel, so call WorldUIManager.Instance.Toggle(MailWindow.Instance) from your key handling. (The Inspector's bindings list only takes uGUI UIPanels; step 2 adds window hotkeys.)
  • Text fields: WorldUIManager.IsTypingInField includes UI Toolkit text fields, so typing never fires hotkeys.
  • Mouse over UI: with an EventSystem in the scene, EventSystem.current.IsPointerOverGameObject() is also true over UI Toolkit windows, so clicks on a window don't target the world.
  • UI scale: UiRoot.Instance.Scale = 1.25f; (0.75 to 1.5). A settings slider comes later.

4. The pilot: the shop window (classic MMO layout)#

ShopWindow replaces ShopPanelUI (the prefab version). W2CShopOpen now opens the new window; the old prefab and scripts are still in the project, unused, until step 4 deletes them.

  • Search. It filters as you type. Exact Match matches the whole name. The ↻ button clears the search.
  • Purchase tab. The merchant's goods sit in a two-column grid, ten to a page, with page arrows. Each card shows the icon, the name, and the price with a coin. Hover a card for the tooltip, which ends in "Shop Price".
  • Cart. Click a card to add one, or Shift+click to add ten.
  • It holds up to 10 kinds of item.
  • Click an item in the cart to take it out; the bin empties the cart.
  • Price and New Balance update as you go; New Balance turns red when you can't afford the cart.
  • Purchase sends one buy per line, and the server answers each.
  • Sell tab. It shows what's in your bag that this merchant buys, and what they'll pay. Click a card to sell that stack; 50 g or more asks first. Right-clicking an item in your bag also sells it.
  • It opens beside your bag. Drag it by the title; it remembers where you put it.
  • It closes itself when you walk away from the merchant.
  • Not yet: a Repurchase tab (buying back what you just sold) needs a server-side buyback list. It's a small server patch for later.

Items that show no icon (the Horse Whistle, the Leather armour) have an icon_name with no matching PNG in Resources/Icons. That's a data or art gap, not the window.

5. Lua UI#

Scripts in StreamingAssets/Lua/UI/*.lua run when you enter the world, in name order. They're plain files, so you can edit them without a rebuild.

  • /lua reload re-runs them; their windows are closed and rebuilt.
  • /lua lists the scripts and their commands.
  • The example, 00_character_summary.lua, adds /summary: a small window with health, mana and labor bars and your gold, refreshed twice a second.
local w = UI.Window("hello", "Hello", 320, 0)      -- id, title, width, height (0 = fit)
local name = w:Label("", "ac-h2")                  -- builders return the new element
local row = w:Row()
row:Label("Gold", "ac-muted"):Grow(1)
local gold = row:Label("", "ac-gold")
local hp = w:Bar("#C9423A")                        -- a bar, tinted
w:Slot(56, 3)                                      -- an item slot (with its tooltip)
w:Button("Close", function() w:Close() end)

UI.Every(0.5, function()
  name:SetText(Game.Name())
  gold:SetText(Game.Gold() .. "g")
  hp:SetValue(Game.Health() / math.max(1, Game.MaxHealth()))
end)
UI.Command("hello", function(args) w:Toggle() end)  -- /hello
API
UI.Window(id, title, w, h) a window: every element method, plus :Open() :Close() :Toggle() :IsOpen() :SetTitle(t) :OnClose(fn)
UI.Command(name, fn(args)) /name in chat
UI.Every(sec, fn), UI.After(sec, fn) timers; t:Stop()
UI.SetScale(x) the whole UI's scale
Element builders :Label(text, classes) :Button(text, fn, classes) :Row() :Column() :Box() :Scroll() :Divider() :Bar(colour) :Slot(itemId, count)
Element changes :SetText :SetValue(0..1) :SetItem(id, n) :SetColor("#hex") :AddClass :RemoveClass :Show :Hide :Clear :Width :Height :Grow :OnClick(fn) :Tooltip(text)
Game.* Name Level Gold Health MaxHealth Mana MaxMana Labor LaborMax Count(itemId) ItemName(itemId) (read-only)

classes is a space-separated list of theme classes ("ac-gold ac-small").

Safety:

  • Scripts get MoonSharp's soft sandbox: no io, os or load.
  • Each run and callback has an instruction budget: 5M instructions when a script loads, 200k per button, command or timer. A runaway loop is stopped and reported in chat instead of freezing the game.
  • Lua can only read game state and build UI. The server stays authoritative, so this matters for addons later, not for cheating now.
  • IL2CPP: Scripts/UI/Toolkit/Lua/link.xml keeps the API from being stripped.

6. Setting it up in Unity#

Nothing to wire; the first window creates everything. After importing:

  1. Wait for the import. Editor/UiArtImporter.cs sets the art's import options itself. If you imported the PNGs before the script, right-click Resources/UI/Art → Reimport.
  2. The fonts import as Font assets. Nothing to do.
  3. Talk to Hilda. The shop opens in the new style.
  4. Type /summary in chat for the Lua example.

If windows show but look unstyled (grey default buttons, no frames), the theme didn't load. Check the console for Resources/UI/AxiomTheme.tss is missing, and that AxiomTheme.tss imported as a Theme Style Sheet.

Optional: to tune scaling in the Inspector, create a PanelSettings asset at Resources/UI/AxiomPanelSettings (Create > UI Toolkit > Panel Settings Asset) with the theme assigned. It's used instead of the built-in settings.

Draw order vs the old uGUI: the UI Toolkit panel sorts at 100, above the HUD canvases. If an old uGUI element (the old item tooltip, a uGUI dialog) ends up behind a new window, that piece moves to UI Toolkit in its step. It's temporary.
