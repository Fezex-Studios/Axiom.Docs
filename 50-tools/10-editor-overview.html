The Editor Suite#

Everything is under the Axiom menu (code in Assets/AxiomMMOKit/Editor). The full generated list of menu items with descriptions is in Editor menu reference.

First-time setup#

  1. Open the project, then Tools ▸ Axiom ▸ Home. Red lines in Status have a Fix button.
  2. Tools ▸ Axiom ▸ Settings… (Dev Tools ▸ Settings): set, or Auto-detect, the server repository (the folder that holds src/). Everything else is worked out from it: the World database (the newest worldserver.db of src/Servers/Axiom.Server.World), the SQL patches folder, the server Data folder, the NavBake tool, Auth's game data. Override a single path with Change…. Saved in ProjectSettings/AxiomDevTools.asset, with paths near the project stored relative - commit it. Red rows put a banner on every Dev Tools tab until fixed (Editor settings).
  3. Tools ▸ Axiom ▸ Project Setup and Health: fix what's red (game data key and output paths, Auth's game data path, DLL versions).
  4. Tools ▸ Axiom ▸ Server Control ▸ Start All (Persistence → Auth → World → Auction).

The Dev Tools status bar shows World DB ● Auth ● Persistence ● World ● Data pills; click one for details.

The world database lock#

Most tools write to worldserver.db and write a numbered SQL patch into SQL/patches. While the World server is running it holds the database; tools detect this (a quick BEGIN IMMEDIATE probe) and then only write the patch, which the server applies on its next start. So the workflow with a running server is: edit → save (patch only) → restart the World server. Patches are tracked in schema_versions, so nothing is applied twice (worldserver.db).

Adding your own tool#

A menu item that appears in Home's tool list with a description:

// Assets/AxiomMMOKit/Editor/MyTools/CountNpcsTool.cs
using Axiom.EditorTools;
using UnityEditor;
using UnityEngine;

public static class CountNpcsTool
{
    [MenuItem("Axiom/My Tools/Count NPC Templates")]
    [AxiomTool("Print how many NPC templates the world database has.", Keywords = "npc count")]
    public static void Run()
    {
        string db = AxiomEditor.WorldDbPath;                       // the shared setting
        using var conn = new SQLite.SQLiteConnection(db, SQLite.SQLiteOpenFlags.ReadOnly);
        int n = conn.ExecuteScalar<int>("SELECT COUNT(*) FROM NpcTemplates");
        Debug.Log($"[My Tools] {n} NPC templates in {db}");
    }
}

Use AxiomMenu constants for paths and AxiomMenu.Order for ordering if you want it to sit with the built-in items.

A Dev Tools tab is a class implementing IDevToolsTab; the window finds it by reflection - no registration:

using Axiom.EditorTools.DevTools;
using UnityEditor;
using UnityEngine;

public sealed class ServerNotesTab : IDevToolsTab
{
    public string Title => "📝  Notes";
    public int Order => 900;                                  // gaps of 10; sidebar order
    public string Category => DevToolsCategories.Other;
    public string Description => "Scratch notes for this machine.";
    private string _text;

    public void OnEnable(DevToolsContext ctx)  => _text = EditorPrefs.GetString("Axiom.Notes", "");
    public void OnDisable(DevToolsContext ctx) => EditorPrefs.SetString("Axiom.Notes", _text);
    public void OnGUI(DevToolsContext ctx)
    {
        _text = EditorGUILayout.TextArea(_text, GUILayout.ExpandHeight(true));
        if (GUILayout.Button("Log it")) ctx.Info(_text, "Notes");   // the shared log at the bottom
    }
    public bool HasUnsavedChanges => false;
}

DevToolsContext gives tabs the shared settings (WorldDbPath, PatchDir, HasWorldDb), the log (Info/Success/Warn/Error), Repaint, and helpers (PathField, FileStatus). OnSceneGUI is called for the active tab only, for Scene-view overlays.

A Create wizard is a class deriving from CreateWizard (found by reflection by AxiomCreateWindow); a validation check is added to AxiomCheckRunner. Read an existing one first - they are small.
