Server Systems

Persistence Server#

Axiom.Server.Persistence is an ASP.NET Core minimal-API app (port 7778) that owns axiom_persistence (MySQL). Only World servers (and the Auction server, for mail) call it. Why it exists and how saves work is on Persistence flow; tables are on MySQL databases.

Layout#

File
Program.cs start-up, the secret gate, every route (grouped by // ── /route ── banners), and the save helpers (ApplyFullSaveAsync, ValidateFullSave, load builders)
Api/Data/PersistenceDbContext.cs EF model: every table and its column names
Api/Models/*.cs entity classes (one per table)
Api/Data/BulkInsert.cs multi-row INSERT for the full save (one statement per table instead of one per row)
Api/Data/ItemUidAudit.cs records any gear uid found in two places (item_uid_conflicts), inside the save's transaction; never blocks a save
Api/CommunityEndpoints.cs /community/command (friends, blocks, families)
Api/Extensions/Extensions.cs ReadMsgPackAsync<T> (null on a malformed body) and WriteMsgPackAsync<T>
Api/AppearanceJson.cs characters.appearance JSON
Migrations/ EF migrations, applied automatically on start (AutoMigrate, default on)
SQL/ hand-runnable equivalents of feature migrations, plus seeds (cash_shop_seed.sql, admin_mail_examples.sql)

Start-up#

  1. PacketSerialization.Configure() (shared MessagePack options).
  2. Reads appsettings.json, appsettings.Local.json, environment.
  3. Refuses to start without a connection string or with a missing/placeholder/short InternalSecret.
  4. Migrations. With AutoMigrate (default true), creates the database if it doesn't exist and applies every pending migration (MigrateAsync), like Auth. If a table already exists because one of the SQL/*.sql scripts made it, start-up stops and says how to record that migration as applied. With AutoMigrate: false, it checks pending migrations without changing the database: it refuses to start if the class-based characters, warehouse or world outbox migrations are missing, switches Patron off if account_patron is missing, and warns about any other pending ones.
  5. Installs the secret gate: every request without the right x-internal-secret gets 404 (not 403, so a scanner learns nothing).
  6. Maps the routes and listens.

Route conventions#

Every route follows the same shape:

app.MapPost("/trade/demand/list", async (HttpContext context, PersistenceDbContext db) =>
{
    var request = await context.Request.ReadMsgPackAsync<W2PTradeDemandListRequest>();
    if (request is null) { context.Response.StatusCode = StatusCodes.Status400BadRequest; return; }

    string shard = request.Shard ?? "";
    var rows = await db.TradeDemand.AsNoTracking()
        .Where(d => d.Shard == shard)
        .Select(d => new TradeDemandDto { OutletId = d.OutletId, PackItemId = d.PackItemId, DemandPct = d.DemandPct, UpdatedAtUnixMs = d.UpdatedAtUnixMs })
        .ToArrayAsync();

    await context.Response.WriteMsgPackAsync(new P2WTradeDemandListResponse { Rows = rows });
});
  • Request/response types are W2P*/P2W* classes in Axiom.Network (shared with the World server).
  • Validate everything (counts, ranges, finite floats): the World server is trusted, but a bug there must not corrupt the database. A malformed request gets a definite answer (Invalid or 400), never a 500 the caller would retry forever.
  • Definite vs retryable: 200 with a result means "this is what happened"; 500 means "rolled back, safe to retry". Commit is the last thing in a try, so any exception means nothing was written.
  • Out-of-order safety: writes that can race carry a version or sequence and only replace older data (save_seq, doodad version, updated_at_unix_ms upserts like the one above).
  • Idempotency by key: deliveries (mail_receipts), outbox entries (op_key), placement keys.

The full-save transaction (/characters/save-full → ApplyFullSaveAsync) is described step by step in Persistence flow. /characters/save-pair runs it twice in one transaction (player trades).

Example: a new route end to end#

Goal: a server-wide bounty board: the World server stores and lists bounties.

1. Shared types (Axiom.Network/Shared/Packets/W2P/W2PBountyPackets.cs):

[MessagePackObject] public class BountyDto
{
    [Key(0)] public long TargetCharacterId;
    [Key(1)] public string TargetName;
    [Key(2)] public int RewardCopper;
    [Key(3)] public long PostedAtUnixMs;
}
[MessagePackObject] public class W2PBountyListRequest  { [Key(0)] public string Shard; }
[MessagePackObject] public class P2WBountyListResponse { [Key(0)] public BountyDto[] Rows; }
[MessagePackObject] public class W2PBountyPostRequest  { [Key(0)] public string Shard; [Key(1)] public BountyDto Bounty; [Key(2)] public string Key; }
[MessagePackObject] public class P2WBountyPostResponse { [Key(0)] public bool Posted; [Key(1)] public string Message; }

Rebuild Axiom.Network (the World server and Persistence reference the project; the client only needs the DLL if it sees these types).

2. Table (Api/Models/Bounty.cs + PersistenceDbContext + migration):

public class Bounty
{
    public string Key { get; set; } = "";              // idempotency key from the World server (PK)
    public string Shard { get; set; } = "";
    public long TargetCharacterId { get; set; }
    public string TargetName { get; set; } = "";
    public int RewardCopper { get; set; }
    public long PostedAtUnixMs { get; set; }
}
// PersistenceDbContext.OnModelCreating:
modelBuilder.Entity<Bounty>(e => {
    e.ToTable("bounties"); e.HasKey(x => x.Key);
    e.Property(x => x.Key).HasColumnName("op_key").HasMaxLength(64);
    e.Property(x => x.Shard).HasColumnName("shard").HasMaxLength(64);
    e.Property(x => x.TargetCharacterId).HasColumnName("target_character_id");
    e.Property(x => x.TargetName).HasColumnName("target_name").HasMaxLength(32);
    e.Property(x => x.RewardCopper).HasColumnName("reward_copper");
    e.Property(x => x.PostedAtUnixMs).HasColumnName("posted_at_unix_ms");
    e.HasIndex(x => x.Shard);
});
public DbSet<Bounty> Bounties => Set<Bounty>();

cd src/Servers/Axiom.Server.Persistence
dotnet ef migrations add Bounties
dotnet ef database update

3. Routes (Program.cs, next to the others):

// ── /bounties ─────────────────────────────────────────────────────────
app.MapPost("/bounties/list", async (HttpContext context, PersistenceDbContext db) =>
{
    var req = await context.Request.ReadMsgPackAsync<W2PBountyListRequest>();
    if (req is null) { context.Response.StatusCode = 400; return; }
    var rows = await db.Bounties.AsNoTracking().Where(b => b.Shard == (req.Shard ?? ""))
        .OrderByDescending(b => b.RewardCopper).Take(100)
        .Select(b => new BountyDto { TargetCharacterId = b.TargetCharacterId, TargetName = b.TargetName,
                                     RewardCopper = b.RewardCopper, PostedAtUnixMs = b.PostedAtUnixMs })
        .ToArrayAsync();
    await context.Response.WriteMsgPackAsync(new P2WBountyListResponse { Rows = rows });
});

app.MapPost("/bounties/post", async (HttpContext context, PersistenceDbContext db) =>
{
    var req = await context.Request.ReadMsgPackAsync<W2PBountyPostRequest>();
    if (req?.Bounty is null || string.IsNullOrEmpty(req.Key) || req.Key.Length > 64 ||
        req.Bounty.RewardCopper <= 0 || req.Bounty.TargetCharacterId <= 0)
    { await context.Response.WriteMsgPackAsync(new P2WBountyPostResponse { Message = "Invalid bounty." }); return; }

    // Idempotent: the same key posted twice is one bounty.
    if (await db.Bounties.AnyAsync(b => b.Key == req.Key))
    { await context.Response.WriteMsgPackAsync(new P2WBountyPostResponse { Posted = true }); return; }

    db.Bounties.Add(new Bounty { Key = req.Key, Shard = req.Shard ?? "", TargetCharacterId = req.Bounty.TargetCharacterId,
        TargetName = req.Bounty.TargetName ?? "", RewardCopper = req.Bounty.RewardCopper,
        PostedAtUnixMs = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds() });
    await db.SaveChangesAsync();
    await context.Response.WriteMsgPackAsync(new P2WBountyPostResponse { Posted = true });
});

4. World side: a small store class like TradeDemandStore, calling _persistence.PostAsync<W2PBountyPostRequest, P2WBountyPostResponse>("/bounties/post", …) from an async method and hopping back with EnqueueAction (threading rule). Because posting a bounty takes gold from the player, use the economy pattern: take the gold, SaveNowAsync(session, outboxAdd) with the bounty as an outbox entry, then post with the same key; delete the outbox entry when it's posted (Economy).

The new routes appear in the generated Service endpoints next time the docs are built.
