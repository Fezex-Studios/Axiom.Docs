14. Characters, Races and Genders#

How races and genders work, how to give each one its own body, and how to add a new race.

You'll use: Dev Tools > Characters & Races, Gear Workshop, and (to add a race) the server source.

How it fits together#

Piece Where Notes
The list of races world database tables Races and Body Types (Content Studio) read by the World server on start, sent to clients: Human (1), Elf (2), Fairy (3); Male (1), Female (2)
Genders same file: Male (1), Female (2)
A character's race and gender MySQL characters.race_id, gender_id chosen at creation, never changes. Characters from before races are Human Male
Which body is drawn the WorldObjectPrefabs catalog, key Character_{Race}_{Gender} client only
Which armour is drawn the item's gear visual + variants {Prefab}_{Gender}, {Prefab}_{Race}_{Gender} client only (guide 12)

One faction. Every character is in Westmark, the only playable faction (world patch 096_single_playable_faction.sql). With one faction to pick, the creation screen hides the faction choice. Pirates still exist as the outlaw faction a guilty verdict exiles you to. To rename Westmark, edit its row in Content Studio > Factions.

The creation screen shows every race, both genders and a live 3D preview. The World server checks the choice, the Persistence server saves it, and every client that sees the character draws the matching body.

Step 1: Give each race and gender a body#

  1. Make the body prefab: a rigged character FBX, Rig: Humanoid, pivot at the feet, facing +Z, with AxiomCharacter.controller on its Animator (guide 13, Part A).
  2. Dev Tools > Characters & Races > Bodies.
  3. Drag the prefab into the slot for that race and gender, e.g. Elf / Female. Done: it's saved into the catalog.

You don't need every body at once. Empty slots fall back, and the grey text under each slot says which body that character gets today:

Character_Elf_Female  →  Character_Elf  →  Character_Default_Female  →  Character_Faction{N}  →  Character_Default

A good order: Character_Default first (everyone has a body), then Default / Female (every woman looks female), then each race as its art arrives.

Fairies: wings and size#

  • Wings belong to the body. Model them into Character_Fairy_Male / Character_Fairy_Female, as their own mesh (a separate renderer), not merged into the torso. Gear that hides Torso hides only the renderers marked as the torso in the body's CharacterSockets, so wings stay visible under a chest piece.
  • Chest armour for fairies usually needs an opening for the wings: make _Fairy_Female / _Fairy_Male variants (guide 12, Part E). The Wardrobe page shows which pieces still lack one.
  • A smaller body is fine: scale the model inside the body prefab (the child, not the root). Socket gear rides on the bones, so it scales with them. Check that nameplates and the camera still sit well on a fairy.

Step 1b: Give each body its attachment points#

Characters & Races > Sockets > pick the body > Add missing sockets, then line each one up with a reference weapon. Weapons won't sit right until you do: see guide 11, Part A.

Step 2: Check what everyone wears#

Dev Tools > Characters & Races > Wardrobe shows every gear visual against every body you've assigned:

Cell Means
✓ Female, ✓ Elf_Female this body wears that variant
base this body wears the original prefab (fine for weapons, hats)
⚠ base mesh skinned armour made for another rig. Make a variant for this body (guide 12, Part E)
✖ no prefab the gear visual's prefab is missing

Press Fit… on a row to open it in the Gear Workshop.

Step 3: Test#

  1. Press Play, create a character of each race and gender. The preview on the creation screen should show the right body.
  2. Enter the world and equip a few pieces of armour.

Adding or changing a race#

Renaming or describing a race: edit its line in CharacterRaceRules.Races. The name is also its art name (Character_Elf_Female, IronPlate_Elf_Female), so rename those keys and prefabs too.

Tying a race to a faction (only matters if you add a second playable faction later): pass the faction id as the last argument. The creation screen then picks that faction for the race, and the servers refuse anything else:

new RaceInfo((int)CharacterRace.Fairy, "Fairy", "Small, quick…", 1),   // Westmark only

Adding a race (since protocol 42 it's data): Content Studio > Races > New: the next free Id, a one-word Name (Dwarf), a description, SortOrder. Ctrl+S, restart the World server, then give it bodies (Step 1). No code, DLL rebuild or migration. Body types (Male, Female, or more) work the same way in Content Studio > Body Types. Details: guide 17.

Never renumber an existing race. The number is stored on every character; renumbering would turn existing elves into dwarves.

If it doesn't work#

Problem Fix
Everyone looks the same no race/gender bodies assigned; or the client DLL is older than protocol 41 (Overview > Network protocol)
Creation says "Choose a race" the server's race list and the client's DLL differ: rebuild and copy the DLL, restart the servers
"That race can't join that faction" the race is tied to another faction (above)
Old characters are Human / in Westmark now expected: the ThreeRacesOneFaction migration moved Dwarf/Orc characters to Human and Eastreach characters to Westmark
Database error creating a character of a new race the persistence migration wasn't applied (step 2)
Women wear men's armour no _Female variant: Wardrobe page
