Cookbook (How-To)

Add a Persisted Character Field#

Characters are saved as full snapshots: the World server sends everything that changed in one W2PCharacterSaveFullRequest, Persistence writes it in one MySQL transaction if its SaveSeq is newer than the stored one, and loading returns it all in P2WCharacterLoadResponse (Persistence flow). A new saved field travels the same road. The cleanest existing example is dungeon entry counts (DungeonEntryComponent), which this page follows step by step.

Example: keep each character's lifetime minutes online and the last playtime reward they got, so rewards continue across logins.

World  PlaytimeComponent (IPersistentComponent)
         │ WriteTo(snapshot)           ▲ Load(dto)
         ▼                             │
       W2PCharacterSaveFullRequest.Playtime  ─►  Persistence ApplyFullSaveAsync ─► character_playtime (MySQL)
       P2WCharacterLoadResponse.Playtime     ◄─  /characters/load               ◄─

1. The DTO (Axiom.Network)#

src/Shared/Axiom.Network/Shared/Packets/PlaytimeDto.cs:

using MessagePack;

namespace Axiom.Network.Shared.Packets.PersistenceServer
{
    /// <summary>Lifetime playtime. In the full save (null = leave it alone) and on load (null = an older Persistence).</summary>
    [MessagePackObject]
    public class PlaytimeDto
    {
        [Key(0)] public long TotalMinutes;
        [Key(1)] public int  LastRewardMinutes;
    }
}

Add it to both packets with the next free key (never reuse a key):

// W2P/W2PCharacterSaveFullRequest.cs  (last key is 25 today)
        /// <summary>Lifetime playtime - or null to leave it alone.</summary>
        [Key(26)] public PlaytimeDto Playtime;

// P2W/P2WCharacterLoadResponse.cs      (last key is 26 today)
        /// <summary>Null = a persistence server older than playtime.</summary>
        [Key(27)] public PlaytimeDto Playtime;

Null means "not included" in a save and "not supported" on load. That's what lets a newer World talk to an older Persistence (and vice versa) without wiping data.

Rebuild Axiom.Network; the World and Persistence servers both reference it, so deploy them together.

2. The component (World)#

src/Servers/Axiom.Server.World/Core/Players/Components/PlaytimeComponent.cs:

using Axiom.Network.Shared.Packets.PersistenceServer;
using Axiom.Network.Shared.Packets.PersistenceServer.W2P;

namespace Axiom.Server.World.Managers
{
    /// <summary>Lifetime minutes online and the last reward given. Only PlaytimeRewardService writes it.</summary>
    public sealed class PlaytimeComponent : IPersistentComponent
    {
        /// <summary>False = Persistence doesn't support it: nothing is saved (values live until logout).</summary>
        public bool Loaded;
        public long TotalMinutes { get; private set; }
        public int  LastRewardMinutes { get; private set; }
        private bool _dirty;

        public void AddMinute()            { TotalMinutes++; _dirty = true; }
        public void RewardGiven(int at)    { LastRewardMinutes = at; _dirty = true; }

        public void Load(PlaytimeDto dto)
        {
            Loaded = dto != null;
            TotalMinutes = dto?.TotalMinutes ?? 0;
            LastRewardMinutes = dto?.LastRewardMinutes ?? 0;
            _dirty = false;
        }

        public bool IsDirty => Loaded && _dirty;

        public void WriteTo(W2PCharacterSaveFullRequest snapshot) =>
            snapshot.Playtime = Loaded ? new PlaytimeDto { TotalMinutes = TotalMinutes, LastRewardMinutes = LastRewardMinutes } : null;

        public void MarkSaved() => _dirty = false;
    }
}

The contract (IPersistentComponent): IsDirty, WriteTo(snapshot), MarkSaved(). The save system asks every component in PlayerSession.PersistentComponents; autosave picks up dirty sessions, logout and important events save immediately.

Register it on the session (Core/Players/PlayerSession.cs):

        public readonly PlaytimeComponent Playtime = new();
        // in the constructor, add it to the list:
        PersistentComponents = new IPersistentComponent[] { Inventory, Warehouse, Quests, Equipment, Abilities, Labor,
                                                            Proficiency, Pvp, Achievements, DungeonEntries, Playtime, ... };

Load it on login (Core/Players/PlayerSpawnManager.cs, next to session.DungeonEntries.Load(character.DungeonEntries);):

            session.Playtime.Load(character.Playtime);

Use it (PlaytimeRewardService.Sweep): session.Playtime.AddMinute(), and compare against session.Playtime.TotalMinutes instead of the in-memory dictionary.

3. The table (Persistence, MySQL)#

Model, src/Servers/Axiom.Server.Persistence/Api/Models/Playtime.cs:

namespace Axiom.Server.Persistence.Api.Models
{
    public class CharacterPlaytime
    {
        public long CharacterId       { get; set; }
        public long TotalMinutes      { get; set; }
        public int  LastRewardMinutes { get; set; }
    }
}

Api/Data/PersistenceDbContext.cs:

        public DbSet<CharacterPlaytime> CharacterPlaytime => Set<CharacterPlaytime>();

        // in OnModelCreating (snake_case columns, like every table here):
            modelBuilder.Entity<CharacterPlaytime>(entity =>
            {
                entity.ToTable("character_playtime");
                entity.HasKey(e => e.CharacterId);
                entity.Property(e => e.CharacterId).HasColumnName("character_id");
                entity.Property(e => e.TotalMinutes).HasColumnName("total_minutes");
                entity.Property(e => e.LastRewardMinutes).HasColumnName("last_reward_minutes");
            });

Migration (Persistence uses generated EF migrations, applied by hand):

cd src/Servers/Axiom.Server.Persistence
dotnet ef migrations add CharacterPlaytime
dotnet ef database update        # on every environment, before starting the new Persistence build

At start-up Persistence lists pending migrations: it refuses to start for the critical ones and warns about the rest - a missing character_playtime table would make every full save that includes playtime fail, so apply it everywhere before deploying (MySQL databases).

4. Write it in the save transaction (Persistence)#

In Program.cs, ApplyFullSaveAsync (inside the transaction, next to the dungeon entries block):

            // Lifetime playtime - or left alone when null.
            if (request.Playtime is not null)
            {
                await db.Database.ExecuteSqlInterpolatedAsync($"""
                    INSERT INTO character_playtime (character_id, total_minutes, last_reward_minutes)
                    VALUES ({request.CharacterId}, {request.Playtime.TotalMinutes}, {request.Playtime.LastRewardMinutes})
                    ON DUPLICATE KEY UPDATE total_minutes = VALUES(total_minutes),
                                            last_reward_minutes = VALUES(last_reward_minutes)
                    """);
            }

And validate it in ValidateFullSave (a save that fails validation is rejected whole):

    if (r.Playtime is not null && (r.Playtime.TotalMinutes < 0 || r.Playtime.LastRewardMinutes < 0))
        return $"playtime {r.Playtime.TotalMinutes}/{r.Playtime.LastRewardMinutes}";

5. Return it on load (Persistence)#

In the /characters/load route, next to the dungeon entries query:

    var playtimeRow = await db.CharacterPlaytime.AsNoTracking()
        .FirstOrDefaultAsync(p => p.CharacterId == row.CharacterId);
    var playtime = new PlaytimeDto { TotalMinutes = playtimeRow?.TotalMinutes ?? 0,
                                     LastRewardMinutes = playtimeRow?.LastRewardMinutes ?? 0 };
    // ...
        DungeonEntries = dungeonEntries,
        Playtime = playtime,

Return a DTO (with zeros) even when there's no row yet - null is reserved for "this server doesn't know about playtime".

If characters can be deleted for real, also delete character_playtime rows where the other per-character tables are cleaned up.

6. Test#

  1. dotnet ef database update, start Persistence, Auth, World.
  2. Log in, wait a few minutes, log out. In MySQL: SELECT * FROM axiom_persistence.character_playtime;
  3. Log back in: the count continues.
  4. Kill the World server process (no clean shutdown) after a minute: the last autosave's value survives - that's the guarantee you get for anything not saved with SaveNowAsync.

Rules worth repeating#

  • Everything in one transaction: the component rides on the full save, so playtime and inventory can never disagree after a crash.
  • Null = leave alone in saves; null = unsupported on load; empty/zero = "really nothing".
  • Never write per-character state from the World server to MySQL any other way (no side channels): the SaveSeq ordering and the CharacterSaveChain are what stop an old save overwriting a newer one.
  • Account-wide data (labor, patron) is keyed by account, not character - see LaborDto / PatronDto.
  • Anything owed to another service as part of the same change (mail, auction escrow) goes through the outbox (SaveNowAsync(session, outboxAdd)), see Economy.
