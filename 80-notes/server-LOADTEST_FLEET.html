Server Notes
Feature note, kept next to the code it describes. Source: src/Tools/Axiom.LoadTest/FLEET.md

See LOADTEST.md for the current workflow: preflight, automatic generator sizing, bot fidelity (full/lite/mixed), the diagnosis in every report, and the diagnose command. The settings below still apply.

Fleet: testing 1,000 to 10,000 bots#

One generator process runs at most 512 bots (about 250 is comfortable). A fleet starts many generators from one file, gives each its own slice of accounts, starts them together, prints one progress line, and combines the results. A ladder runs several fleet sizes one after another (1k, 2k, 3k, 4k, 5k, 10k) and tells you the largest that passed.

What is new in this version#

  • Zone spread ("ZoneSpread": true). Every bot gets a home inside one of the world's zones, read from the same zones.aczmap the World server loads. With ZoneThreads on, each zone is its own server thread, so the load lands on every zone host, not just the starting one.
  • Zones not connected by ground to the home zone are left out automatically: the instanced dungeons (the_sunken_crypt, the_warrens) live on their own far-away tiles and cannot be walked into.
  • Homes are checked against the collision files: there is ground underneath, no water, no steep slope, room for the character, and at least 16 m inside the zone border.
  • "ZoneWeighting": "even" puts the same number of bots in every zone. "area" sends more bots to bigger zones.
  • Account N always gets the same zone and the same home, on every machine and every run.
  • Players per zone everywhere. The console line, zones.csv, report.html, the fleet report and the ladder report count how many bots stood in each zone. Each zone also gets its own hold RTT, movement gap and correction.
  • Server tick time per zone host. With ZoneThreads, each host logs its own [zone] [TickHealth] line. The report now keeps them apart, so you can see which zone thread gets expensive first.
  • Navmesh routes. Bots walking somewhere far (their home, a long wander) follow a route on the World server's own navmesh (Data/navmesh/default), so they go around the village instead of pressing into the first wall.
  • If something blocks a route corner for 4 s, the bot skips that corner. This happens when the navmesh is older than the collision.
  • A bot trapped on a ledge hops down (up to 6 m), and one stuck in a lake swims out. A bot stuck on a step jumps.
  • Settle (settle / fleet-settle). Bots walk to their homes and log out there. The server saves where they stopped, so the next run logs everyone in already spread out. This is what makes 1k–10k numbers accurate: a real server at 5,000 players does not have 5,000 people standing on one spawn point.
  • Ladder ("Ladder": [1000, 2000, 3000, 4000, 5000, 10000]). Results go to ladder-report.txt, with one row per size and the highest size that passed.
  • TotalConnectionsPerSecond: the whole fleet's login rate, shared out over the generators. A 10,000-bot step then logs in no faster than a 1,000-bot one.
  • Cheaper per-second checks. The neighbour count and the visibility probe use a 75 m grid instead of comparing every pair of bots.
  • The console menu runs fleet files (Plan / Run / Settle), and has a Zones settings group plus Z (show zones) and S (settle) for single presets.

Before the first big run#

  1. Use bypass auth on your test server. In the World server's appsettings.Local.json, set "World": { "AllowLoadTestBypass": true }. The presets use "AuthMode": "bypass" with "CreateCharacters": true, so there is nothing to register: 10,000 accounts at 2 registrations a second would take 83 minutes. Never turn this on for a public server.
  2. Point the logs at the server. Settings.ServerLogPath must be the World server's logs folder. The presets use ../../../Servers/Axiom.Server.World/bin/Debug/net10.0/logs. fleet-plan warns if that folder is missing.
  3. Keep the data current. The presets read collision, zones and navmesh straight from Servers/Axiom.Server.World/Data, the same files the server loads. * If the run says the navmesh was baked from an older collision export, rebake the navmesh. NPCs walk into the same new walls. * Older presets use the copy in Axiom.LoadTest/Data/world_collision. If the run warns that it is not the server's export, bots will be refused; point them at the server's folder.

Run it#

cd src/Tools/Axiom.LoadTest
dotnet run -c Release -- zones presets/20-zones-500-one-process.json        # which zones, how many bots each (no connections)
dotnet run -c Release -- fleet-plan presets/13-ladder-1k-to-10k-zones.json  # sizes, generators, warnings (no connections)
dotnet run -c Release -- fleet-settle presets/13-ladder-1k-to-10k-zones.json  # once: walk all 10,000 accounts home, 2,000 at a time
dotnet run -c Release -- fleet presets/13-ladder-1k-to-10k-zones.json       # the ladder

Or just dotnet run -c Release and pick a preset: fleet files open the Plan / Run / Settle menu.

Single sizes: 14-fleet-1000-zones.json, 15-fleet-2000-zones.json, 16-fleet-3000-zones.json, 17-fleet-4000-zones.json, 18-fleet-5000-zones.json, 19-fleet-10000-zones.json. One process, 500 bots: 20-zones-500-one-process.json.

  • A settle run stops when 95% of the bots are home (SettleFraction), or after 15 minutes (SettleTimeoutSeconds). Run it again and the stragglers carry on from where they stopped.
  • Run settle again after you change Seed, Zones, ExcludeZones, ZoneWeighting or repaint the zones, since homes depend on them.
  • Without settling, bots walk from the spawn point. The 240 s warmup covers the 600 m walk to the far side of Axiom Wilds, but the first minutes then measure a crowd at spawn.

Reading the result#

  • ladder-report.txt has one row per size: ready fraction, the worst generator's loop p99, RTT p95, movement gap p99, correction p95, and the server's work p99. Under that come players per zone and server work per zone host for each size.
  • Highest size that passed every check is your number for this world, this workload and this machine.
  • GENERATOR LIMITED means the test machine ran out of CPU, not the server. That step says nothing about the server. Lower BotsPerGenerator or add a machine.
  • A zone that held fewer bots than were sent (in the report's problems) means bots could not reach it: look at stuck bots in that step's report.html map.

How many machines#

  • Each generator needs about a core at 250 bots, so 10,000 bots is roughly 35–40 cores of bot work.
  • The World server needs its own cores too: one per zone host, plus networking.
  • On one 16-core PC, the ladder will likely stop being meaningful around 3,000–4,000. The report will say GENERATOR LIMITED.
  • Windows also gives out about 16,000 UDP ports.

For bigger sizes, use several machines. A ladder runs from one machine, so run each size as its own fleet file instead:

  • Use the same file on every machine, each with a different OnlyGenerators (for example [0,...,19] on one and [20,...,39] on the other).
  • Set the same Settings.StartAtUtc (a time a few minutes ahead) on every machine.
  • Only generator 0 follows the server log.
  • Afterwards, aggregate the summary.json files from every machine.

What 10,000 means in this world#

Your world has two walkable zones (zone_test1 and axiom_wilds, one 512 m tile each). At 10,000 bots that is 5,000 players on each tile, which is far denser than a real server. Every bot can see hundreds of others, so snapshot traffic grows with the square of the count. Treat the 5k and 10k steps as worst-case stress. As you paint more zones, zone spread uses them automatically and the numbers get closer to a real launch.

Limits#

These are headless protocol bots:

  • They walk, follow routes, jump, swim, talk to NPCs and reconnect.
  • They do not fight unless AttackTemplateId is set, and they do not craft, trade or render.
  • Density counts cover each generator's own bots; the fleet report adds them up.
  • Percentiles are never averaged across generators; the report shows the worst one.

A pass is evidence about this workload, not a capacity certificate.
