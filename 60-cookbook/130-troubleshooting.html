Troubleshooting#

First move, always: read the first screen of the World server log after starting it, and the Unity console. Most problems announce themselves there. Older notes: Handbook troubleshooting (archive).

Servers won't start#

Symptom Cause → fix
"…replace_this_with_a_real_secret…" / refuses to start no appsettings.Local.json with InternalSecret (or env var). Same value in all four services (Configuration).
World crashes at start-up with an HTTP error to /connect Persistence isn't running yet, or World:PersistenceBaseUrl / secret wrong. Start Persistence first.
Persistence: pending migrations Only with AutoMigrate: false: dotnet ef database update in Axiom.Server.Persistence (MySQL).
Persistence: "A table this migration creates already exists" A SQL/*.sql script made it, so EF's history doesn't know. Record the migration in __EFMigrationsHistory, or set AutoMigrate: false (MySQL).
[Patcher] Failed applying NNN_… — rolled back a SQL patch has an error. Fix the file (it was never recorded) and restart. Never edit a patch that already ran elsewhere; add a new one.
[Content] … KeyHex is missing set World:ClientContent:KeyHex (64 hex chars) in appsettings.Local.json.
No instance registered for X a handler/manager asks for a type not registered in WorldServer.RegisterServices - add services.Register(...).
Address already in use another copy is running (check Server Control, task manager), or a port clash in Kestrel/Network:Port.

Login and connection#

Symptom Cause → fix
Server list empty / world "offline" the World's directory heartbeat isn't reaching Auth: WorldDirectory:Enabled, Id matching Auth's WorldDirectory:Worlds, PublicHost not 0.0.0.0, same InternalSecret. Stale after 25 s.
"Protocol mismatch" / version message on connect client Axiom.Network.dll older/newer than the server. Rebuild the DLL, copy to Assets/AxiomMMOKit/Plugins, Validate Netcode Build.
Token rejected launch tokens are one-use, 120 s. Get a fresh one. In the editor, turn on ClientNetwork ▸ Editor Login ▸ Log in when I press Play so every Play gets one; its message under the button says why a login failed. Each ParrelSync clone logs in with its own account.
Disconnected right after the loading screen ("Client and server world collision versions differ. Please update your client."; the client logs [Movement] Client/server collision data mismatch) C2WMovementReady.CollisionHash ≠ server's collision hash → re-export Movement Collision so client StreamingAssets and server Data/world_collision match, and restart World (it loads collision at start-up).
Stuck on the loading screen world entry gate waiting: collision for that area not loaded (missing export), tile scene missing from Build Settings, or catalogues never arrived (server exception - check the World log).
Kicked for flooding a client sends faster than PacketRateLimiter allows; raise that opcode's rule if it's legitimate.

Packets that do nothing#

Symptom Cause → fix
Server sends, client shows nothing, no error handler not registered in ClientNetwork.RegisterHandlers (the dispatcher's "Unhandled packet" goes to Console.WriteLine, which Unity doesn't show).
Client sends, server does nothing no [PacketOpcode] handler; or dropped by the rate limiter; or the handler returns early (not in world: NetworkId == null). Add a log line.
"Could not read X packet (Axiom.Network.dll out of date?)" DLL mismatch between client and server.
Works only before entering the world, or not during character select the client filters opcodes while in character selection (ClientNetwork.OnNetworkReceive); add yours to the allowed list if it must arrive there.
A world object handler crashes when entering it touched main_world objects before the scene loaded: use WorldLoader.RunWhenReady.

Movement#

Symptom Cause → fix
Constant rubber-banding client and server collision differ (stale export), or a client-side collider the server doesn't know (an unexported prop). Re-export; check the collision hash line.
Character jumps once and hangs in the air a collider parented under the player prefab; the ground probe hits it. Remove it or put it on a non-collision layer.
Falling through terrain at spawn tile scene missing from Build Settings, or the ground gate disabled because tile size differs (rebuild Axiom.Movement.dll).
Remote players jitter or lag normal interpolation delay is ~200 ms; a jumpy one means WorldSettings.TickRate wrong or a huge snapshot gap (server overloaded - check tick health).
Things drift after travelling far a component caching a world Vector3 without subscribing to WorldOrigin.Shifted.

NPCs#

Symptom Cause → fix
NPC never spawns spawner TemplateId missing (Dev Tools ▸ Validate), Count 0, Dormant, time window (ActiveFromHour), or a DungeonId set by mistake. NPCs activate only when a player is near.
NPC under the ground / floating no terrain heightmap (or movement collision) exported for that tile, so ground snapping has nothing to snap to; or the spawner's Y is far from the ground - place spawners with the World Map tab, which uses the scene's real height.
NPC walks through walls / stands still when chasing no navmesh for that area ([NavMesh] No navmesh), or it's stale after a collision change - rebake. Unreachable targets make NPCs evade home after 6 s.
NPC has no body / players walk through it model key has no NPC collision shape: export NPC Collision. BlocksPlayers is in NpcTemplates.
Shows as a coloured box its ModelType key isn't in WorldObjectPrefabs (Asset Audit lists these).

Content doesn't show up#

Symptom Cause → fix
Changed data, nothing changed in game the World server reads content at start-up - restart it. If it was running when you saved, the tool wrote a patch only; check it applied (schema_versions).
New item shows as #90123 client gamedata.bin is old: World re-exports at boot to OutputPaths; restart the client so it downloads from Auth.
[…] row X invalid … skipped warnings the catalogue rejected your row (missing item/phase/template, bad numbers). Content Studio F5 shows the same rules.
Quest giver has no quest button the NPC talks by default; add an InteractableActions row with ActionType 7 (Quests) for a button. Check MinLevel, RequiredQuestId.
Icon missing PNG not at Resources/Icons/<IconName> (case matters in builds); IconAliases.json typo.
Gear invisible on a character no GearVisuals row (or not exported to gamedata.bin), prefab key wrong, or skinned gear on a different rig (Wardrobe shows it).

Builds and releases#

Symptom Cause → fix
Build fails: "Axiom.Network.dll … is protocol X, but …ProtocolVersion.cs says Y" the DLL in Assets/AxiomMMOKit/Plugins is older or newer than the server source. Rebuild Axiom.Network and Axiom.Movement and copy both DLLs in. The check finds the source through the server folder in Axiom Setup; if it can't, it warns and builds anyway.
UI checks fail only when run together with a build (window geometry, auction filter, housing Save; RenderTreeManager NullReferenceException) the checks ran while the player build was going, when Unity can't draw editor windows. Press Run all checks, wait for the report, then build.
"EndLayoutGroup: BeginLayoutGroup must be called first" after a build an older Build and Release that built inside its own OnGUI; update AxiomBuildRelease.cs. Harmless.
Launcher install/update problems see Client publish ▸ Troubleshooting.

Client logs and crashes#

A built client writes Unity's log to %USERPROFILE%\AppData\LocalLow\<Company Name>\<Product Name>\Player.log (names from Project Settings ▸ Player). Starting the game again moves the last run to Player-prev.log, so after a crash ask testers for Player-prev.log if they've already restarted. A hard crash also leaves crash.dmp, error.log and a copy of the log in %TEMP%\<Company Name>\<Product Name>\Crashes\. The launcher shows the game's exit code when it closes unexpectedly.

Harmless lines you'll see in every client log: MoonSharp's Error initializing UnityScriptLoader (it can't find a default script folder and carries on; the Lua UI loads right after) and "The tree TestTree must use the Nature/Soft Occlusion shader".

Editor tools#

Symptom Cause → fix
"Database is locked" / tools write patches only the World server is running and holds worldserver.db. Expected - restart the server to apply, or stop it to write directly.
Tools point at the wrong database Tools ▸ Axiom ▸ Settings… paths (ProjectSettings/AxiomDevTools.asset).
Content Studio lost my edits? pending edits live in Library/Axiom/ContentStudio.pending; deleting Library deletes them. Commit before cleaning the project.
Movement collision export "NOT copied to the server" set the server Data folder (Dev Tools ▸ NavMesh), or copy StreamingAssets/World/MovementCollision to Data/world_collision yourself.
Model keys list empty in Content Studio open main_world (the registry lives there).

Lua#

Symptom Cause → fix
Script not running not in Lua/Server next to the built server, or a load error ([LuaEngine] line with file:line). Restart after edits.
Handler stopped firing it overran its 200 000-instruction budget 3 times and was switched off (logged).
attempt to index a nil value on player the player left; check player:IsOnline() in timers.
Event name typo Server:On("OnKil", …) is ignored - use the Events table or the annotations for autocompletion.

Still stuck?#

  • Turn a logger up to Debug in nlog.config (minlevel).
  • Reproduce with one client and a fresh database (delete worldserver.db; it rebuilds from migrations + patches).
  • The load tester's selftest-network exercises login, select and movement against a local server with bypass auth - a quick way to tell client problems from server problems.
