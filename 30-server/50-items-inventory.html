Items, Inventory & Equipment#

Piece File Job
ItemManager Core/Items/ItemManager.cs Every item definition in memory: exists?, stack size, binding, gear info, grades, gems, upgrade materials, uses, vendor price.
ItemInstance Axiom.Network/Shared/Items/ItemInstance.cs What makes one copy different: grade, wear, gems, uid. Travels with the item everywhere.
InventoryComponent, BagMath Core/Players/Components, Core/Inventory The bag and the one set of placement rules every writer uses.
PlayerManager item API Core/Players/PlayerManager.cs TryAddItem, TryRemoveItem, TryMoveItem, TryDropItem, TryUseItem... (Players)
EquipmentManager Core/Items/EquipmentManager.cs Equip/unequip, binding on equip, stat recalculation.
ItemUpgradeService Core/Items/ItemUpgradeService.cs Regrade, socket, unsocket, repair.
ItemUids Core/Items/ItemUids.cs Snowflake ids for gear copies.
WarehouseService Core/Warehouse The personal warehouse (bank).
StorageService Core/Housing/StorageService.cs Coffers: storage inside a doodad.
InventoryExpansion Core/Inventory Bag expansion scrolls.

Templates vs copies#

An item template is a row of Items (+ ItemStats for gear, ItemUses for usables, ItemGems, ItemUpgradeMaterials, GearVisuals...). Players never hold templates; they hold slots:

public struct InventorySlot
{
    public int ItemTemplateId;   // 0 = empty
    public int Quantity;
    public bool Bound;           // soulbound: can't trade, never stacks with unbound
    public ItemInstance Inst;    // grade, wear, gems, uid - default = plain
}

ItemInstance (protocol 28):

Field Meaning
Grade 0 = the item's BaseGrade; otherwise an ItemGrades.Id (1 Crude … 12 Mythic). Grade multiplies the gear's stats.
Wear durability used. At MaxDurability the item is broken: its stats stop counting until repaired.
Gem1..3 socketed gem item ids (up to the gear's SocketCount). Gem stats aren't scaled by grade.
Uid unique id of this copy of gear (ItemUids): 41 bits ms since 2026-01-01, 10 bits World:ItemUidNode, 12 bits sequence. Stackables never get one.

ItemManager.Normalize(itemId, inst) makes non-gear plain and clamps values, so a stack of 200 Iron Ore never carries an identity.

The bag#

  • Capacity starts at InventoryRules.DefaultSlots (50), grows by 10 per Inventory Expansion Scroll (item 90003), up to 500.
  • Stacking (BagMath): two stacks merge only if item, binding and instance are identical and the item stacks at all. A stack never exceeds ItemManager.MaxStack(item): Items.max_stack, or 1 for gear, or CombatRules.ItemDefaultMaxStack (1000).
  • Placement is all-or-nothing: TryAddItem plans on a copy of the bag; if the whole quantity doesn't fit, nothing changes.
  • The client never changes its own bag. It sends requests (C2WMoveItem, C2WUseItem, C2WDropItem) and waits for W2CInventorySlotChanged from the server. Sort (slot -2) and expand (slot -1) are special requests.

Using an item#

C2WUseItem { Slot } → PlayerManager.TryUseItem:

  1. Gear (has an equip slot) → EquipmentManager.TryEquip.
  2. Otherwise the item's ItemUses row: cooldown (CooldownMs, shared by everything in the same CooldownGroup), optional CastTimeMs (a cast bar like a skill), LaborCost.
  3. Its effects: Effects rows with OwnerType = 1 and OwnerId = item_id, through EffectApplier (Combat). A potion is a Heal effect, a mount whistle a Mount effect, a seed bag a Place Doodad effect, a scroll a Grant Patron effect.
  4. ConsumeOnUse removes one.
  5. W2CItemCooldown { ItemIds[], DurationMs } greys out every item in the group, and Lua OnItemUse fires.

Equipment#

EquipSlot: 1 Head, 2 Chest, 3 Legs, 4 Hands, 5 Feet, 6 MainHand, 7 OffHand, 8 Neck, 9 Ring, 10 Trinket, 11 Backpack (a carried trade pack, not gear).

Equipping checks class (AllowedClasses, CharacterClassRules.CanWear), level (required_level), two-handed rules (needs a free bag slot for the off-hand), binds bind-on-equip items, marks bag and equipment dirty, recalculates stats (W2CStats) and sends the bag slot and the whole set (W2CEquipment). Others see the change through W2CPlayerAppearance (visible gear). C2WUnequip { Slot } takes one off.

What gear looks like on a body is client data: GearVisuals exported into gamedata.bin (Characters).

Grades, gems, repair#

C2WItemUpgrade → ItemUpgradeService → W2CItemUpgradeResult:

Command Needs Result
Regrade a regrade scroll (ItemUpgradeMaterials.Kind 1, valid for the current grade), optional charm (Kind 2: bonus chance, protection), gold up a grade, stay, down a grade or destroyed, by the target grade's odds in ItemGrades
Socket a gem item (ItemGems) in your bag, an empty socket gem goes in
Unsocket optional gem extractor (Kind 3) gem back with an extractor, destroyed without
Repair gold at a merchant (RepairGoldPerPoint per point of wear), or field repair from the bag (out of combat, at FieldRepairCostPct) wear reset

Grades, gems, upgrade materials and stack limits reach the client in W2CItemGearCatalog. See Items and grades (note).

Warehouse and coffers#

  • Warehouse: a personal bank per character (character_warehouse_items, warehouse_gold, warehouse_capacity), opened at a warehouse NPC (InteractionActionType.Warehouse, 22). It uses a compact custom protocol (WarehouseProtocol.Request/Frame, feature opcodes 210/211) with server-owned revisions; every move is planned on copies first (WarehousePlan) so a failure never changes either side. Saved in the character snapshot.
  • Coffers: storage inside a placed doodad (a chest in your house). Contents live in Persistence doodad_storage; a bag↔coffer move is one transaction (the character's full save carries the coffer's new contents, guarded by storage_seq). C2WStorageMove / W2CStorage.

Recipes#

A health potion#

-- SQL/patches/122_greater_healing_potion.sql
INSERT OR REPLACE INTO Items (item_id, name, description, icon_name, category_id, rarity_id, required_level, bind_type, no_trade, max_stack, vendor_price)
VALUES (6100, 'Greater Healing Potion', 'Restores 400 health.', 'Items/potion_red_large', 3, 2, 10, 0, 0, 50, 250);

-- right-click: 30 s cooldown shared with every potion in group 1, consumed
INSERT OR REPLACE INTO ItemUses (Id, ItemId, ConsumeOnUse, EffectType, EffectValue, CooldownMs, CooldownGroup, CastTimeMs, LaborCost)
VALUES (6100, 6100, 1, 0, 0, 30000, 1, 0, 0);

-- what it does: heal self 380-420 (OwnerType 1 = item, Target 0 = self)
INSERT OR REPLACE INTO Effects (Id, OwnerType, OwnerId, Sort, Kind, Target, Min, Max, RefId, DurationMs, School, Coefficient)
VALUES (9200, 1, 6100, 0, 1, 0, 380, 420, 0, 0, 0, 0);

-- sell it at a vendor (shop 1) for 1 gold
INSERT OR REPLACE INTO ShopItems (Id, ShopId, ItemId, BuyPrice, SellPrice, SortOrder) VALUES (300, 1, 6100, 10000, 0, 50);

Restart the World server (it rebuilds gamedata.bin so the client knows the name and icon), restart the client. The Tools ▸ Axiom ▸ Create ▸ Item… wizard does this with validation.

A new kind of item behaviour#

Most item behaviours are an existing effect kind on an ItemUses item. For something new (say, "teleport to your house"), add an effect kind (recipe) and give the item an Effects row with it. For script-only behaviour, use Kind 0 (Script) and handle Lua OnItemUse:

-- Lua/Server/hearthstone.lua
Server:On("OnItemUse", function(player, itemId, slot)
    if itemId == 6200 then
        player:Teleport(1024, 0, 980)        -- y = 0: ground height
        player:SendMessage("<color=#e2b45c>You return home.</color>")
    end
end)

Check the Lua API for event names and arguments.
