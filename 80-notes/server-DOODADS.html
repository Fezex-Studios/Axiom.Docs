Server Notes
Feature note, kept next to the code it describes. Source: docs/notes/server/DOODADS.md

Doodads - interactive world objects#

A doodad is anything in the world you can interact with that isn't a character. Today that means harvest nodes, the Supply Crate, planted wheat and a placeable crate. Later it will cover crafting stations, doors and levers, housing furniture and fixtures, storage chests, placed trade packs, fishing spots, and siege structures.

It is one foundation system, built before the phases that need it. Phases 7-10 each add a kind of doodad (rows), not a new object system (code). The model, in short:

Concept Axiom
Doodad : BaseUnit (in the world grid, not a living unit) DoodadEntity (interest grid, NPC id range)
FuncGroupId (the current phase) DoodadEntity.PhaseId (DoodadPhases)
DoodadFunc (what using it does) DoodadFuncs rows; the outcome is Effects rows
DoodadPhaseFunc (timers, growth, final) DoodadPhaseFuncs rows (Timer today)
doodad_almighties / doodad_groups DoodadTemplates
IsPersistent + MySQL doodads + SpawnPersistentDoodads IsPersistent + persistence doodads table + DoodadManager.Restore
DoodadSpawner (JSON) DoodadSpawns rows
OwnerId, ParentObjId/AttachPoint, ItemId OwnerCharacterId, ParentDoodadId/AttachPoint (reserved), HeldItemId

The state machine#

      ┌───── F/G action (DoodadFuncs) ─────▶ NextPhaseId (0 = stay, -1 = removed)
phase ┤
      └───── timer (DoodadPhaseFuncs) ─────▶ NextPhaseId (-1 = removed)

For example, the Iron Vein:

Full ── Mine (3s): +1-3 Iron Ore ──▶ Depleted ── 30s ──▶ Full

And the Wheat Crop, planted from Wheat Seeds:

Sprout ─2m─▶ Growing ─3m─▶ Ripe ─30m─▶ Withered ─30m─▶ (gone)
                            │              │
                            │ Harvest (owner, 2s): +2-4 Wheat, +1 Seeds ──▶ (gone)
                            │              │
                                           Clear (owner) ──▶ (gone)

An action, step by step (DoodadManager.TryUse)#

  1. It's offered. The current phase must offer the action (the same list the client drew its F/G prompts from), and it must be enabled.
  2. Checks, before anything is claimed or spent: - the doodad isn't busy, and no one else is using it; - OwnerOnly (only the placer); - RequiredItemId x RequiredItemCount is in the bag; - its Effects can land (EffectApplier.Check), e.g. a bag too full for the harvest is refused now.
  3. Instant, or timed. An action with UseTimeMs claims the doodad and shows a bar ("Mine: Iron Vein"). Walking away or disconnecting cancels it; you dismount first. An action without one happens at once.
  4. When the time is up: - every check again; - the Effects run (GiveItem, a heal, a buff: the one EffectApplier); - the required item is used up if ConsumeRequiredItem; - the doodad moves to NextPhaseId; - Lua OnHarvest fires for each item given, then OnDoodadUse.

Timers#

  • Wall-clock. Timers are stored as Unix ms, so they survive a restart.
  • Random delay. DelayMaxMs gives a random delay between DelayMs and DelayMaxMs.
  • Catch-up. If a timer should have fired while the server was down, the doodad catches up through as many phases as the elapsed time covers. A crop planted before a 6-minute outage comes back Ripe. A crop left for an hour comes back gone, and its row is deleted.

Data#

Table Columns that matter
DoodadTemplates Name, Description, ModelType (the client prefab key), InteractRange, StartPhaseId, IsPersistent, PlaceRadius (spacing when placed), Scale
DoodadPhases TemplateId, Name, Visual (the client look key)
DoodadFuncs PhaseId, Slot (0 = F, 1 = G), ActionType, Label, IconName, CursorName, IsEnabled, UseTimeMs, OwnerOnly, RequiredItemId/RequiredItemCount/ConsumeRequiredItem, NextPhaseId
DoodadPhaseFuncs PhaseId, Kind (1 = Timer), DelayMs, DelayMaxMs, NextPhaseId
DoodadSpawns TemplateId, X/Y/Z, Yaw, Scale (0 = the template's), RespawnSeconds (if a func or timer removes it)
Effects with OwnerType 4 What a func does. OwnerId = DoodadFuncs.Id.

ActionType (InteractionActionType) sets the client's icon and cursor meaning:

  • 3 Harvest
  • 11 Use (open, pull, drink)
  • 12 PickUp
  • 6 Climb (shown greyed out)

New effect kinds:

  • GiveItem (11): RefId item, Min..Max. RefId 0 means the item the doodad holds, which is how picking up a crate gives back that crate.
  • PlaceDoodad (12): on an item; RefId = doodad template. It places one in front of you, owned by you. It's refused up front if the spot is closer than PlaceRadius to another doodad, or you already have CombatRules MaxPlacedDoodads (20) placed.

Bad rows are skipped at boot, with a warning naming them:

  • a start phase that doesn't exist or belongs to another template;
  • an action on a key that's already taken, or leading into another template's phase;
  • a missing required item;
  • a second timer on the same phase;
  • a world spawn of a persistent template.

Saving (persistent doodads)#

A template with IsPersistent = 1 and placed by a player is saved in the persistence server's doodads table and restored when the world server starts (/doodads/list). If persistence isn't up yet, the world server retries every 10s. World spawns are never saved: a restart brings every node back fresh, as harvest nodes always did.

Two rules keep saved doodads from duplicating anything:

  • Placing. The placer's save (the seed gone from the bag) is written first, then the doodad's row. The doodad is visible straight away but can't be used until its row exists. A crash in between loses the seed; it can never leave both.
  • Rewards. An action that changes or removes a saved doodad writes the doodad's new state (or deletes the row) first, and only then gives the reward. A lost answer loses the reward; the reward can't be taken twice. /doodads/delete says whether it really deleted anything, so a crate can't be picked up twice.

The endpoints are safe to repeat and to arrive out of order:

  • Create is keyed by a PlacementKey: a retry after a lost answer gets the same row back.
  • Update only lands with a higher Version.
  • Timer changes are saved in the background: one write in flight per doodad, and the newest version wins.

Client#

  • Handlers. W2CSpawnDoodad, W2CDoodadState, W2CDoodadUseStarted and W2CDoodadUseEnded replace the five harvest-node packets. DoodadRegistry replaces HarvestNodeRegistry, and W2CNpcDespawn removes doodads too.
  • How a phase looks. DoodadIdentity.Apply picks the first of these that applies: 1. A DoodadVisuals component on the prefab: each phase Visual key maps to a child object. 2. An old HarvestNodeIdentity on the prefab: its available and depleted visuals, so existing node prefabs keep working. 3. The hidden or depleted key: renderers and colliders are turned off. 4. No prefab yet: a placeholder cube, coloured and sized by the phase, so new doodads are usable before they have art.
  • Tooltip. It shows the owner, the phase, and a live "Changes in 2m 14s".
  • Progress bar. The bar is the existing HarvestProgressUI, labelled "Mine: Iron Vein", "Open: Supply Crate" and so on.

Adding content#

A harvestable (what patch 040 did for the four nodes):

  1. A template.
  2. Phases Full/Depleted.
  3. A Harvest func with UseTimeMs, going to Depleted, plus a GiveItem effect.
  4. A Depleted timer back to Full.
  5. Spawns.

A crafting station (Phase 7, built - see PHASE7.md):

  1. A template with one phase.
  2. A Craft func (ActionType 13) whose effect is OpenCrafting (kind 13).
  3. Recipes name the station's template; crafting checks you're within its interact range.

Gathering that costs labor (Phase 7): set LaborCost, ProfessionId (and optionally RequiredRank) on the func. The labor is checked up front and spent on success, the profession gains that much proficiency, and a higher rank sometimes yields one extra.

A door or lever: Closed ⇄ Open, with a Use func each way and a Timer on Open back to Closed. The client prefab shows Closed/Open children through DoodadVisuals.

Furniture or a storage chest (Phase 8):

  • The template is persistent with a PlaceRadius, placed from an item (PlaceDoodad).
  • PickUp gives it back (GiveItem RefId 0).
  • For storage, it would get an inventory the way a storage coffer does: a table keyed by doodad_id.

A crop (Phase 8): exactly the Wheat Crop. Theft, meaning a non-owner able to harvest after N minutes, would be a second func with OwnerOnly = 0 and a time condition.

A trade pack (Phase 9):

  • The pack item places a persistent doodad that holds the pack (HeldItemId).
  • PickUp gives that exact pack back.
  • A delivery NPC checks what's held.

A siege structure (Phase 10): a persistent doodad with health would extend DoodadEntity with health and let Damage effects land on it. It's a sizeable change, flagged for that phase.

Deploying#

  1. World: the Doodads migration runs on start, then patch 040 converts harvest nodes and adds the new content. HarvestNodeTemplates/HarvestNodeSpawns stay in the file, unused.
  2. Persistence: add the doodads table with dotnet ef database update (migration WorldDoodads), or run SQL/doodads.sql.
  3. Protocol 6: rebuild Axiom.Network.dll and copy it into Unity. Delete the old harvest code from the server first (copying new files over it doesn't remove it, and it won't build): - Axiom.Network/Shared/Packets/W2C/: W2CHarvestCancelledPacket.cs, W2CHarvestCompletedPacket.cs, W2CHarvestNodeStatePacket.cs, W2CHarvestStartedPacket.cs, W2CSpawnHarvestNodePacket.cs - Axiom.Server.World/Core/Entities/HarvestNodeEntity.cs - Axiom.Server.World/Core/Managers/HarvestManager.cs - Axiom.Server.World/Core/Packets/W2CSenders/W2CHarvestPacketSenders.cs - Axiom.Server.World/GameData/Harvest/HarvestNodeSpawn.cs and HarvestNodeTemplate.cs
  4. Client: - Copy the scripts in. - Delete Networking/W2CHandlers/W2CHarvestHandlers.cs and Scripts/Gameplay/HarvestNodeRegistry.cs, with their .meta files. - Existing node prefabs keep working. - Add prefabs for SupplyCrate, WheatCrop and WoodenCrate to WorldObjectPrefabRegistry when you have art. Until then they're placeholder cubes.
  5. Dev tool: C2WDebugDoodadAdvance (opcode 104, AllowDebugCommands only) runs a doodad's pending timer now.

Testing#

  • Axiom.LoadTest:
  • D.1: data checks.
  • D.2: phases, timers, restart catch-up (still growing, ripened while down, withered away while down), background saves and version ordering.
  • D.3: the real persistence endpoints (create is idempotent, versioned update, delete reports once).
  • D.x: patch 040 on the real worldserver.db (Iron Vein unchanged in behaviour).
  • Axiom.LoadTest:
  • Mine a vein (bar, ore, Depleted for everyone).
  • A depleted node refuses.
  • Walking away interrupts opening the crate; standing still opens it.
  • Plant wheat (owned; too close refused), grow it, a stranger can't harvest, the planter can, and it's gone.
  • persist-place / persist-check around a world-server restart: the crate and the growing crop come back with their timer carried on; the crate is picked up once, not twice.

Not built yet (reserved)#

  • Phase funcs other than Timer: time of day (needs a world clock), and pulses (an area effect every N seconds).
  • Parent/attach points (houses, vehicles): the columns exist, nothing uses them.
  • Doodad storage (coffers), theft, doodads with health (siege).
  • Placement preview on the client: placing drops it 1.5m in front of you.
