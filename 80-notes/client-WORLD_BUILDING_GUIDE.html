World building guide#

This guide takes you from an empty flat map to a zone you can walk around: terrain, textures, trees, props, sky and light, then NPCs, spawn points, gatherables and the map, all wired into the server. It's for Unity 6.3 with HDRP, and assumes you're new to Unity.

Do Part 1 once. After that, Part 2 is the loop you'll repeat for every new area.

Part What
0 Unity basics you'll use constantly
1 One-time setup: sky, light, settings, packages
2 Build a zone, step by step
3 Props, buildings and art
4 Putting gameplay in the world (NPCs, spawns, gatherables, zones, map)
5 Dungeons
6 Performance
7 Checklist, troubleshooting, links

How Axiom's world is built (read once)#

  • One persistent scene, many tiles. Assets/AxiomMMOKit/Axiom.Client/World/main_world.unity is always loaded. It holds the camera, sun, sky, UI and the registries. The ground is split into tiles: 512 m × 512 m squares, each its own scene named tile_<x>_<z> (for example tile_-1_0).
  • Tile scenes live in Assets/AxiomMMOKit/Axiom.Client/World/Tiles/<zone>/.
  • Tile (0,0) covers world X 0-512 and Z 0-512. Tile (-1,0) covers X -512 to 0.
  • Streaming. In play, WorldStreamer loads the 3×3 block of tiles around you and unloads tiles further away. There are no loading screens: that's the seamless world. A tile scene that isn't in Build Settings is treated as empty, so new tiles must be added there (Part 2, step 9).
  • The server knows the ground from the collision export. The server has no Unity. It walks players and NPCs on the movement collision you export (terrain heightmaps plus static colliders, in Axiom.Server.World/Data/world_collision). Client and server must hold identical files.
  • Re-export after every sculpt or scenery move, or the server's ground and yours disagree and players rubber-band (or are refused with "collision data mismatch").
  • Gameplay things are data, not scene objects. NPCs, player spawn points, gatherable nodes and chests live in the world database. Dev Tools lets you place some of them in the Scene view and write them to the database (Part 4).
  • Floating origin. Far from (0,0) the world shifts under you to keep numbers precise. You don't need to do anything, but Static Batching must stay off (Part 1).

Part 0: Unity basics you'll use constantly#

Windows (all under the Window menu if one goes missing):

Window What it's for
Scene Where you build. Fly around and place things
Game What the player sees in Play mode
Hierarchy Every object in the open scenes, as a tree. Scenes appear as bold headers when several are open
Project Your files (Assets/...)
Inspector Settings of whatever is selected
Console Errors (red), warnings (yellow), logs

Moving around the Scene view: - Hold right mouse + WASD flies, like a game. Q/E go down/up. Scroll while flying changes speed. - F frames the selected object. Double-click an object in the Hierarchy does the same. - Alt + left drag orbits, middle drag pans, scroll zooms.

Tools (top-left of the Scene view, or the keys): - W move, E rotate, R scale. - Hold V while moving to snap a corner to another object's corner. - Ctrl + Shift + drag the move handle to drop the object onto the surface under the mouse. This is the fastest way to place props on terrain.

Prefabs: a saved, reusable object (a house, a tree). Drag one from Project into the Scene to place a copy. Double-click a prefab to edit the original; every copy updates.

Several scenes at once: drag a scene file from Project into the Hierarchy and it opens alongside the others (additively). That's how you edit tiles: main_world plus the tiles you're working on. Right-click a scene header in the Hierarchy for Save Scene and Unload Scene. Ctrl+S saves all open scenes.

Packages: Window > Package Manager (in Unity 6.3 it's under Window > Package Management). Install things from Unity Registry.

Part 1: One-time setup#

1.1 Turn off static batching#

Edit > Project Settings > Player > Other Settings. Untick Static Batching. Static batching bakes positions, which breaks when the floating origin moves the world.

1.2 Install Terrain Tools#

Package Manager > Unity Registry, search Terrain Tools, then Install. It adds better sculpting brushes (Smooth, Terrace, Erosion, Noise...) and the Terrain Toolbox.

Optional but very useful: the free Terrain Sample Asset Pack from the Asset Store. It has rock, grass, dirt and snow terrain layers and brushes, so your first terrain doesn't look like a grey blob.

1.3 Sky, fog and exposure in main_world#

main_world has a sun but no sky volume yet. HDRP needs one for sky, ambient light, fog and exposure.

  1. Open main_world.unity.
  2. GameObject > Volume > Sky and Fog Global Volume. This creates a Global Volume with a Visual Environment, a Physically Based Sky and Fog.
  3. Select it. In the Volume component, make sure Mode = Global and a Profile is assigned. Click New if the Profile is empty. Then check these overrides; click Add Override to add any that are missing:
Override Set
Visual Environment Sky Type: Physically Based Sky. Ambient Mode: Dynamic
Physically Based Sky The defaults are an Earth-like sky. Planet type Earth (Simple) is fine
Fog Enable on. Fog Attenuation Distance around 400-1000 m to start. Turn Volumetric Fog on for light shafts
Exposure Mode: Automatic Histogram (adapts like an eye). Limit Min/Max around 8 and 15
Volumetric Clouds (optional) Enable. Pick a preset like Sparse or Cloudy
  1. Select Directional Light (the sun): - Intensity about 100000 lux for midday (HDRP uses real-world light units). Lower is dawn or dusk. - Rotate it with E to move the sun. The sky follows it. - Shadows: on.

Keep this volume in main_world only, never in a tile scene, so the sky is the same everywhere. For a special area later (a gloomy swamp), add a Local Volume with a box collider in that tile, with stronger fog.

1.4 Check the tile tools#

Open Tools > Axiom > Dev Tools (Shift+Alt+D) and go to the World Tiles tab. Tile scene folder must read Assets/AxiomMMOKit/Axiom.Client/World/Tiles; set it if not. Turn on the Scene view grid there. You'll see:

  • bright blue: tiles that are open;
  • dim blue: tiles that exist but aren't open;
  • grey: no tile yet.

Part 2: Build a zone, step by step#

Example: a starting meadow east of town, tiles (0,0) and (1,0).

Step 1: Plan on paper#

Sketch the zone: where the town is, the roads, a river or lake, a forest, a mob camp, a rift spot. Note the world coordinates. Tiles are 512 m, so two tiles is a kilometre end to end. That's a lot of walking: real MMO zones put something interesting every 100-150 m.

Step 2: Create the tiles#

Dev Tools > World Tiles > Create tiles:

  1. Enter From (0, 0) To (1, 0), or select Tile under Scene camera.
  2. Tick Create terrain. - Heightmap resolution: 513 (1 m detail per sample). Use 1025 for a hero area with lots of detail. - Max height: 600 (the tallest peak possible, in metres).
  3. Click Create. Each tile gets its own scene and a 512 m terrain, and the terrains connect at the edges.

Existing tiles are skipped, so this is safe to repeat.

Step 3: Open the tiles to edit#

Open main_world, then drag the tile scenes from World/Tiles/... into the Hierarchy. Or, on the Zones tab, use Open tiles for a zone. Always keep main_world open as well, so you see the real sky and light.

Step 4: Sculpt#

Select a terrain. In the Inspector, the Terrain component has a toolbar. The brush icon is Paint Terrain. Its dropdown has the sculpt tools (with Terrain Tools installed you get many more):

Tool Use it for
Raise or Lower Terrain Hills (click). Hold Shift to lower: valleys, lake beds
Set Height Flat building plots and town squares. Shift-click samples a height
Smooth Height Softens everything. Use it a lot
Stamp Terrain Drops a mountain or crater shape from a brush texture
Erosion (Terrain Tools) Makes hills look weathered and real
Terrace Rice fields, cliffs

Tips: - Brush Size is in metres; Opacity is strength. Start big and soft for the overall shape, then go small for detail. - Keep slopes you want walkable under about 50°. The motor's slope limit is 50°; steeper is a wall. - Brushes work across tile edges when both tiles are open, so sculpt over seams freely. - Ground level is up to you. Leave room below if you'll want lakes and a coast later, for example a base ground height of 20-50 m.

Step 5: Paint ground textures (terrain layers)#

  1. Get textures: Poly Haven and ambientCG are free (CC0). Download the 2K "color/albedo", "normal" and optionally "AO/roughness" maps for grass, dirt, rock and path. Put them in Assets/AxiomMMOKit/Axiom.Client/Art/Terrain/<name>/.
  2. Create > Terrain Layer (in the Project window). Set Diffuse to the colour map and Normal Map to the normal map. If Unity asks, click Fix Now to mark it as a normal map. Set Tiling Size around 4-10 m.
  3. Select the terrain, choose Paint Terrain > Paint Texture, and Add Layer for each one. The first layer covers everything: make it grass.
  4. Paint dirt along paths, rock on steep slopes, and so on.
  5. The terrain's material must be HDRP's TerrainLit. New terrains get it automatically; if a terrain is pink, set its Material to HDRP/TerrainLit.

Step 6: Trees and grass#

Trees (Paint Trees tool): 1. Get tree prefabs (Quaternius "Stylized Nature" / "Ultimate Nature" packs, or the Terrain Sample Asset Pack). Import them into Assets/AxiomMMOKit/Axiom.Client/Art/Nature/ and convert their materials to HDRP (see CHARACTER_ANIMATION_README.md 3.2). 2. Edit Trees > Add Tree, then pick the prefab. A tree with a LODGroup performs much better. 3. Set Brush Size and Tree Density and paint. Shift erases.

Grass and small plants (Paint Details tool): - Use Add Detail Mesh with a grass mesh prefab and Render Mode Instanced Mesh, not grass-texture billboards, which HDRP doesn't draw well. - Keep Detail Distance (terrain Settings, the gear tab) around 80 m for performance.

Trees and grass are visuals only. The server doesn't know about them, so they don't block movement there.

Step 7: Water (later)#

Water and the ocean were taken out on purpose until the land exists. When you're ready, a lake is: a dip in the terrain, an HDRP Water Surface (GameObject > Water > Surface > Lake or Pool), and a flat collider on a water layer set as the LocalCharacterMotor's Water Mask. Ask for it when you get there; the server side needs a matching water table.

Step 8: Export the ground to the server#

Do this after every sculpt. It's the step everyone forgets.

  1. Save your open scenes.
  2. Dev Tools > World Tiles > Server collision > Export collision (changed scenes only). It bakes the tile scenes and prefabs that changed since last time into StreamingAssets/World/MovementCollision and copies the result to the server's Data/world_collision and every built copy under bin/ (where the server is is set once, in Dev Tools > Settings).
  3. The section shows whether the server's copy matches the client's. Restart the World server to load it.

The same export is on Tools > Axiom > Server Exports > Movement Collision. Use Full rebuild if an incremental export ever looks wrong.

The old Export All Terrain (.achtmap files into Data/terrain_data) and World > Terrain > Export Heightmap For Server are gone: the server never read that folder.

Step 9: Build Settings#

Dev Tools > World Tiles > Add all tile scenes to Build Settings. A tile that's missing from Build Settings is silently treated as empty land when you play.

Step 10: Validate and play#

  1. Dev Tools > World Tiles > Validate world partition: oversized terrains, objects outside their tile, missing scenes.
  2. Start the servers (Auth, Persistence, World), open server_select and press Play.
  3. Teleport or walk to your zone. Check that: - you walk on the ground, not floating or sunk; - you don't snap back on slopes; - tiles appear before you reach them.

Part 3: Props, buildings and art#

Where art goes#

The folder decides how a model imports (see ASSET_PIPELINE.md):

Folder For Import
Art/Props/, Art/Doodads/, Art/Nature/ Rocks, crates, fences, trees, nodes Static, no colliders
Art/Housing/ Houses, furniture Static, mesh colliders, lightmap UVs
Art/Dungeons/ Dungeon walls, floors, kit pieces Static, mesh colliders, lightmap UVs
Art/Vehicles/ Carts Static
Art/Creatures/ Monsters (Creatures/Humanoid/ for human NPCs) Rigged
Art/Characters/, Art/Animations/, Art/Gear/ See CHARACTER_ANIMATION_README.md

Rules for every model: 1 unit = 1 metre, pivot at the base, front faces +Z. LODs named Name_LOD0, Name_LOD1... get a LODGroup automatically.

Two kinds of props#

1. Scenery: just place it in the tile scene. Rocks, fences, ruins, houses in town you can't own, bridges, cliffs. They're visual and block movement on the client. 1. Make a prefab: select the model and run Tools > Axiom > Art & Assets > Make World Prefab From Selected Model. 2. Drag the prefab into the tile scene it stands in (check the Hierarchy: the object must sit under that tile's scene header, not main_world's). 3. Drop it on the ground with Ctrl+Shift+drag. 4. Tick Static (top-right of the Inspector), so it gets baked lighting and occlusion.

An object must belong to the tile it's in. If it straddles a border, put it in the tile that holds its centre. Validate world partition flags mistakes.

2. Gameplay objects: data, not scene. Anything the server must know about: ore veins, herb bushes, trees you can chop, chests, doors, crafting stations, dungeon portals. These are doodads (Part 4.3). Make the prefab the same way, but don't place it in a scene: the server spawns it.

Free art#

Site What Licence
Quaternius Nature, medieval village, dungeon, monster and weapon packs CC0
Kenney Stylised props and kits CC0
Poly Haven Photoreal textures, HDRIs, some models CC0
ambientCG Textures CC0
Unity Asset Store, free Lots; check each pack says HDRP or Built-in Asset Store licence

Mix styles carefully. Quaternius and Kenney are low-poly and colourful; Poly Haven is photoreal. Pick one look per zone.

Making it look good (fast wins)#

  • Big shapes first: hills, cliffs and forest masses. Details last.
  • Paths tell players where to go. A dirt path from town to the first quest area does more than any signpost.
  • Landmarks visible from far away (a tower, a giant tree) stop players getting lost.
  • Cluster props in groups of 3-7, mixed sizes, rotated randomly. Never in perfect rows, unless it's a fence.
  • Fog in the volume adds depth to everything; raise it a little.
  • Sun angle: a lower sun (morning or evening) gives longer shadows and looks better than noon.

Part 4: Putting gameplay in the world#

4.1 Zones (names, PvP rules, levels)#

Dev Tools > Zones: 1. Add zone: give it a Key (eastern_meadow), a Display name ("Eastern Meadow"), PvP mode (Safe / Peaceful / Contested / War) and a level range. 2. Paint it on the map (32 m cells; Ctrl+click fills a whole tile), or tick Paint in Scene view and paint straight onto the terrain. 3. Save (client + server). It writes the client's StreamingAssets/World/zones.aczmap and the server's Data/world/zones.aczmap. 4. Restart the World server. Entering the zone now shows its name, and Safe/Peaceful zones block PvP. 5. Optional: Organize tile scenes into zone folders tidies World/Tiles/<zone>/.

4.2 NPC spawners (mobs, vendors, quest givers)#

Dev Tools > World Map: 1. ⟳ Load reads the world database. 2. DB → Scene shows existing spawners as markers under ~WorldMap_NpcSpawners in main_world. 3. Fly to where you want mobs and click + Add at Camera. In the marker's Inspector, set: - TemplateId: the NPC, from Content Studio > NpcTemplates; - Count: how many; - Radius: how far they wander; - then click Snap to Ground. 4. Scene → DB writes everything in one go. Stop the World server first (it locks the database), or use Export Patch to write an .sql file instead. 5. Restart the World server.

Marker colours: grey = new, amber = edited, red = saved.

To make a new kind of NPC (a wolf, a guard), use Tools > Axiom > Create > NPC…: copy one that works, set its stats, model, loot and spawners, and press Create (EDITOR_SUITE.md, section 4). Content Studio > NpcTemplates is for editing ones that exist. Its model and animations are Part 7 of CHARACTER_ANIMATION_README.md.

4.3 Gatherables, chests, stations (doodads)#

  1. A new kind of object (skip if it exists): Tools > Axiom > Create > World Object…. Copy a working one (Iron Vein), rename it, drag its model in, change what its action gives and its timers, press Create. (EDITOR_SUITE.md section 4; DOODADS.md explains phases and actions.)
  2. Place them: Dev Tools > Doodads. - Load into scene shows the ones already saved nearby. - Pick the object in the list, Place in the Scene view, click the ground (Shift keeps the facing, Esc stops). - Move, rotate and delete markers like any object. - Save to database.
  3. Restart the World server.

4.4 Player spawn points (graveyards, starting area)#

Dev Tools > Spawn Points. It works the same way as 4.2: ⟳ Load from DB, DB → Scene, + Add at Camera, then Scene → DB.

4.5 The world map#

After building, bake the map so the M-key map shows your terrain: - Tools > Axiom > World > Maps > Bake Loaded Scene Map (open the tiles first) for a top-down picture. - Or Rebuild Terrain Atlas for a terrain-only version. - Export Scene Map Points turns MapPointAnchor components (towns, landmarks you add) into labelled map points. - Validate Atlas and Coordinates checks the result.

4.6 Housing plots#

  1. Content Studio > HousingAreas has a row per area.
  2. Draw its outline with Tools > Axiom > World > Housing > Create Zone Outline, in the tile.
  3. Write it to the server with Export loaded zone outlines. The outline's AreaId must match the row.

Part 5: Dungeons#

A dungeon is a set of tiles far away from the overworld, in its own spot on the grid (the existing ones are at tiles 32,32 and 33,32). Players are teleported there by a portal doodad.

  1. Create tiles at an unused far coordinate, next to the existing dungeons (the Dungeon wizard picks the next free one, e.g. 34,32).
  2. Build it from a dungeon kit in Art/Dungeons/ (mesh colliders on) on a flat terrain, or no terrain and a modelled floor. The server only knows terrain height, so a dungeon floor at a single height is simplest.
  3. Export the heightmap (Part 2, step 8).
  4. Tools > Axiom > Create > Dungeon… does the rest in one window: the Dungeons row (its region must cover your tiles), mobs and a boss, the entrance and exit portals, and the run rules (runs per day, a time limit).

The complete walkthrough is DUNGEONS.md (Hub > Guides > Dungeons).

Part 6: Performance (an MMO has many players on screen)#

Do Why
LODs on anything placed often (trees, rocks, houses) Far objects draw cheaply
Mark scenery Static Occlusion culling and baked light
Keep terrain Pixel Error at 5-8, and Detail Distance around 80 m Terrain is often the biggest cost
One material atlas per pack (Quaternius does this) Fewer draw calls
Turn on Window > Analysis > Rendering Debugger or the Stats button in the Game view Shows what's expensive
Profile with Window > Analysis > Profiler Finds the frame-time spikes
Keep Static Batching off The floating origin breaks it

Budget per tile, roughly: a few hundred unique props, trees as terrain trees, not separate objects.

Part 7: Checklist, troubleshooting and links#

New zone checklist#

  • [ ] Tiles created, sculpted, painted, trees and props placed.
  • [ ] Every prop sits under its own tile's scene header.
  • [ ] Heightmaps exported and the server restarted.
  • [ ] Tiles in Build Settings.
  • [ ] Zone painted and saved (client + server).
  • [ ] NPC spawners and a spawn point saved to the database.
  • [ ] Doodads placed (Dev Tools > Doodads) and saved.
  • [ ] Map baked.
  • [ ] Walked through it in Play: no floating, no rubber-banding, no pop-in next to you.

Troubleshooting#

Problem Cause
Rubber-band or snap back on hills The server's heightmap is old: export and restart (Part 2, step 8)
Falling through the ground at a tile That tile isn't in Build Settings, or the terrain wasn't saved in its scene
A whole tile is missing in play Not in Build Settings, or its name isn't tile_x_z
Pink terrain or props Not HDRP materials: TerrainLit for terrain, HDRP/Lit for props
Everything is too dark or blown out Exposure: use Automatic Histogram; the sun around 100000 lux
No sky (black or grey) No Global Volume in main_world, or Visual Environment's Sky Type isn't set (Part 1.3)
Objects jitter far from the start area Static Batching is on (Part 1.1)
A prop disappears when you walk away and back It's in main_world or the wrong tile: move it to the tile it stands in
New NPC spawner does nothing Not saved (Scene → DB), the server not restarted, or the TemplateId's ModelType has no prefab (Audit)
Can't save spawners: database locked Stop the World server, or use Export Patch
