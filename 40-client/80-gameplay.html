Unity Client

Client Gameplay Systems#

The rule for everything on this page: the client asks, the server decides, the client shows. Client checks (range, cooldown, "can I do that?") exist only to avoid sending requests the server would refuse and to give instant feedback; the server re-checks all of them.

Code: Assets/AxiomMMOKit/Axiom.Client/Scripts/Gameplay, the matching handlers in Networking/W2CHandlers and senders in Networking/C2WSenders.

Targeting#

Class
CombatClient Static: your current target, attack cooldown, incoming W2CCombatEvent → damage numbers, health on frames, animator triggers.
TabTargeting Tab next enemy (on screen first, nearest and most central), Shift+Tab previous; nothing on screen → the nearest enemy in range. "Enemy" = what nameplates colour red (FactionState.NpcRelation, hostile factions).
PlayerPicking Remote players have no collider (the interpolator owns their transform, crowd LOD may swap models), so the mouse ray is tested against a capsule per player, sized to their model and mount; terrain/walls/NPCs in between hide them.
F1 target self.

Target changes are sent as C2WFocusTarget (opcode 174). The server uses it to pin your target in your interest set (InterestManager.PinTarget) so it keeps being replicated to you under crowd limits; abilities carry their own target id.

Combat input and skills#

CombatController (creates itself; also creates the hotbar, cast bar, target frame and buff row):

  • Left-click an enemy: target it (the same click that interacts).
  • Hotbar 1-0: use the slot (ability or item). Hostile abilities go at the enemy under the cursor, else your target, and turn you toward it; friendly abilities go at your target if it's a player, else yourself; self/area abilities need no target.
  • Escape: cancel your cast.
  • Ignored while typing or before entering the world. Presses the server would refuse (cooldown, already casting) aren't sent; ones it would refuse with a reason show the reason locally.

SkillBook holds the skill catalogue (W2CSkillCatalog), your class, ranks, points and hotbar (W2CAbilities), and cooldowns (global cooldown from W2CCastStart.GcdMs, per-skill from W2CCastEnd.CooldownMs) so keys grey out exactly as long as the server would refuse them.

CastState tracks cast bars (yours and others') from W2CCastStart / W2CCastEnd. SkillStepPresenter plays multi-step skills (skill plots): the step's animation trigger, area VFX and cosmetic projectiles (projectile flights are budgeted; damage still comes only from combat events).

LocalCrowdControl reads your statuses (StatusState + catalogue crowd flags): stunned = no moving or turning, rooted = no moving. The server enforces the same and corrects you; this just stops the client trying.

DeathState: your death screen and respawn (C2WRespawn); CorpseRegistry: lootable corpses (W2CSpawnCorpse).

Interaction#

InteractionController (classic MMO-style proximity interaction) picks one target each frame:

  1. what you're hovering, if in range and it has actions; else
  2. the nearest in-range interactable with actions, preferring what the camera faces.

F = first action, G = second, right-click a hovered object = its first action (on a corpse: loot). Every action is a request (C2WInteractPacket, opcode 16) carrying the server's ActionType, SkillId and FunctionId exactly as the server sent them; the server re-checks range and that the object really offers it.

ActionPromptUI shows the prompts ("F Mine", "G Inspect"); CursorManager changes the cursor: enemy → attack, anything with actions → the primary action's CursorName from data (interact, loot, talk), from Resources/Cursors/<name>.png.

NPC dialogue, vendors, quest givers, bankers etc. are InteractableActions rows on the server (NPCs); NpcInteractionActions only presents them. InteractionSkillPresentation plays the animation for "interaction skills" (gathering, crafting at a station).

Doodads (world objects)#

W2CSpawnDoodad creates a DoodadIdentity with the template's model from WorldObjectPrefabs (ModelType), registered in DoodadRegistry. Its phase comes from the server (W2CDoodadState; W2CDoodadUseStarted/Ended for timed uses); Apply shows the phase's look and actions. How a phase looks, first match wins:

  1. a DoodadVisuals component on the prefab: the child listed under the phase's Visual key;
  2. a legacy HarvestNodeIdentity: its available/depleted objects;
  3. key hidden or depleted: renderers and colliders off;
  4. no prefab yet: a coloured placeholder sized by key, so content works before art exists.

Example - a wheat crop prefab: a soil mound (always visible) plus children Sprout, Growing, Ripe, Withered; add DoodadVisuals with entries sprout → Sprout, growing → Growing, ripe → Ripe, withered → Withered, matching the Visual column of the template's DoodadPhases rows. Register the prefab as WheatCrop in WorldObjectPrefabs. Server side: Doodads & gathering.

NPCs#

W2CSpawnNpc → NpcIdentity (name, level, faction relation, health, model ModelType) in NpcRegistry, moved by RemoteEntityInterpolator, animated by CharacterAnimator. Nameplate colour comes from FactionState.NpcRelation. A missing model key logs once and shows the placeholder.

Mounts, trade packs, vehicles#

  • Mounts (MountVisuals): a mount is a model parented to the rider, not a separate entity (no second interest entry, no vehicle physics). The rider sits on the mount's RiderSeat child. W2CMountState gives speed, CanFly, fly speeds; MovementSpeed.SetMount applies them to the local motor (the server's motor uses the same values). Mount animators get Speed, VerticalSpeed, Grounded, Flying if they declare them.
  • Trade packs (CarryVisuals): the pack's ModelType (TradePack_Grain...) on a BackAttach child or behind the shoulders; slowness arrives as the MoveSpeedPct stat, not here.
  • Vehicles (VehicleSeating): carts with seats; the driver moves the vehicle, passengers are seated.

Housing and furniture#

HousingPlacementClient: a ghost of the house follows the mouse; mouse position and yaw are only suggestions, the server validates the plot (HousingAreas, overlap, ownership) and only its reply enables Place. House parts (HouseDoor, HouseWindow, HouseTeleporter, HouseClimbable, HousePlacard) are components on the house prefab that expose interactions. Furniture: FurnitureView, FurnitureUseClient (sit, play the piano), FurniturePoseDriver. Validation: Tools ▸ Axiom ▸ Validation ▸ Housing / Furniture.

Quests, dungeons, social, PvP#

State Fed by Shown by
QuestState W2CQuestCatalog, progress packets QuestTrackerUI, QuestLogWindow, quest dialogue
InstanceState dungeon enter/leave/progress DungeonTrackerUI; hides HLOD proxies inside
SocialState, CommunityState party, raid, guild, family, friends PartyFrameUI, RaidFrameUI, CommunityWindow
FactionState, SiegeState faction catalogue, honor/crime, siege state nameplates, PvpWindow, SiegeHudUI
TradeState, WarehouseState, StorageState trade catalogue, warehouse, house storage trade and storage windows
PatronState patron status, labor PatronClaimUI, LaborUI
ExplorationState, AchievementState exploration, achievements ExplorationHud, AchievementWindow

Hooking in new behaviour#

  1. Server sends a packet → a handler writes a state class (and raises an event).
  2. A HUD component or window subscribes and draws.
  3. Player input → a sender → server → back to 1.
  4. Visible objects: a model key in WorldObjectPrefabs, placeholder until the art exists.

The complete walkthrough with real code is Add a packet and Add a server system.
