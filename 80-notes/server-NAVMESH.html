NavMesh: NPCs walk paths, not straight lines#

18 Oct 2026. Code: src/Axiom.Navigation (format, bake, runtime set), src/Axiom.Tools.NavBake (CLI), Core/Navigation/ (server), Assets/AxiomMMOKit/Editor/Navigation and Dev Tools > NavMesh (Unity).

Why this design#

Before this, NPCs moved in a straight line toward their target and were snapped to the heightmap. They walked through walls, couldn't use stairs or bridges, and in dungeons (where there is no heightmap) they moved in 3D lines.

Unity's NavMesh can't be used on the server: Unity isn't there. This design uses the same algorithm instead, Recast/Detour. That is what Unity's NavMesh is built on, and what most shipped MMOs use. On .NET it comes from DotRecast (zlib licence, pinned at 2026.3.1).

The navmesh is baked offline from the movement collision export (manifest.acm), which holds the same triangles the server already holds players to. So an NPC can't walk where a player can't, and it isn't stopped where a player can walk.

Pipeline#

Unity scenes ──Export Movement Collision──▶ manifest.acm + *.actri + *.achtmap
                                              │
                         Axiom.Tools.NavBake ─┘  (Dev Tools > NavMesh > Bake)
                                              ▼
                 Data/navmesh/<profile>/manifest.acnm
                                        page_X_Z.acnav      (server: Detour tiles)
                                        page_X_Z.acnavdbg   (Unity overlay only)
                                              │
              NavMeshService (world server) ◀─┘  streams pages, searches paths on workers
                                              │
              NpcAiManager.NavStep ◀──────────┘  chase, leash home, wander, pets

Grid#

  • Pages: 512 m, the same as the WorldGrid tiles. There is one file per page, and pages are streamed like heightmaps.
  • Nav tiles: 64 m (256 cells × 0.25 m), 8×8 per page. Small enough to rebuild quickly; big enough that a path crosses few of them.
  • Origin: fixed at (-32768, -32768). Adding a new zone never renumbers existing tiles, and a page that loads later links to its neighbours automatically (Detour connects the tile edges).
  • Layers: every instance layer shares the mesh, because a dungeon's rooms are the same geometry in every copy.

Profiles (agent sizes)#

There is one navmesh per body size, each in its own folder: default (radius 0.5, height 2, step 0.6, slope 45°), plus large (e.g. --profile large --radius 1.5 --height 4) if you need it. An NPC walks on the smallest profile its collision radius fits (npc_collision.json, NpcCollisionService.RadiusOf). If no profile fits, it uses the largest one.

Baking#

dotnet run -c Release --project src/Axiom.Tools.NavBake -- \
    --collision Axiom.Server.World/Data/world_collision \
    --out Axiom.Server.World/Data/navmesh --verify

Or in Unity: Dev Tools > NavMesh > Export collision + Bake. The tab starts the same tool, streams its output into the Dev Tools log, and refreshes the overlay.

  • Incremental. Each page stores a hash of the settings plus every collision file that reaches into it. Re-exporting one scene only rebakes the pages it touches. --force rebakes everything; --pages x,z;x,z bakes only the pages listed.
  • Terrain is triangulated at its own spacing, but never finer than 2 cells. Terrain holes (cave mouths) stay holes.
  • Static meshes: every collider in the export, turned face-up. The export's winding isn't consistent, and Recast's low-height filter removes ceilings.
  • Doodads are not baked. They are built, opened, chopped and moved at runtime. NPCs still stop at solid doodads, as before (DoodadManager.BlockingBetween).
  • --verify loads every page into one mesh, the way the server does, and runs 200 random path queries.

Server#

NavMeshService (registered in WorldServer, Tick() before NPC AI):

  • Streaming. A page loads the first time an NPC needs it, or when an NPC is within 64 m of its edge. The file is read and hash-checked on the thread pool, then added to the mesh on the tick. A page unloads after NavMeshIdleUnloadMinutes unused, and PreloadAllNavMesh loads everything at boot.
  • Path searches run on NavMeshWorkers background threads. Each search is a sliced A* capped at NavMeshMaxSearchNodes; if it gives up, it returns the best partial path. Results are handed back on the next tick, so the tick never searches and never waits.
  • Locking. The mesh changes only on the tick (pages in and out), under a write lock taken with a zero timeout. If a search is running, the change waits a tick; the tick never blocks. Workers search under the read lock.

NavAgent (one per moving NPC, tick thread):

  • Wraps Detour's DtPathCorridor. Each tick it finds the steering corners, moves along the surface (it can't leave the mesh), and takes the height from the mesh. On open terrain, the exact heightmap height is used instead.
  • Repathing. When a chased player moves a little, the end of the corridor slides along the mesh with no search. When the player moves more than 1.5 m, a new search is made, at most every 400 ms. While it runs, the NPC keeps walking, and the new path is joined where the NPC now is.
  • Unreachable. If the best path ends short of the target and the NPC is standing at that end (the player is on a rock, across a gap, or in a hole), it evades after NpcUnreachableEvadeSeconds (6): it forgets everyone, walks home and heals. This stops people killing mobs for free from an unreachable spot.
  • No mesh here (none baked, or the NPC is off it): the NPC falls back to the old straight-line movement, so nothing breaks before you bake.

NpcAiManager:

  • Chase, return home (leash), wander and pets go through NavStep.
  • Wander points are random points on the mesh, so an NPC never walks into a rock or across a river.
  • The leash distance, aggro and attack range are unchanged.

Unity overlay#

Tools > Axiom > Navigation > Show NavMesh Overlay (or the toggle on the tab) draws the baked pages within the draw distance of the Scene camera. Walkable polygons are tinted by height. Edges where the mesh ends (walls, ledges) are drawn as yellow lines. Pages are turned into Meshes once and reloaded when their file changes.

If there's a hole where you expected floor, it is almost always a collider missing from the movement export: a trigger, the wrong layer (the export mask is 119), or a marker or actor object.

Config#

"World": {
  "NavMeshEnabled": true,
  "NavMeshDirectory": "Data/navmesh",
  "NavMeshWorkers": 2,              // 1-16 path search threads
  "NavMeshMaxTiles": 16384,         // per profile, loaded at once (256 pages)
  "NavMeshMaxSearchNodes": 4096,    // A* cap per search
  "NavMeshIdleUnloadMinutes": 10,
  "PreloadAllNavMesh": false,
  "NpcUnreachableEvadeSeconds": 6   // 0 = never evade
}

The tick-health log adds [NavMesh] pages=default:3/40 paths=… complete=… partial=… failed=… queued=… maxSearchMs=….

Next steps (designed for, not built yet)#

  • Dynamic obstacles (player houses, gates opening and closing). Rebuild the affected 64 m tiles on a worker with the obstacle carved out, then swap them in under the same write lock. DotRecast's TileCache does this, and the tile grid is already the right size.
  • Off-mesh links (ladders, jump-downs, doors) as Recast off-mesh connections in the bake input.
  • Crowd separation (NPCs not overlapping), using a Detour crowd per layer.
