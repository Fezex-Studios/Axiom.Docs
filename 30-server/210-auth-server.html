Server Systems

Auth Server#

Axiom.Server.Auth is an ASP.NET Core minimal-API app (port 3000, JSON) with its own MySQL database (axiom_auth). It knows accounts, never characters. The flow it takes part in is on Login & world entry; this page is the server's internals.

Layout#

Folder
Program.cs configuration, JSON options (PascalCase), DB, services, CORS, rate limiting, migrations, endpoint mapping
Config/ AuthServerConfig (Auth section), WorldDirectoryConfig
Contracts/ request/response classes (LoginRequest, LoginResponse, ValidateSessionResponse, world directory DTOs)
Data/AuthDbContext.cs accounts, sessions, refresh_tokens, failed_logins
Endpoints/ one static class per route group, each with a Map… extension
Services/ PasswordService (BCrypt 12, timing defence), TokenService, RefreshTokens, LoginThrottle, WorldDirectoryRegistry, WorldCharacterCounts, GameDataProvider, SessionPurgeService, ClientAddress
Migrations/ EF migrations, applied automatically at start

Endpoints#

Route Caller Purpose
POST /register launcher create an account: username 3–20 chars [A-Za-z0-9_], password 8–72 bytes; level 1 always
POST /login launcher password → launch token + refresh token (lockouts, bans)
POST /session/launch-token launcher refresh token → new launch token + replacement refresh token
POST /logout launcher revoke a refresh token
GET /worlds client, launcher the world list with online status
GET /worlds/characters client characters per world for the bearer of a launch token (doesn't redeem it)
POST /worlds/heartbeat World (secret) "I'm up": id, host, port, population
POST /worlds/selection-token World (secret) mint a one-use token for switching worlds
POST /validate-session World (secret) redeem a launch token → account id + access level
GET /gamedata/version, /gamedata/db client, launcher hash of and download of gamedata.bin
POST /internal/account-access World (secret) an account's current access level
POST /internal/account-lookup, /internal/account-ban World (secret) GM panel account tools (ban also ends the session and revokes refresh tokens)

All request/response shapes: Service endpoints.

JSON is serialised with the exact property names (PropertyNamingPolicy = null): the launcher and the World server read Success, Token, Valid, AccountId. Switching to camelCase would make every field read as null.

Security details worth knowing#

  • Passwords: BCrypt work factor 12 (~250 ms). Unknown usernames still burn a hash so timing doesn't reveal which names exist; error messages are identical.
  • Lockouts: per (username, IP) in memory, and account-wide in failed_logins (Login flow).
  • Bans are only revealed after a correct password.
  • Launch tokens: 120 s, one use, deleted atomically on redemption (ExecuteDeleteAsync), never logged. REPLACE INTO sessions keeps one per account.
  • Refresh tokens: only their hash is stored; rotated on every use; revoked on logout and ban.
  • Internal secret: compared in constant time (CryptographicOperations.FixedTimeEquals); missing/placeholder/short secrets stop the server at start.
  • Rate limiting: global 10 requests/min per IP; /login and /register 5/min (auth-strict); /worlds 30/min; /internal/*, /validate-session, /gamedata exempt (server-to-server or downloads). 429 responses.
  • Client IP: X-Forwarded-For is trusted only with Auth:TrustForwardedFor = true (behind your reverse proxy).
  • CORS: any origin, GET/POST, no credentials (the launcher is a webview whose origin varies).

The world directory#

Worlds are configured in WorldDirectory:Worlds (id, name, host, port, restrictions, maintenance, max characters, optional per-world PersistenceBaseUrl). A registered world stays visible when offline; only recent authenticated heartbeats (within StaleAfterSeconds) mark it Online. WorldCharacterCounts asks each world's Persistence for the account's roster size (4 s timeout) for /worlds/characters.

To add a shard: start another World server with a new WorldDirectory:Id, ShardName, port and ItemUidNode, and add an entry with that id to Auth's list.

Game data#

GameDataProvider serves the file at Auth:GameDataPath. The SHA-256 is cached and recomputed only when the file's write time or length changes, so replacing gamedata.bin needs no restart. /gamedata/version answers 503 when the file is missing (gamedata.bin).

A launcher#

The repository doesn't include the launcher (a Tauri app in the original design), only the API it uses. A minimal launcher:

  1. POST /login {Username, Password} (or /session/launch-token {RefreshToken} if remembered). Store RefreshToken securely.
  2. Optionally GET /gamedata/version and update the client's file.
  3. Start Axiom.Client.exe -token <Token> -auth-url <your auth url>.
  4. On logout, POST /logout {RefreshToken}.

Adding an endpoint#

// Endpoints/AccountInfoEndpoint.cs
public static class AccountInfoEndpoint
{
    public static void MapAccountInfo(this IEndpointRouteBuilder app)
    {
        // World-to-Auth only: protect it with the internal secret like the others.
        app.MapPost("/internal/account-created", async (HttpContext http, AccountIdRequest req,
                                                        AuthDbContext db, IOptions<AuthServerConfig> cfg) =>
        {
            if (!InternalSecret.Matches(http, cfg.Value)) return Results.StatusCode(403);   // see WorldDirectoryEndpoints.Authorized
            var created = await db.Accounts.AsNoTracking()
                .Where(a => a.AccountId == req.AccountId).Select(a => a.CreatedAt).FirstOrDefaultAsync();
            return Results.Ok(new { CreatedAt = created });
        });
    }
}

Register it in Program.cs with the others (app.MapAccountInfo();). Copy the secret check from WorldDirectoryEndpoints.Authorized (or factor it into a small helper like the InternalSecret.Matches used above). Paths under /internal/ are already exempt from the global rate limiter. For a public endpoint, add .RequireRateLimiting("auth-strict") or a new policy. New columns → a new EF migration in Migrations/ (dotnet ef migrations add Name), applied automatically on the next start.
