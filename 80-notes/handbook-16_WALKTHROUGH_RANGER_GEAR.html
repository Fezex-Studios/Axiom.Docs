16. Walkthrough: the Ranger Tunic, then Boots and a Sword#

This is the exact path we took to get the Ranger Tunic working on men and women, written up so the next pieces go quickly. Part A is the one-time setup, Part B is the tunic as we did it, and Parts C and D are the Ranger Boots and a sword on the same pattern.

The other guides explain the why: armour in guide 12, weapons in guide 11, bodies in guide 14. This one is just the steps.

Assets used: Quaternius Modular Character Outfits - Fantasy, on the Universal Base Characters bodies (Superhero_Male_FullBody, Superhero_Female_FullBody). Every Ranger part is skinned to the same 65-bone skeleton as those bodies (root, pelvis, spine_01…), so they bind with no positioning.

Part A: One-time setup#

Do these once. If they're done, skip to Part B.

A1. Dev Tools must point at the database the server runs on#

The World server runs from bin\Debug\ (Server Control builds Debug), so that's the database the tools must edit.

  1. Tools > Axiom > Settings…
  2. World database: press Use next to src\Axiom.Server.World\bin\Debug\net10.0\Data\worldserver.db.
  3. Patches folder stays src\Axiom.Server.World\SQL\patches.

We lost time here: Settings pointed at src\…\Data\worldserver.db, the source copy, which never gets the server's new tables. Saving then failed with "Run the patched world server once to create GearVisuals…". Building the server also copies the source database over the bin one whenever the source is newer, so editing the wrong copy can undo your work.

Check: Dev Tools > Overview > World database shows a folder ending in bin\Debug\net10.0\Data, and the status bar shows World DB green.

A2. The two bodies#

Each body is a prefab with an empty root and the model as a child.

Default_Male_Char Default_Female_Char
FBX Superhero_Male_FullBody.fbx Superhero_Female_FullBody.fbx
FBX import Rig: Humanoid, Avatar: Create From This Model same
Root Position 0,0,0 · Rotation 0,0,0 · Scale 1 same
Child (the model) Position 0,0,0 · Rotation 0,180,0 same
Child's Animator Controller AxiomCharacter, Apply Root Motion off same
Saved in Assets/AxiomMMOKit/Axiom.Client/Prefabs/World/Characters/ same

Why the child is turned 180°: these models face backwards (−Z). Turn the child, never the root. Test: press forward in game; he must run away from the camera. If he runs at it, the child's Y is wrong.

Why the child's position must be 0: our first male body had the model 1.36 m off its root. The camera and movement follow the root, so he swung around an empty point. Keep the child at 0,0,0.

Never drag armour into a body prefab. The game puts it on at runtime. A deleted armour prefab left inside a body shows as "Missing Nested Prefab Asset".

A3. Register the bodies#

Dev Tools > Characters & Races > Bodies:

Row Male Female Any gender
Human Default_Male_Char Default_Female_Char
Default Default_Male_Char Default_Female_Char Default_Male_Char

The Gear Workshop's body line then says e.g. Uses Character_Human_Female (Default_Female_Char).

A4. Sockets (only needed for weapons and hats)#

Characters & Races > Sockets, for each body: Add missing sockets. All seven rows turn ✓. Lining them up is in Part D.

A5. Import the outfit pack#

  1. Put the pack's Exports/FBX (Unity) and Textures folders under one folder, e.g. Assets/AxiomMMOKit/Axiom.Client/Art/Armor/.
  2. Delete Textures/Ranger/Normals-UnrealEngine/. It's the Unreal-format normal map with the same name as the Unity one, and would make the lighting look inverted.
  3. Tools > Axiom > Characters & Gear > Import Outfit Pack…: Pack folder = Assets/AxiomMMOKit/Axiom.Client/Art/Armor, Output folder = Assets/AxiomMMOKit/Axiom.Client/Art/Gear/Outfits. Import.

You get the material M_Ranger and one prefab per part in Assets/AxiomMMOKit/Axiom.Client/Art/Gear/Outfits/: Male_Ranger_Body, Female_Ranger_Body, Male_Ranger_Feet_Boots, Female_Ranger_Feet, …

Part B: The Ranger Tunic (what we did)#

The pattern for every piece of body armour: one item, the male model as the base, the female model as its Female variant.

B1. Create the item#

Tools > Axiom > Create > Item… → Copy an existing one (a chest armour):

Field Value
Name Ranger Tunic
Gear stats → EquipSlot 2 (Chest)
Gear stats → ArmorKind 2 (Leather: Warriors and Healers; use 1 Cloth for everyone)
Gear stats → ArmorRating 12
Sold by a vendor's shop, with a Buy Price

Check, Create. Ours got id 970006.

We forgot two things the first time; both fix the same way in Content Studio (Ctrl+Alt+E → Ctrl+K → the item): - EquipSlot: set it on the item's Gear stats row (or press Make it wearable if there's none). Ctrl+S. - The vendor: on the item's Shop Items, Add a row: ShopId = the shop, BuyPrice = the price. Ctrl+S.

Then restart the World server. Shops live on the server only, so no game data export is needed for those.

B2. The male look: "Everyone"#

The pack's clothes are made to replace the body under them, and they come in sets: the tunic (Male_Ranger_Body) is sleeveless and stops short of the shoulders, and the pack's sleeves (Male_Ranger_Arms: leather sleeves, bracers and gloves) fill the gap. Worn alone on our male body, the tunic shows skin at the chest (the body's Shoulders part pokes through), and hiding Shoulders leaves holes at the shoulder caps. So the Ranger Tunic uses the tunic and the sleeves together (see "Clipping" below for the whole story).

  1. Make the set prefab. In Assets/AxiomMMOKit/Axiom.Client/Art/Gear/Outfits/, select Male_Ranger.prefab (the pack's complete outfit, every piece on one skeleton), Ctrl+D, rename the copy Male_Ranger_Tunic. Open it and untick the pieces this item doesn't include: Male_Ranger_Legs, Male_Ranger_Feet_Boots, Male_Ranger_Head_Hood and, unless you want the shoulder plate, Male_Ranger_Acc_Pauldron. Keep Male_Ranger_Body, its two belts, Male_Ranger_Arms and Male_Ranger_Arms_Bracer. Ctrl+S. Switched-off pieces stay hidden when the game puts the gear on.
  2. Tools > Axiom > Characters & Gear > Gear Workshop: Body: Human, Male.
  3. Item id: 970006 → Load. Load reads what's saved in the world database, so it replaces whatever is in the form: load first, then change the fields.
  4. Equip slot: Chest. Gear prefab: Male_Ranger_Tunic.
  5. Attach: Skinned. Hide body parts: Torso, Shoulders, Arms, Hands (the sleeves include gloves).
  6. Preview in Scene → "Armour bound to the body's bones." No skin at the chest, no holes at the shoulders.
  7. Save for: Everyone → Save to world database. Log: Saved gear visual: item 970006, Chest, prefab Gear/Prefabs/… (a new name each time you save a different prefab).

Why "Everyone" and not "Male": an item has exactly one gear visual row (slot, attach, hidden parts, base prefab), and that's what Everyone saves. A variant is only an extra prefab next to the base, so it needs the base saved first. The base is also the fallback for any body without its own version.

B3. The female look: "Variant: Female"#

  1. Make the female set prefab the same way: copy Female_Ranger.prefab, name it Female_Ranger_Tunic, untick its legs, feet, hood and pauldrons, keep the body, belts and arms. Ctrl+S.
  2. Gear Workshop, Body: switch to Female (uses Default_Female_Char).
  3. Load again.
  4. Gear prefab: Female_Ranger_Tunic. Preview in Scene → bound.
  5. Save for: Variant: Female → Save as 'Female' variant.

⚠ Don't press Save to world database with "Everyone" here, or the female model replaces the male base for everyone.

The variant must be saved with this button. It's stored next to the base under the base's generated name (Resources/Gear/Prefabs/<name>_Female); a prefab you name …_Female yourself in Gear/Outfits isn't found. Saving a different base prefab gives it a new name, so any variants saved for the old one stop applying: save them again after changing the base.

Female, not Human_Female: Female covers women of every race. Human_Female would only cover humans, and elf and fairy women would fall back to the male base. Add race versions (Fairy_Female…) later only where a body needs a different model; they stack on top.

B4. Ship it and test#

  1. Dev Tools > Overview > Export game data now.
  2. Servers > World > Restart.
  3. Characters & Races > Wardrobe: Ranger Tunic shows base on the male body and ✓ Female on the female body.
  4. In game: buy and equip it on a male, then a female character.

Part C: The Ranger Boots (next)#

Exactly Part B, with these differences:

Ranger Tunic Ranger Boots
EquipSlot 2 (Chest) 5 (Feet)
ArmorRating 12 6
Male prefab (Everyone) Male_Ranger_Body Male_Ranger_Feet_Boots
Female prefab (Variant: Female) Female_Ranger_Body Female_Ranger_Feet
  1. Create > Item…: name Ranger Boots, EquipSlot 5, ArmorKind 2, ArmorRating 6, Sold by your vendor. Create, note the id.
  2. Gear Workshop: Human / Male, id → Load, Equip slot Feet, Gear prefab Male_Ranger_Feet_Boots, Skinned, Hide body parts: Feet, Preview, Save for: Everyone → Save to world database. (Our Ranger Boots item is 970007.)
  3. Female, Load, Gear prefab Female_Ranger_Feet, Preview, Save for: Variant: Female → Save as 'Female' variant.
  4. Export game data now, restart the World server, check the Wardrobe, test.

The rest of the Ranger set works the same way: Ranger Pants (*_Ranger_Legs, Legs slot 3, hide Legs) and the hood (*_Ranger_Head_Hood, Head slot 1, hide Hair). The hood is skinned in this pack, so use Skinned, not Socket. The sleeves (*_Ranger_Arms) are part of the tunic (B2), not an item of their own.

Pants and boots are a pair too: the pants (Male_Ranger_Legs) cover the hips down to mid-shin (0.42 m), the boots the floor up to just under the knee (0.56 m). Pants hide Legs, so worn without boots the shins would be missing, unless the shins count as Feet (one Pipeline setting, see "Clipping"). The Peasant pants and shoes are cut the same way.

Part D: A sword (next)#

Weapons are different from armour: they're Socket gear. They're rigid, glued to a point on the body, and sheathed somewhere else out of combat. Three things make that work:

Piece Lives on Done
Where the hand, hip and back are each body: Socket_ points once per body (D1)
How the model sits on those points the weapon prefab: one rule once per weapon (D2)
Where a sword is carried its weapon kind: swords → left hip automatic (Weapon Sheaths)

Get those right and every offset stays at 0.

D1. Line up the body's sockets (once per body)#

Characters & Races > Sockets, Body Character_Default (then do the female body too):

  1. Reference weapon: a one-handed sword prefab built to the rule in D2.
  2. MainHand → Line up. The body appears in the Scene with the sword on the point, and the point is selected.
  3. Rotate and move the socket, not the sword (Rotate tool, handle set to Local) until the sword is gripped in the fist, pointing forward, blade edge up. Save sockets to the prefab.
  4. HipLeft → Line up: rotate until it hangs at the left hip, blade down and slightly back. Save sockets to the prefab.
  5. Do HipRight and Back the same way when you need them (axes and maces go on the right hip; two-handers and staves on the back).

Best final check, in the real pose: Play → equip → draw → Pause → rotate the live Socket_MainHand until it looks right → right-click Transform → Copy → Component → stop Play → open the body prefab → select Socket_MainHand → Paste → Component Values → save.

What happened with the poleaxe: before the sockets existed, the game glued weapons to raw bones (hand_r, spine_03), whose axes point in arbitrary directions. The poleaxe sat sideways, and offsets couldn't fix both hand and back at once. Sockets fixed it.

D2. Build the sword prefab to the rule#

The rule, for every weapon: root = the centre of the grip, blade along +Y (green), edge along +Z (blue).

  1. Scene toolbar: Pivot (not Center) and Local (not Global).
  2. Hierarchy → Create Empty, named Sword_Ranger: Position 0,0,0, Rotation 0,0,0, Scale 1.
  3. Drag the sword model onto it, so the model is a child.
  4. Rotate the child until the blade points up the green arrow. Try 0,0,90, 0,0,-90, 90,0,0 or -90,0,0.
  5. Rotate the child around Y (0, 90, 180, −90) until the edge faces the blue arrow. From the side (click the red cone on the Scene gizmo), you should see the flat of the blade.
  6. Move the child (Position Y) until the root's gizmo sits where the fist closes on the handle.
  7. Any size change goes on the child's Scale, never the root's.
  8. Drag Sword_Ranger into Assets/AxiomMMOKit/Axiom.Client/Art/Weapons/, then delete it from the scene.

The poleaxe ended up as child Rotation 0, −90, −90 with its Y position moved so the root sat a third of the way up the shaft. Every model is different, which is why you check with the gizmo instead of copying numbers.

The root's position, rotation and scale are overwritten when the game attaches a weapon, so anything you set on the root is lost. That's why all the adjusting happens on the child.

D3. Create the item#

Create > Item… → copy an existing sword:

Gear stats field Value
EquipSlot 6 (Main Hand)
WeaponKind 1 (Sword): Warriors only (Healers and Mages can't use swords)
TwoHanded off (on = a greatsword, carried on the back)
AttackPower e.g. 25

Plus Sold by your vendor. Create, note the id.

D4. Fit it#

Gear Workshop:

  1. Body: Human / Male. Item id → Load (this reads the weapon kind).
  2. Equip slot Main Hand, Gear prefab Sword_Ranger.
  3. Attach: Socket. In use: (the slot's hand). Sheathed: (by weapon kind). The line underneath should read drawn on MainHand, sheathed on HipLeft (from Sword in Weapon Sheaths).
  4. Position and Rotation 0, Scale 1.
  5. Preview in Scene; tick Preview sheathed to see it on the hip. Switch the body to Female and Rebuild preview to check her too.
  6. Sheathed size below 1 only if it clips on the hip (0.85 is typical for big weapons on the back).
  7. Save for: Everyone → Save to world database. Weapons usually need no Female variant: the sockets already fit each body.
  8. Export game data now, restart the World server, test: equip, draw, sheathe, run.

Clipping: split the body, then hide what the clothes cover#

The outfit pack's Readme says the clothes are made to replace the skin under them. Out of the box our bodies are one mesh head to toe, so Hide body parts can't hide just the torso. The tunic is drawn over the full skin, and as she walks her hips push through the bottom of it.

Fix it once per body:

  1. Dev Tools > Characters & Races > Sockets. Pick the body (Character_Default_Female, then the male one).
  2. In the Body parts card, press Split body into parts. It cuts the skin by its bone weights into Head, Torso, Arms, Hands, Legs, Feet (eyes and eyebrows go with the head; the hips, crotch and buttocks go with Legs, because the pants cover them, not the top), keeps the original mesh switched off, and fills in the body's Character Sockets → Body list. The card turns ✓ and lists the pieces. It turns on the model's Read/Write import setting itself if needed. Undo split puts it back.
  3. Content Studio > Gear Visuals: set Hide Body Parts on each piece:
Item Gear prefab Hide Body Parts
Ranger Tunic Male_Ranger_Tunic (tunic + sleeves, B2) Torso, Shoulders, Arms, Hands
Ranger Boots Male_Ranger_Feet_Boots Feet
Ranger Pants Male_Ranger_Legs Legs
Ranger Hood Male_Ranger_Head_Hood Hair

Ctrl+S. Edit it here rather than re-saving in the Gear Workshop: saving "Everyone" there with the female body selected would make the female model the base. 4. Export game data now, restart the World server, and walk around.

The parts meet with no seams: every piece keeps all the original vertices and weights, it just draws its own triangles.

Why the hips are Legs, not Torso: the first version put them in Torso, and a tunic then hid the crotch along with the chest, leaving a hole under its short flaps. Modular outfits split the body the other way: the top covers chest and back, the pants cover hips and legs. So a tunic worn alone leaves the hips visible (and they can poke through its flaps a little); wearing the Ranger Legs with it hides them. If you split a body before this change, press Split again.

Sets, not single pieces#

What the pack's models actually do (we checked them against the bodies):

  • Every piece sits inside the body. The bodies are bigger than the clothes everywhere except the tunic's collar, so whatever body part a piece doesn't hide pokes through it.
  • The male body has a Shoulders part (SuperHero_Male__Shoulders); the female's shoulders are in her Torso. It covers the shoulder caps and the top corners of the chest. A tunic that hides only Torso shows two wedges of skin on the chest; hiding Shoulders as well removes them but leaves holes at the shoulder caps, because the tunic stops short of the shoulders.
  • The sleeves (*_Ranger_Arms) are the other half of the tunic. They run from the shoulder to the gloves and close that gap. So the tunic item uses both (B2), hiding Torso, Shoulders, Arms and Hands.
  • Pants and boots overlap at the shin. With the body split the standard way (Legs = hips to ankles), pants worn without boots leave the shins missing. Fix: Characters & Races > Pipeline > Part rules, add Left Lower Leg → Feet and Right Lower Leg → Feet, then Split again on each body. Now pants hide hips to knee, boots hide knee down, and any mix works (a little shin may show just under the pant hem; boots cover it).
  • Nothing on, nothing underneath. The Superhero bodies have no underwear, so a character without pants is bare under the tunic's flaps. Give every new character a starter pants item if you don't want that.

Lighting looks wrong (sleeves black from behind)#

The pack's materials as imported used the normal maps from Textures/<Outfit>/Normals-UnrealEngine/. Unreal's normal maps have the green channel the other way round from Unity's, so bumps are lit upside down and surfaces facing away from the sun go almost black. Either select those textures and tick Flip Green Channel (Apply), or point M_Ranger / M_Peasant's Normal Map at Textures/<Outfit>/T_<Outfit>_Normal.png (the one outside the Unreal folder; Fix Now if Unity asks to mark it as a normal map). Materials update at once, no export needed.

Checklist for every new piece#

  • [ ] Item: created, EquipSlot set, armour/weapon kind set, sold somewhere
  • [ ] Prefab: armour straight from the pack (keep its Armature), or a copy of the pack's whole outfit with the other pieces switched off when pieces come as a pair (tunic + sleeves); weapon built to the rule
  • [ ] Hide body parts: everything the piece covers, checked in Preview on the male and the female body (the male has a separate Shoulders part)
  • [ ] Gear Workshop: male body → Everyone → Save to world database
  • [ ] Armour: female body → Variant: Female → Save as variant
  • [ ] Export game data now, then restart the World server
  • [ ] Wardrobe: ✓ on every body
  • [ ] Tested in game on a male and a female character
