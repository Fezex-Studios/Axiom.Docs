Unity Client

Client Networking#

All client networking is under Assets/AxiomMMOKit/Axiom.Client/Networking.

File Job
ClientNetwork.cs The one MonoBehaviour that owns the LiteNetLib NetManager (4 channels), connects, authenticates, receives, dispatches, handles disconnects. Singleton, DontDestroyOnLoad.
W2CHandlers/ One IClientPacketHandler per incoming opcode (some files hold several).
C2WSenders/ One static sender per outgoing packet.
WorldLoader.cs Loads main_world and queues world-object work until it's ready.
ClientSpawnQueue.cs Creates remote objects within a frame budget and sends spawn acknowledgements.
SnapshotReader.cs Decodes W2CWorldSnapshot (mirror of the server's SnapshotWriter).
MovementPredictionClient.cs Movement config/state, client collision set, NPC collision frames (Movement).
WorldEntryGate.cs Holds input until collision, essential spawns and catalogues have arrived.
ClientSelectionFlow.cs Returning to character select and switching worlds.
WorldDirectoryClient.cs GET /worlds, /worlds/characters from Auth.
ClientExit.cs Keeps the network alive during a requested disconnect so the server can save.
ClientCreationBudget.cs One soft per-frame budget for scene-ready callbacks and object creation.

The loop#

ClientNetwork.Update() each frame:

client?.PollEvents();          // LiteNetLib callbacks → OnNetworkReceive → handlers (main thread)
WorldLoader.Pump();            // run queued world work once main_world is ready
ClientSpawnQueue.Pump();       // create remote objects within budget, send C2WSpawnAck
MovementPredictionClient.Pump(); // apply movement config/state to the local motor
WorldEntryGate.Pump();         // release input when entry is complete

Everything runs on Unity's main thread: handlers may create GameObjects and touch UI.

Receiving#

OnNetworkReceive reads the 2-byte opcode and calls dispatcher.Handle(opcode, reader), with filters:

  • packets from a stale peer, or while quitting/switching worlds, are dropped;
  • while returning to selection only W2CSelectionReturn and movement packets pass;
  • while in character selection only the character list, create-failed, selection return, MOTD, announcements, account access status and movement packets pass;
  • a MessagePackSerializationException is logged as "Could not read X packet (Axiom.Network.dll out of date?)"; any other handler exception is logged and the packet dropped.

A handler:

// Networking/W2CHandlers/W2CGoldUpdatehandler.cs (real file)
public class W2CGoldUpdatehandler : IClientPacketHandler
{
    public void Handle(NetPacketReader reader)
    {
        var packet = MessagePackSerializer.Deserialize<W2CGoldUpdatePacket>(reader.GetRemainingBytesMemory());
        LocalCharacterState.ApplyGold(packet.Gold);   // cache + PlayerStatEvents.OnGoldChanged; the HUD listens
    }
}

Registration is manual, in ClientNetwork.RegisterHandlers() (116 lines of dispatcher.Register(Opcodes.X, new XHandler())). A packet without a registered handler is dropped with [ClientPacketDispatcher] Unhandled packet: X - written with Console.WriteLine inside Axiom.Network.dll, which the Unity console does not show, so a forgotten registration looks like silence. ClientPacketDispatcher also has an AutoRegister(assembly) that scans for handlers with a [PacketOpcode] attribute; the client doesn't use it (no client handler carries the attribute).

World objects wait for the world#

The spawn burst on entering arrives while main_world is still loading. Any handler that touches world objects calls:

WorldLoader.RunWhenReady(() => PlayerRegistry.Instance.Spawn(packet));

The first call starts loading main_world (it's the only code that loads it); queued actions run in arrival order once the scene and its registries exist, so a despawn can never run before its spawn.

Spawning remote objects#

W2CSpawnPlayer/W2CSpawnNpc/W2CSpawnDoodad/W2CSpawnCorpse go through ClientSpawnQueue, which creates objects within ClientCreationBudget and sends C2WSpawnAck { NetworkId, Generation, Baseline } so the server knows the object exists and starts including it in snapshots (Interest & replication). Despawns cancel pending creations.

Snapshots#

W2CWorldSnapshotHandler copies the raw packet (custom binary, not MessagePack) into a reusable buffer and decodes it with SnapshotReader: per entity the newest tick wins; an entity missing from a snapshot has not despawned. Each entity's RemoteEntityInterpolator buffers the samples and renders a fixed delay in the past, at the server's measured tick rate (RemotePlaybackClock).

World entry gate#

After a teleport or world entry, WorldEntryGate keeps the player frozen behind a loading screen until the movement collision is loaded, essential spawns (NPCs within 20 m) are acknowledged, and catalogues have arrived on the ordered channel (W2CWorldEntryReady carries the movement baseline). Short teleports (< TeleportLoadingScreenMeters) skip the loading screen.

Sending#

// Networking/C2WSenders/C2WInventorySenders.cs (real)
public static class C2WUseItemPacketSender
{
    public static void Send(NetPeer peer, int slot)
    {
        if (peer == null) return;
        ClientPacketSender.SendPacket(peer, Opcodes.C2WUseItem, new C2WUseItemPacket { Slot = slot });
    }
}

// from UI code
var peer = ClientNetwork.Instance?.ServerPeer;
if (peer != null) C2WUseItemPacketSender.Send(peer, slot);

ClientPacketSender.SendPacket<T>(peer, opcode, payload, delivery = ReliableOrdered) (in Axiom.Network/Client) rents a pooled writer, writes the 2-byte opcode and the MessagePack body, and sends on the channel PacketChannels.For(opcode) picks. Related senders share a file (C2WInventorySenders.cs, C2WCombatSenders.cs, C2WQuestSenders.cs...). Movement inputs are sent by LocalCharacterMotor in the binary MovementInputCodec format, unreliable and redundant.

Never change local state optimistically for anything authoritative (bag, gold, equipment): send the request and let the server's answer update the UI.

Disconnects and quitting#

OnPeerDisconnected turns the reason into a readable message (protocol mismatch, kicked with a reason, timed out, server down), resets every per-world state class, and returns to server_select (WorldLoader.ReturnToScene). Quitting goes through ClientExit: it sends the disconnect and keeps polling briefly so the server receives it and saves, instead of the socket dying with the process.

Connect() resets all per-connection state (snapshot handler, spawn queue, prediction, world loader queue, LocalCharacterState, community/exploration/achievement/mail state, floating origin, world settings) so nothing from a previous world leaks into the next.

Adding a client handler (checklist)#

  1. The packet class exists in Axiom.Network and the client has the current DLL.
  2. Networking/W2CHandlers/W2CMyThingHandler.cs implementing IClientPacketHandler.
  3. dispatcher.Register(Opcodes.W2CMyThing, new W2CMyThingHandler()); in ClientNetwork.RegisterHandlers().
  4. If it touches world objects: WorldLoader.RunWhenReady. If it may arrive before the HUD exists: cache it in a state class.
  5. If it must be accepted during character selection, add it to the filter in OnNetworkReceive.
