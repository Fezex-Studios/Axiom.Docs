Instances & Dungeons#

A dungeon's rooms are ordinary world space: tile scenes, collision and heightmaps built once in a region of the map nobody can walk to (around x/z 16 384 in the shipped data). An instance is one group's copy of what's in it: its NPCs and doodads, spawned into an interest layer of its own. Because every system sees the world through InterestManager, and a layer only sees itself, NPC AI, combat, threat, loot, parties and doodads all just work inside, with no instance-specific code.

Piece File Job
InstanceManager Core/Instances/InstanceManager.cs Opening, entering, leaving, closing instances; entry limits; login inside.
InstanceManager.Scripts Core/Instances/InstanceManager.Scripts.cs Applies the commands scripts produce (spawn tags, gates, teleports, chests).
InstanceZone Core/Instances/Zones/InstanceZone.cs One run's own state and logic: bosses, clock, script, outcome.
ZoneThread, ZoneProtocol Core/Instances/Zones Each run ticks on its own thread; it talks to the world only by messages.
InstanceRotation Core/Instances Fair share of the per-tick dungeon AI budget.

Entering and leaving#

  • Enter: a portal doodad with an Enter Dungeon effect (RefId = dungeon). You go to the instance you already belong to; else one a party member is in; else a new one. Refused up front if full (MaxPlayers), too low (MinLevel), already in a dungeon, or out of runs.
  • Inside: dying respawns you at the entrance, inside. Mounts only if AllowMounts.
  • Leave: the exit portal (Leave Dungeon effect), or C2WLeaveDungeon (the tracker's Leave button): you appear at the dungeon's exit (ExitX/Y/Z) in the open world.
  • Log out inside: on login you're put back into the instance if it's still open, otherwise at the exit.
  • An empty instance closes after EmptySeconds.

W2CInstance tells the client it entered/left (its floor, region, client key for the scene), and W2CDungeonProgress drives the tracker (bosses, timer, cleared/failed).

Dungeons#

Column Meaning
Name, Description, ClientKey display; ClientKey names the client scene/region
MinLevel, MaxPlayers entry rules
EntryX/Y/Z/Yaw, ExitX/Y/Z where you appear inside, and outside when you leave
MinX/MinZ/MaxX/MaxZ, FloorY the dungeon's region
EntryLimit, EntryLimitPeriodHours, CountEntryOn runs per period (saved per character in character_dungeon_entries)
TimeLimitSeconds a timed run fails when it runs out
CompleteExitSeconds after clearing, everyone is moved out after this long
EmptySeconds, AllowMounts

Contents: NpcSpawners and DoodadSpawns rows with DungeonId = the dungeon are spawned once per instance and never respawn (a cleared room stays cleared). Rows with Dormant = 1 wait for a script.

Scripts: rooms, events, actions#

A dungeon says "when this happens, do these things" in three tables:

Table
DungeonRooms named circles (X, Z, Radius) for Enter Room / Room Wiped and the tracker
DungeonEvents a trigger and the first action of the chain it starts: Trigger, TriggerRef (NPC template, doodad...), TriggerKey (a tag, room or timer name), Count, Param (e.g. health %), Once, FirstActionId
DungeonActions one step each: Kind, RefId, Param, Key, Text, X/Y/Z, then NextActionId after DelayMs

Triggers: 1 Run Started, 2 NPC Killed, 3 Tag Cleared, 4 NPC Health Below, 5 NPC Combat Started, 6 NPC Combat Ended, 7 Enter Room, 8 Room Wiped, 9 Doodad Used, 10 Timer Elapsed, 11 Bosses Cleared.

Actions: 1 Spawn Tag (wake dormant spawners with that tag), 2 Despawn Tag, 3 Change Doodad Phase (open a gate), 4 Banner (text on everyone's screen), 5 Start Timer, 6 Stop Timer, 7 Apply Status, 8 Teleport, 9 Set Room Cleared, 10 Reset Room, 11 Spawn Chest, 12 Complete Run, 13 Fail Run, 14 Run Lua.

Tags (NpcSpawners.Tag, DoodadSpawns.Tag) group things for the script. Bosses (Rank = 2), dormant ones included, count toward the run's total; when the last dies, a Bosses Cleared event decides what happens (otherwise the run completes).

Instance zones and threads#

Each run's InstanceZone ticks on its own thread (ZoneThread, at World:InstanceTickRate) and wakes immediately when the world posts an event (a boss died). It never touches sessions, entities or the grid: it reads events and a periodic view from the world and answers with commands the world applies on its tick (within InstanceCommandBudgetMs). A slow script delays only its own run. With World:InstanceThreads = false zones run inline on the world tick with the same results. Dungeon NPC AI shares InstanceAiBudgetMs per world tick, rotated fairly across dungeons.

Example: a two-room dungeon script#

The shipped The Warrens (dungeon 1) is a complete example. This is its whole script, exactly as in worldserver.db:

-- events: trigger -> first action
INSERT OR REPLACE INTO DungeonEvents (Id, DungeonId, Name, Trigger, TriggerRef, TriggerKey, Count, Param, Once, FirstActionId) VALUES
  (1, 1, 'Intro',             1,  0,  '',         1, 0,  1, 1),    -- run started
  (2, 1, 'Sentries down',     3,  0,  'sentries', 1, 0,  1, 2),    -- every NPC tagged "sentries" dead
  (3, 1, 'Chieftain at half', 4,  20, '',         1, 50, 0, 5),    -- NPC template 20 below 50 %
  (4, 1, 'Chieftain dead',    11, 0,  '',         1, 0,  1, 7),    -- all bosses dead
  (5, 1, 'Into the den',      7,  2,  '',         1, 0,  1, 10),   -- someone entered room 2
  (6, 1, 'Wiped in the den',  8,  2,  '',         1, 0,  0, 11);   -- everyone in room 2 died

-- actions: one step each, then NextActionId after DelayMs
INSERT OR REPLACE INTO DungeonActions (Id, DungeonId, Kind, RefId, Param, Key, Text, DelayMs, X, Y, Z, NextActionId) VALUES
  (1,  1, 4,  0,    0, '',         'The Warrens stir. Cut down the sentries to reach the den.', 0, 0,0,0, 0),   -- Banner
  (2,  1, 3,  1262, 0, 'den_gate', '',                                     0,    0,0,0, 3),    -- gate (tag den_gate) -> phase 1262 (open)
  (3,  1, 4,  0,    0, '',         'The den gate grinds open...',          0,    0,0,0, 4),
  (4,  1, 9,  1,    0, '',         '',                                     0,    0,0,0, 0),    -- room 1 cleared
  (5,  1, 4,  0,    0, '',         'The Chieftain bellows for his guard!', 0,    0,0,0, 6),
  (6,  1, 1,  0,    0, 'den_adds', '',                                     500,  0,0,0, 0),    -- wake the dormant "den_adds"
  (7,  1, 2,  0,    0, 'den_adds', '',                                     0,    0,0,0, 8),    -- boss dead: remove adds
  (8,  1, 9,  2,    0, '',         '',                                     0,    0,0,0, 9),    -- room 2 cleared
  (9,  1, 12, 0,    0, '',         'Warren Chieftain',                     1500, 0,0,0, 0),    -- Complete Run
  (10, 1, 4,  0,    0, '',         'Chieftain''s Den',                     0,    0,0,0, 0),
  (11, 1, 4,  0,    0, '',         'The Chieftain gloats over the fallen. The den resets.', 0, 0,0,0, 12),
  (12, 1, 2,  0,    0, 'den_adds', '',                                     3000, 0,0,0, 13),   -- despawn adds
  (13, 1, 10, 2,    0, '',         '',                                     0,    0,0,0, 0);    -- Reset Room 2

Its contents: NpcSpawners 100–101 (tag sentries), 102 (the chieftain, template 20, a boss), 103 (tag den_adds, Dormant = 1); DoodadSpawns 126 (the gate, tag den_gate: closed phase blocks, open phase 1262 doesn't) and the den_wall pieces. Rooms 1 and 2 are DungeonRooms rows.

The easiest way to start: Tools ▸ Axiom ▸ Create ▸ Dungeon… (run limits, timer, mobs, boss, entrance portal and exit), then add events in Content Studio. Build the rooms as tile scenes in the dungeon region, export collision and navmesh like any other area. See Dungeons (note), Dungeon scripts (note), Instance zones (note).

Extending scripts (code)#

To add an action kind (e.g. "Play Sound"): add the value to DungeonActionKind (GameData/Instances/DungeonScripts.cs) and ContentEnums.cs; in InstanceZone, emit a zone command for it; in InstanceManager.Scripts, apply the command on the world tick (send a packet to everyone in the instance's layer). Triggers work the same way in reverse: the world posts a new ZoneEvent (ZoneProtocol.cs) and InstanceZone matches it against events. Keep the boundary: the zone never touches world objects directly.
