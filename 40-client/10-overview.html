Unity Client

Client Overview#

The client is a Unity project (HDRP, the new Input System, UI Toolkit, Cinemachine) whose game code lives in Assets/AxiomMMOKit/Axiom.Client (assembly Axiom.Client) and whose editor tooling lives in Assets/AxiomMMOKit/Editor. It is not authoritative: it renders, predicts the local player's movement, and sends intentions.

Folders#

Assets/
├── Axiom.Client/                  game code + content (assembly Axiom.Client)
│   ├── Networking/                ClientNetwork, dispatch, W2CHandlers/ (60), C2WSenders/ (30), WorldLoader,
│   │                              snapshots, movement prediction, spawn queue, world directory, selection flow
│   ├── Movement/                  LocalCharacterMotor, input, control schemes, UnityCollisionWorld
│   ├── Scripts/
│   │   ├── GameData/              gamedata.bin: bootstrap, crypto, format, repositories, icons
│   │   ├── Gameplay/              players, NPCs, characters, combat, interaction, quests, mounts, ... (77 files)
│   │   ├── UI/                    windows, HUD, chat, nameplates; UI/Toolkit is the UI Toolkit framework (160 files)
│   │   ├── World/                 streaming, floating origin, zones, prefab registry, editor markers
│   │   ├── Exploration/, Pvp/, Staff/, ClientConfig/
│   ├── Doodads/, Furniture/, Housing/, Entities/   prefabs for world objects (trees, veins, crafting stations,
│   │                              characters, mounts, NPCs, pets, vehicles, houses, furniture)
│   ├── Content/                   NpcCollisionProfiles.asset (per-NPC collision shape overrides)
│   ├── db/                        legacy client content DB (_oggamedata.db) and Game Data tab outputs
│   ├── World/                     scenes: server_select, main_world, Tiles/<area>/tile_X_Z
│   ├── Lua/                       DesignerScripts/UI (UI addons) and LuaSDK/Client
│   ├── Docs/                      design notes and the Handbook (see Archive)
│   └── Art/                       models, textures, materials, animations, Resources (often kept separately)
├── Editor/                        the Axiom editor suite (Tools section)
├── Plugins/                       Axiom.Network.dll, Axiom.Movement.dll, MoonSharp, ParrelSync (Sirenix: empty folder)
├── Packages/                      NuGet via NuGetForUnity (packages.config): LiteNetLib 2.1.4, MessagePack 3.1.12,
│                                  sqlite-net-pcl + SQLitePCLRaw (editor tools), Newtonsoft.Json
├── StreamingAssets/               GameData/gamedata.bin, World/MovementCollision, World/NpcCollision, World/zones.aczmap
└── Resources/                     only performance-test settings; the game's Resources are in Axiom.Client/Art/Resources
                                   (Icons, Cursors, UI, World catalogues, CharacterPipeline, Settings/CrowdSettings.json)

Assembly references (Axiom.Client.asmdef): MoonSharp, TextMeshPro, UnityEngine.UI, Input System, Cinemachine, MessagePack, LiteNetLib, HDRP runtime. The two shared DLLs in Plugins are referenced automatically.

The shared DLLs. Axiom.Network.dll and Axiom.Movement.dll are built from the server solution. After any change to src/Shared/Axiom.Network or Axiom.Movement, build them (dotnet build -c Release) and copy the two DLLs into Assets/AxiomMMOKit/Plugins. Tools ▸ Axiom ▸ Server Exports ▸ Validate Netcode Build checks they're current.

Scenes#

Scene Role
server_select the front end: game data bootstrap, world list, character select/create (UI Toolkit screens)
main_world the persistent world scene: camera, lighting, sky, registries, UI. Players, NPCs and doodads spawned from packets live here. Loaded once by WorldLoader.
Tiles/<area>/tile_X_Z the static world, one 512 m tile per scene, streamed around the player by WorldStreamer

Boot sequence#

Application start
 ├─ LegacyNameMigration           copies old ArcheCore.* PlayerPrefs to Axiom.*
 ├─ UiBootstrap (BeforeSceneLoad) hooks scene loads: server_select → LoginScreenManager; main_world → HUD
 └─ server_select
     ├─ ClientNetwork.Awake        DontDestroyOnLoad; MessagePack config; reads -token (or Editor Login's token / Editor Token)
     ├─ GameDataBootstrap          gamedata.bin: bundled → cache, check Auth hash, download, load
     ├─ CommandLineBootstrap       optional -ip auto-connect, once per run
     └─ LoginScreenManager         ServerSelectUI (GET /worlds) → Connect
            ClientNetwork.Connect → "Axiom/45" → Authenticate{token}
            W2CCharacterList → CharacterSelectUI / CharacterCreateUI → C2WSelectCharacter / create
 └─ world entry
     ├─ W2CSpawnPlayer (self) → WorldLoader.RunWhenReady → load main_world (single)
     ├─ W2CEnterWorld → WorldSettings, LocalCharacterState (cached until the HUD exists), Lua UI starts
     ├─ catalogues (skills, statuses, gear, quests...) → client caches
     ├─ W2CMovementConfig → load MovementCollision, configure the local motor → C2WMovementReady
     ├─ WorldStreamer loads tiles around the player; FloatingOrigin keeps them near (0,0,0)
     └─ W2CWorldEntryReady → WorldEntryGate releases input; play

Details: Login & world entry, Client networking, World streaming.

Conventions in the client code#

  • The server decides. The client never changes its own inventory, gold, health or position authoritatively; it sends a request and waits for the server's packet. (The local motor predicts movement, and is corrected.)
  • Handlers run on the main thread (ClientNetwork.Update → PollEvents), so they may touch GameObjects.
  • World-object handlers go through WorldLoader.RunWhenReady so packets that arrive while main_world loads are applied in order afterwards.
  • State caches + events: handlers write into a static state class (LocalCharacterState, CommunityState, ExplorationState, PatronState...) which raises C# events; UI subscribes. State that arrives before the HUD exists isn't lost.
  • World vs local space: everything from the network is in world coordinates; convert with WorldOrigin before writing a transform (World streaming).
  • One writer per transform: for the local player the motor, for everyone else RemoteEntityInterpolator.
  • Namespaces follow the folder (Axiom.Client.Axiom.Client.Scripts.UI...); a few marker components are deliberately in the global namespace so saved scenes keep their links.

Testing with two clients#

ParrelSync (in Plugins) clones the project so you can run two editors against the same server: each logs in with its own account (ClientNetwork ▸ Editor Login, saved per project). Or build the client and run it with -token.
