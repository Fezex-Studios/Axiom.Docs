Axiom Editor Suite#

Everything you use inside Unity to add content to Axiom: items, NPCs, world objects, loot, spawns, terrain, maps, models and animations. All of it lives under one menu, Axiom, and one folder, Assets/AxiomMMOKit/Editor.

This guide is written for someone new to Unity. Read sections 1–3 once; after that, jump to whatever you're doing.

1. First-time setup#

  1. Open the project in Unity 6.3.
  2. Tools > Axiom > Settings… (Dev Tools > Settings). It finds your server repository next to the project and works out every path from it; set Server repository yourself only if it lives somewhere unusual.
  3. Check the two paths that matter (both are worked out for you):
Setting Point it at Why
World database the worldserver.db the server runs on: src/Axiom.Server.World/bin/<Debug or Release>/net10.0/Data/worldserver.db Edits go straight into the database the server loads, so a restart is all it takes to see them
Patches folder src/Axiom.Server.World/SQL/patches Every change is also written here as a numbered .sql patch: the permanent record that goes into git

The Settings page lists every worldserver.db it found, newest first, with a Use button. There are two copies on purpose: Data/worldserver.db is the source that gets copied into bin/ when you build the server; the server runs on the bin/ copy. Pick the bin/ one.

  1. Nothing to set for item names and icons: Dev Tools > Game Data builds gamedata.bin from the world database into StreamingAssets and every built Auth server (and the World server rebuilds it on start).
  2. Go back to Status. Fix anything red or yellow with the button next to it. Green across the board means you're ready.

The settings are saved in ProjectSettings/AxiomDevTools.asset, shared by every tool in the suite.

2. How content gets into the game#

The World server owns all game data: items, NPCs, loot, world objects, quests, spawns. It reads them from its SQLite database, worldserver.db. The Unity client only draws things; it never decides what an item does.

Every tool that changes content works the same way:

 you edit  ──►  Create / Commit / Save
                  │
                  ├─► worldserver.db       (written straight away, in one transaction)
                  └─► SQL/patches/NNN_*.sql (the same change, as a numbered patch)

 restart the World server  ──►  it loads the new content
  • The database edit is what makes it show up on your machine.
  • The patch is what makes it show up everywhere else. Commit it to git with your code. When the server starts, it applies every patch its database hasn't had yet (it keeps a list in the schema_versions table), so a teammate's server, or a fresh one, catches up on its own.
  • Restart the World server after a change. It reads content once, at startup.
  • Items only: run Update Game Data (Hub > Tools, or the Item wizard does it for you) so the client's gamedata.bin knows the new item's name, icon and tooltip.

If the database is locked#

If another program is writing to worldserver.db at the moment you press Create or Save (usually the World server), the Create wizards and the Doodads tab refuse and write nothing. Wait a moment or stop the server, then press the button again. Content Studio instead lets you choose Write patch only: it leaves the database alone and the server applies the patch on its next start.

Why refuse? A patch-only change isn't in the database yet, so the next tool to ask for "the next free id" would hand out the same id again, and the second patch would fail when the server applied it.

Backups#

Before every commit that touches the database, a copy is saved to Library/Axiom/WorldDbBackups/. To roll back, close the server and copy a backup over worldserver.db.

3. The Hub#

Tools > Axiom > Home (Ctrl+Alt+H). The front door. Five pages:

Status#

One line per thing that can be wrong, each with a button that fixes it:

Line What it means
World database / Patches folder the paths are set and the files exist
Database lock whether something has a write lock on the database right now
Patches not applied .sql files in the patches folder that this database hasn't had. Restart the server, or point Settings at the database the server runs
Content Studio unsaved (uncommitted) edits waiting in Content Studio
Client item catalog whether gamedata.bin is older than the database (names or icons may be stale in game). Update now rebuilds it
Model keys NPCs, world objects, mounts etc. whose model key has no prefab in the catalog: they'll be invisible or a placeholder in game
Tile scenes world tiles that aren't in Build Settings (they won't stream in). Add them
Unfinished wizards a Create wizard you started and didn't finish. Continue

Press Refresh after fixing things outside Unity.

Create#

Big buttons for each Create wizard (section 4), and Anything else, which opens Content Studio.

Tools#

Every tool in the suite with one line on what it's for. Faster than hunting through menus.

Settings#

The paths from section 1, the list of databases found, and Find paths automatically.

Guides#

Opens this guide and the others: World Building, Animation, Asset Pipeline, Movement and Camera, Content Studio, Dungeons, Mounts and Pets, and the server's Doodads and Zones docs.

4. Create wizards#

Tools > Axiom > Create > …, or Hub > Create. A wizard walks you through everything a piece of content needs, in one window, and saves it all in one go. Use one whenever you're making something new. Use Content Studio (section 5) for editing what already exists, or for tables no wizard covers.

How every wizard works#

  1. Start. Pick one: - Copy an existing one. Strongly recommended. You get something that already works (stats, abilities, phases, actions), then change what you need. Type in the picker to search by name or id. The suggested starting point is pre-filled. - Start blank. Every field at its default. Not offered for world objects, which have too many moving parts to build from nothing.
  2. Details. The important fields first. Hover any field for an explanation. Everything else is under More fields. Reference fields (a faction, an item, a loot table) have a picker: click it and type.
  3. The extras. Sections specific to the wizard (below): stats, drops, shops, spawners, phases. Each has Add buttons and an ✕ per row.
  4. Finish. - Check runs the same validation as Content Studio on just your new rows and lists any problems (errors in red, warnings in yellow). - Create checks again, then writes everything as one patch named after what you made (for example 061_content_new_npc_frost_wolf.sql) and into the database. - Discard throws the work away. Nothing was written.

Your work is kept. Close the window, close Unity: the wizard reopens where you left off (the Hub shows it under Unfinished wizards). Each wizard keeps its own pending file in Library/Axiom/, separate from Content Studio's, so the two never mix. If Content Studio has unsaved new rows that would take the same ids, Create stops and tells you which; commit or discard them in Content Studio first.

After Create, restart the World server.

Item#

Weapons, armour, potions, materials, quest items.

Section What you set
Details name, description, icon name (the icon file in the client's icon set), category, rarity, required level, bind type, tradeable
Gear stats if it can be worn: the stat block (strength, armour…). One row
On use if it can be used: what it does (heal, buff, place a doodad, learn…), cooldown, whether it's used up
Effects extra effects the item carries
Dropped by which loot tables drop it, with chance and quantity
Sold by which shops sell it, buy and sell price, position in the shop
How it looks for gear: the prefab shown on the character and where it attaches (main hand, back…). Added to the Gear Visual Catalog after Create
Game data Update gamedata.bin after Create (on by default): rebuilds gamedata.bin so the name and icon show in game

NPC#

Monsters, guards, vendors, quest givers. The suggested copy is a basic orc that already fights.

Section What you set
Details name, title, level, rank, faction, health, armour, damage, attack range and speed, aggro radius, AI profile, XP, respawn time, stationary, greeting
Model the model key. Drag an FBX in and it's turned into a world prefab and given a key (see section 7); drag an existing prefab and its catalog key is used
Abilities the skills it uses in combat
Loot Make a loot table for this NPC (its own), or keep the shared one (a warning tells you who else uses it, because changing shared drops changes them for every NPC that uses that table), then add drops
Shop Make it a vendor, then stock it
Spawners where it appears in the world. Add a spawner where the Scene view is looking drops one on the ground at the centre of the Scene view. Move the Scene view, press it again for another

World Object#

Ore veins, herbs, trees to chop, chests, crafting stations, doors. In Axiom these are doodads. Always starts from a copy (suggested: Iron). On start, the copy gets its own actions, so changing what the copy gives never changes the original.

Section What you set
Details name, description, interact range, persistent, scale, health, placement rules
Model as for NPCs
Phases a doodad is a little state machine: Full → Depleted → (timer) → Full. For each phase: its name and model
Actions (per phase) what F / G do on that phase: label, how long it takes, which skill animation plays, which phase it goes to next
Gives (per action) the effects that run when the action finishes: give items, XP, gold…
Timers (per phase) move to another phase after N seconds (regrowth, closing a chest, despawning)
Placement where it spawns. Add one where the Scene view is looking, or place many by clicking with Dev Tools > Doodads afterwards

For how phases, actions and functions work on the server, read DOODADS.md (Hub > Guides).

Loot Table#

A gold range and a list of drops. Chance is per kill: 0.25 means one kill in four, 1 means always. Give it to an NPC… assigns the table (an NPC has exactly one loot table, so this replaces its old one). Used by lists the NPCs that drop it; Take it away unassigns.

Dungeon#

An instanced dungeon, end to end: its run rules (runs per day or week, a time limit, time to loot after the boss, mounts), its region and entry / exit points, its mobs and boss (spawners inside it), an entrance portal in the open world pointed at it, and an exit portal inside. Copying a dungeon moves the copy to the next free region automatically. The full guide is DUNGEONS.md (Hub > Guides > Dungeons).

5. Content Studio#

Tools > Axiom > Content Studio (Ctrl+Alt+E). Every content table in the database as browsable, editable records: the tool for editing what exists, and for everything the wizards don't cover (quests, skills, recipes, factions, mounts, zones' data…).

The short version:

Area Use
Sidebar (left) tables grouped by area, with counts of pending changes
Records (middle) search: plain words, column:text (rarity:epic), column=value (Kind=11), #new / #modified / #error
Inspector (right) the selected record's fields, its child rows (an NPC's abilities, a recipe's ingredients), what refers to it, and previews
Toolbar Go to… (Ctrl+K), Undo (Ctrl+Z), Redo (Ctrl+Y), Validate, Commit (Ctrl+S)

Edits are pending until you commit. They survive closing Unity. Commit shows every change; choose Commit to database + patch (normal) or Write patch only (server running). Duplicate a record with its children from the record menu.

The full guide is Assets/AxiomMMOKit/Editor/ContentStudio/CONTENT_STUDIO.md (Hub > Guides > Content Studio).

6. Dev Tools#

Tools > Axiom > Dev Tools (Shift+Alt+D). Tabs for the world as it sits in the Scene view. The tab bar wraps when the window is narrow; a • after a tab name means unsaved work in that tab. A log at the bottom shows what each action did.

Tab What it's for
🗺 World Map NPC spawners: load them into the scene as markers, move them, add new ones, save back to the database
🪨 Doodads world objects (ore, herbs, chests): place by clicking, move, save. See below
🧱 World Tiles the 512 m tile grid: create tile scenes, export terrain heights to the server, add tiles to Build Settings
🧭 Zones paint zones: names, PvP rules, level ranges
⚑ Spawn Points where players appear and respawn
🔍 Validate spawners and spawn points checked against the database and the terrain (floating, buried, unknown template)
🧩 SQL Patches the patches folder against the database: what's applied, what isn't
📦 Game Data item sync and gamedata.bin build, step by step
🗃 Content Studio a shortcut into Content Studio

Doodads tab, step by step#

  1. Open the tile scene you're working on.
  2. Load into scene. Puts a marker (with a preview of the model) at every saved doodad. Tick Only near the Scene view to load just the area around where you're looking (radius in metres): much faster on a big world.
  3. Place: click an object in the Objects list, press Place in the Scene view, then click on the ground. Every click places one. Random rotation varies the facing; hold Shift to keep the last facing. Esc stops placing.
  4. Move / rotate / scale markers with the normal Unity tools (W, E, R). Only the Y rotation and a uniform scale are saved; scale 1 means "the object's normal size".
  5. Delete a marker (select, Delete key, or ✕ in the list) to remove that spawn.
  6. Save to database. Shows the counts (+new, ~moved, −removed) and writes one patch.

Marker colours: grey = new (not saved), orange = moved or edited, blue = matches the database. Select a marker to see its state in the Inspector.

Safety: a missing marker only deletes a spawn if that spawn was loaded into a scene that's still open. Closing or swapping scenes never reads as "everything was deleted". Clear markers removes the markers from the scene without touching the database. Markers' model previews are never saved into your scene.

7. Asset Pipeline#

Tools > Axiom > Characters & Gear > … Getting art in. The full guide is ASSET_PIPELINE.md; for characters read CHARACTER_ANIMATION_README.md.

Menu What it does

8. Checks#

Tools > Axiom > Validation > Run All Checks runs every check and shows a report: PASS, FAIL (with the reason), or SKIP (needs Play Mode, or must not be in Play Mode). The individual checks are listed under Tools > Axiom > Validation by area (UI, Housing, Furniture, Maps, Shops, Gameplay).

Run them before committing UI or housing work. A new check is picked up automatically (section 12).

10. Recipes#

A new monster with its own drops, placed in the world#

  1. Hub > Create > NPC. Copy Orc (or anything close).
  2. Rename it, set level, health, damage. Drag its FBX onto Model.
  3. Loot: Make a loot table for this NPC, add two or three drops.
  4. Fly the Scene view to where it should live; Add a spawner where the Scene view is looking. Repeat for more.
  5. Check, then Create. Restart the World server. Log in and go there.

A new ore vein that gives a new material#

  1. Hub > Create > Item: "Mithril Ore", category material, no gear stats. Create.
  2. Hub > Create > World Object: copy Iron. Rename to "Mithril Vein", drag in its model.
  3. On the Full phase's action, under Gives, change the item to Mithril Ore. Adjust the respawn timer on Depleted.
  4. Create. Then Dev Tools > Doodads: pick Mithril Vein, Place, click around the mountain, Save to database. Restart the server.

A weapon sold by a vendor#

  1. Hub > Create > Item: name, icon, category weapon, rarity, required level. Gear stats: add the row and fill in damage and stats.
  2. Sold by: add the vendor's shop with a buy price. How it looks: drag in the weapon prefab, attach to main hand.
  3. Create (leave Update game data ticked). Restart the server.

Change something that already exists#

Content Studio (Ctrl+Alt+E) > Ctrl+K > type its name > edit > Ctrl+S. Restart the server.

Bring a teammate's content in#

Pull from git. Restart the World server; it applies the new patches. If items were added, Hub > Tools > Update Game Data.

11. Troubleshooting#

Symptom Fix
"The world database isn't open" Tools > Axiom > Settings…: set the world database. The file must exist
Create says the database is locked the server is writing to it. Wait a few seconds or stop the server, then Create again. Nothing was written
My change isn't in game restart the World server. Check Tools > Axiom > Settings… points at the bin/ database the server runs. For items, Update Game Data
Hub: "patches not applied" the database you're pointed at is behind. Restart the server (it applies them), or pick the database the server runs in Settings
An NPC or object is invisible its model key has no prefab: Hub > Status > model keys, or Art & Assets > Asset Audit. Make a world prefab with that key
New item has no name or icon Update Game Data (Hub > Tools). Check the client item database path in Settings
"Id clash with Content Studio" Content Studio has unsaved new rows with the same ids. Commit or discard them there, then Create again
Doodads tab says spawns will be removed that I didn't delete markers for those spawns are missing from an open scene (deleted, or moved to an unloaded scene). Press Load into scene to bring them back, or Clear markers
A wizard field is missing that column doesn't exist in your database yet: the server patch that adds it hasn't been applied. Restart the server once, then reopen the wizard
Something is wrong after a commit stop the server; copy the newest file from Library/Axiom/WorldDbBackups/ over worldserver.db; delete the patch it wrote
A Dev Tools tab shows an error box press Copy full exception and send it to a programmer; other tabs still work

12. For programmers#

  • One editor assembly. Everything in Assets/AxiomMMOKit/Editor compiles into Assembly-CSharp-Editor; there are no editor asmdefs. New suite code goes in namespace Axiom.EditorTools.* (never a namespace segment called Editor, which clashes with UnityEditor.Editor). Some older tools still use Axiom.Client.Editor.*.
  • Menus. Take every path and priority from AxiomMenu (Core/AxiomMenu.cs) so the menu stays grouped, and add [AxiomTool].
  • Paths and status. AxiomEditor.WorldDbPath, PatchDir, FindDoc/OpenDoc; WorldDbStatus.Get() (cached) and WorldDbStatus.IsLocked(path).
  • A new Create wizard. Subclass CreateWizard (Create/). Give it Id, Title, Blurb, RootTable, DetailColumns; override BuildExtras for sections (helpers: ChildRows, ModelPicker, PlaceButton, AddField, Section, Note), OnStarted to fix up a copy, AfterCommit for follow-ups. It is found automatically and appears in the Create window; add a Hub tile and a menu item in AxiomCreateWindow if you want them. All reads and writes go through ContentSession (S), which is schema-tolerant: a missing table or column is skipped, not an exception.
  • A new Dev Tools tab. Implement IDevToolsTab with a parameterless constructor. Found automatically. DevToolsWindow.OpenTab("name") opens it from anywhere.
  • A new check. A static, parameterless method with [MenuItem("Axiom/Checks/<Area>: <Name>")] that throws on failure. Throw a message containing "Play Mode" if it can't run in the current mode, and the runner reports SKIP.
  • Writing content from code. Never write SQL by hand: build a Changeset through a WorkingSet (RecordOps.NewRow, Insert, SetRow, Delete) and call CommitService.Commit, which writes the database transaction, the numbered patch and the backup together.
