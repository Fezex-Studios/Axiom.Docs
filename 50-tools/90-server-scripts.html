Server Scripts & Command Line#

scripts#

Run these from the scripts folder (double-click works): every path in them is relative (..\src\Servers\…).

File Does Notes
Build.Servers.bat dotnet build -c Debug Auction, Auth, Persistence, World one after the other, then waits for a key
Launch.GameServers.bat opens the four Start.*.Server.bat in their own windows at once starts them simultaneously. The World server calls Persistence's /connect during start-up (PersistenceClient.Start) and fails to boot if Persistence isn't listening yet - start Persistence first, then Auth, then World. The window titles are swapped (the "World" window runs Auction and the "Auction" window runs World)
Start.Persistence.Server.bat, Start.Auth.Server.bat, Start.World.Server.bat, Start.Auction.Server.bat run the built .exe from bin\Debug\net10.0 need a prior build; the working directory is the bin folder, so the appsettings*.json there are used
Client.Launcher.bat starts a built client (..\..\Axiom.Client\bin\…) with -token <guid> a launch token is one-use and lives 120 s, so the hardcoded token can't work; get a fresh one from /login (Login flow)
Build.Docs.bat rebuilds the offline docs site Axiom-Docs/ from docs/ and the source code needs Python 3.10+ with pip install markdown pygments; see How these docs are built
MySQL/migrate_databases_to_axiom.sql renames the old archecore_* databases to axiom_* once, on old installs (MySQL databases)
MySQLServer/main.py (+ PyInstaller main.spec) Windows console to start/stop the LocalMySQLServer service (asks for admin) Windows only; the service name is hardcoded

src/Servers/Axiom.Server.World/WorldServerDevelopmentStart.bat contains PowerShell syntax ($env:DOTNET_ENVIRONMENT = …) - rename it .ps1 or run the two lines in PowerShell. src/Tools/Axiom.LoadTest/Start_Axiom_LoadTest.cmd builds the load tester, runs both self-tests and opens its menu; src/Tools/Axiom.LoadTest/scripts/*.ps1 are its helpers (Run.ps1, Measure-Server.ps1, Read-TickHealth.ps1).

In Unity, Tools ▸ Axiom ▸ Server Control does all of this with logs per server, in dependency order (Persistence → Auth → World → Auction).

A better start script (PowerShell)#

# scripts/Start-All.ps1   -  build once, start in order, Development environment
$ErrorActionPreference = "Stop"
$src = Join-Path $PSScriptRoot "..\src\Servers"
$env:DOTNET_ENVIRONMENT = "Development"
$servers = "Axiom.Server.Persistence", "Axiom.Server.Auth", "Axiom.Server.World", "Axiom.Server.Auction"

foreach ($s in $servers) { dotnet build (Join-Path $src $s) -c Debug --nologo -v q }

foreach ($s in $servers) {
    $dir = Join-Path $src $s
    Start-Process powershell -WorkingDirectory $dir -ArgumentList "-NoExit", "-Command", "dotnet run --no-build"
    Start-Sleep -Seconds 5        # Persistence must be listening before World starts
}

dotnet run from the project folder uses the project folder's appsettings.json, then appsettings.<Environment>.json if present, then appsettings.Local.json (and World.Performance.json for World) (Configuration).

dotnet commands#

# the whole solution
dotnet build AxiomCore.slnx -c Debug          # from the repository root

# run one server (from its project folder)
cd src/Servers/Axiom.Server.World && dotnet run
cd src/Servers/Axiom.Server.Auth  && dotnet run

# Persistence database migrations (MySQL axiom_persistence) - applied by hand
dotnet tool install --global dotnet-ef            # once
cd src/Servers/Axiom.Server.Persistence
dotnet ef migrations add AddBounties               # after changing a model / DbContext
dotnet ef database update                          # apply to the configured database

# publish for deployment (self-contained folder per server)
dotnet publish src/Servers/Axiom.Server.World -c Release -o out/world
dotnet publish src/Servers/Axiom.Server.World -c Release -r linux-x64 --self-contained -o out/world-linux

Auth migrates axiom_auth itself at start-up; Auction creates axiom_auction with EnsureCreated; the World server applies its own SQLite migrations and SQL patches at boot (MySQL databases, worldserver.db).

Command-line tools#

Tool
Axiom.Tools.NavBake bake/verify the navmesh: dotnet run -c Release -- --collision <dir> --out <dir> --verify (NPC navigation)
Axiom.LoadTest headless bots: init, plan, validate, register, run, fleet, compare, aggregate, selftest (Load testing)
Axiom.Tools.ClientPublish axiom-publish: sign a client build and write it as static files for the launcher to download: keygen, publish, verify (Client publish)
Unity batch mode -executeMethod …MovementCollisionExporter.ExportFromCommandLine (Server exports)

Logs#

Each server logs with NLog to the console and to logs/ next to the executable (World: logs/worldserver-<date>.log, configured in nlog.config). The World server prints periodic health lines per subsystem ([AoI], [NavMesh], [MovementInput], [SpawnWork], [CrowdWork], [ParallelStages], [Zones]) and [PersistenceTiming] for every Persistence call - see The World server. The load tester reads the World log (ServerLogPath) for tick evidence.
