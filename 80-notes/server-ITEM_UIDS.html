Server Notes
Feature note, kept next to the code it describes. Source: docs/notes/server/ITEM_UIDS.md

Item uids#

Every piece of gear has a unique 64-bit id. This is the classic per-item id: the thing that lets staff trace a duplicated item, answer "where is that sword now?", and keep an item history.

Where it lives#

ItemInstance.Uid (MessagePack key 6) is the id. ItemInstance already travels with an item everywhere it goes (bag, equipment, warehouse, coffer, mail, trade, auction), so the uid goes everywhere too.

The persistence database stores it as item_uid BIGINT on these tables, each with an index:

  • character_inventory
  • character_equipment
  • character_warehouse_items
  • doodad_storage
  • mail

The auction database stores it on auction_listings and mail_outbox.

Uid is deliberately not part of Equals, GetHashCode or IsPlain. Identity is not a property: stacking, "is this still the item you clicked", and the warehouse's expected-item check behave exactly as before.

Who gets one#

Gear gets a uid. ItemManager.Normalize already makes every non-gear item plain, and a stack of 200 iron ore has no single identity, so stackables keep Uid 0.

When it's assigned#

A gear item gets its uid the first time its holder is saved. ItemUids.Ensure is called in the WriteTo of the inventory, equipment and warehouse components, and for coffer slots in SaveWithStorageAsync.

That is one choke point instead of every place an item can be created (loot, crafting, shops, quests, mail). The id is written back into the in-memory slot, so it is stable from then on.

Rows saved before uids existed get one on their next save.

How ids are made (Core/Items/ItemUids.cs)#

Ids are Snowflake-style, generated with no database round trip:

Bits Content
41 Milliseconds since 2026-01-01 (good until about 2095)
10 Node: World:ItemUidNode, 0-1023
12 Sequence within the millisecond

Every world server running at the same time needs its own ItemUidNode (default 1).

Ids keep increasing even if the system clock steps backwards. More than 4,096 ids in one millisecond borrows the next millisecond.

ItemUids.NodeOf and ItemUids.TimeOf decode an id for audits.

Duplicate detection#

Before a save commits, ItemUidAudit (persistence server) looks for each of the save's uids in two places:

  • elsewhere in the same save;
  • in any other character's bag, equipment or warehouse, or in any other coffer.

Every sighting is logged (ITEM UID SEEN TWICE) and recorded in item_uid_conflicts, with the time.

The audit never blocks the save. Refusing it would lose a player's progress over something staff must look at, not something the save can fix.

Trades go through save-pair, which audits both sides together, so a traded item is not reported. The integration run checks this.

Migration#

Apply the EF migration 20261019120000_ItemUids, or run SQL/item_uids.sql instead (not both).

The auction server adds its columns itself at start-up.

Staff query: where is copy N?#

SELECT 'bag', character_id FROM character_inventory WHERE item_uid = N
UNION ALL SELECT 'worn', character_id FROM character_equipment WHERE item_uid = N
UNION ALL SELECT 'warehouse', character_id FROM character_warehouse_items WHERE item_uid = N
UNION ALL SELECT 'coffer', doodad_id FROM doodad_storage WHERE item_uid = N
UNION ALL SELECT 'mail', character_id FROM mail WHERE item_uid = N;
