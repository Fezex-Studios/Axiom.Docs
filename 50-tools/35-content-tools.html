Tools

Content Tools#

Every tool here checks content against the same rules the World server uses when it loads it. The server skips a bad quest, skill or world event with only a log line, so here those rules are errors, shown before anything is written.

The loop#

edit (wizard / Quest Graph / Skill Lab / Content Studio)
  → Commit (one SQL patch)
  → pushed to the running World server automatically (Content Hot Reload)
  → test it in Play Mode with Live Tools
Tool Menu Shortcut
Push Content to Running Server Tools > Axiom Ctrl+Alt+R
Push Content Automatically After Commit (on by default) Tools > Axiom
Play Mode Live Tools Tools > Axiom Ctrl+Alt+L
Create > Quest… / Skill… / World Event (rift, world boss)… Tools > Axiom > Create
Quest Graph, Skill Lab, World Events Tools > Axiom > Content

The server side, and what does or doesn't reload: Content Hot Reload.

Play Mode Live Tools#

While the game runs in the editor and you're logged in with a staff account (Game Master 4 or Developer 5):

  • push content, and see the last result;
  • Go to Scene view: your character moves to the point the Scene view looks at;
  • heal, revive or level yourself, and clear your cooldowns;
  • reset, kill or despawn your target;
  • search and give items, spawn NPCs at your feet, start world events.

It uses the same GM commands as the in-game staff panel.

Quests#

Create > Quest… builds a quest from start to finish: - Details: the giver and hand-in NPCs. - Dialogue: description, accept and complete text, and the giver's greeting, with a preview of what the player reads. Objective text left empty shows the server's own wording. - Objectives: pick a kind, then its target. "Write objective texts" fills in "Slay 5 Orc Grunts". - Rewards, and its place in a chain.

Quest Graph shows every chain left to right: - Gold arrows are Required Quest; blue arrows are Complete Quest objectives. - Outlines: red means the server would skip the quest, orange means it's in a loop, green means unsaved. - Drag a quest's ● onto another quest to make that one come after it. A loop is refused. - Right-click for New follow-up. - The side panel edits dialogue and objective text with a live preview.

Skills#

Create > Skill… covers targeting, timing, cost and the skill's Effects rows. Its preview works the skill out against an NPC you pick.

Skill Lab is for tuning existing skills: - Edit numbers and effects (damage, heal, apply status) and see the result straight away: per hit, per cast, DPS, damage per mana and time to kill. - Pick the caster as a class at a level (no gear) or type stats in, and pick the target from your NPC templates. - Includes rank, number of area targets, and combo statuses. - A 20-second timeline shows casts, the global cooldown, cooldowns and DoT ticks. - Pin a result to compare before and after.

The numbers use the server's own formulas (CombatMath, StatSheet, status ticks, rank scaling, haste) as averages over miss, glance and crit. Checked against 400,000 rolls of the server's CombatMath.Damage, they agree to within 0.3%; the rest is rounding to whole hits.

World events#

Create > World Event… places a rift or world boss where the Scene view looks and shows: - the next runs in your local time ("make a run start at 20:00" sets the anchor); - each wave's monsters and their total health; - whether a group at a given DPS clears it in time; - clashes with other events in the same place at the same time.

World Events draws every event in the Scene view: its area, the ring its monsters appear on, the boss's spot, and the reward range (twice the radius). Handles move and resize the selected one. It also shows a 24-hour timeline, and Start now in Play Mode.

World events are read when the World server starts, so restart it after a commit.

Editor assembly and tests#

  • Editor/Axiom.Editor.asmdef: the editor code is its own assembly, so editing game scripts no longer recompiles the 30,000 lines of tools.
  • Editor/Tests/ (Axiom.Editor.Tests): needs the Test Framework package, and is skipped without it.
  • Every check under Validation runs as an EditMode test. Play Mode-only checks are reported as Ignored.
  • Tests run the server's rules against your world database, on a temporary copy.
  • Headless: Unity -batchmode -projectPath <project> -runTests -testPlatform EditMode -testResults results.xml Unity -batchmode -nographics -projectPath <project> -logFile - -executeMethod Axiom.EditorTools.Checks.AxiomChecksCommandLine.Run The second form needs no Test Framework package. Its exit code is 0 when everything passes.

The logic (Create/Quests, Create/Skills, Create/Events, Project/ContentPush) is plain C# with no Unity dependency, so it can be tested outside the editor.
