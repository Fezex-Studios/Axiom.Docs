Server Systems

Social: Chat, Parties, Guilds & Friends#

Piece File Job
C2WChatHandler Core/Packets/C2WHandlers/C2WChatHandler.cs Validates and routes chat by channel.
ChatChannel, ChatRules Axiom.Network/Shared Channel numbers; sanitising and link rules (shared).
PartyManager Core/Social/PartyManager.cs Parties and raids, invites, loot rules, kill sharing, party frames. In memory.
GuildManager, GuildStore Core/Social Guilds: a cached copy of what Persistence says.
C2WCommunityHandler, FamilyNameService Core/Packets, Core/Social Friends, blocks, mutes, families (stored in Persistence).

Chat#

ChatMessage (opcode 22) carries Channel, Message, optional TargetName (whispers) and a structured link (label + URL).

# Channel Who hears it
0 Local everyone who can see you (your interest set)
1 Shout everyone within 4 grid cells (~200 m)
2 Whisper one player by name
3 NpcYell server only (boss phase yells)
4 Party your party (in a raid: your group)
5 Raid your raid
6 Guild your guild, anywhere on the shard
7 Zone same zone and layer
8 System server only (notices)
9 Trade same zone and layer; /tr

Every message: muted players (GM) are dropped; control characters and bidi overrides are stripped (ChatRules.Clean, max 200 characters); links must be absolute http(s) without credentials. The client shows player text inside <noparse>, so rich-text tags in a message are harmless.

Before routing, PlayerManager.FireChatEvent gives Lua the message: a registered .command consumes it, and an OnChat hook returning false blocks it:

-- Lua/Server/chat_commands.lua
Server:RegisterCommand("roll", function(player, args)          -- ".roll" in chat
    local n = math.random(1, 100)
    local x, _, z = player:GetPosition()                       -- GetPosition returns x, y, z
    for _, p in ipairs(Server:Players()) do
        if p:DistanceTo(x, z) < 30 then                        -- flat distance in metres
            p:SendMessage(player:GetName() .. " rolls " .. n .. " (1-100).")
        end
    end
end)

Server:On("OnChat", function(player, channel, message)
    if message:lower():find("buy gold") then return false end   -- swallow spam
end)

Client slash commands (ChatUI): /general, /p, /ra, /g, /z, /shout, /tr, /w name, /r.

Parties and raids#

Parties live in memory on the World server (PartyManager); members who disconnect stay for PartyOfflineGraceSeconds so a relog keeps the group.

  • C2WPartyCommand { Action, Name, TargetNetworkId, CharacterId, Value } with PartyAction: Invite, Accept, Decline, Leave, Kick, Promote, ConvertToRaid, SetLootRule, MoveToGroup, SetRole, RadiusInvite.
  • W2CPartyState (the whole party on every change), W2CPartyVitals (health/mana/level/position for party frames, periodically), W2CPartyInvite.
  • Sizes: PartyMaxSize 5; a raid is up to RaidMaxSize 50 (10 groups of 5).
  • Sharing: a kill tagged by a party is shared by members alive and within PartyShareRange (80 m): XP (with PartyXpBonusPct per extra member), quest credit and loot eligibility by the party's loot rule.

Guilds#

Guilds live in Persistence (guilds, guild_members, guild_ranks). The World server keeps a copy of every guild with someone online and changes it only with what Persistence answers: each command is written there first (/guilds/command), and the answer, the guild as it now is, replaces the copy and goes to everyone online in it. Commands for one guild run one at a time, in order.

  • C2WGuildCommand { Action, Name, CharacterId, Rank, Text, Permissions } with GuildAction: Create, Invite, Accept, Decline, Leave, Kick, SetRank, TransferLeader, SetMotd, EditRank, Disband.
  • Ranks 0 (leader) to 4, each with GuildPermission flags: Invite, Kick, SetRanks, EditMotd, UseShop, ActivateBuffs (All). The leader can do everything.
  • Checked twice: permissions here, invariants there (one guild per character, always a leader, rank bounds, GuildMaxMembers 100, GuildNameRules).
  • W2CGuildState, W2CGuildMemberStatus (online/offline/level), W2CGuildInvite, W2CPlayerGuild (the name under a player's name, to everyone who can see them).

Guild and family progression#

Guilds and families level up through missions, which also earn a guild Prestige. Levels unlock perks and buffs for every member; Prestige buys from the guild shop and activates temporary guild buffs. These run on the World server (Core/Social/Missions, Core/Social/Recruitment) and are saved in Persistence's shard_state:

  • Guild & Family Progression: missions, levels, the buffs that grow with level.
  • Guild Recruitment: the Recruit/Search tab, posts and applications.
  • Guild Shop & Prestige: the shop, rank permissions, timed buffs, the guild log.

Friends, blocks and families#

C2WCommunityCommand → /community/command on Persistence (community_contacts, community_families, community_family_members) → W2CCommunityState. Families show a family name line on nameplates (W2CPlayerFamily, via FamilyNameService).

Recipes#

A new chat channel ("Faction")#

  1. Add Faction = 10 to ChatChannel (shared; rebuild DLL, bump protocol).
  2. In C2WChatHandler, add a case that collects peers with the same faction (PvpService.FactionOf(session)) and calls SendToRecipients(...).
  3. Client: a tab/colour and a slash command in ChatUI.

A guild feature (guild bank gold)#

Because guilds are owned by Persistence, add it there first: a column (guilds.bank_gold), a new command in the /guilds/command handler (deposit/withdraw with checks inside the transaction), and the field on the guild DTO. Then in GuildManager add the action, check the rank permission (add a GuildPermission flag), take the gold from the player with a write-through save and send the command; apply the answer. Follow the economy pattern: the gold leaves the player only once the save is confirmed, and the deposit is idempotent by key.
