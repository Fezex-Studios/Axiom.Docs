Data & Databases

Data Overview#

Axiom keeps data in four kinds of store. Knowing which is which answers most "where do I change X?" questions.

Store Format Holds Changed by Read by When it takes effect
worldserver.db SQLite, ~90 tables Game content: items, NPCs, skills, effects, loot, quests, doodads, recipes, shops, dungeons, factions, world events, rules Content Studio, Create wizards, Dev Tools, hand-written SQL patches World server at boot; Content Studio/Dev Tools in the editor World server restart
MySQL axiom_auth MySQL Accounts, password hashes, sessions, refresh tokens, failed logins, bans, access levels Auth server Auth server immediately
MySQL axiom_persistence MySQL Player state: characters, bags, gear, quests, abilities, warehouse, guilds, mail, placed doodads, shard state, outbox, community, cash shop Persistence server (on World's request) Persistence server immediately
MySQL axiom_auction MySQL Auction listings, bids, receipts, mail outbox Auction server Auction server immediately
gamedata.bin encrypted binary (AGDB v4) Client copy of item display data and gear visuals World server at boot (generated) Unity client; served by Auth next client start
World files binary/JSON files in the World's Data/ Terrain heightmaps, movement collision, zone map, navmesh, NPC collision shapes, housing outlines Unity editor exports, NavBake World server (and the client's copies) World restart (client rebuild for its copies)
Configuration appsettings*.json Ports, URLs, secrets, tick rate, performance budgets, feature switches you each server at start restart
Unity assets prefabs, scenes, materials, ScriptableObjects Art, UI, world scenes, prefab catalogues artists, editor tools client client build

How they relate#

Content Studio ─────┤                                                        ▼
Create wizards      └─▶ worldserver.db ──(boot)──▶ World server ──▶ ClientContentExporter
Dev Tools                    │                         │                    │
                             │                         │              gamedata.bin ──▶ client StreamingAssets
                             │                         │                    └────────▶ Auth /gamedata/db ──▶ client cache
                             │                         │
                             │          catalogue packets on world entry (skills, statuses, gear, quests,
                             │          shops, recipes...) ──▶ client memory
                             │
Unity scenes ──export──▶ Data/world_collision, terrain_data, world/zones.aczmap, navmesh, npc_collision.json
                         (+ client copies in StreamingAssets/World)

World server ──HTTP──▶ Persistence ──▶ axiom_persistence     (player state)
World server ──HTTP──▶ Auction     ──▶ axiom_auction
Client/World ──HTTP──▶ Auth        ──▶ axiom_auth

Content reaches the client two ways#

  1. gamedata.bin: item names, descriptions, icons, categories, rarities, required level, usable flags, and gear visuals (which prefab each item shows on the body, where it attaches, which body parts it hides). These are needed before entering the world (character creation preview, inventory tooltips) and are large, so they ship as a file.
  2. Catalogue packets on world entry: the skill catalogue, status catalogue, item gear catalogue (stats, grades, gems, upgrade materials), quest catalogue, crafting catalogue, trade catalogue, exploration catalogue, achievement catalogue, shop lists. They're built from worldserver.db at boot, cached pre-encoded, and sent on the Bulk channel.

So adding a skill needs no client change: it arrives in the skill catalogue. Adding an item needs a World restart (to rebuild gamedata.bin) and the client to pick up the new file (from StreamingAssets in a build, or downloaded from Auth).

Rules of thumb#

  • Content → worldserver.db, via Content Studio or a SQL patch. Never hard-code item ids, numbers or names in C#.
  • Player progress → a Persistence table, saved as part of the character snapshot (Persistence flow).
  • World geometry → a Unity scene, then export (World files).
  • Per-machine settings and secrets → appsettings.Local.json (git-ignored).
  • Server tuning → appsettings.json / World.Performance.json.
  • Combat formula numbers → the CombatRules table, not constants.
