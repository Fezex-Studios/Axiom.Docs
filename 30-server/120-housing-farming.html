Server Systems

Housing, Farming & Furniture#

Housing in Axiom is built on the doodad system: a house (or scarecrow farm) is a persistent doodad whose template's PlaceRule is House. Building it, taxing it and demolishing it are its phases and timers; housing only adds the rules doodads don't know (where, who, access).

Piece File Job
HousingService Core/Housing/HousingService.cs Where houses may stand, who may use what, access settings, cleanup when a house goes.
HousingPlacementWorkflow Core/Housing Preview tickets: show a ghost house, validate, confirm. Previews never spend anything.
HousePartService Core/Housing Bound house parts (door, windows, vines, lift) and server-driven climbing.
FurnitureService Core/Furniture Sitting, playing, lighting the fireplace: furniture actions and occupancy.
StorageService Core/Housing/StorageService.cs Coffers (and vehicle cargo).
shared rules Axiom.Network/Shared/Housing, Shared/Furniture Geometry, attachment layouts, placard reach, furniture definitions: the same code checks on client (preview) and server.

The life of a house#

design item ── Place Doodad (preview → confirm) ──▶ [Foundation] ── Build (materials, labor, Carpentry) ──▶ … ──▶ [Standing]
                                                                                                             │ timer = tax period
                                                         demolished ◀── timer (grace) ── [Taxes Due] ◀───────┘
                                                                                  └── Pay taxes (Take Gold) ──▶ [Standing]
  1. Place: using a design item runs a Place Doodad effect. The client shows a preview (HousingProtocol.Request/Response, feature opcodes 200/201); the server validates and issues a ticket; confirming spends the item and places the doodad (save first, doodad row second; see Doodads).
  2. Build: each construction phase offers a Build action that costs materials, labor and Carpentry proficiency and moves to the next phase.
  3. Standing: the phase timer is the tax period. When it ends → Taxes Due; Pay Taxes (a Take Gold effect) goes back to Standing; the grace timer running out demolishes the house.
  4. Gone: a removed house takes its furniture out of the world; Persistence deletes their rows with it and mails any coffer contents to their owners. Timers keep running while the server is down, so a house whose taxes lapsed during downtime is gone when it comes back.

Where#

  • Only inside a housing area: HousingAreas rows (rectangles) plus the polygon outlines in Data/housing/zones.json exported from Unity (Tools ▸ Axiom ▸ World ▸ Housing: Create Zone Outline, Export Loaded Zone Outlines).
  • A house's whole land must be inside the area and off any other house's land. HouseMaxPerCharacter (2) per character.
  • Plants and furniture only on land you own, their full footprint inside it. Furniture is the house's child (ParentDoodadId).

Who: access#

Doodad actions carry an Access: Owner, House (the owner, or whoever the house's access setting lets in), or Theft (anyone, except on house land where House rules apply). The owner cycles private → guild → public with the House Access effect (from the placard's house menu: HouseMenuProtocol 204/205: open, set access, pay taxes, demolish, furniture pickup lock). It's saved with the house.

House parts and climbing#

A cottage's door, windows, vines and lift are bound parts: persistent doodads attached at fixed positions from the house's pivot (HouseAttachmentLayout, shared). Climbing vines or riding the lift is server-driven traversal (HouseTraversalProtocol 202/203): the player becomes managed, the server moves them along the route, and their own inputs are ignored until it ends (Movement).

Furniture#

Furniture templates have PlaceRule = Furniture. FurnitureService handles using them (sit in a chair, play the piano, light the fireplace): FurnitureProtocol.Request/Frame (206/207), occupancy (one sitter per seat), viewer-specific actions. Behaviours are bound to interaction skills (FurnitureInteractionSkills). Owners can lock furniture against pickup. Starter furniture prefabs: Tools ▸ Axiom ▸ World ▸ Furniture ▸ Build and Install Starter Furniture.

Coffers are furniture with storage: contents in Persistence doodad_storage, moved in one transaction with the character save (Items). Soulbound items can't be stored.

Farming#

Crops are persistent PlaceRule = Plant doodads (seeds are items whose use is a Place Doodad effect), planted only on your own land (house plot or scarecrow farm). Growth phases depend on climate (Doodads); an unharvested crop goes overripe and withers; harvesting rolls a loot table. Harvesting someone else's crop is theft.

A new piece of furniture (a bookshelf)#

-- SQL/patches/128_bookshelf.sql
INSERT OR REPLACE INTO DoodadTemplates (Id, Name, Description, ModelType, InteractRange, StartPhaseId, IsPersistent, PlaceRadius, Scale, PlaceRule, LandRadius, BrokenPhaseId, MaxHealth, SiegeRole, SiegeRing, ClimateId, BlockWidth, BlockDepth, BlockHeight)
VALUES (2710, 'Oak Bookshelf', 'Holds more books than you''ll read.', 'FurnitureBookshelf', 3, 27101, 1, 1.2, 1, 2, 0, 0, 0, 0, 0, 0, 1.2, 0.4, 2.0);
INSERT OR REPLACE INTO DoodadPhases (Id, TemplateId, Name, Visual, Blocks) VALUES (27101, 2710, 'Placed', 'placed', 1);

-- the item that places it: Place Doodad 2710
INSERT OR REPLACE INTO Items (item_id, name, description, icon_name, category_id, rarity_id, required_level, bind_type, no_trade, max_stack, vendor_price)
VALUES (6400, 'Oak Bookshelf', 'Place it in your house.', 'Items/furniture_bookshelf', 4, 2, 1, 0, 0, 1, 1500);
INSERT OR REPLACE INTO ItemUses (Id, ItemId, ConsumeOnUse, EffectType, EffectValue, CooldownMs, CooldownGroup, CastTimeMs, LaborCost)
VALUES (6400, 6400, 1, 0, 0, 0, 0, 0, 0);
INSERT OR REPLACE INTO Effects (Id, OwnerType, OwnerId, Sort, Kind, Target, Min, Max, RefId, DurationMs) VALUES (9400, 1, 6400, 0, 12, 0, 0, 0, 2710, 0);

Add a "Pick Up" action (an ActionType 12 DoodadFuncs row with OwnerOnly, NextPhaseId -1 and a Give Item effect returning item 6400) so owners can take it back, the FurnitureBookshelf prefab to the client's world prefab catalogue, and a recipe at the Carpenter's Bench.

A new house type#

Copy the Cottage (template 130) in Content Studio with Duplicate + children (Ctrl+Shift+D): it copies phases, build actions, tax timers and their effects, re-pointing every reference at the copies. Change the model keys and costs, add a design item with a Place Doodad effect, and (if it has parts) an attachment layout in Shared/Housing/HouseAttachmentLayout.cs (shared code: rebuild the DLL).
