Art & Assets#

Art lives in Assets/AxiomMMOKit/Axiom.Client/Art (AxiomAssetPaths.Art). It is large (about 460 MB, 4 000 files in the current snapshot), so it's often kept and shipped separately from the code - it must be put back at exactly that path before opening the project, or every prefab reference and Resources.Load breaks.

What's in it#

Folder Size Contents
Enviroment/ (sic) ~337 MB environment kits: Fantasy props, Medieval village, grass, trees
Animations/ ~49 MB CharacterAnims clips; Controllers/ holds generated Animator controllers
Textures/ ~55 MB terrain texture sets (dry-dirt2, patchy-meadow1)
Terrain/Layers TerrainLayer assets for the terrain painter
Gear/Outfits imported outfit packs (Gear Workshop)
Objects/ game-ready world prefabs made by the prefab maker, one folder per kind
Resources/ ~19 MB everything loaded by key at runtime (below)

Resources/:

Path
Characters/CharacterPipeline.asset sockets, part rules, bone aliases (Characters)
World/WorldObjectPrefabs.asset model key → prefab for everything spawned from the server
World/TileProxies.asset, World/Proxies/ HLOD
Gear/Prefabs/ gear prefabs referenced by GearVisuals.PrefabKey
World/GearVisuals.asset legacy import source for gear looks (runtime uses the database)
Icons/ (Actions, Gear, Skills, Status, Imported, loose) icons by name (Icons)
Cursors/ attack, interact, loot, talk
UI/ theme (AxiomTheme.tss, AxiomBase.uss, AxiomSkin.uss), 9-slice art, chat/selection sheets, IconAliases.json, LuaUiScripts.asset
Settings/CrowdSettings.json crowd budgets

Enviroment is misspelled; rename it inside Unity (Project window) if you want - Unity keeps GUID references, and nothing loads it by path.

Import rules: the folder decides#

AxiomArtImporter applies import settings by folder under Art/, only on an asset's first import (hand-tuned settings are never overwritten):

Folder Import
Characters/ Humanoid, avatar from the model, no clips
Animations/ Humanoid, clips only; loops if the name contains Idle, Walk, Run, Swim, Loop, Cycle
Gear/Skinned/ Generic rig kept (bones re-pointed by name at runtime)
Gear/ static weapons, shields
Mounts/ Generic rig, clips allowed
Creatures/ Generic rig (Creatures/Humanoid/ → Humanoid)
Housing/, Dungeons/ static, lightmap UVs, mesh colliders
Vehicles/ static, no colliders (the prefab root's collider is the body)
Props/, Doodads/, Nature/ static, no colliders
FX/ static, no colliders, no lightmap UVs

Textures anywhere under Art/: *_N / *_Normal → normal map; *_M, *_Mask, *_ORM, *_Rough, *_AO → linear. UI art in Resources/UI/Art gets no mipmaps, no compression, clamped (UiArtImporter).

From a model to something in the world#

  1. Drop the FBX in the right Art/ folder (e.g. Art/Creatures/Wolf.fbx).
  2. Select it, Tools ▸ Axiom ▸ Art & Assets ▸ Make World Prefab From Selected Model. It creates Art/Objects/<folder>/<Key>.prefab with the root at the model's base centre, and per folder: Characters get CharacterSockets; Creatures get a click capsule on the NPC layer, root motion off; Mounts get a RiderSeat (then Create Mount Animator Controller); Vehicles get Seat1..2 + a box collider; LOD children (*_LOD0..n) get a LODGroup; everything else a box collider for the interact ray.
  3. It registers the prefab in WorldObjectPrefabs under the key = file name (Wolf). If the key is already in the catalog, the prefab is still made but the entry keeps its old prefab: drag the new one onto it.
  4. Use the key in data: NpcTemplates.ModelType = "Wolf", DoodadTemplates.ModelType, Mounts.ModelType, TradePacks.ModelType...
  5. Tools ▸ Axiom ▸ Art & Assets ▸ Asset Audit lists every model key the database uses that has no prefab, every wearable item without a look, and import problems, with fixes.

Until a prefab exists, the game shows a placeholder, so designers and artists don't block each other.

Characters and animation#

  • Tools ▸ Axiom ▸ Characters & Gear ▸ Characters and Races (Dev Tools tab): bodies per race/gender, sockets, part splitting, preview.
  • Gear Workshop: fit weapons and armour on any body live in the Scene, then save offsets to the database.
  • Import Outfit Pack…: bring in a modular outfit set.
  • Animation ▸ Create Character Animator Controller: builds a controller with every parameter CharacterAnimator drives, wired to your clips; Upgrade Selected Animator Controller adds missing parameters to an existing one.
  • Run Gear Binding Checks / Check and Export Gear Visuals.

Guides: Adding animations, Bring your own characters, Asset pipeline (note).

Terrain textures and Python helpers#

Terrain layers live in Art/Terrain/Layers. HDRP terrain wants a mask map (metallic, AO, height, smoothness packed into RGBA); Tools ▸ Axiom ▸ Art & Assets ▸ Python ▸ Pack Terrain Mask Maps runs a script from <project>/Tools/Python (outside Assets, so Unity doesn't import it) to build them. It needs Python 3 on the PATH (python, py or python3). Open Scripts Folder opens that folder.

Keeping art out of the way#

Professional teams don't keep hundreds of MB of binaries in a plain Git repository:

  • Git LFS for *.fbx, *.png, *.tga, *.psd, *.wav, *.exr, *.asset (large ones) in the client repository, with a .gitattributes; or
  • a separate art repository checked out to Assets/AxiomMMOKit/Axiom.Client/Art (submodule, or a sync script); or
  • Unity Version Control (Plastic) for the whole client, which handles binaries and locking natively.

Whichever you choose, keep the .meta files with their assets (they hold the GUIDs every prefab and scene references), use Force Text serialization and Visible Meta Files (Project Settings ▸ Editor), and lock binary files that two people might edit.
