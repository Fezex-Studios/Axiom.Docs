Configuration Reference#

Every option class the servers bind from configuration, with defaults and descriptions, then the shipped settings files with secrets replaced by <secret>. Values come from appsettings.json, then appsettings.{Environment}.json, then your git-ignored appsettings.Local.json, then environment variables (World__TickRate=30). Guide: Configuration.

Option classes#

AuthServerConfig#

Section Auth · Axiom.Server.Auth · Servers/Axiom.Server.Auth/Config/AuthServerConfig.cs

Replaces ServerConfig.ts and the .env file it read. The old server pulled AUTH_DATABASE_PATH, GAME_DATABASE_PATH and INTERNAL_SECRET out of process.env via dotenv, which meant the auth server's configuration lived in a different place, a different format, and a different editor from the other two servers. It's all appsettings.json now, same as World and Persistence. Environment variables still work and still win, which is what you want for deployment: ASP.NET Core's default configuration chain reads appsettings.json, then appsettings.{Environment}.json, then environment variables. So Auth__InternalSecret=... in the environment overrides the file without editing it. (Double underscore is the separator for nested keys.) The database connection is NOT here — it lives under ConnectionStrings with the name "Auth", matching how the persistence server does it.

Key Type Default Description
GameDataPath string "gamedata.bin" Path to the encrypted client game data blob served by /gamedata/db. Was GAME_DATABASE_PATH. The route never inspects the file's format, so this can point at gamedata.bin or gamedata.db equally.
InternalSecret string (set in appsettings.Local.json) Shared with the WorldServer ONLY. Must match World:InternalSecret in the world server's appsettings.json and InternalSecret in the persistence server's. Never sent to a client.
MaxLoginAttempts int 5 Failed logins allowed from ONE address before that username is locked for that address (LoginThrottle). The owner logging in from elsewhere is unaffected.
LockoutMinutes int 15 How long a lockout lasts.
AccountLockAttempts int 50 Failed logins from ALL addresses together before the account itself is locked everywhere. The backstop against one account being guessed at from many machines; high enough that nobody can lock someone else out casually.
TrustForwardedFor bool false Believe the X-Forwarded-For header for the client's address. ONLY turn this on when Auth sits behind a reverse proxy (nginx, Caddy) that sets it - otherwise any client can type a fake address into the header and walk around every per-IP limit.
TrustedProxies string[] Array.Empty<string>() Proxies on OTHER machines whose X-Forwarded-For / X-Forwarded-Proto are believed (addresses or networks, e.g. "10.0.0.5" or "10.0.0.0/24"). This machine (loopback) is always trusted, which covers Caddy or nginx on the same box. Only used with TrustForwardedFor.
RequireHttps bool true Refuse plain HTTP from other machines (HttpsGuard). This machine is always allowed. Leave on for anything players reach over the internet.
PlainHttpAllowedNetworks string[] Array.Empty<string>() Machines allowed to use plain HTTP anyway while RequireHttps is on: addresses, networks, or "private" (10/8, 172.16/12, 192.168/16, fc00::/7, fe80::/10) for testing with friends on one LAN. Not for a public server.
SessionLifetimeHours int 24 Unused. Every token Auth hands out is a one-use launch ticket that lives LaunchTokenSeconds and is deleted when a World server redeems it. Kept so an old appsettings file still binds.
LaunchTokenSeconds int 120 How long a one-shot LAUNCH token lives (launcher L3). It is passed to the game on the command line, where other local processes can read it, so it should be dead within a couple of minutes whether or not the world server burned it. Replaces SessionLifetimeHours for launch tokens; that setting is now unused.
RefreshTokenDays int 30 How long a refresh token (what the launcher keeps instead of the password) lives without being used. Every use replaces it with a new one, so an active player never hits this.

NpcGroundSnap bool true NPCs follow the terrain height while they walk, where terrain data exists. Off keeps the old behaviour (NPCs keep the Y they spawned at), for debugging.
ZoneMapPath String "Data/world/zones.aczmap" The shard's zone map (*.aczmap), painted and saved by Dev Tools > Zones: which zone every point of the world is in, plus each zone's name, level range and PvP mode. The client ships its own copy in StreamingAssets; the two are compared by hash on entering the world. Missing is fine - the whole shard is simply "no zone".
InstanceThreads bool true Every dungeon instance runs its script, bosses and clock on its own tick thread (Docs/INSTANCE_ZONES.md), so one slow dungeon script never stalls the open world. False runs them inline on the world tick, the old way - a fallback switch, and what tests use.
InstanceTickRate int 20 Each instance zone thread's rate (Hz). Events (a boss died) are handled at once regardless.
InstanceAiBudgetMs double 3.0 Milliseconds of each world tick that dungeon NPCs (AI, movement, attacks) may use (Docs/INSTANCE_ZONES.md, "Dungeon AI budget"). Open-world NPCs run first, in full; dungeons past the budget run next tick. 0 = no limit (the old behaviour).
InstanceViewIntervalMs int 250 How often a zone whose script watches health, combat or rooms is sent a fresh view (ms).
InstanceCommandBudgetMs double 2.0 World-tick time spent applying zone commands each tick (ms); the rest wait a tick.
NavMeshEnabled bool true NPCs walk on the navmesh (Docs/NAVMESH.md): paths around walls, up stairs, through dungeons. Baked by Axiom.Tools.NavBake (or Unity Dev Tools > NavMesh) from the movement collision export into NavMeshDirectory/<profile>. No navmesh there = straight lines, as before.

PreloadAllNavMesh bool false Load every page at boot (small worlds, profiling). Default: on demand.
NpcUnreachableEvadeSeconds int 6 An NPC whose target the navmesh can't reach gives up (evades home) after this long. 0 = never.
