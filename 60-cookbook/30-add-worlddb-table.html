Cookbook (How-To)

Add a worldserver.db Table#

Add a server system gave one reward from three CombatRules numbers. Designers want a schedule instead: 30 min → a potion, 60 min → a box, 120 min → a mount whistle. That's a content table.

Background: worldserver.db (schema vs content streams, patches, migrations).

1. The migration (schema)#

World migrations are hand-written, idempotent SQL in src/Servers/Axiom.Server.World/Migrations/, named with a timestamp so they sort in time order.

Migrations/20261027120000_PlaytimeRewards.cs:

using Axiom.Server.World.Utils.Database.SQLite;
using Microsoft.EntityFrameworkCore.Infrastructure;
using Microsoft.EntityFrameworkCore.Migrations;

#nullable disable
namespace Axiom.Server.World.Migrations;

/// <summary>
/// Playtime rewards (27 Oct 2026): what a character receives after N minutes online in one login.
///   Minutes   when (unique)       ItemId / Count  what       Message  shown in system chat ('' = default)
/// </summary>
[DbContext(typeof(WorldDataDbContext))]
[Migration("20261027120000_PlaytimeRewards")]
public partial class PlaytimeRewards : Migration
{
    protected override void Up(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.Sql(@"
CREATE TABLE IF NOT EXISTS ""PlaytimeRewards"" (
    ""Id""      INTEGER NOT NULL CONSTRAINT ""PK_PlaytimeRewards"" PRIMARY KEY,
    ""Minutes"" INTEGER NOT NULL,
    ""ItemId""  INTEGER NOT NULL,
    ""Count""   INTEGER NOT NULL DEFAULT 1,
    ""Message"" TEXT    NOT NULL DEFAULT '',
    CONSTRAINT ""CK_PlaytimeRewards_Minutes"" CHECK (Minutes > 0),
    CONSTRAINT ""CK_PlaytimeRewards_Count""   CHECK (Count BETWEEN 1 AND 1000)
);
CREATE UNIQUE INDEX IF NOT EXISTS ""IX_PlaytimeRewards_Minutes"" ON ""PlaytimeRewards"" (""Minutes"");
");
    }

    protected override void Down(MigrationBuilder migrationBuilder) =>
        migrationBuilder.Sql(@"DROP TABLE IF EXISTS ""PlaytimeRewards"";");
}

Rules:

  • CREATE TABLE IF NOT EXISTS / CREATE INDEX IF NOT EXISTS: safe on a database that already has it.
  • Put constraints in the table (CHECK, UNIQUE); the database refusing bad rows beats a server that half-loads them.
  • Changing an existing table: ALTER TABLE "X" ADD COLUMN "Y" INTEGER NOT NULL DEFAULT 0; - SQLite can't drop or retype columns in place; for that, create a new table, copy, drop, rename (in one migration).
  • Seed a few example rows with INSERT OR IGNORE if the feature needs them to work out of the box; real content goes in patches (step 4).
  • Don't use dotnet ef migrations add for the World database: migrations are hand-written, and the model snapshot isn't the source of truth.

Applied automatically at the next World start (MigrateAsync, boot step 0b), recorded in __EFMigrationsHistory.

2. Entity and DbSet#

GameData/Playtime/PlaytimeReward.cs:

namespace Axiom.Server.World.GameData.Playtime;

/// <summary>One row of PlaytimeRewards.</summary>
public class PlaytimeReward
{
    public int    Id      { get; set; }
    public int    Minutes { get; set; }
    public int    ItemId  { get; set; }
    public int    Count   { get; set; }
    public string Message { get; set; } = "";
}

Utils/Database/SQLite/WorldDataDbContext.cs - next to the other sets (the property name is the table name):

    public DbSet<PlaytimeReward> PlaytimeRewards => Set<PlaytimeReward>();

Constraints that EF should know about (indexes, check constraints, relationships) go in OnModelCreating, as GearVisualDefinition does; for a simple table the property is enough.

3. Load and validate at boot#

Catalogues are read once at start-up and kept in memory (a content change needs a restart). Validate every row the way ShopManager.LoadFromDatabase does: skip bad rows with a warning, never crash, never half-apply.

// in PlaytimeRewardService
private readonly IDbContextFactory<WorldDataDbContext> _dbFactory;
private readonly SortedDictionary<int, PlaytimeReward> _schedule = new();   // minutes -> reward

public PlaytimeRewardService(IDbContextFactory<WorldDataDbContext> dbFactory) => _dbFactory = dbFactory;

public void LoadFromDatabase()
{
    _schedule.Clear();
    using var db = _dbFactory.CreateDbContext();
    foreach (var row in db.PlaytimeRewards.AsNoTracking().OrderBy(r => r.Minutes))
    {
        if (!_items.Exists(row.ItemId) || row.Count <= 0 || row.Minutes <= 0)
        { Logger.Warn("[Playtime] Row {Id} invalid (item {Item}, count {Count}, minutes {Min}) - skipped.", row.Id, row.ItemId, row.Count, row.Minutes); continue; }
        _schedule[row.Minutes] = row;
    }
    Logger.Info("[Playtime] {Count} reward(s) loaded.", _schedule.Count);
}

// in Sweep(): instead of "minutes % every == 0"
if (_schedule.TryGetValue(minutes, out var reward) && _players.TryAddItem(peer, reward.ItemId, reward.Count))
    Tell(peer, reward.Message.Length > 0 ? reward.Message : $"{minutes} minutes online - here's a reward!");

Construct it with the factory in WorldServer (the factory is available there, as for the other managers), and call _playtime.LoadFromDatabase() in step 3b, after _itemManager.LoadFromDatabase() because it checks item ids.

4. Content as a SQL patch#

SQL/patches/NNN_playtime_rewards.sql (the next free number):

-- Playtime rewards: needs migration 20261027120000_PlaytimeRewards and the items below.
INSERT OR REPLACE INTO PlaytimeRewards (Id, Minutes, ItemId, Count, Message) VALUES
    (1,  30,     4, 3, 'Half an hour already! Have some potions.'),   -- Minor Health Potion
    (2,  60, 90301, 1, ''),                                            -- Starter Supply Box
    (3, 120,    73, 1, 'Two hours! This whistle calls a donkey.');    -- Pack Donkey Whistle

Patches run in name order at boot, each once (tracked in schema_versions), in a transaction; a failing patch stops the server. (Ids from the shipped database; check yours.) Or skip writing SQL by hand: add the rows in Content Studio (step 5), which writes the patch for you.

5. Teach Content Studio#

The table appears under Other Tables automatically. Annotate it in Assets/AxiomMMOKit/Editor/ContentStudio/Schema/ContentSchema.Definitions.cs, inside the right Category(...):

            T("PlaytimeRewards", "Playtime Rewards", "Playtime Reward")
                .Name("Message")
                .Ref("ItemId", "Items", true)
                .List("Id", "Minutes", "ItemId", "Count");

Now designers get an item picker, validation of missing items, and the "Where used" panel on items shows playtime rewards. A domain rule (e.g. "Minutes must be unique") goes in Validation/ContentValidator.cs.

6. Does the client need it?#

  • Only the server uses it → done.
  • The client must show it (a "next reward in 12 min" widget) → send it: a small catalogue packet on entering the world, or a field in an existing packet (Add a packet).
  • Needed before entering the world (character creation) → gamedata.bin (extending the package).

Checklist#
Migration Migrations/<timestamp>_<Name>.cs, idempotent schema
Entity in GameData/... + DbSet in WorldDataDbContext mapping
Loader with validation, called in boot step 3b in dependency order runtime
SQL patch with content (or Content Studio) content
Content Studio annotation (T(...)) and rules tooling
Client delivery, if the client needs it packets / gamedata
Restart the World server; read the [Playtime] lines verify
