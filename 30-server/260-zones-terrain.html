World Grid, Zones & Terrain#

Piece File Job
WorldGrid Axiom.Movement/World/WorldGrid.cs (shared) Integer tiles of 512 m; scene names tile_X_Z.
ZoneMap Axiom.Movement/World/ZoneMap.cs (shared) Zones, PvP modes, painted cells, the .aczmap format.
ZoneService Core/World/ZoneService.cs Which zone each point is in; zone lookups for every system.
WorldTerrainService Core/World/WorldTerrainService.cs Terrain height queries (exported collision + heightmaps), idle unload.
TiledHeightField, HeightmapData Axiom.Movement/Terrain Heightmaps indexed by tile, loaded on demand.
ZoneStateService Core/Pvp/ZoneStateService.cs The PvP mode in force now (zone + festival + siege).

The grid#

The world is unbounded and sparse: tile (0,0) covers x, z in [0, 512), tile (-1,0) covers [-512, 0). An ocean with nothing in it costs nothing. The client streams tile scenes around the player; the server streams collision, heightmaps and navmesh pages around wherever players and NPCs are. Dungeons are tiles in a far-away region (around 16 384).

Zones#

A zone is a named region painted onto the map in cells (Dev Tools ▸ Zones):

Field
Id 1–65535 (0 = unpainted)
Key stable identifier for code, data and Lua (sunreach, greywatch_1). Lowercase, no spaces, never shown to players. Never rename once content uses it.
DisplayName, Subtitle the banner players see
PvpMode Safe, Peaceful, Contested, War
MinLevel, MaxLevel display
ColorRgba editor colour

ZoneService loads World:ZoneMapPath at boot. Who uses it:

  • PlayerManager tracks each player's ZoneId on every accepted move and fires OnEnterZone (Lua, quests' area/zone objectives, achievements' Enter Zone).
  • Combat/PvP rules (ZoneStateService, PvpService).
  • Zone and Trade chat channels.
  • Data that refers to zones by key: ZoneClimates, Territories, ZoneFestivals, QuestObjectives.TargetKey (Kill In Zone).
  • W2CEnterWorld sends the map's hash; the client warns if its copy differs.

No zone map file is a supported state: everything is zone 0 and the whole shard is one zone.

Terrain on the server#

WorldTerrainService answers "where is the ground at (x, z)?" for NPC ground snapping, spawn placement, teleports with y = 0, digging treasure and line of sight (LineOfSight marches the line in 1 m steps against the heightfield: a hill blocks a cast). Since protocol 32 it uses the exported movement collision where available and never overlays a legacy heightmap across a terrain hole. Heightmaps (Data/terrain_data/*.achtmap) are indexed by their 32-byte headers at boot and loaded on first use; idle ones unload after TerrainIdleUnloadMinutes.

"No ground data here" is a normal answer (open water, an unexported tile, an interior): callers treat it as "can't validate", never as height 0.

Recipes#

A new zone#

  1. Unity: Dev Tools ▸ Zones: add a zone (key, names, PvP mode, levels, colour), paint it, Save (client + server).
  2. Data that hangs off the key: ZoneClimates (crops), a Territories row (sieges), ZoneFestivals, quest areas.
  3. Optional Lua:

lua Server:On("OnEnterZone", function(player, zoneId, zoneKey, previousZoneId) if zoneKey == "crimson_marsh" and player:GetLevel() < 20 then player:SendAnnouncementMessage("The marsh is deadly below level 20.") end end)

  1. Restart the World server.

A new region of the world#

Build tile scenes (tile_X_Z) in Unity with terrain, then: export heightmaps, export movement collision, paint zones, bake the navmesh for it, place spawners and doodads, add respawn points (SpawnPointTables), regenerate the map atlas. The full checklist is in Add a zone or region and World files.
