Patron, Loyalty Tokens and the new character select#

18 Oct 2026, protocol 38. Code: Core/Patron/ (world), PatronComponent, Axiom.Server.Persistence (account_patron), client Scripts/Gameplay/Patron, Scripts/UI/Patron, Scripts/UI/CharacterSelectUI.cs.

What a player sees#

  • Character select is classic MMO-style:
  • The selected character stands in the middle of the screen. It uses the real body prefab (Character_Faction{N} or Character_Default), playing its idle, and wears its equipment (the same GearVisualCatalog rows as in the world). Drag to turn it.
  • Left: level and class, name, coins, faction, location (the zone they logged out in).
  • Right: the roster. Top centre: Patron (time left), Labor (3,450 / 4,000 (2,000 + 2,000) while a Patron) and Loyalty Token count.
  • Bottom: Exit / Select Server / Options / Create Character, and Start Game.
  • In the world: a Patron button sits bottom-left, above the chat.
  • It counts down to the next Loyalty Token claim and glows gold when one is ready. Left-click claims it.
  • Right-click opens the Loyalty Exchange (shop 90020).
  • The tooltip shows the time left, the perks, the next claim and the token balance.
  • The Patron status icon shows in the buff row.

Rules#
Patron An ACCOUNT subscription: an end date. Every character of the account shares it, like labor.
Getting it A Patron Pass (items 90010/90011/90012: 30/90/365 days). The cash shop sells them for credits, and they're giftable. Using one adds its days to the end date, or to now if it already ended, so unused time is never lost. GMs: GrantPatron (Developer, level 5; days can be negative).
Perks (CombatRules) PatronLaborMaxBonus 2000 (cap 2000 → 4000). PatronLaborRegenOnlineBonus +10 and PatronLaborRegenOfflineBonus +5 per 5-minute interval. PatronXpBonusPct 10% (kills and quests). The Patron status (PatronStatusId 17): add StatusModifiers rows for stat bonuses.
Loyalty Tokens An ACCOUNT currency. A Patron's play time earns a claim every LoyaltyClaimIntervalMinutes (10). Each claim gives LoyaltyTokensPerClaim (1). Progress doesn't bank past one claim. LoyaltyMaxClaimsPerDay (0 = no limit) is counted per UTC day. GMs: GiveLoyalty (level 4, debug worlds).
Spending Currency shop offers with "CurrencyItemId": -2 (like -1 for honor). The Loyalty Exchange in currency-shops.json is the example.
Expiry Checked every 10 s. The buff comes off, the labor cap shrinks back (points above it stay but don't regenerate), and the player is told. Offline labor regeneration uses the Patron rate up to the end date, then the normal rate.

How it's stored#

  • The account_patron table in persistence (migration 20261018120000_AccountPatron, or SQL/account_patron.sql) has the end date, tokens, claim progress, claim day and claims today. It's raw SQL like world_outbox, so the EF model is unchanged.
  • It loads with the character (P2WCharacterLoadResponse.Patron, and the create response for a new character) into PlayerSession.Patron. It is saved in save-full (W2PCharacterSaveFullRequest.Patron, an upsert in the same transaction).
  • A Patron Pass used and the days it adds land together.
  • Tokens spent and the items bought land together.
  • A claim saves at once. Claim progress alone doesn't mark the session dirty; it rides along with the next save.
  • Without the migration Persistence logs "Patron and Loyalty Tokens are OFF" and returns no Patron data. The world server then hides it, and nothing breaks.
  • /characters/list returns the account part (labor + Patron) and, per character, coins, position and worn gear. The world server fills in the zone name and the header (labor counted up to now, Patron cap and rate included). Both the login roster and the return-to-selection roster carry it.

Protocol 38#

  • C2WPatronClaim (180), W2CPatronState (181).
  • CharacterSummary keys 5-10 (Gold, X, Y, Z, Gear, Location).
  • AccountSummaryData on W2CCharacterList (key 3) and W2CSelectionReturn (key 7).
  • PatronDto on load, create and save-full.
  • GmCommand 48 GrantPatron, 49 GiveLoyalty. EffectKind 41 GrantPatron (items only, Min = days).

Character select preview: making it look right#

  • Body: a rigged prefab in WorldObjectPrefabs under Character_Default (and Character_Faction{N}). Its gameplay scripts are stripped before it wakes. Only the Animator, renderers and CharacterSockets stay.
  • Idle: the body's Animator controller, with every float at 0 and only Grounded true, so the default state should be your idle. If the body has no controller, set Idle Clip on Resources/UI/Selection/CharacterPreviewVisuals. The asset also has the camera field of view and the background colour.
  • Gear: GearVisualCatalog rows (Tools > Axiom > Asset Pipeline > Create Gear Visual Catalog). Without rows, gear isn't drawn, in the world or here.
  • Not built: deleting a character (there's no server support yet), and a 3D backdrop. The stage is a colour plus a vignette and a floor glow.

Testing it#

  1. Apply the persistence migration (or run SQL/account_patron.sql), rebuild, and copy Axiom.Network.dll to Assets/AxiomMMOKit/Plugins. Start Persistence, then World. Patch 065 adds the status, the passes and their effects.
  2. GM panel > Grants > Patron: Add Patron Days 30 on yourself. The buff appears, the labor cap shows 4,000, and the Patron button appears bottom-left.
  3. Wait 10 minutes in the world, or set LoyaltyClaimIntervalMinutes to 1 in CombatRules. The button glows; click it, and a Loyalty Token arrives with a chat line.
  4. Right-click the button: the Loyalty Exchange, priced in tokens.
  5. Log out to character select: the header shows Patron, labor and tokens, and the character wears its gear.
  6. Buy a Patron Pass in the cash shop (credits), take it from the mailbox, and use it: +30 days.
