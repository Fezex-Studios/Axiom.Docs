Tools

Content Studio#

Tools ▸ Axiom ▸ Content Studio (Ctrl+Alt+E) edits every content table in worldserver.db as records instead of SQL. It is the main tool for designers: items, NPCs, skills, effects, quests, loot, shops, recipes, doodads, dungeons, world events, factions, sieges.

The workflow#

 edit  ──►  pending changes  ──►  validate  ──►  commit
            (undo/redo, kept       (Problems,     ├─ worldserver.db (one transaction, backed up first)
             across reloads)        live)         └─ SQL/patches/0NN_content_<title>.sql
  1. Edit. Nothing touches the database while you work. Changes are staged as state (each touched row's before and after), with undo/redo (Ctrl+Z / Ctrl+Y). They survive script reloads and editor restarts (Library/Axiom/ContentStudio.pending). Setting a field back to its original value removes the change.
  2. Validate. The inspector shows the selected record's problems live; Problems lists everything; F5 re-checks all tables.

  3. Commit (Ctrl+S):

    • backs up worldserver.db to Library/Axiom/WorldDbBackups (newest 15 kept);
    • in one transaction runs the generated patch against the database and records it in schema_versions, so the server's patcher won't run it again;
    • moves the patch into the server's SQL/patches.

    If any step fails, nothing changes. Restart the World server to see the change in game (content is read at start-up).

    Write patch only is for when the World server is running and holding the database: it writes the patch and nothing else, and the server applies it on its next start.

Generated SQL: new rows INSERT OR REPLACE, edits UPDATE … SET only the changed columns (two designers editing different fields of the same item don't overwrite each other), removed rows DELETE. Because content is a patch in SQL/patches, it goes through git like code, and a fresh database built from the patches gets it.

If the item changes names, icons or gear looks, the client needs a new gamedata.bin: Dev Tools ▸ Game Data ▸ export (or restart the World server, which rebuilds it) - see gamedata.bin.

The window#

Area
Sidebar Tables by category: Items, NPCs, Combat, Quests & Progression, Loot & Economy, Crafting, World, Factions & PvP; row counts, pending changes (•n), problem dots. Unannotated tables are under Other Tables, still editable.
Records Virtualised list, sortable; stripes for new/edited/deleted rows. Right-click: Duplicate (with or without children), Revert, Delete, Copy as SQL, Copy id. CSV export/import.
Inspector Header, live problems, a preview, grouped fields, child rows editable in place, Where used.
Dock Problems, Changes (before → after per field, per-row Revert), Activity.

Search#

Query Matches
iron sword every word appears somewhere in the row (including reference names)
rarity:epic that column contains the text (reference/enum names count)
Kind=11 that column equals the value
#new #modified #deleted #changed pending edits
#error #warning #issues validation results

Ctrl+K jumps to any record by name, id or table.

Field editors#

  • References show the target's name and id; click to pick, → to jump, or type an id. Some follow another column (Effects.RefId follows Kind, QuestObjectives.TargetId follows ObjectiveType). Special values are named (DoodadFuncs.NextPhaseId −1 = remove the doodad, 0 = stay).
  • Enums: dropdowns with the server's names (EffectKind, EquipSlot, InteractionActionType, ~30 more). Flags (CrowdControl): checklists.
  • Icons: preview + browser over Resources/Icons. Model keys (ModelType): the keys in the scene's WorldObjectPrefabRegistry with a prefab preview (open main_world).
  • Colours, durations (90000 ms = 1 min 30 s), percentages get hints. Keys of saved rows are read-only.

Previews#

Items (as players see them, where they come from, what they're used for) · Loot tables (odds, expected drops, a 1 000-kill simulator) · Recipes (cost vs sell price) · Doodads (the state machine graph, unreachable phases flagged) · World events (next six starts, 24 h timeline) · Quests (chain, objectives, rewards, XP share) · NPCs (DPS, abilities by priority, spawners) · Skills/statuses/doodad actions (effects as sentences: "Deal 10-14 Fire damage + 0.6× power") · Trade packs (payout per outlet by distance).

Record operations#
New (Ctrl+N) column defaults + next id; fills the parent link when added from a child grid
Duplicate (Ctrl+D) copies the row
Duplicate + children (Ctrl+Shift+D) copies the whole tree with new ids, re-pointing links between the copies (a doodad with its phases, actions, timers and effects; an NPC with abilities and phases)
Delete also removes owned rows; warns how many links elsewhere will break
CSV import previews new/changed/missing rows first; one undo step

Validation#

  • Generic (every column, from schema annotations): missing references, required references at 0, unknown enum values, out-of-range numbers, empty NOT NULL, missing icons (warning), unregistered model keys (info).
  • Domain rules mirror what the server's catalogues check at load: doodad phase graphs, quest chains that loop or have no giver, world event schedules, effects with no target, achievements, loot/recipe min ≤ max, faction/territory rules, one-row-per-item uniqueness, a gap-free experience curve.

Errors don't stop you working; committing with errors asks twice.

Worked example: a new sword that drops from wolves#

  1. Items ▸ Items, select an existing sword, Ctrl+Shift+D (duplicate with children: its Gear Stats come along). Rename it Fang Blade, set icon_name to a PNG under Resources/Icons, rarity, required level, sell price.
  2. In the inspector's Gear Stats child row: EquipSlot MainHand, WeaponKind Sword, damage min/max, stats.
  3. Gear Visuals child row: PrefabKey of the sword prefab, AttachType Socket, DrawnSocket MainHand, SheathSocket HipLeft.
  4. Loot & Economy ▸ Loot Entries, New: LootTableId = the wolves' table (the preview shows which NPCs use it), ItemId = Fang Blade, chance 2 %. The loot table preview's simulator shows how often it drops.
  5. F5, fix anything red, Ctrl+S. Restart the World server; export game data so clients see the name and icon.

The Item wizard does steps 1-4 in one form.

Teaching it about a new table#

A new server table appears automatically under Other Tables. To give it a category, references, enums and children, add an entry to Assets/AxiomMMOKit/Editor/ContentStudio/Schema/ContentSchema.Definitions.cs:

Category("World", "🗺");
// ...
T("Bounties", "Bounties", "Bounty")                 // table, plural, singular
    .Name("TargetName")                              // the column shown as the record's name
    .Ref("RewardItemId", "Items")                    // a reference (picker + validation)
    .Ref("NpcTemplateId", "NpcTemplates", true)      // true = required (0 is an error)
    .Enum("Kind", "BountyKind")                      // enum from ContentEnums.cs
    .Group("Reward", "RewardGold", "RewardItemId")   // inspector grouping
    .List("Id", "TargetName", "Kind", "RewardGold"); // columns in the records list

Conventions work before you annotate: …ItemId → Items, …NpcTemplateId → NpcTemplates, …StatusId → StatusTemplates, Is…/Has…/Can… → checkbox, …Ms → milliseconds, IconName → icon, ModelType → model key. New enum values go in Schema/ContentEnums.cs; new rules in Validation/ContentValidator.cs (Rules per row, TableRules per table); new previews derive from VisualizerBase under UI/Visualizers (found by reflection).
