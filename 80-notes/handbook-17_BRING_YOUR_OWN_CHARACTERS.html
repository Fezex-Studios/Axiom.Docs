17. Bringing Your Own Characters#

Axiom doesn't care which character models, skeleton or naming you use. The rules the character tools and the game follow live in one settings asset, the Character Pipeline, so a project can adapt them without changing code.

Open it: Dev Tools > Characters & Races > Pipeline. The first time, press Create Character Pipeline settings. It's saved at Assets/AxiomMMOKit/Axiom.Client/Resources/Characters/CharacterPipeline.asset, and without it the defaults apply, which are exactly how Axiom behaved before.

What a character needs#

Requirement Why How
Rig: Humanoid, Avatar mapping all green sockets, body splitting and animation retargeting all find bones through it FBX Inspector > Rig > Humanoid > Apply; Configure… to fix any bone it couldn't map
Skinned with real weights gear and the body split follow the weights Blender: Ctrl+P > With Automatic Weights, then tidy borders (waist, shoulders, wrists, neck, ankles) in Weight Paint
A body prefab: empty root, model as a child the game moves the root; the child carries the model root 0/0/0, child 0/0/0, child turned 180° if the model faces −Z (guide 16, A2)
The Animator: AxiomCharacter controller, Apply Root Motion off movement is the server's, not the animation's on the child's Animator
The same skeleton shape as its clothes skinned gear binds bone by bone one rig for every body in the project is easiest

Names don't have to match: see Bone aliases.

The four sections of the Pipeline#

Sockets#

The attachment points every body carries. Defaults: MainHand, OffHand, Back, BackOffHand, HipLeft, HipRight, Head.

Add your own (a quiver on the back, a belt pouch, a tail tip, wing mounts):

Field Meaning
Name what gear and Weapon Sheaths refer to (Quiver)
Bone the humanoid bone it hangs from (UpperChest)
Pose where a new one starts: InHand, BackDiagonal, BackFlat, HipLeft, HipRight, OnTop, AtBone
Description shown in the tools

New sockets appear straight away on Sockets (with Add missing sockets and Line up) and in the Gear Workshop's socket lists. To carry a weapon kind there, put the name in Content Studio > Weapon Sheaths.

Part rules#

Which body part each humanoid bone's skin belongs to, for Split body into parts. Leave it empty for the defaults:

Bones Part
Neck, Head, Jaw, Eyes Head
Spine, Chest, UpperChest, Shoulders Torso
Hips Legs (the pants cover the hips, not the top)
UpperArm, LowerArm Arms
Hand and fingers Hands
UpperLeg, LowerLeg Legs
Foot, Toes Feet

Add a row to change one, e.g. Hips → Torso if your tops are long tunics that always cover the hips. Then Split again on each body.

Name rules#

Text in a bone or mesh name that picks a part. Used two ways:

  • For bones the Avatar doesn't know. A rule wing → Torso makes the skin moved by wing_l, wing_r… part of the Torso. (More parts such as Wings and Tail arrive in Phase 2.)
  • For bodies split by hand in Blender. Name the pieces Body_Head, Body_Torso, Body_Arms, Body_Hands, Body_Legs, Body_Feet (the defaults match _head, _torso, _arms, _hands, _legs, _feet, and hair). Then press List meshes by name on the Sockets page instead of Split. Nothing is cut; each mesh is listed with its part.

Bone aliases and prefixes#

Gear binds to the body by bone name. When a name doesn't match exactly, the game tries again:

  1. Strip prefixes: mixamorig:, Bip01, DEF-, ORG-, Armature|… (built in), plus any you add.
  2. Aliases: built-in groups for the humanoid bones under Unity/Mixamo, Unreal, Blender (Rigify) and 3ds Max Biped names, for example:
Mixamo Unreal Blender 3ds Max
Hips pelvis Bip01 Pelvis
LeftArm upperarm_l upper_arm.L Bip01 L UpperArm
LeftHandIndex1 index_01_l f_index.01.L

Add your own groups for anything else (twist bones, custom names).

So armour made for a Mixamo body binds to an Unreal-named body, as long as the skeletons have the same shape. Aliases rename bones; they can't fix different proportions or rest poses. Armour still has to be modelled for the body's shape.

Test it: the Test: does this gear bind to this body? card at the bottom of the Pipeline page runs the game's own binding on any body and gear prefab, and logs ✓, or the bone it couldn't find.

Bringing in a new character, start to finish#

  1. Import the FBX: Rig Humanoid, Avatar Create From This Model, Apply; fix the mapping if it isn't all green.
  2. Body prefab: empty root + model child, 0/0/0; turn the child 180° if needed; Animator controller AxiomCharacter, Apply Root Motion off.
  3. Characters & Races > Bodies: drag it into its race / gender slot.
  4. Sockets page: Add missing sockets, then Line up each one with a reference weapon (guide 11, Part A).
  5. Body parts: Split body into parts (one mesh) or List meshes by name (already split in Blender).
  6. Pipeline > Test binding with a piece of armour. If a bone is missing, add an alias group, or fit the armour to this skeleton.
  7. Press Play: walk forward (he should run away from the camera), equip gear, draw and sheathe a weapon.

Races and body types are data (Phase 2)#

Races and body types live in the world database, not in code:

Table (Content Studio) Columns Notes
Races Id, Name, Description, FactionId, IsPlayable, SortOrder Name is one word: it's the art name (Character_{Name}_{BodyType})
Body Types Id, Name, Description, IsPlayable, SortOrder Male and Female by default; add Large, Slim, Child…

To add a race (e.g. Dwarf): Content Studio > Races > New: Id 4, Name Dwarf, a description, SortOrder 40. Ctrl+S. Restart the World server. It's on the creation screen at the next login, and gets a row on Characters & Races > Bodies for its body prefabs. No code, no DLL rebuild, no migration.

To add a body type (e.g. Large): Content Studio > Body Types > New. Bodies are then Character_{Race}_Large, and gear variants {Prefab}_Large.

  • Never change an Id once characters use it: it's saved on them.
  • IsPlayable = 0 hides a race from the creation screen; existing characters of that race keep it.
  • FactionId ties a race to one starting faction (0 = any).
  • The World server reads the tables on start and sends them to every client with the character list.

32 body parts (Phase 2)#

Hide body parts now has 32 flags. The original seven keep their values; the new ones:

Flag Use it for
Hips its own part only if a Part rule says Hips → Hips (by default the hips stay with Legs)
Shoulders, Neck pauldrons, high collars
Ears, Beard helmets that hide elf ears; masks
Wings, Tail non-human races: name rules wing → Wings, tail → Tail
Underwear the body's always-on underwear meshes (below)
Custom1–Custom8 anything your project needs; write down what each means

To use a new part: add a Part rule or Name rule that produces it, Split again (or List meshes by name), then tick it in Hide body parts on the gear that covers it.

The underwear layer#

So a character wearing nothing isn't bare: model underwear as its own mesh on the body, named e.g. Body_Underwear. Add a name rule underwear → Underwear and press List meshes by name (or keep it out of the automatic split; it's a separate mesh already). It's always drawn, except under gear that hides Underwear: tick that on pants, robes, costumes and undergarment items.

New equipment slots (Phase 2)#

Slot Id Notes
Shoulders 13 pauldrons; Socket (rigid) or Skinned
Cloak 14 usually Skinned; hide nothing, or Torso if it wraps
Belt 15 Skinned or Socket on the hips
Wrists 16 bracers
Costume 17 drawn over armour: while worn, Chest, Legs, Hands, Feet, Shoulders, Belt, Wrists and Undergarments aren't drawn (their stats still count). Head, Cloak and weapons still show, as in classic MMOs
Undergarments 18 underwear as an item; usually hides the body's Underwear part

Slot 12 stays unused: it was the removed Glider, and old saved gliders in it are skipped. Use the new slots like any other: an item's Gear stats > EquipSlot, then the Gear Workshop. They appear in the Character window.
