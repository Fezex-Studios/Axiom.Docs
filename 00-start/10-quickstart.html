Getting Started

Quick Start#

The fast way: open the Unity project and follow Tools ▸ Axiom ▸ Setup (Axiom Setup). It opens by itself on the first import, checks each step below, and does most of them with one button: packages, unzipping the server, the secret and MySQL login for all four servers, the databases, the right world database, a test account. This page is the same thing by hand.

About an hour the first time. Windows is assumed (the scripts are .bat); Linux/macOS work the same with the dotnet commands.

1. Install#

Tool For
.NET 10 SDK building and running the servers (dotnet --version)
dotnet-ef (optional) dotnet tool install --global dotnet-ef - only to add migrations, or to run them by hand with Persistence's AutoMigrate off
MySQL 8 (Community Server + Workbench) accounts, player data, auctions
Unity (the version in the client's ProjectSettings/ProjectVersion.txt, with HDRP) the client and the editor tools
Python 3 (optional) the terrain mask-map helper
VS Code + Lua extension (optional) Lua scripting with autocompletion

Put the two repositories side by side, e.g. F:\Development\AxiomCore (server) and F:\Development\AxiomCore\Axiom.Client (Unity). If the Art folder is kept separately, copy it to Axiom.Client/Assets/AxiomMMOKit/Axiom.Client/Art before opening Unity.

2. MySQL#

CREATE DATABASE axiom_auth        CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE axiom_persistence CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE axiom_auction     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'axiom'@'localhost' IDENTIFIED BY 'choose-a-password';
GRANT ALL PRIVILEGES ON axiom_auth.*        TO 'axiom'@'localhost';
GRANT ALL PRIVILEGES ON axiom_persistence.* TO 'axiom'@'localhost';
GRANT ALL PRIVILEGES ON axiom_auction.*     TO 'axiom'@'localhost';

3. Local settings and secrets#

Each server folder (src/Servers/Axiom.Server.*) has an appsettings.Local.example.json. Copy it to appsettings.Local.json (git-ignored) and fill it in. Generate one secret and use it in all four:

[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(48))   # PowerShell 7; or: openssl rand -base64 48
Server Keys
World World:InternalSecret, World:ClientContent:KeyHex (64 hex chars = the client's game data key)
Auth Auth:InternalSecret, ConnectionStrings:Auth
Persistence InternalSecret, ConnectionStrings:Persistence
Auction Persistence:InternalSecret, ConnectionStrings:AuctionDb

Connection string shape: Server=127.0.0.1;Port=3306;Database=axiom_persistence;User=axiom;Password=…;. Every key: Configuration. The game data key must match GameDataCrypto in the client; Tools ▸ Axiom ▸ Project Setup and Health checks and fixes this for you.

4. Database tables#

Nothing to do: Persistence, Auth and Auction each create their tables on first start (Persistence's AutoMigrate, default on, applies its EF migrations), and the World server builds worldserver.db from migrations + SQL patches. The CREATE DATABASE lines above are only needed when the MySQL user isn't allowed to create databases.

5. Start the servers - in this order#

cd src/Servers/Axiom.Server.Persistence && dotnet run     # HTTP 127.0.0.1:7778
cd src/Servers/Axiom.Server.Auth        && dotnet run     # HTTP :3000
cd src/Servers/Axiom.Server.World       && dotnet run     # UDP :7777
cd src/Servers/Axiom.Server.Auction     && dotnet run     # HTTP 127.0.0.1:5090 (optional)

Each in its own terminal (or Tools ▸ Axiom ▸ Server Control ▸ Start All from Unity, which builds and starts them in this order with a log tab each). The World server's first start runs migrations and every SQL patch, builds gamedata.bin, loads all catalogues and opens UDP 7777 - read its log; it should end with the tick loop running and no errors.

6. An account#

Invoke-RestMethod -Method Post http://127.0.0.1:3000/register -ContentType application/json `
  -Body '{"username":"aidan","password":"choose-a-password"}'

Make it staff (for the GM panel, F12): UPDATE axiom_auth.accounts SET access_level = 5 WHERE username = 'aidan';

7. Open the client#

  1. Open Axiom.Client in Unity (first import takes a while).
  2. Tools ▸ Axiom ▸ Home → Settings: the server repository, the World database, the SQL patches folder (…/SQL/patches). Then fix anything red in Status. For the World database pick the copy the server runs, …/Axiom.Server.World/bin/Debug/net10.0/Data/worldserver.db (Server Control runs the Debug build): Content Studio, Push Content and the wizards then edit the database the running server uses. Setup's step 7 picks it for you.
  3. Tools ▸ Axiom ▸ Project Setup and Health: everything green (game data key and paths, DLL protocol).
  4. Open the server_select scene (Assets/AxiomMMOKit/Axiom.Client/World/server_select.unity).

8. Play#

The editor has no launcher. Select the ClientNetwork object in the scene and, in its Inspector under Editor Login, enter the account's Username and Password (leave Log in when I press Play on). They're saved on this machine only, not in the scene; use a test account.

Press Play: the editor logs in, the token is used for that session, then pick the world, create a character, enter. Every Play logs in again (a launch token is one use and lasts 120 s). Without Editor Login, paste a token from /login into Editor Token (Login & world entry).

Two clients at once: clone the project with ParrelSync and give each clone its own account in Editor Login.

If something's wrong#

  • Server list empty: the World isn't reporting to Auth (secret, WorldDirectory:Id, PublicHost).
  • "Protocol mismatch": rebuild Axiom.Network and copy the DLLs into Assets/AxiomMMOKit/Plugins.
  • Disconnected after loading: re-export movement collision (Tools ▸ Axiom ▸ Server Exports ▸ Movement Collision ▸ Export).

More in Troubleshooting. Next: Project layout and the Learning path.
