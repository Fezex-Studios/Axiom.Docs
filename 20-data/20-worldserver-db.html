Data & Databases

worldserver.db#

worldserver.db is a single SQLite file that holds every piece of game content: items, NPCs, skills, effects, statuses, loot, quests, doodads, recipes, shops, trade, dungeons, factions, territories, world events, mounts, achievements and the combat formula numbers. It holds no player data. A fresh copy plus the SQL patches is the whole game design.
Path World:Database:WorldDb, default Data/worldserver.db next to the World server exe (in the repo: src/Servers/Axiom.Server.World/Data/worldserver.db, copied to bin/…/Data/ on build)
Opened by the World server (EF Core, read at boot), Content Studio and Dev Tools in Unity (direct SQLite)
Size ~90 tables, a few hundred KB
Browse it Content Studio, or any SQLite browser (DB Browser for SQLite)

Every table, column, reference, enum and sample row is listed in the generated worldserver.db reference.

Schema vs content: two version streams#

Schema (tables, columns, indexes) Content (rows)
Lives in src/Servers/Axiom.Server.World/Migrations/*.cs (EF Core migrations) src/Servers/Axiom.Server.World/SQL/patches/*.sql
Tracked in __EFMigrationsHistory schema_versions (patch, applied_at)
Applied by db.Database.MigrateAsync(), boot step 0b GameDataPatchRunner.RunAsync(), boot step 0c
Written by a programmer, by hand Content Studio / Create wizards (automatically), or by hand

Both run every time the World server starts, schema first, before anything else touches the database. Then the World server builds gamedata.bin from the result.

SQL patches#

GameDataPatchRunner (Utils/Database/SQLite/GameDataPatchRunner.cs):

  1. Creates schema_versions if missing.
  2. Lists *.sql in World:Database:PatchDirectory (default: SQL/patches next to the exe), sorted by file name (ordinal), so 026_… runs before 101_….
  3. Skips any file whose name is already in schema_versions.
  4. Runs each new file in a transaction and records it. A failing patch is rolled back and stops the server: [Patcher] Failed applying X — rolled back. Fix the script and restart.

Conventions:

  • Name: NNN_short_description.sql, the next free number. Content Studio writes NNN_content_<title>.sql.
  • First lines: a comment saying what it does and what it needs (the patch list in the reference shows these headers).
  • Idempotent: INSERT OR REPLACE, UPDATE … WHERE, DELETE … WHERE. A patch should be safe to run on a database that already has some of it.
  • Never edit a patch that has been applied anywhere. Its name is in schema_versions, so the edit will never run. Write a new patch.
  • Patches are content only. A patch that creates tables (only 056_class_based_characters.sql does, historically) belongs in a migration.

The patch runner only runs patches whose names are new. Renaming a patch re-runs it.

Migrations#

World migrations are hand-written and idempotent, in this style (Migrations/20261026100000_AppearanceOptions.cs):

[DbContext(typeof(WorldDataDbContext))]
[Migration("20261026100000_AppearanceOptions")]
public partial class AppearanceOptions : Migration
{
    protected override void Up(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.Sql(@"
CREATE TABLE IF NOT EXISTS ""AppearanceOptions"" (
    ""Id""   INTEGER NOT NULL CONSTRAINT ""PK_AppearanceOptions"" PRIMARY KEY,
    ""Kind"" INTEGER NOT NULL,
    ""Name"" TEXT NOT NULL,
    CONSTRAINT ""CK_AppearanceOptions_Kind"" CHECK (Kind BETWEEN 1 AND 6)
);
INSERT OR IGNORE INTO ""AppearanceOptions"" (Id, Kind, Name) VALUES (101, 1, 'Natural');");
    }

    protected override void Down(MigrationBuilder migrationBuilder) =>
        migrationBuilder.Sql(@"DROP TABLE IF EXISTS ""AppearanceOptions"";");
}

The id is a timestamp (yyyyMMddHHmmss_Name), so migrations sort in time order. Seeding a few starter rows with INSERT OR IGNORE in the migration is fine; real content goes in patches. Full walkthrough: Add a worldserver.db table.

How the World server reads it#

Each system has a catalog that loads its tables once at boot (step 3b on the World server page) and keeps them in memory. The pattern, from Core/Doodads/ClimateService.cs:

// 1. An entity class per table: GameData/Climate/Climate.cs
public class Climate
{
    public int    Id       { get; set; }
    public string Name     { get; set; } = string.Empty;
    public string ColorHex { get; set; } = "#FFFFFF";
}

// 2. A DbSet in Utils/Database/SQLite/WorldDataDbContext.cs
public DbSet<Climate> Climates => Set<Climate>();

// 3. A catalog that loads once and validates
public void LoadFromDatabase()
{
    using var db = _dbFactory.CreateDbContext();                // short-lived context
    Load(db.Climates.AsNoTracking().ToList(), db.ZoneClimates.AsNoTracking().ToList());
}

public void Load(IEnumerable<Climate> climates, IEnumerable<ZoneClimate> zones)   // testable without a db
{
    _climates = climates.ToDictionary(c => c.Id);
    foreach (var z in zones)
    {
        if (!_climates.ContainsKey(z.ClimateId))
        {   // bad rows are skipped with a warning, never crash the server
            Logger.Warn("[Climate] ZoneClimates {Id}: climate {Climate} doesn't exist - skipped", z.Id, z.ClimateId);
            continue;
        }
        // ...
    }
    Logger.Info("[Climate] {Climates} climate(s), {Zones} zone(s) with climates.", _climates.Count, _byZone.Count);
}

Consequences:

  • Content changes need a World restart. There's no hot reload.
  • Bad rows are skipped and logged, not fatal. Read the World log after changing content: [Loot] … skipped, [Quests] … unknown item. Content Studio runs the same checks before you commit.
  • Load order matters. Items load first because quests, shops, loot and recipes check item ids against ItemManager.

Naming#

Two naming styles exist, for history:

  • The oldest tables use snake_case columns: Items (item_id, icon_name, category_id, rarity_id, vendor_price...).
  • Everything newer uses PascalCase: NpcTemplates.MaxHealth, Effects.OwnerType.

Table names are PascalCase plurals. Keys are Id (or item_id), integers chosen by you, not auto-increment in practice: Content Studio's New picks the next id.

The table families#

Items 📦#

Table What
Items Everything that can be in a bag: name, description, icon, category, rarity, required level, bind type, no_trade, max_stack, vendor_price (copper).
ItemCategories, ItemRarities Tooltip labels; rarity has the name colour.
ItemStats Gear only: EquipSlot, WeaponKind/ArmorKind, TwoHanded, AllowedClasses (class mask), primary and secondary stats, SocketCount, MaxDurability, base/max grade. One row per item.
ItemUses What right-click does: ConsumeOnUse, CooldownMs + CooldownGroup, CastTimeMs, LaborCost. The actual effects are Effects rows with OwnerType = 1 (Item) and OwnerId = the item.
ItemGrades, ItemGradeDistributions 12 grade tiers (Crude, Basic, Grand, Rare, Arcane, Heroic, Unique, Celestial, Divine, Epic, Legendary, Mythic) with colour, stat multipliers and upgrade odds; ItemGradeDistributions gives grade roll weights per loot source.
ItemGems, ItemUpgradeMaterials Socket gems and regrade/upgrade materials.
GearVisuals, GearVisualSlotDefaults, WeaponSheaths How gear looks: prefab key, attach type (skinned or socket), drawn/sheath sockets, hidden body parts, offsets. Exported into gamedata.bin.
Races, BodyTypes, AppearanceOptions Character creation: races, bodies per race and gender, skin/hair/eye colours, hair styles, face presets.
TreasureMaps, TreasureLoot Treasure map items and what digging gives.

NPCs 🧌#

Table What
NpcTemplates Every creature or character: model key, rank, health, armor, damage, aggro radius, XP, loot table, AI profile, faction, title, greeting.
NpcSpawners Where they appear: template, position, count, radius, respawn time, movement type (wander, patrol path, stationary), active hours, dungeon.
NpcAbilities What an NPC casts: skill, Priority, target, health window (MinHealthPct–MaxHealthPct), boss Phase, Chance, CooldownMs, InitialDelayMs.
NpcPhases Boss phases: below HealthBelowPct enter Phase, yell, summon adds.
AiProfiles Combat role (Role: melee, caster, healer...), HealBelowPct, AssistRadius.
SpawnPointTables Player spawn and respawn points.
Mounts, PetBuffs Mount model, SpeedMultiplier, CanCarryPack, CanFly and flight speeds; statuses a pet gives its owner.

Combat ⚔#

Table What
Classes Warrior, Healer, Mage (CharacterClassRules).
Skills Every ability: class, target rule, range, radius, cast time, cooldown, mana, max rank, required level/weapon, flags (passive, starter, spell, interaction, NPC-only), animation parameter.
SkillSteps Multi-step skills: combos, cones, channels, chains, projectiles.
Effects What everything does. See below.
StatusTemplates, StatusModifiers Buffs/debuffs/DoTs: duration, tick, stack rule, dispel type, crowd control flags; stat modifiers.
AbilityPassiveModifiers Passive skills' stat changes.
CombatRules Key/value: every number in the stat and combat formulas (StatBase, HealthPerVitality, CritMultiplier...). A key not in the table uses the default in GameRules.
ExperienceLevels XP needed per level.

Effects: the universal verb table#

Effects is polymorphic. Every row says who owns it and what it does:

Column Meaning
OwnerType + OwnerId 1 Item (ItemUses), 2 Skill, 3 Status (ticks), 4 legacy doodad func, 5 Doodad function template, 6 Skill step
Kind 0 Script, 1 Heal, 2 Apply Status, 3 Cast Skill, 4 Mount, 5 Summon Pet, 6 Damage, 7 Dispel, 8 Taunt, 9 Interrupt, 10 Summon NPC, 11 Give Item, 12 Place Doodad, 13 Open Crafting, 14 Enter Dungeon, ... 41 Grant Patron
RefId what Kind refers to (a status for Apply Status, an item for Give Item, a doodad template for Place Doodad...)
Target, School, min/max, scaling, chance, Sort how and in which order
RequiresStatus, BonusStatus, ConsumesStatus combo conditions

So a potion, a fireball, a poison tick and "open this chest" are all just Effects rows run by one EffectApplier. Adding a new verb means a new EffectKind value and a case in the applier (Add an ability).

Quests & progression 📜#

Quests (giver, turn-in, prerequisite, rewards, repeatable, time limit), QuestObjectives (type: kill, collect, talk, craft, use item, use skill, enter area, interact, kill group, kill in zone, reach level, complete quest, gather, proficiency rank; TargetId depends on type), QuestRewards (choice lists), QuestCategories, QuestAreas, QuestMonsterGroups(+Npcs), Achievements, CollectionItems, Titles.

Loot & economy 💰#

LootTables + LootTableEntries (group 0 entries roll their own chance; each other group rolls once and drops one entry by weight), LootGroups, NpcLootTables (extra tables per NPC), Shops + ShopItems, TradePacks, TradeOutlets, TradeRoutes, FishingLoot.

Crafting ⚒#

Professions, ProficiencyRanks, Recipes (station, output, labor, profession, rank), RecipeMaterials, RecipeGrades.

World 🗺#

Table What
DoodadTemplates Interactive objects: model key, start/broken phase, persistent, place rule, blocking box, climate, health.
DoodadPhases A doodad's states (seedling → grown → harvested).
DoodadFuncs What F/G do in a phase: action type, function template, required item/profession/rank, labor, access, next phase (−1 = remove).
DoodadFunctionTemplates Reusable behaviours with their Effects.
DoodadPhaseFuncs Timers: after N ms go to phase X.
DoodadSpawns World-placed doodads (ore, herbs, chests, stations).
InteractableActions NPC right-click actions (talk, shop, mailbox, auction, quests...).
Dungeons, DungeonRooms, DungeonEvents, DungeonActions Instanced dungeons and their scripted events.
HousingAreas, Climates, ZoneClimates, ClimbRoutes, WorldEvents, Vehicles, FurnitureInteractionSkills

Factions & PvP 🛡#

Factions, FactionRelations, Territories, SiegeWeapons, SiegeRewards, LodestoneRewards, CastleUpgrades, ZoneFestivals, ZoneConflicts.

Unused leftovers: HarvestNodeTemplates/HarvestNodeSpawns (replaced by doodads), TestTableOnes.

Editing content safely#

Tool Use for
Create wizards (Tools ▸ Axiom ▸ Create ▸ …) A new item, NPC, loot table, world object or dungeon, with every related row, in one guided window.
Content Studio (Tools ▸ Axiom ▸ Content Studio, Ctrl+Alt+E) Editing anything: records, references, enums, validation, undo, previews.
Dev Tools tabs Spatial data: spawn points, doodad spawns, zones, world map.
A hand-written patch Bulk changes, data migrations, anything scripted.

When Content Studio commits it backs up the db (Library/Axiom/WorldDbBackups, newest 15), runs the patch and records it in schema_versions in one transaction, and moves the patch file into SQL/patches. The World server then won't run it again, and a teammate's fresh database gets it from git. If the World server is running (holding the file), use Write patch only: the server applies it on its next start.

Commit the patch files. worldserver.db itself is a build product: anyone can rebuild it from migrations + patches. The patches are the source of truth.

Rebuilding from scratch#

Delete (or rename) Data/worldserver.db and start the World server: migrations create every table, then every patch runs in order. If that fails, a patch depends on data it doesn't create; fix it with a new earlier-sorting patch or a migration seed.

Ids and conventions#

  • Choose id ranges per kind of content so ids are recognisable (the shipped data has low ids for the original test content, 6000s and 90000s for later items, 970000+ for Gear Workshop gear). Whatever you choose, never reuse an id players may hold: inventories, mail and auctions in MySQL store item ids.
  • Times are milliseconds (CooldownMs, DurationMs), money is copper (10 000 copper = 1 gold).
  • Model keys (ModelType, PrefabKey) are strings resolved on the client by the prefab catalogue (Art & assets).
  • Icon names resolve under Resources/Icons on the client.
