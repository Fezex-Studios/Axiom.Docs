Axiom project layout#

How the server repository and the Unity client are organized, and where new things go. Set up by tools/Reorganize-Server.ps1 (server) and Tools > Axiom > Project > Reorganize Folders... (client). Both only moved files: no code or logic changed, and namespaces were kept as they were.

Server repository (AxiomCore)#

AxiomCore/
  AxiomCore.slnx                 solution, grouped: Shared / Servers / Tools / Tests
  src/
    Axiom.Network/               SHARED with the client (built into Assets/AxiomMMOKit/Plugins): packets, protocol, DTOs
    Axiom.Movement/              SHARED with the client: movement, collision, prediction
    Axiom.Navigation/            navmesh (server)
    Axiom.Server.World/          the game simulation (below)
    Axiom.Server.Auth/           login, accounts, tokens
    Axiom.Server.Persistence/    MySQL character storage service
    Axiom.Server.Auction/        auction house service
    Axiom.LoadTest/              bot load generator (tool)
    Axiom.Tools.NavBake/         navmesh baker (tool)
  tests/
    Axiom.Server.World.Checks/   run-anywhere checks (dotnet run; exit 0 = pass)
  tools/                         dev tools and scripts (Reorganize-Server.ps1, DevTools, MySQL setup)
  scripts/                       start / build batch files
  docs/                          architecture and system docs (start at 00-INDEX.md)
  archive/                       old one-off data kept for reference, never shipped

Project folders keep their names and places under src/: the Unity editor tools and the build validator find the server by those paths.

Inside Axiom.Server.World#

Program.cs                       entry point (the only code file at the root)
Bootstrap/                       ServerBootStrap, DemoServiceBootstrap
Core/
  WorldServer.cs                 composition root: builds and wires every service
  Simulation/                    the tick: TickClock, TickPacer, Scheduler, ServerClock, queues, TickHealthMonitor
  Players/                       PlayerManager (+ partials), PlayerSession, PlayerSpawnManager, SessionManager
    Components/                  per-session state (inventory, equipment, quests, ...)
    Saving/                      CharacterPersistence, CharacterSaveChain, AutosaveScheduler
  Movement/                      authoritative movement, validation, zone workers, broadcasts
  Interest/                      InterestManager (+ partials), ReplicationManager, spatial grid, spawn delivery
  Npcs/                          NpcAiManager, SpawnManager, NpcCollisionService
  Companions/                    PetManager, MountManager
  Combat/  Items/  Loot/  Quests/  Economy/  Shops/  Social/  Interaction/  Housing/  Trade/ ...
                                 one folder per game system: its manager, rules and helpers together
  Packets/
    C2WHandlers/                 one handler per client->world packet
    W2CSenders/                  one sender per world->client packet
  Lua/                           the Lua engine and its bindings (Server SDK)
  Dev/                           demo / development-only code
GameData/                        database models (EF) for content tables
Migrations/                      world database migrations
SQL/patches/                     numbered content patches (applied once at startup)
Data/                            runtime data copied next to the server (database, navmesh, collision)
Lua/Server/                      server scripts (loaded at startup)
LuaSDK/Server/                   Lua SDK: guide, editor definitions, examples
Docs/                            World server docs

Namespaces. Files kept their namespaces when they moved (CombatManager is still Axiom.Server.World.Core.Managers while living in Core/Combat/), so nothing had to be edited. New files should use their folder's namespace. Aligning the old ones is a separate, optional, mechanical pass (rename namespace + add usings, then build).

Where new code goes - A new game system: Core/<System>/ with its manager, rules and data together. - A new packet: the DTO in Axiom.Network/Shared/Packets/..., the handler in Core/Packets/C2WHandlers/, the sender in Core/Packets/W2CSenders/ (docs/ADDING_PACKETSv2.md). - A content table: model in GameData/, migration in Migrations/, data in SQL/patches/. - Anything run only by developers: Core/Dev/ or a project under tools/ / src/Axiom.Tools.*.

Unity client#

<Unity project>/
  Assets/
    Axiom/                       everything that is ours
      Code/                      ALL game C#: Axiom.Client.asmdef lives here (one assembly)
        Core/  Networking/  Movement/  Gameplay/  UI/  World/  GameData/  Exploration/  Pvp/
        Staff/  Interfaces/  ClientConfig/  Testing/  Debug/
        Editor/                  editor code that is part of the game assembly (as before)
      Editor/                    editor tools: Content Studio, Dev Tools, Hub, checks, pipelines
      Scenes/                    server_select, main_world, Tiles/ (streamed terrain tiles)
      Content/                   Prefabs/, Housing/, Furniture/, Data/ (gameplay assets)
      Art/                       Animations/, Characters/, Materials/, Brushes/
      Resources/                 only what's loaded by name at runtime (Resources.Load paths unchanged)
      LuaUI/                     designer Lua UI scripts (000_axiom_sdk.lua loads first)
      Settings/                  input actions
      Docs/                      client docs
      Databases/                 development databases (gamedata source, encrypted output)
    Plugins/                     Axiom.Network.dll, Axiom.Movement.dll, MoonSharp, ParrelSync, Sirenix
    Packages/  NuGet/            NuGetForUnity (must stay where NuGetForUnity puts them)
    StreamingAssets/             files read at runtime by path (must stay here)
    Settings/                    HDRP render pipeline assets (Unity's convention)
    TextMesh/                    third-party
  LuaSDK/Client/                 the client Lua SDK (not a Unity asset)

Rules that keep it working - All game C# goes under Assets/Axiom/Code/. That folder is the Axiom.Client assembly; a script anywhere else compiles into a different assembly. - Editor-only C# goes under Assets/Axiom/Editor/ (a folder named Editor). - Move assets inside Unity (Project window or AssetDatabase.MoveAsset), never in Explorer: Unity then keeps every reference. - Resources/ only for things loaded by name. Everything else is referenced directly. - Never move StreamingAssets/, Plugins/, Packages/ or NuGet/. - Folders are PascalCase. Third-party code stays in its own folder, unmodified.
